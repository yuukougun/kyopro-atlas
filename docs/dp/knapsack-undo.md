!!! abstract "要点"
    - **何ができるか**：数え上げの部分和 DP の更新は逆向きに解けるので、表を作り直さずに要素を 1 つ取り除いた状態へ $O(K)$ で戻せる。max・min・可否（OR）の DP は戻せないので、前後からの DP のマージや、時間軸の分割統治を使う。
    - **いつ使うか**：
        - 要素の追加と削除のクエリのたびに、和が K になる選び方の数を答える。
        - 各 i について、i を使わないときの答え（〜を除いたとき）を求める。
        - クエリの数 Q と目標の和 K がともに 5000 程度（$O(QK)$ が通る）。
    - **計算量**：和（重さ）の上限を $K$ として、追加・削除は 1 回 $O(K)$。前後からのマージは前計算 $O(NK)$ と各 $i$ で $O(K)$。時間軸の分割統治は $O(QK \log Q)$。
    - **前提**：[部分和 DP](../dp/subset-sum.md)、[ナップサック DP](../dp/knapsack-01.md)

戻す DP は、数え上げの[部分和](../dp/subset-sum.md)の表から、すでに入れた要素を 1 つ取り除く方法である。追加の更新 $\mathrm{dp}[s] \mathrel{+}= \mathrm{dp}[s - x]$ は足し算だけでできているので、引き算で逆にたどれる。逆にたどれない max や可否の DP では、表を前後から作っておいて合わせる方法に切り替える。

## 足し算の更新は引き算で戻せる（ループの向きは追加と逆） {#undo-by-subtraction}

箱に整数を入れたり出したりするたびに「箱の中から和がちょうど $K$ になる選び方の数」を答える問題を考える。表を毎回作り直すと 1 回 $O(NK)$ かかり、$Q$ 回で $O(QNK)$ になる。$Q = K = 5000$ なら $10^{11}$ を超えて間に合わない。追加は 1 回 $O(K)$ の更新で済むので、削除も $O(K)$ でできれば全体は $O(QK)$ になる。

表の意味は「$\mathrm{dp}[s]$ ＝ いま箱にある要素から選んで、和を $s$ にする選び方の数」である。同じ値の要素も別のものとして数える。空の箱では $\mathrm{dp}[0] = 1$ で、ほかは 0 である。値 $x$ を入れると、新しい表 $\mathrm{dp}'$ は「$x$ を選ばない」と「$x$ を選ぶ」の和になる。

$$
\mathrm{dp}'[s] = \mathrm{dp}[s] + \mathrm{dp}[s - x] \quad (s \ge x)
$$

$s < x$ では $\mathrm{dp}'[s] = \mathrm{dp}[s]$ である。1 本の配列で書くときは、[0-1 ナップサック](../dp/knapsack-01.md#dp-rolling-array)と同じく $s$ の大きい方から更新する。

**戻せる理由**。この表は、どの順に要素を入れても同じになる（箱の中身の多重集合だけで決まる）。だから取り除きたい $x$ を「最後に入れた要素」とみなしてよい。最後の更新の式を移項すると、元の表が求まる。

$$
\mathrm{dp}[s] = \mathrm{dp}'[s] - \mathrm{dp}[s - x]
$$

右辺には元の表の $\mathrm{dp}[s - x]$ が要る。$s$ の小さい方から求めれば、$\mathrm{dp}[s - x]$ は先に元へ戻っている。$s < x$ の部分は追加で変わらないので、そこから始めればよい。追加は大きい方から、削除は小さい方から、とループの向きが逆になる。

次の図は、要素 $\{1, 3\}$ の表に 2 を入れてから取り除く様子である。追加では上の表の $\mathrm{dp}[s - 2]$ を足し、削除では戻し終えた $\mathrm{dp}[s - 2]$ を引く。

![要素 1 と 3 の表 1 1 0 1 1 0 0 に 2 を追加すると、s の大きい方から dp[s − 2] を足して 1 1 1 2 1 1 1 になる。削除では s の小さい方から、戻し終えた dp[s − 2] を引いて 1 1 0 1 1 0 0 に戻る](../img/knapsack-undo/add-remove.svg)

数は大きくなるので、ふつうは素数 $p$（998244353 など）で割った余りで持つ。足し算と引き算は余りのままでも成り立つから、削除も余りの表で正しく戻る。C++ では引いた結果が負にならないよう $p$ を足してから余りを取る。

追加と削除はどちらも表を 1 回なめるだけなので 1 回 $O(K)$ になり、$Q$ 回のクエリは $O(QK)$ である。

**ほかの更新でも同じ考え方が使える**。表を多項式 $f(z) = \sum_s \mathrm{dp}[s] z^s$ とみると、値 $x$ の追加は $(1 + z^x)$ を掛けること、削除は $(1 + z^x)$ で割ることにあたる。定数項が 1 の多項式で割る操作は、$K$ 次までに限っても一通りに決まる。同じ見方で、個数制限なしの数え上げの更新も戻せる。

| 更新 | 追加の向き | 削除の更新と向き |
| --- | --- | --- |
| 0-1（$(1 + z^x)$ を掛ける） | $s$ の大きい方から $+\mathrm{dp}[s - x]$ | 小さい方から $-\mathrm{dp}[s - x]$ |
| 個数制限なし（$1 / (1 - z^x)$ を掛ける） | $s$ の小さい方から $+\mathrm{dp}[s - x]$ | 大きい方から $-\mathrm{dp}[s - x]$ |

母関数としての見方は[母関数による数え上げ](../comb/generating-function-counting.md#dp-as-polynomial)と[形式的冪級数](../math/fps-basics.md)にある。

## 戻せない DP（max・min・OR） {#not-undoable}

戻す DP が使えるのは、更新が足し算だけでできている数え上げの DP である。価値の最大を持つナップサック、最小の個数を持つ DP、作れるかどうか（OR）の DP は戻せない。

理由は、$\max$ や OR には引き算にあたる逆の演算がないからである。たとえば重さ 1・価値 5 と、重さ 1・価値 3 の品物があり、重さの上限が 1 なら $\mathrm{dp}[1] = 5$ である。価値 5 の品物を取り除いた後の答えは 3 だが、表には 5 しか残っておらず、3 の情報は $\max$ を取ったときに捨てられている。可否の DP でも同じことが起きる。箱が $\{2, 2\}$ のときと $\{2\}$ のときで、和 3 までの可否の表は同じ（$\mathrm{can}[0]$ と $\mathrm{can}[2]$ だけが true）になる。2 を 1 つ除くと、$\{2, 2\}$ からなら $\mathrm{can}[2]$ は true のまま、$\{2\}$ からなら false になるべきだが、表からはどちらか区別できない。

可否を知りたいだけなら、選び方の数を素数で割った余りで数え、余りが 0 でなければ作れると判定する手がある。数え上げなので戻せる。ただし、法を素数 $p$ とすると、選び方の数がちょうど $p$ の倍数のときは作れるのに 0 と出る。法を 2 つ使うか乱択で選ぶと、外れる確率をさらに下げられる。

max・min の DP で要素を除きたいときは、取り除く操作そのものをやめる。除く要素が「各 $i$ について 1 つずつ」なら[前後からの DP のマージ](#prefix-and-suffix)、追加と削除が任意の順に来るなら[時間軸の分割統治](#offline-divide-and-conquer)を使う。

## 前後からの DP をマージする {#prefix-and-suffix}

「各 $i$ について、品物 $i$ を使わないときの最大の価値」を求めたいとする。品物 $i$ を除いた $N - 1$ 個は、前の $i$ 個（$0, \dots, i - 1$）と後ろの $N - i - 1$ 個（$i + 1, \dots, N - 1$）に分かれる。前からの表と後ろからの表を作っておけば、2 つを合わせるだけで答えが出る。

- $\mathrm{pre}[i][j]$ ＝ 品物 $0, \dots, i - 1$ から、重さの和 $j$ 以下で選んだときの価値の最大
- $\mathrm{suf}[i][j]$ ＝ 品物 $i, \dots, N - 1$ から、重さの和 $j$ 以下で選んだときの価値の最大

$\mathrm{pre}[0][j]$ と $\mathrm{suf}[N][j]$ をすべて 0 で始めれば、更新は普通のナップサックのままで「$j$ 以下」の意味になる。「ちょうど $j$」の意味にするなら、$j = 0$ だけを 0、ほかを $-\infty$ で始める。どちらも $O(NW)$ で作れる（$W$ は重さの上限で、要点の和の上限 $K$ にあたる）。品物 $i$ を除いた最大は、前に重さ $j$、後ろに $W - j$ を割り振る全通りの最大である。

$$
\mathrm{without}[i] = \max_{0 \le j \le W} \left( \mathrm{pre}[i][j] + \mathrm{suf}[i + 1][W - j] \right)
$$

表を「$j$ 以下」の意味で持つのが要点である。前で実際に使う重さを $a$、後ろを $b$ とする。$a + b \le W$ なら、$j = a$ のとき後ろの上限 $W - j \ge b$ に収まる。だから最適な選び方は必ずどれかの $j$ で数えられる。「ちょうど $j$」の表で同じことをすると、$j$ と $W - j$ の組だけでは足りず、和が $W$ 未満の組を取りこぼす。

前計算が $O(NW)$、各 $i$ のマージが $O(W)$ なので、全体で $O(NW)$ である。メモリも $O(NW)$ 使い、`long long` の表 2 つで約 $16NW$ バイトになる。$NW = 6.4 \times 10^7$ で 1024MB に達するので、$NW$ が $10^7$ を超えるあたりからはメモリを見積もる。足りなければ、後ろの表だけを全部持ち、前の表は $i$ を進めながら 1 本で更新するとよい（メモリが半分になる）。

マージの形は問いに合わせて変える。

- **品物 $i$ を必ず使うときの最大**：$\max_j \left( \mathrm{pre}[i][j] + \mathrm{suf}[i + 1][W - w_i - j] \right) + v_i$。全体の最大と比べれば、$i$ が「どの最適解にも入る」「どれにも入らない」「入る最適解と入らない最適解の両方がある」を判定できる
- **数え上げで和がちょうど $K$**：$\sum_j \mathrm{pre}[i][j] \cdot \mathrm{suf}[i + 1][K - j]$。ここでは表を「ちょうど $j$」の意味で持つ
- **和が区間 $[L, R)$ に入るものがあるか**：後ろの表の可否を累積和にしておけば、各 $j$ について $[L - j, R - j)$ に作れる和があるかを $O(1)$ で調べられる

数え上げなら戻す DP でも同じ答えが出る。全部を入れた表から $i$ を取り除いて答えを読み、また $i$ を入れ直せばよく、1 回 $O(K)$ である。

## 分割統治でオフラインに処理する {#offline-divide-and-conquer}

この節は[オフライン動的連結性](../graph/offline-dynamic-connectivity.md#time-segment-tree)の考え方（時間軸のセグメント木）を使う。max のナップサックに品物の追加と削除のクエリが任意の順に来て、クエリをすべて先に読める（[オフライン](../guide/glossary.md#offline)）なら、削除を使わずに処理できる。

各品物について、箱に入っている時間を半開区間 $[l, r)$（$l$ 番目のクエリで入り、$r$ 番目で出る）として求める。時刻 $t$ は $t$ 番目のクエリを処理した直後の状態を指し、最後まで残る品物は $r = Q$ とする。時間 $0, \dots, Q - 1$ の上にセグメント木を考え、各品物を、その区間をちょうど覆う $O(\log Q)$ 個のノードに載せる。すると、ある時刻に箱に入っている品物は、その時刻の葉から根までのノードに載っている品物と一致する。

```text
dfs(node, dp):            # dp は親までの品物を入れた表
    for 品物 in node に載った品物:
        dp に品物を追加する       # O(K)
    if node が葉 t:
        時刻 t の答えを dp から読む
    else:
        dfs(左の子, dp のコピー)
        dfs(右の子, dp のコピー)
```

削除の代わりに「子を処理し終えたら、入る前の表に戻す」ことをする。戻すには入る前の表のコピーを取っておけばよく、深さは $O(\log Q)$ なので、コピーのメモリは $O(K \log Q)$ に収まる。品物の追加は 1 品につき $O(\log Q)$ 回なので、全体の時間は $O(QK \log Q)$ である。

同じ形の工夫はほかにもある。

- **削除が古い順だけ**（窓をずらす形）なら、スタック 2 本でキューを作る [SWAG](../ds/monotonic-stack.md#swag) の考え方で、表をスタックに積む。答えは 2 本の一番上の表を[前後からのマージ](#prefix-and-suffix)と同じ式で合わせればよく、各操作はならし $O(K)$ で済む
- **区間の品物だけを使う**クエリなら、区間の中央で分けて左右の表を合わせる分割統治を使う（[分割統治](../basics/divide-and-conquer.md#range-knapsack)）

## 落とし穴 {#pitfalls}

**削除のループの向きを追加と同じにする**。大きい方から $\mathrm{dp}[s] \mathrel{-}= \mathrm{dp}[s - x]$ とすると、まだ戻していない $\mathrm{dp}[s - x]$ を引いてしまう。図の例（2 を入れた表 1 1 1 2 1 1 1 から 2 を除く）でこの誤りをすると、$\mathrm{dp}[5] = 1 - 2 = -1$ のように負の値が出る。余りで計算していると負の値は大きな数に化けて、誤りに気づきにくい。

**値 0 の要素**。$x = 0$ の追加は $\mathrm{dp}[s] \mathrel{+}= \mathrm{dp}[s]$ で、すべてを 2 倍にする。削除を同じ形の引き算で書くと $\mathrm{dp}[s] - \mathrm{dp}[s] = 0$ になり、表が消える。値 0 の要素は、表に入れずに個数 $c$ だけ数えて答えに $2^c$ を掛けるか、削除で 2 の[逆元](../guide/glossary.md#inverse-element)を掛ける。

**箱にない要素を取り除く**。引き算は「その要素が入っている」ことを前提にしている。入っていない値で削除を呼ぶと、表は意味のない値になり、以後のクエリもすべて狂う。入力の保証を確かめ、不安なら多重集合で中身を持って確かめる。

**余りの引き算で負になる**。C++ の `%` は負の数に負の余りを返す。`(dp[s] - dp[s - x] + MOD) % MOD` のように、引いた後で法を足す。modint を使えば気にしなくてよい。

**max の DP を引き算で戻す**。$\mathrm{dp}'[s] = \max(\mathrm{dp}[s], \mathrm{dp}[s - x] + v)$ は移項できない。コードが通っても、取り除いた品物が最適解に入っていた場合に誤った値が残る。小さな入力を全探索と比べると見つかる。

## 例題 {#examples}

### ABC321 F. #(subset sum = K) with Add and Erase {#abc321_f}

<div class="kp-problems" data-role="example" markdown>

- [ABC321 F. #(subset sum = K) with Add and Erase](https://atcoder.jp/contests/abc321/tasks/abc321_f)（diff 1645）：箱に整数を入れる・取り出すクエリのたびに、箱の中から和がちょうど K になるように選ぶ方法の数を答える。

</div>

選び方の数を mod 998244353 で持つ部分和の表を 1 本だけ持ち、クエリのたびに更新する。入れるクエリは和の大きい方から $\mathrm{dp}[s] \mathrel{+}= \mathrm{dp}[s - x]$、取り出すクエリは和の小さい方から $\mathrm{dp}[s] \mathrel{-}= \mathrm{dp}[s - x]$ で、どちらの後も $\mathrm{dp}[K]$ を出力する。$Q, K$ はどちらも 5000 までなので、$O(QK)$ で間に合う。

??? note "解法の詳細"
    - 表は $K$ までの $K + 1$ 個だけ持つ。$K$ より大きい和は、以後のどの更新でも $K$ 以下の値に影響しない（更新は $s$ を増やす向きにしか値を運ばない）。
    - 初期値は $\mathrm{dp}[0] = 1$（何も選ばない 1 通り）。
    - 取り出すクエリでは、その値が箱にあることが保証されている。同じ値が複数あっても、どれを取り除いても表は同じになる。
    - コードは[足し算の更新は引き算で戻せる](#undo-by-subtraction)の節の `add` と `remove` をそのまま使えばよい。

</div>

??? note "練習の方針"
    - **ABC441 F**：価値の最大なので戻せない。前からと後ろからの表を「代金 $j$ 以下での最大」の意味で作り、品物 $i$ を「買わない場合の最大」と「必ず買う場合の最大」をマージで求める。全体の最大と比べ、買わないと届かなければ必ず買う、買うと届かなければ買わない、どちらも届けば両方ありうる。全体で $O(NM)$。
    - **ARC070 D**：$a_i \ge K$ のカードは必要である。$a_i < K$ のカードが不要なのは、ほかのカードから作れる和が $[K - a_i, K)$ に 1 つもないときである。各カードを除いた部分和を、選び方の数の余りを使った戻す DP で求めるか、前後からの表のマージ（後ろの表を累積和にする）で調べる。$N, K \le 5000$ なので $O(NK)$ で間に合う。不要なカードは値の小さい側にまとまるので、値でソートして二分探索する解法もある。

## 確認問題 {#quiz}

??? question "確認問題：max のナップサックで品物を 1 つ取り除けないのはなぜか"
    重さの上限が 1 で、重さ 1・価値 5 と重さ 1・価値 3 の品物があるとき、表の $\mathrm{dp}[1]$ には何が入っていて、価値 5 の品物を除くと何になるべきか。

    ??? success "答え"
        $\mathrm{dp}[1] = 5$ が入っており、除いた後は 3 になるべきである。しかし 3 は $\max$ を取ったときに捨てられていて、表のどこにも残っていない。足し算なら引けば元に戻るが、$\max$ には元の 2 つの値を取り戻す逆の演算がない。

??? question "確認問題：個数制限なしの数え上げで、品物を 1 種類取り除く"
    個数制限なしの数え上げでは、値 $x$ の品物を入れるとき $s$ の小さい方から $\mathrm{dp}[s] \mathrel{+}= \mathrm{dp}[s - x]$ とする。この品物を取り除くには、どちら向きに何をすればよいか。

    ??? success "答え"
        $s$ の大きい方から $\mathrm{dp}[s] \mathrel{-}= \mathrm{dp}[s - x]$ とする。追加は $1 / (1 - z^x)$ を掛けることなので、削除は $(1 - z^x)$ を掛けることになる。新しい $\mathrm{dp}[s]$ は元の $\mathrm{dp}[s] - \mathrm{dp}[s - x]$ で、右辺は更新前の値なので、大きい方から更新すれば読む前に書き換えずに済む。0-1 の場合と向きがちょうど入れ替わる。

??? question "確認問題：前後からのマージで、表を「ちょうど」の意味で持つとどうなるか"
    $\mathrm{pre}$ と $\mathrm{suf}$ を「重さの和がちょうど $j$ のときの価値の最大」（作れなければ $-\infty$）で持ち、$\max_j (\mathrm{pre}[i][j] + \mathrm{suf}[i + 1][W - j])$ を答えにした。何が起きるか。

    ??? success "答え"
        重さの合計がちょうど $W$ になる選び方しか数えないので、合計が $W$ 未満の最適解を取りこぼす。「以下」の意味で持ち直すか、和を $W$ 以下の全通り $\max_{a + b \le W}$ で取る必要がある。後者は $O(W^2)$ かかるので、「以下」で持つ方がよい。

## 使い分け {#comparison}

- 数え上げ（和・個数）の DP から要素を取り除くなら、戻す DP で 1 回 $O(K)$
- max・min・可否の DP で「各 $i$ を除いたとき」なら、[前後からの DP のマージ](#prefix-and-suffix)
- max・min の DP に追加と削除が任意の順に来るなら、オフラインで[時間軸の分割統治](#offline-divide-and-conquer)。削除が古い順だけならスタック 2 本
- 区間の品物だけを使うクエリなら、[分割統治](../basics/divide-and-conquer.md#range-knapsack)で左右の表を合わせる
- 表の添字にする量が大きすぎるときは、添字と値の入れ替えを先に考える（[DP の状態の削減](../dp/dp-dimension-reduction.md)）
