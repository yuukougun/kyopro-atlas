区間 DP は、列の連続した部分 $[l, r)$ を[状態](../guide/glossary.md#state)にして、その部分だけを取り出した小さな問題の答えを表に持つ DP である。合体・削除・取り合いのように、操作の後も「まとまり」が連続した区間のまま残る問題で使える。肝は「区間の中で最後に起きること」を 1 つ決めて、残りを独立な短い区間に割ることである。

## 区間を状態にする（状態・遷移・初期値・答え） {#state}

区間 DP が必要になるのは、左から順に決めていく DP では状態が足りない問題である。たとえば「隣り合う 2 つを合体させる」操作では、合体の結果がまた隣と合体するので、どこで区切れるかが操作の順に左右される。それでも、ある連続した部分が最終的に 1 つにまとまることだけは変わらない。そこで、まとまりの単位である区間そのものを状態にする。

この節では例として、次の問題を使う（[例題](#dp_n)の EDPC N と同じ形）。

> 列 $A = (a_0, \dots, a_{N-1})$ の隣り合う 2 つを合体させると、大きさの和のコストがかかり、和の大きさの 1 つになる。全体を 1 つにするコストの合計の最小を求める。

- **状態**：$\mathrm{dp}[l][r]$ ＝ $a_l, \dots, a_{r-1}$ だけを取り出して 1 つにするときのコストの最小（[半開区間](../guide/glossary.md#half-open-interval) $[l, r)$、$0 \le l < r \le N$）
- **遷移**：区間 $[l, r)$ の最後の合体は、$[l, m)$ をまとめたものと $[m, r)$ をまとめたものを合わせる操作である。境目 $m$ を全部試して $\mathrm{dp}[l][r] = \min_{l < m < r} (\mathrm{dp}[l][m] + \mathrm{dp}[m][r]) + (S_r - S_l)$。$S$ は累積和で、$S_0 = 0$、$S_{i+1} = S_i + a_i$
- **初期値**：長さ 1 の区間は合体が要らないので $\mathrm{dp}[l][l+1] = 0$。最小を求めるので、ほかは $+\infty$ から始める
- **答え**：$\mathrm{dp}[0][N]$

この状態で足りる理由は、境目 $m$ を決めると左右の部分が互いに影響しないことにある。最後の合体より前は、$[l, m)$ の中の合体と $[m, r)$ の中の合体しか起きない。だから左右を別々に最小にしてよく、それぞれの最小は短い区間の値として表にある。最後の合体のコストは区間全体の和で、境目によらない。

![A = 2, 5, 1, 3 の区間 \[0, 4) を、最後の合体の境目 m で 2 つに割る木の図。m = 1・2・3 の候補のうち、左右の和が最小になるのは m = 2 の 7 + 4 = 11 で、最後の合体のコスト 11 を足して dp[0][4] = 22](../img/interval-dp/split.svg)

$A = (2, 5, 1, 3)$ なら、長さ 2 の区間は $\mathrm{dp}[0][2] = 7$、$\mathrm{dp}[1][3] = 6$、$\mathrm{dp}[2][4] = 4$ である。長さ 3 は $\mathrm{dp}[0][3] = \min(0 + 6,\ 7 + 0) + 8 = 14$、$\mathrm{dp}[1][4] = \min(0 + 4,\ 6 + 0) + 9 = 13$ になる。全体は、左右の和が $m = 1$ で 13、$m = 2$ で $7 + 4 = 11$、$m = 3$ で 14 なので、図のとおり $m = 2$ で割るのが最小で、$\mathrm{dp}[0][4] = 11 + 11 = 22$ になる。

状態は $O(N^2)$ 個、各状態の遷移は $O(N)$ 個なので、全体で $O(N^3)$ である。$l < m < r$ を満たす組は約 $N^3 / 6$ 個しかないので、$N = 400$ でも約 $10^7$ 回で済む。$N \le 300$〜$500$ という制約は、この型を疑う合図になる。

## 長さ順に埋める理由（l を昇順に回すと困ること） {#by-length}

区間 DP の表は、外側を区間の長さ $r - l$ にして、短い順に埋める。$\mathrm{dp}[l][r]$ が使う $\mathrm{dp}[l][m]$ と $\mathrm{dp}[m][r]$ は、どちらも $[l, r)$ の真に内側の区間で、長さが短いからである。長さの順なら、使う値はすべて先に計算されている（[DP の計算順序](../dp/dp-order.md)の「真に小さいものから」の一例）。

![行を l、列を r にした表で、dp[0][4] は同じ行の左にある dp[0][1]・dp[0][2]・dp[0][3] と、同じ列の下にある dp[1][4]・dp[2][4]・dp[3][4] を使う。斜めの並びが同じ長さの区間で、長さ 1 から 4 の順に埋める](../img/interval-dp/table.svg)

よくある誤りは、普通の 2 次元の表のつもりで $l$ を外側に $0$ から昇順、$r$ を内側に回すことである。表の行を $l$、列を $r$ にすると、$\mathrm{dp}[l][r]$ は同じ行の左（$\mathrm{dp}[l][m]$）と同じ列の下（$\mathrm{dp}[m][r]$、$m > l$）を使う。$l = 0$ の行を埋める時点で下の行はまだ空なので、未計算の $+\infty$ を読んで答えが壊れる。コンパイルも実行も通り、小さな入力では合うこともあるので気づきにくい。

正しい順序は次の 3 つのどれかである。

```text
// (1) 長さの順（基本）
for len = 2 .. N:
    for l = 0 .. N - len:
        r = l + len
        dp[l][r] を dp[l][m], dp[m][r]（l < m < r）から求める

// (2) l を大きい方から、r を小さい方から
for l = N-1 .. 0:
    for r = l+2 .. N:
        dp[l][r] を求める      // 下の行と、同じ行の左はもう埋まっている

// (3) メモ化再帰：solve(l, r) の中で solve(l, m) と solve(m, r) を呼ぶ
```

(2) は図の表を下の行から埋める順で、長さの順と同じく正しい。(3) の[メモ化再帰](../dp/memoized-recursion.md)は順序を考えずに済み、長さが奇数の区間のように使わない状態を飛ばしやすい。ただし関数呼び出しの分だけ遅く、$O(N^3)$ で $N = 500$ のような上限に近い問題では for の方が安心である。

## 分割点型（最後に行う操作で区間を 2 つに割る） {#split-point}

分割点型は、区間 $[l, r)$ の最後の操作が区間を $[l, m)$ と $[m, r)$ の 2 つに分けると見て、境目 $m$ を全探索する型である。遷移の一般形は次のとおりである。

$$
\mathrm{dp}[l][r] = \min_{l < m < r} \bigl( \mathrm{dp}[l][m] + \mathrm{dp}[m][r] + \mathrm{cost}(l, m, r) \bigr)
$$

最後の操作のコストが境目 $m$ によらないとき（Slimes の区間の和）は、$\mathrm{cost}(l, r)$ として $\min$ の外に出せる。

使えるかどうかは、次の 2 つで確かめる。

- **左右が独立**：最後の操作より前に、境目をまたぐ操作が起きない。合体なら、最後の合体より前は左右の中で合体するだけである
- **最後の操作のコストが区間と境目だけで決まる**：$\mathrm{cost}(l, m, r)$ が区間の和のように左右の中の操作の仕方によらない。左右をまとめた結果の値（大きさ・色など）を使うなら、その値も区間だけで決まる必要がある

たとえば合体のコストが左右の大きさの積 $(S_m - S_l)(S_r - S_m)$ でも、左右の大きさは区間の和で決まるので使える。このコストは $m$ によって変わるので、$\min$ の中に入れる。使えないのは、合体した後の値が合体の順で変わる場合である。そのときは値も状態に入れるか、別の型を考える。

**応用の型**：

- **括弧の対応**：正しい括弧列の個数を数える・正しくするための最小の変更回数を求める問題では、$[l, r)$ を「$l$ と対応する括弧 $m - 1$ で閉じた塊」と「残りの $[m, r)$」に分ける。境目 $m$ を「$l$ と対応する括弧の次」に限ると、分割点型は[左端の相手で分ける型](#last-operation)になる
- **区間の値を再帰的に定める**：「区間 $[l, r)$ を 2 つに割ってそれぞれの値を求め、合わせる」という式が問題文に書かれていれば、そのまま分割点型になる
- **高速化**：$\mathrm{cost}(l, r)$ が Monge で、区間を広げても減らない（$[b, c) \subseteq [a, d)$ なら $\mathrm{cost}(b, c) \le \mathrm{cost}(a, d)$）とき、最適な境目が $l$・$r$ について単調になり、$O(N^2)$ に落とせる（Knuth-Yao の高速化。[Monge](../dp/monge.md#knuth-yao)）。Slimes の区間の和は両方を満たす。Monge だけでは境目が単調にならないことがある。ABC の範囲では $O(N^3)$ のまま通る問題がほとんどである

## 両端型（左端か右端を取る） {#ends}

両端型は、区間 $[l, r)$ から左端か右端の 1 つだけを取り除いて $[l+1, r)$ か $[l, r-1)$ に移る型である。遷移が 2 通りなので、全体は $O(N^2)$ で済み、$N \le 3000$ 程度でも使える。

典型は、列の両端から交互に 1 つずつ取る 2 人ゲームである。残りの区間が同じなら、それまでにどちらが何を取ったかは今後に影響しない。手番の人の得点から相手の得点を引いた値の最大を $\mathrm{dp}[l][r]$ とすると、

$$
\mathrm{dp}[l][r] = \max\bigl( a_l - \mathrm{dp}[l+1][r],\ a_{r-1} - \mathrm{dp}[l][r-1] \bigr), \quad \mathrm{dp}[l][l] = 0
$$

である。取った後は相手の手番なので、相手の最善の値を引く（符号を反転する書き方は[ミニマックス](../comb/minimax.md#negamax)）。

両端型で状態を小さく保てる理由は、「すでに何個取ったか」が区間の長さから分かることにある。$N - (r - l)$ 個取ったと分かるので、手番も、次に置くものが何番目かも状態に入れなくてよい。この見方で、次の型も両端型になる。

- **大きい順に左右の端へ置く**：並べ替えで「値の大きいものほど端に置くのがよい」と分かると、大きい順に左端か右端の空きへ置いていけばよい。まだ空いている位置は連続した区間 $[l, r)$ で、何個置いたかは長さで決まる（[練習](#practice)の ABC163 E。順序を決める理由は[並べ替えてから DP する](../dp/exchange-argument-dp.md)）
- **回文にする最小の操作**：文字列 $S$ の $[l, r)$ を回文にする最小の挿入回数は、$S[l] = S[r-1]$ なら $\mathrm{dp}[l+1][r-1]$、違えば $1 + \min(\mathrm{dp}[l+1][r],\ \mathrm{dp}[l][r-1])$ である。長さ 0 と 1 の区間は 0 にする。外側から 1 組ずつ決める考え方は[回文](../string/palindrome.md#build-outside-in)と共通である

半開区間で書くと、長さ 1 の区間 $[l, l+1)$ から $[l+1, l)$ のような逆向きの区間を読みにいくことがある。長さ 0・1 を初期値として先に決め、ループは長さ 2 から始めると安全である。

## 最後に残す・最後に消すものを決める型 {#last-operation}

区間から要素を取り除いていく問題では、分割点を直接探すより、「ある要素がいつ・何と一緒に消えるか」を決めた方が、区間が独立に割れることが多い。決め方には 2 通りある。

**左端と一緒に消える相手を決める**。隣り合う 2 つ（または決まった並びの数個）を取り除く操作を繰り返して $[l, r)$ を全部消すとき、左端 $a_l$ はいつか誰か $a_m$ と一緒に消える。その瞬間 $a_l$ と $a_m$ は隣り合うので、間の $[l+1, m)$ は先に全部消えている。しかも $a_l$ と $a_m$ が残っている間は、間の要素は外と組めない。だから $[l+1, m)$ はその中だけで消え、$[m+1, r)$ もその中だけで消える。

$$
\mathrm{dp}[l][r] = \min_{m} \bigl( \mathrm{dp}[l+1][m] + \mathrm{cost}(a_l, a_m) + \mathrm{dp}[m+1][r] \bigr)
$$

ここで $m$ は $[l+1, m)$ の長さが偶数になる位置だけを試す。[例題](#typical90_s)の典型90 019 はこの形で、空の区間を $\mathrm{dp}[l][l] = 0$ にしておけば境界を特別扱いしなくてよい。

```

**区間の中で最後に消す要素を決める**。各要素を 1 つずつ消し、消すコストがそのときの両隣で決まる問題では、$\mathrm{dp}[l][r]$ を「外の $a_{l-1}$ と $a_r$ が残ったまま $[l, r)$ を全部消すコストの最小」とし、$[l, r)$ の中で最後に消す要素 $k$ を決める。$k$ が残っている間、$k$ は左右を隔てる壁になるので、$[l, k)$ と $[k+1, r)$ はそれぞれ独立に消える。しかも $k$ を消す瞬間の両隣は、区間の外の $a_{l-1}$ と $a_r$ に決まる。「最初に消すもの」で分けると、消した後に両隣がつながって独立に割れないので、「最後」で分けるのがこつである。

$$
\mathrm{dp}[l][r] = \min_{l \le k < r} \bigl( \mathrm{dp}[l][k] + \mathrm{dp}[k+1][r] + \mathrm{cost}(a_{l-1}, a_k, a_r) \bigr), \quad \mathrm{dp}[l][l] = 0
$$

列の両端に番兵 $a_{-1}$・$a_N$ を足しておけば、$l = 0$ や $r = N$ でも外の両隣があり、答えは $\mathrm{dp}[0][N]$ になる。番兵を足した配列では添字が 1 ずれるので、どちらの添字で書くかを先に決めておく。

**全部消せるかを先に判定する**。「取り除く回数の最大」や「残る長さの最小」を問う問題では、まず「$[l, r)$ を全部消せるか」という真偽の区間 DP を作ることが多い。全部消せる区間が分かれば、残す文字と消す区間に列を区切る 1 次元の DP（[区間分割 DP](../dp/dp-sequence-partition.md)）で答えが出る（[練習](#practice)の TDPC I）。区間の中の先頭の文字が何と組んで消えるかで分け、消し方の種類を場合分けする問題もある（[力試し](#challenge)の ABC325 G）。

## 端の相手で分ける数え上げ（二項係数で操作の順序を混ぜる） {#pair-with-left-end}

この節は[二項係数](../comb/binomial-coefficient.md)を前提にする。最小化では同じ消し方を何通りの分け方で数えても答えは変わらないが、数え上げでは重複がそのまま誤りになる。区間 DP で数えるときは、1 つの消し方が 1 つの分け方にだけ対応するように、分け方を決める。

例として、$2n$ 人が一列に並び、組んでよい 2 人が決まっていて、隣り合う 2 人を組にして列から抜く操作を $n$ 回行う問題を考える。操作の列（どの順に抜いたか）の数を求める。

**境目で分けると重複する**。「$[l, m)$ を消す操作」と「$[m, r)$ を消す操作」に分けて境目 $m$ ごとに足すと、塊が 3 つ以上あるときに同じ消し方を何度も数える。たとえば $(0, 1)$・$(2, 3)$・$(4, 5)$ と組む消し方は、境目 $m = 2$ でも $m = 4$ でも分けられる。

**左端の相手で分ければ重複しない**。どの消し方でも、左端 $l$ と組む人 $p$ はただ 1 人に決まる。$p$ で分ければ、1 つの消し方はちょうど 1 つの $p$ で数えられる。[前の節](#last-operation)と同じく、内側 $[l+1, p)$ はその中だけで消え、外側 $[p+1, r)$ もその中だけで消える。

**操作の順序を二項係数で混ぜる**。数えるのは操作の列なので、内側と外側の操作がどう混ざるかも数える。内側の操作と組 $(l, p)$ を合わせた $a = (p - l + 1) / 2$ 回は、内側を全部終えてから $(l, p)$ を最後に行う順に限られる。外側の $b = (r - p - 1) / 2$ 回とは、互いに制約がない。$a + b$ 回の列の中で外側の操作が入る位置の選び方は $\binom{a + b}{b}$ 通りなので、

$$
\mathrm{dp}[l][r] = \sum_{p} \mathrm{dp}[l+1][p] \cdot \mathrm{dp}[p+1][r] \cdot \binom{(r - l)/2}{(r - p - 1)/2}
$$

になる。和は $l$ と $p$ が組んでよく、$[l+1, p)$ の長さが偶数になる $p$ だけを取る。空の区間は $\mathrm{dp}[l][l] = 1$（何もしない 1 通り）である。

```

二項係数の表は $n \le$ 数百ならパスカルの三角形で $O(n^2)$ に作れる。区間は $O(n^2)$ 個、相手の候補は $O(n)$ 個なので全体で $O(n^3)$ である（[練習](#practice)の ABC217 F）。

「内と外を独立に数えて、順序を二項係数で混ぜる」形は、区間で木の形や操作の履歴を数える問題で繰り返し現れる（[区間 DP の応用](../dp/interval-dp-advanced.md)）。

## 落とし穴 {#pitfalls}

**$l$ を昇順に回す**。$\mathrm{dp}[m][r]$（$m > l$）がまだ埋まっていない。長さを外側にするか、$l$ を大きい方から回す（[長さ順に埋める理由](#by-length)）。

**半開区間と閉区間が混ざる**。$\mathrm{dp}[l][r]$ を閉区間 $[l, r]$ で考えると、分け方は $[l, m]$ と $[m+1, r]$、表の大きさは $N \times N$ になる。半開区間なら $[l, m)$ と $[m, r)$、表は $(N+1) \times (N+1)$ である。どちらかに決めて、状態の定義のコメントに書いてから遷移を書く。片方だけ $m+1$ を忘れると、1 つの要素を左右で 2 回使う。

**数え上げで境目ごとに足す**。同じ消し方を何度も数える。左端の相手のように、1 つの消し方からただ 1 つに決まるもので分ける（[端の相手で分ける数え上げ](#pair-with-left-end)）。

**不可能な状態の $+\infty$ どうしを足す**。長さが奇数で消せない区間などは $+\infty$ のまま残る。`LLONG_MAX` を $+\infty$ にすると、2 つ足しただけであふれて負になり、最小として選ばれてしまう。$+\infty$ は `LLONG_MAX / 4` のように和を取っても収まる値にするか、足す前に $+\infty$ を飛ばす。

**$O(N^3)$ の目安を外す**。$N = 3000$ で境目を全探索すると約 $4.5 \times 10^9$ 回で間に合わない。$N$ が数千なら、遷移が 2 通りの両端型を探すか、境目の候補を絞る。

## 例題 {#examples}

### EDPC N. Slimes {#dp_n}

<div class="kp-problems" data-role="example" markdown>

- [EDPC N. Slimes](https://atcoder.jp/contests/dp/tasks/dp_n)（diff なし）：隣り合うスライムを合体させるたびに大きさの和のコストがかかるとき、全部を 1 匹にするコストの最小を求める。

</div>

[区間を状態にする](#state)の節で使った問題そのものである。区間 $[l, r)$ を 1 匹にするコストの最小を $\mathrm{dp}[l][r]$ とし、最後に合体する境目で分ける。最後の合体のコストは区間の大きさの和で、境目によらない。

??? note "解法の詳細"
    - 累積和 $S$ を作り、$\mathrm{dp}[l][l+1] = 0$、ほかを $+\infty$ にする。
    - 長さ $2$ から $N$ の順に、各 $l$ について $r = l + \mathrm{len}$ とし、$\mathrm{dp}[l][r] = \min_{l < m < r}(\mathrm{dp}[l][m] + \mathrm{dp}[m][r]) + S_r - S_l$ とする。
    - 答えは $\mathrm{dp}[0][N]$。$O(N^3)$ で、コストの合計は `int` に収まらないことがあるので `long long` で持つ。
    - コードは[長さ順に埋める理由](#by-length)の節のものと同じである。

### 典型90 019. Pick Two（★6） {#typical90_s}

<div class="kp-problems" data-role="example" markdown>

- [典型90 019. Pick Two（★6）](https://atcoder.jp/contests/typical90/tasks/typical90_s)（diff なし）：2N 個の数の列から隣り合う 2 つを取り除く操作を繰り返して全部消すとき、取り除く 2 つの差の絶対値の和の最小を求める。

</div>

取り除くと両隣がつながるので、左から順に決める DP では扱えない。区間 $[l, r)$ を全部消すコストの最小を $\mathrm{dp}[l][r]$ とし、左端と一緒に取り除かれる相手 $m$ で分ける。間の $[l+1, m)$ は先に全部消え、外の $[m+1, r)$ は独立に消える。

??? note "解法の詳細"
    - $\mathrm{dp}[l][l] = 0$ とし、長さが偶数の区間だけを長さの順に埋める。
    - $\mathrm{dp}[l][r] = \min_m (\mathrm{dp}[l+1][m] + \lvert a_l - a_m \rvert + \mathrm{dp}[m+1][r])$。$m$ は $m - l$ が奇数になる位置だけを試す。
    - 「両端の 2 つを最後に取る（$\mathrm{dp}[l+1][r-1] + \lvert a_l - a_{r-1} \rvert$）」と「境目で 2 つに分ける」の 2 つの遷移で書いても同じ答えになる。同じ消し方を何度も見るが、最小化なので問題ない。
    - 全体で $O(N^3)$。コードは[最後に残す・最後に消すものを決める型](#last-operation)の節のものと同じである。

## 練習問題 {#practice}

<div class="kp-problems" data-role="practice" markdown>

- [EDPC L. Deque](https://atcoder.jp/contests/dp/tasks/dp_l)（diff なし）：数列の両端から交互に 1 つずつ取る 2 人ゲームで、両者が最適に取るときの先手の得点 − 後手の得点を求める。
- [TDPC I. イウィ](https://atcoder.jp/contests/tdpc/tasks/tdpc_iwi)（diff なし）：i と w からなる文字列から、連続する 'iwi' を取り除く操作を繰り返すとき、操作回数の最大を求める。
- [ABC217 F. Make Pair](https://atcoder.jp/contests/abc217/tasks/abc217_f)（diff 1954）：2N 人の列から、仲の良い隣り合う 2 人を取り除く操作を N 回行う方法の数を求める。
- [ABC163 E. Active Infants](https://atcoder.jp/contests/abc163/tasks/abc163_e)（diff 2037）：活発度 A_i の幼児を並べ替えて、各幼児の移動距離×活発度の和の最大を求める。

</div>

??? note "練習の方針"
    - **EDPC L**：残りの区間 $[l, r)$ ごとに「手番の人の得点 − 相手の得点」の最大を持つ両端型。$O(N^2)$（[両端型](#ends)）。
    - **TDPC I**：まず $[l, r)$ を全部消せるかを区間 DP で求める。消える 'iwi' の両端の 'i' と真ん中の 'w' の間がそれぞれ全部消せるか、境目で 2 つの全部消せる区間に分けられるかを調べる。その後、消せる区間と残す文字に区切る DP で回数を最大にする。
    - **ABC217 F**：左端と組む相手で分け、内側と外側の操作の順序を二項係数で混ぜる（[端の相手で分ける数え上げ](#pair-with-left-end)）。
    - **ABC163 E**：活発度の大きい順に、空いている区間の左端か右端に置く。何人置いたかは区間の長さで決まるので、空いている区間を状態にした両端型になる。

## 力試し {#challenge}

<div class="kp-problems" data-role="challenge" markdown>

- [ABC325 G. offence](https://atcoder.jp/contests/abc325/tasks/abc325_g)（diff 2388）：文字列から、連続する 'of' とその直後の K 文字以下をまとめて削除する操作を好きなだけ行ったときの、長さの最小を求める。

</div>

??? note "力試しの方針"
    - **ABC325 G**：区間 $[l, r)$ を操作した後の長さの最小を持つ。境目で 2 つに分ける遷移に加え、先頭が 'o' なら、間 $[l+1, m)$ を全部消せる 'f'（$s_m$）を選び、$\max(0, \mathrm{dp}[m+1][r] - K)$ を候補にする。'of' の削除を後回しにすれば、後ろの区間を先に最小まで縮めてから、その先頭の $K$ 文字以下を消せるからである。drken の記事のように、状態の値の意味を広げる書き方もある。

## 確認問題 {#quiz}

??? question "確認問題：ループの順序"
    $\mathrm{dp}[l][r] = \min_{l < m < r}(\mathrm{dp}[l][m] + \mathrm{dp}[m][r]) + \mathrm{cost}(l, r)$ を、`for l = 0 .. N-1`・`for r = l+2 .. N` の順に計算した。何が起きるか。正しく直す方法を 2 つ挙げよ。

    ??? success "答え"
        $\mathrm{dp}[0][r]$ を計算するとき、$\mathrm{dp}[m][r]$（$m \ge 1$）はまだ計算されておらず、初期値の $+\infty$ のまま読まれる。結果は実際より大きくなるか $+\infty$ になる。直し方は、外側のループを区間の長さにして短い順に回すか、$l$ を $N-1$ から $0$ へ降順に回して $r$ を昇順に回す。メモ化再帰で書いてもよい。

??? question "確認問題：数え上げの重複"
    6 人の列で、組 $(0, 1)$・$(2, 3)$・$(4, 5)$ だけが組める。抜く順を区別して数えると何通りか。また、境目 $m$ ごとに $\mathrm{dp}[0][m] \cdot \mathrm{dp}[m][6] \cdot (\text{順序の混ぜ方})$ を足すと、なぜ答えが合わないか。

    ??? success "答え"
        3 組はどの順でも抜けるので $3! = 6$ 通りである。境目で分けると、どの消し方も $m = 2$ と $m = 4$ の両方で数えられ、2 倍の 12 通りになる。左端 0 の相手は 1 だけなので、相手で分ければ $p = 1$ の 1 通りの分け方だけになり、$\mathrm{dp}[1][1] \cdot \mathrm{dp}[2][6] \cdot \binom{3}{2} = 1 \cdot 2 \cdot 3 = 6$ と正しく数えられる。

??? question "確認問題：N = 3000 の取り合い"
    列の両端から交互に 1 つずつ取るゲームで、$N \le 3000$ である。区間 DP で間に合うか。

    ??? success "答え"
        間に合う。遷移は左端か右端を取る 2 通りだけなので、状態 $O(N^2)$ ＝ 約 $4.5 \times 10^6$ 個の区間に定数回の計算で済む。境目を全探索する型ではないので $O(N^3)$ にはならない。表を `long long` の $(N+1)^2$ 個で持つと約 72 MB になるので、メモリの上限も確かめる。長さごとに 1 次元の配列を使い回せば $O(N)$ に減らせる。

## 使い分け {#comparison}

- 列を左から区切って、区切った区間どうしが影響しないなら[区間分割 DP](../dp/dp-sequence-partition.md#vs-interval-dp)（$\mathrm{dp}[i]$、多くは $O(N^2)$ 以下）。合体や削除で隣が変わるなら区間 DP（$\mathrm{dp}[l][r]$）
- 両端から取るゲームは区間 DP の両端型で、勝ち負けや得点差の扱いは[ミニマックス](../comb/minimax.md)にそろえる
- 分割点型で $N$ が数千あるなら、コストの性質（Monge と単調性）を調べて Knuth-Yao の高速化を考える（[Monge](../dp/monge.md#knuth-yao)）
- 区間を部分木とみる木の数え上げ、区間ごとの Grundy 数、訪れた範囲の両端を状態にする移動は[区間 DP の応用](../dp/interval-dp-advanced.md)
