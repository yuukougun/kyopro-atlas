区間 DP の応用は、問題文に「区間」と書かれていなくても、何かを列に並べると「まとまり」が連続した区間になることを見抜いて、[区間 DP](../dp/interval-dp.md) に持ち込む型の集まりである。木の部分木、ゲームで残った範囲、数直線上で訪れた範囲、同じ数字で始まる文字列の群れが、どれも連続した区間になる。どの型でも「区間を 1 つ決めると、その中と外が互いに影響しない」ことを確かめるのが要である。

## DFS 順の区間＝部分木（木の数え上げ） {#dfs-order-trees}

根付き木を [DFS](../graph/dfs.md) でたどり、頂点を初めて訪れた順に並べた列を行きがけ順という。行きがけ順では、どの頂点 $v$ の部分木も、$v$ から始まる連続した区間になる。$v$ に入ってから出るまでの間に訪れるのは $v$ の子孫だけで、子孫はすべてその間に訪れるからである（[オイラーツアー](../tree/euler-tour.md)の $\mathrm{in}[v]$ と $\mathrm{out}[v]$ の対応と同じ理由）。

そこで、行きがけ順 $P = (P_0, \dots, P_{N-1})$ だけが与えられ、それを生む根付き木を数える問題を考える。DFS は子を番号の小さい順にたどるものとし、$P_0$ が根である。根を $P_0$ に固定した木は $N^{N-2}$ 通りある（[ケイリーの公式](../comb/cayley-pruefer.md)）ので全部は試せないが、区間を部分木とみれば区間 DP で数えられる（[例題](#abc252_g)の ABC252 G）。

状態は 2 種類持つ。どちらも 0-indexed の[半開区間](../guide/glossary.md#half-open-interval) $[l, r)$ で書く。

- $f[l][r]$ ＝ $P_l, \dots, P_{r-1}$ が、$P_l$ を根とする 1 本の部分木の行きがけ順になる木の数
- $g[l][r]$ ＝ $P_l, \dots, P_{r-1}$ が、根の番号が増える順に並んだ部分木の列（森）の行きがけ順になる方法の数

1 本の木は「根」と「根の子の部分木の列」に分かれ、子の部分木の列は「先頭の部分木」と「残りの列」に分かれる。これをそのまま式にする。

$$
\begin{aligned}
f[l][r] &= g[l+1][r] \\
g[l][r] &= \sum_{\substack{l < m \le r \\[0.3em] m = r \text{ または } P_l < P_m}} f[l][m] \cdot g[m][r]
\end{aligned}
$$

$g$ の和の $m$ は先頭の部分木の終わりで、$m = r$ なら区間全体が 1 本の部分木である。条件 $P_l < P_m$ は、兄弟が番号の小さい順にたどられることを表す。先頭の部分木の根 $P_l$ は、残りの森の最初の根 $P_m$ より小さくなければならない。残りの森の中の根どうしの順を保証するのは $g[m][r]$ なので、隣り合う 2 つの根を比べるだけで足りる。空の森を $g[l][l] = 1$ とし、答えは $f[0][N]$ である。

![行きがけ順 P = 1, 2, 4, 3, 5 の区間 \[0, 5) を、根 P[0] = 1 と、子の森 \[1, 5) に分ける。子の森は部分木 \[1, 3)（2 と 4）と部分木 \[3, 5)（3 と 5）に分かれ、根 2 と 3 は 2 < 3 の順に並ぶ。右にはその分け方に対応する木を描いた](../img/interval-dp-advanced/preorder-split.svg)

小さな例で確かめる。$P = (1, 2, 3)$ なら、3 を 2 の子にする木（1−2−3 の道）と、2 と 3 を 1 の子にする木の 2 通りがある。後者は兄弟の 2 と 3 が番号の順に並ぶので数える。$P = (1, 3, 2)$ なら、3 と 2 を兄弟にすると番号の小さい 2 が先にたどられてしまうので、1−3−2 の道の 1 通りだけになる。式でも、$g[1][3]$ の $m = 2$ の項は $P_1 = 3 > P_2 = 2$ で除かれる。

**この状態で足りる理由**。$[l, m)$ が 1 本の部分木と決まると、その中の親子関係は外の頂点とまったく関わらない。外から見えるのは「根が $P_l$ であること」だけで、それは区間の左端から分かる。だから中の数え方 $f[l][m]$ と外の数え方 $g[m][r]$ は独立で、積で数えてよい。また 1 つの木に対して、各部分木の区間は木から一通りに決まるので、同じ木を 2 回数えることはない。

計算順序は区間の長さの短い順でよい。$f[l][r]$ は 1 短い $g[l+1][r]$ を、$g[l][r]$ は同じ長さの $f[l][r]$ と短い区間の値を使う。同じ長さの中では $f$ を先に求める。状態は $O(N^2)$ 個、$g$ の遷移は $O(N)$ 個なので全体で $O(N^3)$ である。$N = 500$ でも組 $l < m \le r$ は約 $2 \times 10^7$ 個で間に合う。

**応用の型**：

- **括弧列と森**：行きがけ順で「入る」を `(`、「出る」を `)` と書くと、森は正しい括弧列と一対一に対応する。部分木は対応する括弧の組で囲まれた区間になる。上の $f$ と $g$ の分け方は、括弧列を「左端の `(` とその相手で閉じた塊」と「残り」に分ける形で、[左端の相手で分ける型](../dp/interval-dp.md#pair-with-left-end)と同じである。「行きがけ順」「括弧列」「区間の入れ子」のどれで書かれていても、同じ DP で数えられる
- **順序も数えるときは二項係数で混ぜる**：木の形に加えて「親より後に消す」のような頂点の順序まで数えるなら、$g$ の遷移で先頭の部分木と残りの森の順序の混ぜ方を掛ける。2 つの部分の間に制約がなければ、$m - l$ 個と $r - m$ 個の並べ方を混ぜる $\binom{r - l}{m - l}$ 通りである（[二項係数](../comb/binomial-coefficient.md)）。各部分の中の順序は $f$ と $g$ が数えている
- **帰りがけ順・BFS 順**：帰りがけ順では部分木は根で終わる区間になるので、右端を根にして同じように分ける。BFS 順では部分木が区間にならないので、この型は使えない。与えられた順で部分木が区間になるかを最初に確かめる
- **区間にならない訪問順**：「訪問済みの頂点に隣接する中で番号が最小の頂点へ進む」のように部分木が区間にならない規則でも、各頂点の親になれる位置が独立に決まるなら、候補の個数の積で数えられる（[訪問順から親の候補を数える](../tree/tree-construction.md#from-order)）

## 区間ごとの Grundy 数（ゲーム） {#grundy}

この節は [Grundy 数](../comb/grundy-number.md)を前提にする。区間を選び合うゲームでは、選んだ区間が場を左右に分け、以後は左右が互いに影響しない 2 つのゲームになる。分かれた局面はゲームの和なので、その Grundy 数は左右の値の XOR である。残っている場の範囲 $[l, r)$ を状態にすれば、区間 DP で全局面の Grundy 数が求まる（求め方の基本は [Grundy 数を DP で求める](../comb/grundy-number.md#dp)）。

$$
G[l][r] = \mathrm{mex}\bigl\{\, G[l][a] \oplus G[b][r] \;\bigm|\; \text{選べる区間 } [a, b) \text{ で } l \le a,\ b \le r \,\bigr\}
$$

区間を 1 つも選べない範囲は $G[l][r] = 0$（負け）である。初めの局面の値が 0 でなければ先手の勝ち、0 なら後手の勝ちになる。

区間 DP の基本形と違うところは 3 つある。

- **状態は区間の番号ではなく座標の範囲**：与えられた区間の集合の部分集合を状態にすると $2^N$ 通りになる。ところが「まだ選べる区間」は「残っている場の範囲に収まる区間」と同じなので、範囲だけを持てば足りる。座標が $1$〜$100$ のように小さければそのまま、大きければ区間の端点を[座標圧縮](../basics/coordinate-compression.md)して $O(N)$ 個の座標にする
- **遷移は区間の全探索**：範囲 $[l, r)$ ごとに $N$ 個の区間すべてを見て、範囲に収まるものだけを手にする。座標の数を $A$ とすると $O(A^2 N)$ である
- **端が接する区間の扱い**：半開区間 $[a, b)$ と $[b, c)$ は共有点がないので、同時に選べる。選んだ後の左右の範囲は $[l, a)$ と $[b, r)$ である。閉区間で与えられるなら、$[l, a)$ と $[b + 1, r)$ のように端を 1 つずらす。問題文の「共有点」の定義を読んで、どちらかに合わせる

mex は行き先の数以下なので、手が $N$ 個なら値は $N$ 以下に収まる。ただし XOR した値は $N$ を超えることがあるので、印の配列は $N$ より大きい値を無視するか、十分大きく取る（[練習](#practice)の ABC206 F）。テストケースが複数あるなら、表をケースごとに初期化し直す。

**応用の型**：

- **列から 1 つか隣り合う数個を取るゲーム**：取った場所で列が左右に分かれ、場の位置によらず長さだけで手が決まるなら、状態は長さ 1 つで済む（Kayles。[Grundy 数を DP で求める](../comb/grundy-number.md#dp)）
- **勝ち負けだけでよいとき**：ゲームが分かれないなら（場の両端から取るなど）、Grundy 数は要らず、勝ち負けか得点差の[ミニマックス](../comb/minimax.md)で足りる（[両端型](../dp/interval-dp.md#ends)）。分かれるゲームを勝ち負けだけで解こうとすると、左右の勝ち負けから全体の勝ち負けが決まらないので誤る

## 訪れた区間の両端と今いる端を状態にする {#visited-range}

数直線の上を左右に動いて点を訪れる問題では、訪れた点の集合は常に連続した区間になる。左右の行き来で途中の点を飛ばすことはできないからである。点を座標の順に並べると、$2^N$ 通りの部分集合のかわりに、訪れた範囲の両端 $(l, r)$ だけを持てばよい。さらに、今いる場所は範囲の左端か右端のどちらかである。範囲を広げた瞬間にいるのは新しく訪れた端だからである。

- **状態**：$\mathrm{dp}[l][r][s]$ ＝ 閉区間 $[l, r]$ の点を訪れ終え、左端（$s = 0$）か右端（$s = 1$）にいるときのコストの最小
- **遷移**：次に訪れるのは $l - 1$ か $r + 1$ の 2 通りだけで、今いる端からそこまで歩く。途中の点はすでに訪れている
- **初期値と答え**：出発点を 1 つの点として入れる。それが $o$ 番目の点なら $\mathrm{dp}[o][o][0] = \mathrm{dp}[o][o][1] = 0$。全部を訪れる問題の答えは $\min(\mathrm{dp}[0][K-1][0], \mathrm{dp}[0][K-1][1])$（点の数を $K$ とする）
- **計算順序**：範囲は広がるだけなので、範囲の長さの短い順に配る

遷移が 2 通りなので、全体は $O(N^2)$ である。$N$ が数千でも時間は足りるが、表も $O(N^2)$ で、$N = 5000$ の long long なら約 400MB になる。そのときは範囲の長さの短い順に配るので、今の長さと次の長さの 2 段だけ持てばよい。範囲の外側の点しか見ないので、「範囲の内側は全部訪れた」ことを使って条件を判定できる。たとえば「ある点を通るには、別の点で何かを拾っておく必要がある」なら、その点へ範囲を広げるときに、拾う場所が範囲 $[l, r]$ の中にあるかを調べればよい。目的地に着いた時点で終わる問題なら、目的地を含む範囲の値を答えの候補にする。

**応用の型：到着時刻の和は「待っている数」で先払いする**。各点に初めて着いた時刻の和を最小にする問題では、時刻そのものを状態に持つと大きすぎる。そこで距離 $d$ を歩くたびに、まだ訪れていない点すべての到着時刻が $d$ ずつ遅れると考え、$d \times (\text{未訪問の点の数})$ をその場でコストに足す。未訪問の点の数は範囲の長さから決まるので、状態は増えない。

## 桁と区間で分ける（'?' を含む数の列） {#digits-and-ranges}

この節は[桁 DP](../dp/digit-dp.md) の考え方を使う。同じ桁数 $M$ の数字の列 $S_0, \dots, S_{N-1}$ に '?' が含まれ、'?' を埋めて $S_0 < S_1 < \dots < S_{N-1}$（狭義増加）にする方法を数える問題を考える（$N, M \le 40$ 程度）。

桁数が同じなので、数の大小は上の桁から見た辞書順の大小と一致する。狭義増加の列を最上位の桁で見ると、上の桁が 0 の数が先頭に連続して並び、その次に 1 の数が並ぶ。同じ数字で始まる数は連続した区間になる。そして同じ数字で始まる区間の中では、残りの $M - 1$ 桁がまた狭義増加でなければならない。区間を桁ごとに細かく分けていく形で、区間と桁を組にした状態で数えられる。

- **状態**：$h(k, l, r, d)$ ＝ 列の区間 $[l, r)$ の数が上から $k$ 桁目まで等しいときに、$k + 1$ 桁目の数字を $d$ 以上に限って $k + 1$ 桁目以降を埋め、区間の中を狭義増加にする方法の数
- **遷移**：数字 $d$ を使う数がないなら $h(k, l, r, d + 1)$。使うなら、$k + 1$ 桁目が $d$ の数は区間の先頭 $[l, x)$ に集まる。$x$ を選んで $h(k + 1, l, x, 0) \cdot h(k, x, r, d + 1)$ を足す。$[l, x)$ のどの数の $k + 1$ 桁目も '?' か $d$ でなければならない
- **初期値と答え**：空の区間は 1。$d = 10$ で区間が空でなければ 0。全桁を見終えた（$k = M$）とき、区間の数が 1 個なら 1、2 個以上なら等しい数が残るので 0。答えは $h(0, 0, N, 0)$

```text
h(k, l, r, d):
    if l == r: return 1
    if k == M: return (r - l == 1) ? 1 : 0
    if d == 10: return 0
    res = h(k, l, r, d + 1)                     // 数字 d で始まる数はない
    for x = l + 1 .. r:                          // [l, x) の k+1 桁目を d にする
        if S[x-1] の k+1 桁目が '?' でも d でもない: break
        res += h(k + 1, l, x, 0) * h(k, x, r, d + 1)
    return res
```

状態は $M \cdot N^2 \cdot 10$ 個、遷移は $O(N)$ 個なので、全体で $O(10 M N^3)$ である。$N = M = 40$ なら約 $2.6 \times 10^7$ 回で済む。[メモ化再帰](../dp/memoized-recursion.md)で書くのが素直で、表は $(M + 1) \times (N + 1) \times (N + 1) \times 11$ 個になる。

区間で分ける理由は、桁 DP だけでは「列の隣どうしの大小」を 1 つずつ見ることになり、隣の比較が「どの桁で初めて差が出るか」に依存して状態が膨らむからである。上の桁で分けた区間の中では上の桁がすべて等しいので、比較は次の桁から始めればよく、区間の外の数とは上の桁だけで大小が決まっている。区間を 1 つ決めると中と外が独立になる、という区間 DP の要の性質がここでも成り立つ。

## 落とし穴 {#pitfalls}

**部分木の区間を分けるとき、兄弟の順の条件を忘れる**。子を番号の小さい順にたどる規則では、隣り合う兄弟の根の番号の大小を遷移で確かめる。忘れると、同じ行きがけ順を生まない木まで数えて答えが大きくなる。条件は先頭の部分木の根 $P_l$ と、次の部分木の根 $P_m$ の比較だけでよい（それより後ろの根との大小は $g[m][r]$ の中で保証される）。

**空の森を 1 通りにしない**。$g[l][l] = 1$ を忘れて 0 のままにすると、$g$ の和の $m = r$ の項（区間全体が 1 本の部分木）と、葉 $f[l][l+1] = g[l+1][l+1]$ がすべて 0 になる。数え上げの DP では、空の対象を「何もしない 1 通り」として初期値に入れる。

**区間ゲームで、区間の番号を状態にする**。「$i$ 番目から $j$ 番目の区間が残っている」は、区間が入れ子や交差をしていると、残っている区間の集合を正しく表さない。残っている場の座標の範囲を状態にする。

**訪れた範囲の DP で、今いる端を持たない**。範囲 $[l, r]$ が同じでも、左端にいるか右端にいるかで次の移動の距離が違う。$s$ を落として「範囲だけ」で最小を取ると、実際には行けない近道を使ったことになる。

**到着時刻の和で、待っている数を数え違える**。歩いている間に遅れるのは未訪問の点だけで、今まさに向かっている点も含む。出発点を点として数えたなら、その点は待っている数に入れない。小さな例を全探索と比べて確かめるとよい。

**$O(N^3)$ の型と $O(N^2)$ の型を取り違える**。部分木や区間の分け方を全探索する型は $O(N^3)$ で、$N \le 500$ 程度が上限である。訪れた範囲を 1 つずつ伸ばす型は $O(N^2)$ で、$N$ が数千でも時間は通る（表は 2 段に減らしてメモリを抑える）。制約の $N$ からどちらの型かの見当を付ける。

## 例題 {#examples}

### ABC252 G. Pre-Order {#abc252_g}

<div class="kp-problems" data-role="example" markdown>

- [ABC252 G. Pre-Order](https://atcoder.jp/contests/abc252/tasks/abc252_g)（diff 2153）：根から子の番号の小さい順にたどって頂点を訪れた順（行きがけ順）が与えられたとき、その順を生む根付き木の個数を求める。

</div>

行きがけ順では部分木が連続した区間になるので、区間を「$P_l$ を根とする 1 本の部分木」とみる $f$、「根の番号が増える部分木の列」とみる $g$ の 2 種類の状態を使う（[DFS 順の区間＝部分木](#dfs-order-trees)）。兄弟の順の条件は、隣り合う 2 つの部分木の根の比較だけで済む。

??? note "解法の詳細"
    - 問題文の頂点は 1-indexed だが、番号の大小だけを使うので値はそのままでよい。列の位置を 0-indexed にして $P_0, \dots, P_{N-1}$ とする。
    - $g[l][l] = 1$ とし、長さ 1 から $N$ の順に、同じ長さの中で $f$ を先に求める。$f[l][r] = g[l+1][r]$、$g[l][r] = \sum f[l][m] \cdot g[m][r]$（$m = r$ か $P_l < P_m$ の $m$ だけ）。
    - 答えは $f[0][N]$ を 998244353 で割った余りである。$O(N^3)$ で、$N \le 500$ なら間に合う。
    - コードは [DFS 順の区間＝部分木](#dfs-order-trees)の節のものと同じである。メモ化再帰で書いてもよい。

## 練習問題 {#practice}

<div class="kp-problems" data-role="practice" markdown>

- [ABC206 F. Interval Game 2](https://atcoder.jp/contests/abc206/tasks/abc206_f)（diff 2221）：区間の集合から、すでに選ばれた区間と交わらない区間を交互に選び、選べなくなった人が負けるゲームの勝者を求める。
- [ABC273 F. Hammer 2](https://atcoder.jp/contests/abc273/tasks/abc273_f)（diff 2277）：壁は対応するハンマーを拾わないと通れない数直線上で、原点からゴールへ行く移動距離の最小を求める。
- [ABC292 G. Count Strictly Increasing Sequences](https://atcoder.jp/contests/abc292/tasks/abc292_g)（diff 2340）：数字と '?' からなる同じ桁数の N 個の文字列の '?' を埋めて、狭義増加の数の列にする方法の数を求める。

</div>

??? note "練習の方針"
    - **ABC206 F**：座標が小さいので、残っている場の範囲 $[l, r)$ ごとの Grundy 数を区間 DP で求める。範囲に収まる区間 $[a, b)$ を選んだ行き先は $G[l][a] \oplus G[b][r]$ で、その mex が $G[l][r]$ になる。テストケースごとに表を初期化する（[区間ごとの Grundy 数](#grundy)）。
    - **ABC273 F**：原点・ゴール・壁・ハンマーの座標をまとめて並べ、訪れた範囲の両端と今いる端を状態にする。壁の点へ範囲を広げるときは、対応するハンマーの座標がすでに範囲の中にあるかを調べる。ゴールを含む範囲の値の最小が答えで、行けなければ $-1$ を出す（[訪れた区間の両端と今いる端を状態にする](#visited-range)）。
    - **ABC292 G**：上の桁で数字ごとに区間を分け、区間の中は次の桁で再び分ける。区間・桁・使い始める数字を状態にしたメモ化再帰で数える（[桁と区間で分ける](#digits-and-ranges)）。

## 確認問題 {#quiz}

??? question "確認問題：兄弟の順の条件"
    行きがけ順 $P = (1, 3, 2)$ を生む木（子は番号の小さい順にたどる）は何通りか。$g[1][3]$ の和で、$m = 2$ の項を足してはいけないのはなぜか。

    ??? success "答え"
        1 通り（1−3−2 の道）である。$m = 2$ の項は、3 と 2 を 1 の子として並べる分け方を表す。子は番号の小さい順にたどるので、この木の行きがけ順は $(1, 2, 3)$ になり、$P$ と違う。先頭の部分木の根 3 が次の根 2 より大きいので除く。

??? question "確認問題：訪れた範囲で足りる理由"
    数直線の上で点を訪れる問題で、訪れた点の集合を $2^N$ 通りの部分集合ではなく、範囲の両端 $(l, r)$ と今いる端で表してよいのはなぜか。今いる端を状態から外すと何が起きるか。

    ??? success "答え"
        数直線の上を動くと、2 つの訪れた点の間にある点は必ず通るので、訪れた点の集合は連続した区間になる。範囲を広げた直後にいるのは新しく訪れた端なので、今いる場所は左端か右端に限られる。今いる端を外すと、左端にいるときの値と右端にいるときの値を区別できず、実際とは違う端から歩き出す距離で計算してしまい、答えが小さくなりすぎる。

??? question "確認問題：区間ゲームの状態"
    区間の集合から交わらない区間を交互に選ぶゲームで、「すでに選ばれた区間の集合」ではなく「残っている場の座標の範囲」を状態にしてよいのはなぜか。

    ??? success "答え"
        区間を 1 つ選ぶと、それと交わる区間は選べなくなり、場は選んだ区間の左と右に分かれる。以後に選べるのは、左右どちらかの範囲に収まる区間だけである。したがって局面は「残っている範囲の集まり」で決まり、範囲ごとのゲームの和になる。和の Grundy 数は各範囲の値の XOR なので、範囲 1 つずつの値を表に持てば足りる。

## 使い分け {#comparison}

- 区間の内側を割るだけの基本の型（分割点・両端・左端の相手で分ける数え上げ）は[区間 DP](../dp/interval-dp.md)。ここで挙げた 4 つの型の工夫は、問題を区間へ言い換える段にある
- 木の形が与えられていて、部分木ごとの値を集めるなら[木 DP](../dp/tree-dp.md)。木の形そのものを数えるときに、行きがけ順の区間で区間 DP にする
- 1 つのゲームの勝ち負けや、場が分かれないゲームは[ミニマックス](../comb/minimax.md)。場が独立に分かれるゲームでは [Grundy 数](../comb/grundy-number.md)を区間ごとに求める
- 1 つの数の桁ごとの条件なら[桁 DP](../dp/digit-dp.md)。複数の数の大小を同時に扱うときに、桁で区間を分ける形になる
