!!! abstract "要点"
    - **何ができるか**：品物を 1 つずつ「選ぶ・選ばない」で分け、重さの合計ごとに価値の最大を求める。1 次元の配列で書くと、ループの向きで 0-1（大きい方から）と個数制限なし（小さい方から）が分かれる。
    - **いつ使うか**：
        - 重さの合計が W 以下で価値の和の最大を求める。
        - 同じものを何度でも使える（硬貨・魔法）。
        - 各品物は $B_i$ 個まで使える。
        - $NW \le 10^7$〜$10^8$ で、$O(NW)$ が通る。
    - **計算量**：品物の数を $N$、重さの上限を $W$ として時間 $O(NW)$。1 次元の配列を使い回せばメモリは $O(W)$。
    - **前提**：[DP の基本](../dp/dp-basics.md)

ナップサック DP は、品物を前から 1 つずつ見て「選ぶ・選ばない」を決め、使った重さの合計を[状態](../guide/glossary.md#state)に持つ DP である。$2^N$ 通りの選び方を、重さの合計が同じものどうしでまとめるので $O(NW)$ で済む。基本形は易しいが、「以下」と「ちょうど」の取り違え、1 次元にしたときのループの向き、上限での打ち切りなど、実装の細部で間違えやすい。このページでは品物を 0-indexed で $i = 0, 1, \dots, N - 1$ と番号付け、品物 $i$ の重さを $w_i$、価値を $v_i$ と書く。

## DP の表の意味（「以下」と「ちょうど」で初期値と答えが変わる） {#meaning}

0-1 ナップサックの表は次のように定める。

- $\mathrm{dp}[i][j]$ ＝ 最初の $i$ 個の品物（品物 $0, \dots, i - 1$）から選び、重さの合計が $j$ 以下のときの価値の和の最大

品物 $i$ を選ばないなら重さと価値はそのままで、選ぶなら重さ $w_i$ を使って価値 $v_i$ を得る。

$$
\mathrm{dp}[i + 1][j] = \max\bigl(\mathrm{dp}[i][j],\ \mathrm{dp}[i][j - w_i] + v_i\bigr) \quad (j \ge w_i \text{ のとき。} j < w_i \text{ なら左だけ})
$$

この状態で足りるのは、品物 $i$ 以降の選び方に影響するのが「重さをあといくつ使えるか」だけだからである。前の品物を何個どう選んだかは、重さの合計が同じなら後の選択肢を変えない。だから重さの合計が同じ選び方のうち、価値が最大のものだけを残せばよい。計算順序は $i$ の昇順で、$\mathrm{dp}[i + 1]$ の行は $\mathrm{dp}[i]$ の行だけから決まる。

次の動く図は、品物 3 個・$W = 5$ の表を 1 行ずつ埋める様子である。選ばない遷移は真下、選ぶ遷移は $w_i$ だけ左の列から斜めに来る。max を取った側の矢印を太線で示し、最後に答えのマスから表を逆にたどる。

<div class="kp-viz" data-viz="knapsack-table" data-config='{"W": 5, "items": [{"w": 2, "v": 3}, {"w": 1, "v": 2}, {"w": 3, "v": 4}], "mode": "at-most"}'></div>

この例では最後の行が $0, 2, 3, 5, 6, 7$ になり、答えは $\mathrm{dp}[3][5] = 7$（品物 0 と品物 2 を選ぶ）。各行は左から右へ減らない。重さの上限が大きいほど選べる組が増えるからである。

「重さの合計が $j$ 以下」と「ちょうど $j$」のどちらで定義しても遷移の式は同じで、違うのは初期値と答えの取り出し方である。

| 定義 | 初期値 $\mathrm{dp}[0][\cdot]$ | 答え |
| --- | --- | --- |
| 重さ $j$ 以下で価値の最大 | すべて $0$ | $\mathrm{dp}[N][W]$ |
| 重さちょうど $j$ で価値の最大 | $\mathrm{dp}[0][0] = 0$、ほかは $-\infty$ | $\max_{j \le W} \mathrm{dp}[N][j]$ |
| 重さちょうど $j$ で費用の最小 | $\mathrm{dp}[0][0] = 0$、ほかは $+\infty$ | 条件を満たす $j$ での最小 |
| 重さちょうど $j$ にする選び方の数 | $\mathrm{dp}[0][0] = 1$、ほかは $0$ | 求める和 $S$ について $\mathrm{dp}[N][S]$ |

「以下」で全体を 0 にしてよいのは、何も選ばない選び方が、どの $j$ でも「重さ $j$ 以下」を満たすからである。「ちょうど」では何も選ばない選び方は $j = 0$ にしか入らないので、ほかは「まだ作れない」の意味で $-\infty$ にする。価値の最大だけが知りたいならどちらでもよいが、「ちょうど $X$ 円を払えるか」「議席を過半数以上にする最小の費用」のように重さそのものに条件があるときは「ちょうど」で持つ。最小化なら初期値は $+\infty$、可否なら `bool`（$\mathrm{dp}[0][0] = \text{true}$）、数え上げなら $\mathrm{dp}[0][0] = 1$ である。可否と数え上げは[部分和](../dp/subset-sum.md)のページでくわしく扱う。

??? question "確認問題：初期値を取り違えると"
    「重さちょうど $j$」の定義のつもりで、初期値を「すべて 0」にした。最後に $\mathrm{dp}[N][W]$ を答えると、何を求めたことになるか。

    ??? success "答え"
        「重さ $W$ 以下」の答えになる。初期値の 0 は「重さ $j$ を何も選ばずに達成した」と読めるので、すべての $j$ が空の選び方から始まり、表は「以下」の定義と同じになる。価値の最大を問う問題なら答えは合うが、「ちょうど $W$ にできるか」を問う問題では、作れない $W$ でも 0 以上の値が出て誤る。

## 配列の使い回しとループの向き（0-1 は大きい方から、個数制限なしは小さい方から） {#dp-rolling-array}

$\mathrm{dp}[i + 1]$ の行は $\mathrm{dp}[i]$ の行だけから決まるので、表を $N + 1$ 行すべて持つ必要はない。2 本の配列を交互に使うか、1 本の配列をその場で書き換える。$N = 5000$・$W = 10^5$ で `long long` の表をすべて持つと約 4 GB になるので、大きな問題では 1 次元にする必要がある。

1 本の配列をその場で書き換えるときは、重さ $j$ を大きい方から更新する。


大きい方からでよい理由は、更新の読み方を見ると分かる。$\mathrm{dp}[j]$ を書き換えるときに読む $\mathrm{dp}[j - w_i]$ は $j$ より左にある。大きい方から進めると、左側はこの品物の更新をまだ受けていないので、そこに残っているのは前の行 $\mathrm{dp}[i][\cdot]$ の値である。2 次元の式をそのまま計算していることになる。

小さい方から進めると、$\mathrm{dp}[j - w_i]$ はすでに品物 $i$ を入れた後の値に変わっている。そこからさらに品物 $i$ を入れるので、同じ品物を何度でも使う問題（個数制限なし）を解いてしまう。

![品物 1 個（重さ 2・価値 3）、W = 6。小さい方から更新すると dp[2] = 3 を dp[4] が読んで 6、dp[6] が 9 になり、同じ品物を 3 回使う。大きい方から更新すると dp[6] は更新前の dp[4] = 0 を読むので、重さ 2 以上はすべて 3 になる](../img/knapsack-01/rolling-direction.svg)

判断の基準は「この段で書き換えた値を、この段の別の更新が読むか」である。読んでほしくない（品物を 1 回だけ使う）なら、読む側より先に書き換えない向きに回す。向きを考えるのが不安なら、2 本の配列 `dp` と `ndp` を使う。`ndp` を作り終えてから入れ替えれば、向きによらず前の段の値だけを読める。

1 次元にすると、どの品物を選んだかを後から辿れなくなる。選んだ品物の一覧を出力する問題では、2 次元の表を残して[復元](../dp/dp-reconstruction.md)する。

??? question "確認問題：2 本の配列でも向きは要るか"
    `dp`（前の段）と `ndp`（今の段）の 2 本を使い、`ndp[j] = max(dp[j], dp[j - w] + v)` で更新する。$j$ を小さい方から回しても 0-1 ナップサックになるか。

    ??? success "答え"
        なる。読むのは常に前の段の `dp` で、書き換えるのは `ndp` だけなので、同じ段の更新を読むことがない。向きが効くのは、1 本の配列で読む場所と書く場所が同じときだけである。

## 個数制限なし（数え上げでは品物と和のループの内外で組合せと列が分かれる） {#knapsack-unbounded}

同じ品物を何個でも使えるときは、2 次元で書くと次の式になる。選ぶときの遷移元が前の段ではなく、同じ段の $\mathrm{dp}[i + 1][j - w_i]$ である点だけが 0-1 と違う。

$$
\mathrm{dp}[i + 1][j] = \max\bigl(\mathrm{dp}[i][j],\ \mathrm{dp}[i + 1][j - w_i] + v_i\bigr)
$$

$\mathrm{dp}[i + 1][j - w_i]$ はすでに品物 $i$ を何個か入れた状態なので、そこにもう 1 個足せる。この式を 1 本の配列で計算すると、$j$ を小さい方から更新したものとまったく同じになる。0-1 のコードの内側のループを `for (int j = w[i]; j <= W; j++)` に変えるだけでよい。

数え上げでは、ループの内外で何を数えるかが変わる。額面 $a_i$ の硬貨を何枚でも使って合計 $s$ にする方法の数を、2 通りに数える。

- **組合せ（順序を区別しない）**：硬貨のループを外側にする。硬貨 0 を使い終えてから硬貨 1 を使う、という決まった順でしか数えないので、同じ硬貨の多重集合は 1 回だけ数えられる
- **列（順序を区別する）**：和のループを外側にし、$\mathrm{dp}[j] = \sum_i \mathrm{dp}[j - a_i]$ とする。「最後に使った硬貨」で場合分けしているので、並べ方の違うものを別に数える

## 多次元の重さ・上限で打ち切る・グループから 1 つ選ぶ {#variants}

基本形からの変形でよく出るのは次の 3 つである。どれも「先の選び方に影響する量だけを状態に持つ」という考え方は変わらない。

**多次元の重さ**。重さと体積のように制約が 2 つあるなら、$\mathrm{dp}[j][k]$（重さの合計 $j$・体積の合計 $k$）と添字を増やす。計算量は $O(N \cdot W_1 \cdot W_2)$ になるので、$N \cdot W_1 \cdot W_2$ が $10^8$ 程度に収まるかを先に確かめる。

**上限で打ち切る**。「たこ焼きを $X$ 個以上」「体力 $H$ を 0 以下に」のように目標以上にしたい量は、$X$ を超えた分を区別する必要がない。添字を $\min(X, j + a)$ に丸めると、配列の長さを $X + 1$ にでき、答えは $\mathrm{dp}[X]$ にそのまま入る。丸めずに $X$ 以上を捨てると、ちょうど $X$ にならない選び方が漏れる。0-1 を 1 本の配列で書くなら、$j$ を大きい方から回して $\mathrm{dp}[\min(X, j + a)]$ へ配る。遷移先は遷移元以上なので、読むのは前の段の値だけである。

**グループから 1 つ選ぶ**。品物がグループに分かれ、各グループから高々 1 個を選ぶなら、段をグループ単位にする。

$$
\mathrm{dp}[g + 1][j] = \max\Bigl(\mathrm{dp}[g][j],\ \max_{(w, v) \in G_g} \bigl(\mathrm{dp}[g][j - w] + v\bigr)\Bigr)
$$

グループの中の品物を、普通の 0-1 のように 1 つずつ同じ配列へ反映すると、同じグループから 2 個選ぶ遷移が混ざる。前の段 $\mathrm{dp}[g]$ だけを読むように、2 本の配列を使うのが確実である。1 本の配列で書くなら、$j$ を外側にして大きい方から回し、各 $j$ でグループの品物をまとめて試す。$\mathrm{dp}[j - w]$ はどれもこの段でまだ書き換えていないので、前の段の値を読める。

??? question "確認問題：グループを 1 つずつ反映すると"
    グループ $\{(w, v)\} = \{(2, 3), (3, 4)\}$ から高々 1 個を選ぶ問題で、2 つの品物を普通の 0-1 ナップサックのように、1 本の配列へ大きい方から順に反映した。$W = 5$ の答えは正しく出るか。

    ??? success "答え"
        出ない。1 つ目の品物の反映で $\mathrm{dp}[2] = 3$ になり、2 つ目の品物の反映で $\mathrm{dp}[5]$ が $\mathrm{dp}[2] + 4 = 7$ を読む。これは同じグループから 2 個選んだ値で、正しい答えは 4 である。グループの中の品物は、どれも前の段の値だけを読むように書く（2 本の配列を使うか、$j$ を外側にする）。

## 計算量で解法を切り替える（重さ・価値・N のどれが小さいか） {#choose-by-size}

$O(NW)$ が通る目安は $NW$ が $10^8$ 程度まで（$N = 100$ なら $W \le 10^6$ 程度）である。重さの上限が $10^9$ のように大きいときは、制約のどれが小さいかで解き方を変える。

| 小さい量 | 解き方 | 計算量 |
| --- | --- | --- |
| 重さの上限 $W$ | このページの重さの DP | $O(NW)$ |
| 価値の総和 $V$ | 添字と値を入れ替え、$\mathrm{dp}[x]$ ＝ 価値の和 $x$ を作る重さの最小 | $O(NV)$ |
| 品物の数 $N$（40 程度） | [半分全列挙](../basics/meet-in-the-middle.md#vs-knapsack) | $O(2^{N/2} N)$ |
| 重さの種類（数種類） | 重さごとに価値の高い順に並べ、何個取るかを全探索 | 種類数による |

価値の DP では、答えは「$\mathrm{dp}[x] \le W$ となる最大の $x$」である。添字と値の入れ替えは、同じ添字なら値の良い方が常に良いときに使える一般的な手法で、[状態の削減](../dp/dp-dimension-reduction.md#dp-swap-key-value)のページで扱う。重さの種類が少ない場合は DP ではなく、同じ重さの品物なら価値の高い方から取るのがよいことを使った全探索になる。

制約に「$N \le 200$、$W \le 10^9$」とだけあって迷ったら、ほかに小さい量がないかを入力の各項目の上限で探す。価値の上限や重さの種類数が小さく設定されていれば、それが解き方の手がかりである。

## 個数制限付き（素朴な展開・二進分解・余りごとのスライド最小値） {#knapsack-bounded}

この節は[単調スタックとスライド最小値](../ds/monotonic-stack.md)を前提にする。品物 $i$ が $b_i$ 個ずつあるときの解き方は 3 段階ある。

**素朴な方法**。品物 $i$ を $k$ 個（$0 \le k \le b_i$）使う場合をすべて試す。$O(W \sum b_i)$ で、$b_i$ が 50 程度なら間に合う。

**二進分解**。$b_i$ 個を $1, 2, 4, \dots, 2^{t-1}$ 個のまとまりと、残り $r = b_i - (2^t - 1)$ 個のまとまりに分ける（$t$ は $2^t - 1 \le b_i$ となる最大）。各まとまりを 1 つの品物とみて 0-1 ナップサックを解けば、$O(W \sum \log b_i)$ になる。

```cpp
--8<-- "knapsack-01/bounded-binary.cpp:core"
```

これで正しいのは、0 個から $b_i$ 個までのどの個数 $c$ も、まとまりの選び方でちょうど作れるからである。$c \le 2^t - 1$ なら $c$ の 2 進表記どおりに $1, 2, \dots, 2^{t-1}$ から選べばよい。$c > 2^t - 1$ なら $r$ を必ず使い、残りの $c - r$ は $0 \le c - r \le 2^t - 1$ なので 2 進表記で作れる。逆に、まとまりの合計は $b_i$ を超えないので、使いすぎることもない。

**余りごとのスライド最小値**。品物 $i$ の更新を、重さ $j$ を $w_i$ で割った余りごとの列に分ける。$j = r + q w_i$ と書き、$\mathrm{dp}$ を品物 $i$ の前の行、$\mathrm{dp}'$ を後の行とすると、

$$
\mathrm{dp}'[r + q w_i] = \max_{\max(0,\, q - b_i) \le q' \le q} \bigl(\mathrm{dp}[r + q' w_i] - q' v_i\bigr) + q v_i
$$

となる。かっこの中は $q'$ だけで決まる値なので、各列で幅 $b_i + 1$ の窓の最大（スライド最小値の大小を逆にしたもの）を求めればよい。単調な deque で窓の最大を取れば品物 1 つあたり $O(W)$、全体で $O(NW)$ になる。選び方の数を数えるなら窓の最大の代わりに窓の和を取ることになり、累積和で済む。

ABC で二進分解やスライド最小値が必須になる問題は少なく、まずは素朴な方法で間に合うかを見積もるとよい。

## 落とし穴 {#pitfalls}

**1 次元にしたときのループの向き**。0-1 なのに $j$ を小さい方から回すと、同じ品物を何度も使った値が出る。入力例が小さいと偶然合うことがあるので、「同じ品物 1 個だけ・$W$ がその重さの 2 倍以上」のような例で確かめる。

**$\pm\infty$ からの遷移**。最小化で $+\infty$ を `LLONG_MAX` にすると、費用を足したときにあふれる（最大化で `LLONG_MIN` に負の値を足すときも同じ）。最大化で `LLONG_MIN` に正の価値を足すとあふれはしないが、作れないのに有限に見える値になる。遷移元が $\pm\infty$ なら飛ばすのが確実である。$10^{18}$ のような値で代えるなら、「作れない」の判定を等号ではなく「$10^{17}$ より大きいか」のように幅を持たせる。

**価値の和のオーバーフロー**。品物 100 個の価値がどれも $10^9$ なら和は $10^{11}$ になり、`int` に収まらない。表は `long long` で持つ（[整数のオーバーフロー](../cpp/cpp-integer-overflow.md)）。

**「以下」と「ちょうど」の取り違え**。「ちょうど $X$ 円を払えるか」を、初期値をすべて 0 にした表で判定すると、払えない $X$ でも可になる。表の定義を 1 文で書き、初期値と答えをそれに合わせる。

**グループと 1 次元の配列**。グループから 1 つ選ぶ遷移を、品物ごとに 1 本の配列へ反映すると、同じグループの別の品物を反映した値を読んでしまう。グループの遷移は 2 本の配列で書くか、$j$ を外側（大きい方から）、品物を内側にする。

**負の添字**。$j - w_i < 0$ のときに $\mathrm{dp}[j - w_i]$ を読むと範囲外になる。配る DP なら遷移先 $j + w_i$ が $W$ を超えないかを確かめる。

## 上位の手法へのつながり {#next-steps}

ナップサック DP は、多くの DP の土台になる。

- **部分和**：価値がなく「和 $S$ を作れるか」「作り方の数」を問う形。`bitset` による高速化も使える（[部分和](../dp/subset-sum.md)）
- **戻す DP**：数え上げのナップサックは足し算だけでできているので、品物を 1 つ取り除く逆の更新ができる。max のナップサックは戻せない（[戻す DP](../dp/knapsack-undo.md#undo-by-subtraction)）
- **順序を決めてから DP**：締切や積み重ねのように順序が効く問題では、交換論法で並べる順を決めてからナップサックにする（[並べ替えてから DP する](../dp/exchange-argument-dp.md)）
- **木の上のナップサック**：部分木ごとに「選んだ個数ごとの最大」を持ち、選んだ個数の範囲を部分木のサイズまでに抑えてマージすると、全体で $O(N^2)$ になる（[二乗の木 DP](../dp/tree-dp-square.md#size-bounded)）
- **区間の品物だけのナップサック**：クエリの区間ごとに答えるときは、分割統治で左右の表をマージする（[分割統治](../basics/divide-and-conquer.md#range-knapsack)）

## 使い分け {#comparison}

- 品物を分割して一部だけ入れてよい（価値は重さに比例）なら、単位重さあたりの価値が高い順に詰める[貪欲法](../basics/greedy-basics.md)が正しい。分割できない 0-1 では貪欲は誤る
- 重さの上限が大きいとき、品物の数 $N$ が 40 程度なら[半分全列挙](../basics/meet-in-the-middle.md#vs-knapsack)を使う

## 例題 {#examples}

### EDPC D. Knapsack 1 {#dp_d}

<div class="kp-problems" data-role="example" markdown>

- [EDPC D. Knapsack 1](https://atcoder.jp/contests/dp/tasks/dp_d)（diff —）：重さと価値が決まった N 個の品物から、重さの合計が W 以下になるように選ぶときの価値の和の最大を求める。

</div>

$N \le 100$、$W \le 10^5$ なので $O(NW) = 10^7$ で間に合う。「重さ $W$ 以下」なので「以下」の定義で表を作り、初期値はすべて 0、答えは $\mathrm{dp}[N][W]$ である。

??? note "解法の詳細"
    - 状態：$\mathrm{dp}[j]$ ＝ ここまでの品物から重さの合計 $j$ 以下で選んだときの価値の最大。長さ $W + 1$ の配列をすべて 0 で始める。
    - 品物ごとに $j = W, W - 1, \dots, w_i$ の順（大きい方から）で $\mathrm{dp}[j] \leftarrow \max(\mathrm{dp}[j], \mathrm{dp}[j - w_i] + v_i)$ とする。
    - 価値は $10^9$ までで品物が 100 個なので、和は $10^{11}$ になりうる。`long long` で持つ。
    - コードは[配列の使い回し](#dp-rolling-array)の節のものと同じである。

## 練習問題 {#practice}

<div class="kp-problems" data-role="practice" markdown>

- [ABC286 D. Money in Hand](https://atcoder.jp/contests/abc286/tasks/abc286_d)（diff 607）：A_i 円硬貨が B_i 枚（≤ 50）ずつあるとき、ちょうど X 円を払えるかを判定する。
- [ABC344 D. String Bags](https://atcoder.jp/contests/abc344/tasks/abc344_d)（diff 854）：N 個の袋からそれぞれ高々 1 つの文字列を選んで順に連結し、文字列 T を作るときの費用の最小を求める。
- [ABC317 D. President](https://atcoder.jp/contests/abc317/tasks/abc317_d)（diff 929）：選挙区ごとに議席数と、議席を取るのに鞍替えさせる必要がある人数が決まっているとき、議席の過半数を取るための鞍替えの人数の最小を求める。
- [ABC153 E. Crested Ibis vs Monster](https://atcoder.jp/contests/abc153/tasks/abc153_e)（diff 1015）：体力 H のモンスターに、ダメージと消費魔力が決まった魔法を何度でも使って体力を 0 以下にするときの、消費魔力の最小を求める。
- [ABC219 D. Strange Lunchbox](https://atcoder.jp/contests/abc219/tasks/abc219_d)（diff 1085）：たこ焼きとたい焼きの個数が決まった弁当を選び、それぞれ X 個以上・Y 個以上にするときの弁当の個数の最小を求める。

</div>

??? note "練習の方針"
    - **ABC286 D**：「ちょうど $j$ 円を払えるか」の `bool` の表で、硬貨 $i$ を使う枚数 $k$（$0 \le k \le B_i$）をすべて試す素朴な個数制限付きの DP。$O(X \sum B_i)$ で間に合う
    - **ABC344 D**：$\mathrm{dp}[i][j]$ ＝ 袋を $i$ 個見て $T$ の先頭 $j$ 文字を作る費用の最小。袋の中の文字列が $T$ の $j$ 文字目から一致すれば遷移する。グループから 1 つ選ぶ形なので 2 本の配列で書く
    - **ABC317 D**：選挙区ごとに勝つのに要る鞍替えの人数を先に計算し、議席数を重さ・人数を費用とした「議席ちょうど $j$ で費用の最小」の表を作る。答えは過半数以上の $j$ での最小
    - **ABC153 E**：個数制限なしなので小さい方から更新する。与えたダメージの合計を添字にし、$H$ 以上は $H$ に丸める
    - **ABC219 D**：たこ焼きの個数とたい焼きの個数を 2 つの添字にし、どちらも $X$・$Y$ で打ち切る。最後まで $+\infty$ なら $-1$ を出力する

## 力試し {#challenge}

<div class="kp-problems" data-role="challenge" markdown>

- [ABC032 D. ナップサック問題](https://atcoder.jp/contests/abc032/tasks/abc032_d)（diff 1731）：N 個の品物の 0-1 ナップサックを、N・重さ・価値のどれか 1 つだけが小さい 3 種類の制約で解く。
- [ABC373 F. Knapsack with Diminishing Values](https://atcoder.jp/contests/abc373/tasks/abc373_f)（diff 2018）：品物 i を k 個選ぶと価値が k·v_i − k^2 になるとき、重さの合計が W 以下での価値の和の最大を求める。

</div>

??? note "力試しの方針"
    - **ABC032 D**：入力を読んでから、$N$ が小さければ半分全列挙、重さが小さければ重さの DP、価値が小さければ価値を添字にした DP に切り替える（[計算量で解法を切り替える](#choose-by-size)の表のとおり）
    - **ABC373 F**：$k$ 個目を足したときの価値の増分は $v_i - (2k - 1)$ と減っていく。品物ごとの更新を重さの余りごとの列に分けると、最適な遷移元の位置が単調に動くので、すべての $k$ を試す $O(W^2)$ の更新を速くできる
