桁 DP は、$N$ 以下の整数を上の桁から 1 桁ずつ決めながら数える DP である。$N \le 10^{18}$ の整数を 1 つずつ調べることはできないが、桁は 19 個しかない。「$N$ を超えないこと」を 2 値のフラグ 1 つで管理できるので、計算量は桁数に比例する。

## N と一致しているかのフラグ（一致したままの道は 1 本だけ） {#tight-flag}

桁 DP の土台は、$N$ 以下の整数の分け方である。$N$ の桁数を $L$ とし、$L$ 桁に足りない整数は左を 0 で埋めて $L$ 桁にそろえる。2 つの $L$ 桁の整数の大小は、上から見て最初に異なる桁で決まる。だから $X \le N$ になるのは、次のどちらか一方のときだけである。

- $X = N$（すべての桁が一致する）
- ある桁 $i$ で初めて $N$ と異なり、そこで $X$ の数字が $N$ の数字より小さい

$X < N$ なら、この桁 $i$ は 1 つに決まる。桁 $i$ より上は $N$ と同じで、桁 $i$ より下は 0〜9 を自由に選んでよい。つまり、上の桁から決めていく途中の数は「$N$ と一致したまま」か「$N$ より小さいことが確定した」かの 2 通りしかない。一致したままの途中の数は $N$ の接頭辞そのものなので、各段で 1 個だけである。

この 2 通りを区別するフラグを $t$ と書く（$t = 1$ が一致、$t = 0$ が未満）。各桁で置ける数字と、次のフラグは次のとおりである。$N$ のその桁の数字を $c$ とする。

| 今のフラグ | 置ける数字 $x$ | 次のフラグ |
| --- | --- | --- |
| 一致（$t = 1$） | $0 \le x < c$ | 未満 |
| 一致（$t = 1$） | $x = c$ | 一致 |
| 未満（$t = 0$） | $0 \le x \le 9$ | 未満 |

一致の状態で $c$ より大きい数字を置くと $N$ を超えるので、その遷移はない。未満の状態は二度と一致に戻らない。

次の図は、$N = 253$ の桁を並べ、「ここで初めて $N$ より小さい数字を選ぶ」分岐を木で描いたものである。一致の道が 1 本だけ伸び、そこから各桁で未満の枝が分かれていく。

図の流れを文章で追うと次のとおりである。

- 百の位：2 を選べば一致のまま進む。0・1 を選ぶと未満になり、十の位と一の位は 00〜99 の 100 通りが自由に選べる
- 十の位（一致の道の上）：5 を選べば一致のまま進む。0〜4 を選ぶと未満になり、一の位は 10 通り自由になる
- 一の位（一致の道の上）：3 を選べば 253 そのものになる。0〜2 を選ぶと未満になる
- 数えた個数は $2 \times 100 + 5 \times 10 + 3 + 1 = 254$ で、0 から 253 までの整数の個数と一致する。数え方に重複と漏れがない

**状態と遷移**：DP の表は次のように決める。添字は 0-indexed で、$N$ の上から $i$ 番目の数字を $c_i$ とする。

- 状態：$\mathrm{dp}[i][t][r]$ ＝ 上から $i$ 桁を決めた数のうち、フラグが $t$ で、問題の情報が $r$ であるものの個数
- 遷移：上の表に従って、次の桁の数字 $x$ ごとに $\mathrm{dp}[i+1][t'][r']$ へ足す（配る形）。$r'$ は $r$ と $x$ から決まる
- 計算順序：$i$ の小さい順。$i + 1$ 桁目の値は $i$ 桁目の値だけから決まる
- 初期値：$\mathrm{dp}[0][1][r_0] = 1$。何も決めていない数は $N$ と一致していると見なす（$r_0$ は空の数の情報で、桁和なら 0）
- 答え：$\mathrm{dp}[L][0][r] + \mathrm{dp}[L][1][r]$ を、条件を満たす $r$ について足す。$t = 1$ の項は $N$ 自身である

**なぜこの状態で足りるか**：残りの桁に置ける数字は、フラグだけで決まる。一致なら $N$ の桁で上限が決まり、未満なら 0〜9 が自由である。最後に条件を満たすかは $r$ だけで決まるように $r$ を選ぶ。だから、ここまでの桁が違っても $t$ と $r$ が同じ途中の数は、この先の選び方がまったく同じになり、1 つの状態にまとめて数えてよい（[状態](../guide/glossary.md#state)の考え方）。

例として、$N = 253$ 以下で桁和が 3 の倍数の整数を数える。$r$ は桁和を 3 で割った余りである。表の各列は、その桁まで決めたときの状態ごとの個数である。

| 状態 | 初め | 2 | 25 | 253 |
| --- | --- | --- | --- | --- |
| 一致（余り） | 1（0） | 1（2） | 1（1） | 1（1） |
| 未満・余り 0 | 0 | 1 | 9 | 85 |
| 未満・余り 1 | 0 | 1 | 8 | 84 |
| 未満・余り 2 | 0 | 0 | 8 | 84 |

一致の行は常に 1 個で、余りだけが $N$ の接頭辞の桁和で変わる。百の位を決めた後の「未満・余り 0」の 1 個は百の位が 0 の数、「未満・余り 1」の 1 個は百の位が 1 の数である。答えは余り 0 の個数の和 $85 + 0 = 85$ である。ただしこれは 0 を含むので、1 以上だけなら答えは 84 である（[落とし穴](#pitfalls)）。

**計算量**：状態は桁ごとに $2S$ 個で（$S$ は $r$ の種類の数）、各状態から最大 10 本の遷移が出る。全体で $O(10 L S)$ である。桁和が $D$ の倍数のものを数えるなら $S = D$ なので $O(10 L D)$ で、$L = 10^4$、$D = 100$（[例題 EDPC S](#dp_s) の上限）でも約 $10^7$ 回で済む。同じ DP は、桁の位置・フラグ・情報を引数にした[メモ化再帰](../dp/memoized-recursion.md)でも書ける。

??? question "確認問題：フラグを持たないと何が起きるか"
    $N = 253$ で、フラグを持たずに各桁で 0〜9 を自由に選ぶ DP を書いた。何を数えてしまうか。逆に、各桁で $N$ のその桁以下の数字だけを選ぶ DP にすると何を数え落とすか。

    ??? success "答え"
        自由に選ぶと、000〜999 のすべてを数えてしまい、254〜999 が余分に入る。各桁で $N$ の桁以下に制限すると、百の位 0〜2・十の位 0〜5・一の位 0〜3 の組だけになり、たとえば 199 のように「上の桁で小さくなった後に大きい数字を置く」数が落ちる。上の桁で小さくなった後は自由に選べる、という切り替えがフラグの役目である。

## 問題の情報を状態に足す（桁和の余り・個数） {#extra-state}

フラグに足す情報 $r$ は、「最後に条件を満たすかを判定するのに、ここまでの桁から何を覚えておけば足りるか」で決める。覚える量が少ないほど状態数 $S$ が小さくなる。典型は次のとおりである。

| 条件 | 覚える情報と遷移（数字 $x$ を置く） | $S$ |
| --- | --- | --- |
| 桁和が $D$ の倍数 | 桁和の余り：$r \to (r + x) \bmod D$ | $D$ |
| 数自身が $m$ の倍数 | 数の余り：$r \to (10r + x) \bmod m$ | $m$ |
| 0 でない桁がちょうど $K$ 個 | 個数：$x \ne 0$ なら $r \to r + 1$ | $K + 1$ |
| 数字 3 を含む | 含んだか：$x = 3$ なら真 | 2 |
| 使った数字の種類 | 数字の集合：$r \to r \cup \{x\}$ | $2^{10}$ |

数自身の余りを $10r + x$ で更新してよいのは、上から 1 桁足すと数が「10 倍して $x$ を足す」になり、足し算・掛け算の後に余りを取っても結果が変わらないからである（[余りを状態にしてよい理由](../dp/dp-mod-state.md#why-remainder)）。

**上限で打ち切る**：「ちょうど $K$ 個」を数えるときは、個数が $K$ を超えた状態は二度と条件を満たさないので捨ててよい。これで $S$ は桁数ではなく $K + 1$ になる。「$K$ 個以上」なら、$K$ 以上をまとめて 1 つの状態 $K$ にする。

**条件を組み合わせる**：複数の条件は、情報を組にして持つ。「数字 7 を含み、かつ 7 の倍数」なら、7 を含んだか（2 通り）と数を 7 で割った余り（7 通り）の組を持ち、$S = 2 \times 7 = 14$ になる。ただし、すでに持っている情報から分かるものは状態に入れない。たとえば数字の集合を持つなら、ある数字を含むかは集合から分かるので、別に持たなくてよい。

**総和を求めるとき**：個数ではなく条件を満たす数の総和を問われたら、状態ごとに「個数」と「数の総和」の 2 つを持つ。数字 $x$ を置くと、各数は 10 倍して $x$ を足したものになるので、総和は「$10 \times$ 総和 $+ x \times$ 個数」になる。詳しくは[桁 DP の応用](../dp/digit-dp-advanced.md#count-and-sum)で扱う。

## leading zero を区別するとき {#leading-zero}

桁数の少ない数を左から 0 で埋めて $L$ 桁にそろえると、埋めた 0（leading zero）が数字として紛れ込む。たとえば $N = 253$ のとき、7 は 007 として数えられる。条件が先頭の 0 で変わらないなら、このままでよい。変わるなら、「数がもう始まったか」のフラグを足して区別する。

| 条件 | 先頭の 0 を区別するか | 理由 |
| --- | --- | --- |
| 桁和・桁和の余り | しない | 0 を足しても桁和は変わらない |
| 数自身の余り | しない | $10 \times 0 + 0 = 0$ のまま |
| 0 でない桁の個数 | しない | 0 は数えない |
| 0 の個数・数字 0 を含むか | する | 007 の 0 を 2 個と数えてしまう |
| 使った数字の集合・種類数 | する | 007 が「0 と 7 の 2 種類」になる |
| 隣り合う桁の条件（隣と異なる・増加など） | する | 00 が「隣が同じ」になる |

始まったかのフラグを $z$ とする（$z = 0$ はまだ 0 しか置いていない）。数字 $x$ を置くと、$z = 0$ かつ $x = 0$ なら $z = 0$ のままで、情報 $r$ も変えない。それ以外は $z = 1$ になり、ふつうに $r$ を更新する。最後まで $z = 0$ の状態は整数の 0 なので、1 以上を数えるときは答えに含めない。

??? question "確認問題：leading zero を区別する必要があるか"
    次の 2 つの条件のそれぞれについて、$N$ 以下の数を数える桁 DP で先頭の 0 を区別する必要があるか。(1) 各桁の積が $K$ 以下。(2) 偶数の数字がちょうど 2 個。

## 2 進の桁 DP（XOR・AND） {#binary}

上限が「$K$ 以下の非負整数 $X$」で、条件が XOR・AND で書かれているときは、$K$ を 2 進で見て同じ DP をする。置ける数字が 0 と 1 だけになり、$K \le 10^{18}$ なら桁は 60 個である。上の bit から決めること自体は、[上の bit から決める貪欲](../basics/bitwise-independence.md#top-down)と同じ考え方である。

**最大化に使う**：$0 \le X \le K$ で $\sum_i (X \oplus A_i)$ を最大にする問題を考える。XOR は bit ごとに独立なので、$X$ の bit $k$ を $b$ にしたときの寄与は「bit $k$ が $b$ と異なる $A_i$ の個数」$\times 2^k$ で、ほかの bit に影響しない。そこで次の DP をする。

- 状態：$\mathrm{dp}[t]$ ＝ 上の bit から決めた途中の $X$ のうち、フラグが $t$ のものの寄与の和の最大
- 遷移：一致の状態で $K$ の bit が 1 なら、0 を置いて未満へ移るか、1 を置いて一致のまま進む。$K$ の bit が 0 なら 0 だけを置ける。未満の状態では 0・1 のどちらも置ける
- 初期値：$\mathrm{dp}[1] = 0$、$\mathrm{dp}[0] = -\infty$（まだ未満の数はない）
- 答え：$\max(\mathrm{dp}[0], \mathrm{dp}[1])$

最大化では、数え上げの「0 通り」にあたるのが $-\infty$ である。未満の状態を初めから 0 にすると、最上位の bit から自由に選べる「未満の数」があることになり、$K$ を超える $X$ の値まで答えに混ざる。到達できない状態は $-\infty$ で表し、遷移の前に飛ばす。

**2 つの数を同時に決める**：「$a + b \le L$ かつ $a + b = a \oplus b$ となる組 $(a, b)$ の個数」のように 2 つの数を決める問題でも、1 つのフラグで済むことがある。$a + b = a \oplus b$ は「同じ bit で両方が 1 にならない」と同じで、繰り上がりが起きない。だから各 bit での $(a, b)$ の組は $(0, 0)$・$(0, 1)$・$(1, 0)$ の 3 通りである。和 $c = a + b$ の bit は、その 2 つの bit の和（0 か 1）になる。$c \le L$ を 1 つのフラグで管理し、$c$ の bit が 1 になる遷移には 2 通りを掛ければよい。

2 つの数のそれぞれに上限があるときは、フラグを数ごとに並べて持つ。この形と、繰り上がりを状態にする形は[桁 DP の応用](../dp/digit-dp-advanced.md#multiple-numbers)で扱う。

**bit の幅**：$K$ と $A_i$ の最大値の両方を表せる幅（$10^{18}$ 未満なら 60 bit）を上から回す。$2^k$ は `1LL << k` と書く。`1 << k` は $k \ge 31$ で int の範囲を超える。

## 割る数を全探索して桁 DP を繰り返す {#fix-divisor}

「$N$ 以下の正の整数のうち、各桁の和で割り切れるもの」を数えたいとする。数自身の余りを状態に持ちたいが、割る数（桁和）が最後の桁まで決まらないので、どの数で割った余りを持てばよいか分からない。

そこで、割る数を先に決め打つ。$N$ の桁数が $L$ なら桁和は $9L$ 以下なので、桁和 $m$ を $1$ から $9L$ まで全部試す。各 $m$ について「桁和がちょうど $m$ で、$m$ で割り切れる数」を桁 DP で数え、最後に足す。整数 $n$ は、自分の桁和 $m = s(n)$ のときにだけ数えられるので、重複と漏れはない。

- 状態：$\mathrm{dp}[t][j][r]$ ＝ フラグが $t$、ここまでの桁和が $j$、ここまでの数を $m$ で割った余りが $r$ のものの個数
- 遷移：数字 $x$ を置くと $j \to j + x$、$r \to (10r + x) \bmod m$。$j$ が $m$ を超えたら捨てる
- 答え：$t$ によらず $j = m$ かつ $r = 0$ の個数

**計算量**：$m$ を決めた DP 1 回は、状態が桁ごとに $2(m + 1)m$ 個で、各状態から最大 10 本の遷移が出るので $O(10 L m^2)$ である。$m \le 9L$ について足すと、$m^2$ の和は約 $(9L)^3 / 3$ なので、全体で $O(10 L \cdot (9L)^3)$ になる。$N \le 10^{14}$ なら $L = 15$ で、多く見積もっても約 $2.5 \times 10^8$ 回である。桁和が $m$ を超える遷移と個数が 0 の状態を飛ばすので、実際はずっと少なく、1 秒もかからない。

割る数を決め打つ考え方は、桁和に限らない。「最後まで決まらない量が状態の定義（割る数・目標の値）に入ってしまう」ときは、その量の候補が少なければ外側で全探索し、内側を固定された条件の DP にする。

## 落とし穴 {#pitfalls}

**一致の状態を答えに足し忘れる**。最後の桁まで一致したままの状態は $N$ 自身である。答えを未満の状態だけから取ると、$N$ が条件を満たすときに 1 個足りなくなる。「$N$ 未満」を問われたときだけ、一致の状態を除く。

**0 を数えてしまう**。左から 0 で埋める DP は、全部 0 の数（整数の 0）も数える。0 は桁和が 0 で、どの $D$ の倍数でもあるので、桁和の余りで数えると必ず紛れ込む。1 以上を数えるなら、最後に 1 を引くか、始まったかのフラグで除く（[leading zero を区別するとき](#leading-zero)）。0 でない桁の個数のように、0 が条件を満たさないなら引かなくてよい。引くかどうかは、$N = 1$ などの小さい入力で確かめる。

**閉区間 $[L, R]$ の下限**。$L$ 以上 $R$ 以下の個数は、$N$ 以下の個数 $f(N)$ を使って $f(R) - f(L - 1)$ で求める。$L$ が文字列で与えられると $L - 1$ の繰り下がりを書くのが手間なので、$f(R) - f(L)$ に「$L$ 自身が条件を満たせば 1」を足してもよい。mod を取っているなら、引き算の後で負の値を直す（[引き算の後の負の数](../math/mod-arithmetic.md#negative)）。

**大きな $N$ を整数型で読む**。$N < 10^{100}$ や $10^4$ 桁は `long long` に入らない。最初から文字列で読み、`c - '0'` で各桁の数字にする。$N \le 10^{18}$ なら `long long` で読んでから `to_string` してよい。$10^{18}$ は 19 桁である。

**一致のまま進む条件を取り違える**。次のフラグが一致になるのは「今が一致で、かつ $N$ の桁と同じ数字を置いた」ときだけである。今が未満なら、$N$ の桁と同じ数字を置いても未満のままである。`nt = (t && x == lim)` と書き、`nt = (x == lim)` としない。

**表の大きさを桁和で取る**。桁和そのものを状態にすると、$10^4$ 桁では $9 \times 10^4$ 通りになる。条件が「$D$ の倍数」なら余りだけを持てば $S = D$ で済む。持つのは条件の判定に要る最小の情報にする。

## 例題 {#examples}

### EDPC S. Digit Sum {#dp_s}

<div class="kp-problems" data-role="example" markdown>

- [EDPC S. Digit Sum](https://atcoder.jp/contests/dp/tasks/dp_s)（diff なし）：1 以上 K 以下（K は最大 10^4 桁）の整数のうち、各桁の和が D の倍数になるものの個数を求める。

</div>

$K$ は $10^4$ 桁なので文字列で読む。$K$ と一致しているかのフラグと、桁和を $D$ で割った余りを状態にする。[フラグの節](#tight-flag)のコードがそのまま解法になる。全部 0 の数も桁和 0 として数えてしまうので、最後に 1 を引く。

??? note "解法の詳細"
    - 状態：$\mathrm{dp}[i][t][r]$ ＝ 上から $i$ 桁を決めた数のうち、フラグが $t$、桁和の余りが $r$ のものの個数（$0 \le r < D$）。
    - 遷移：一致なら $K$ の桁 $c$ 以下の数字、未満なら 0〜9 を置く。$c$ と同じ数字を置いたときだけ一致が続く。余りは $(r + x) \bmod D$。
    - 初期値：$\mathrm{dp}[0][1][0] = 1$。
    - 答え：$\mathrm{dp}[L][0][0] + \mathrm{dp}[L][1][0] - 1$ を $10^9 + 7$ で割った余り。引き算で負にならないよう法を足してから余りを取る。
    - 計算量：$O(10 L D)$ で、$L = 10^4$、$D = 100$ なら $10^7$ 回。

### ABC154 E. Almost Everywhere Zero {#abc154_e}

<div class="kp-problems" data-role="example" markdown>

- [ABC154 E. Almost Everywhere Zero](https://atcoder.jp/contests/abc154/tasks/abc154_e)（diff 1298）：1 以上 N 以下（N < 10^100）の整数のうち、0 でない数字がちょうど K 個のものの個数を求める。

</div>

$N$ は 100 桁まであるので文字列で読む。$N$ と一致しているかのフラグと、ここまでに置いた 0 でない数字の個数を状態にする。個数が $K$ を超えた状態は捨ててよいので、個数は 0〜$K$ の $K + 1$ 通りで足りる。0 でない桁の個数は先頭の 0 で変わらないので、leading zero を区別しなくてよい。

??? note "解法の詳細"
    - 状態：$\mathrm{dp}[i][t][j]$ ＝ 上から $i$ 桁を決めた数のうち、フラグが $t$、0 でない数字の個数が $j$ のものの個数（$0 \le j \le K$）。
    - 遷移：数字 $x$ を置き、$x \ne 0$ なら $j$ を 1 増やす。$j$ が $K$ を超える遷移は捨てる。フラグの規則は[フラグの節](#tight-flag)の表のとおり。
    - 初期値：$\mathrm{dp}[0][1][0] = 1$。
    - 答え：$\mathrm{dp}[L][0][K] + \mathrm{dp}[L][1][K]$。$K \ge 1$ なので整数の 0（0 でない数字が 0 個）は数えられず、1 を引く必要はない。
    - 答えは $\binom{100}{3} \times 9^3$ 程度までで `long long` に収まるので、mod を取らなくてよい。
    - 未満になった後の個数は、残りの桁数 $n$ から $\binom{n}{k} 9^k$ と式でも求まる。DP にすれば式を考えずに済む。

## 練習問題 {#practice}

<div class="kp-problems" data-role="practice" markdown>

- [ABC135 D. Digits Parade](https://atcoder.jp/contests/abc135/tasks/abc135_d)（diff 1334）：数字と '?' からなる文字列の '?' を埋めてできる整数のうち、13 で割って 5 余るものの数を求める。
- [ABC465 E. Digit Circus](https://atcoder.jp/contests/abc465/tasks/abc465_e)（diff 1417）：1 以上 N 以下（N は巨大な数字の列）の整数のうち、「数字がちょうど 3 種類」「数字 3 を含む」「3 の倍数」のちょうど 1 つだけを満たすものの個数を求める。
- [ABC117 D. XXOR](https://atcoder.jp/contests/abc117/tasks/abc117_d)（diff 1423）：0 以上 K 以下の整数 X のうち、Σ (X xor A_i) を最大にするときの最大値を求める。
- [ABC336 E. Digit Sum Divisible](https://atcoder.jp/contests/abc336/tasks/abc336_e)（diff 1538）：N 以下（N ≤ 10^14）の正の整数のうち、各桁の和で割り切れるものの個数を求める。
- [ABC129 E. Sum Equals Xor](https://atcoder.jp/contests/abc129/tasks/abc129_e)（diff 1547）：2 進数で与えられた L について、a + b ≤ L かつ a + b = a xor b を満たす非負整数の組 (a, b) の個数を求める。

</div>

??? note "練習の方針"
    - **ABC135 D**：上限がないので一致のフラグは要らない。上の桁から、13 で割った余りを状態にして数える。'?' の桁では 0〜9 のすべてへ遷移する。
    - **ABC465 E**：使った数字の集合（$2^{10}$）と 3 で割った余り、一致のフラグを状態にする。数字の集合を数えるので先頭の 0 を区別し、空の集合（整数の 0）は答えに入れない。3 を含むかは集合から分かる。
    - **ABC117 D**：2 進の上の bit から、$K$ と一致しているかのフラグで寄与の和の最大を DP する。到達できない状態は $-\infty$ にする。
    - **ABC336 E**：桁和 $m$ を 1 から $9L$（$L$ は $N$ の桁数）まで決め打ち、桁和と $m$ で割った余りを状態にした桁 DP を繰り返して足す。
    - **ABC129 E**：各 bit で $(a, b)$ の組は 3 通りで、和の bit が 1 になる組は 2 通りある。和が $L$ 以下であることを 1 つのフラグで管理する。

## 使い分け {#comparison}

- 上限 $N$ がなく、「$N$ 桁の数」や「'?' を埋めてできる数」を数えるなら、フラグは要らない。余りなどを状態にした DP だけで済む（[余りを状態に持つ DP](../dp/dp-mod-state.md)）
- XOR の和のように各 bit を独立に数えられ、上限がない問題は、桁 DP でなく [bit ごとの寄与](../basics/bitwise-independence.md#per-bit-contribution)で数える
- 2 つ以上の数に別々の上限がある、下の桁から繰り上がる、状態の種類が多いが実際に現れるものは少ない、といった問題は[桁 DP の応用](../dp/digit-dp-advanced.md)
- 「文字列 $T$ を部分文字列として含まない数」のように、パターンとの照合を状態にする DP は、[照合オートマトン上の DP](../string/string-automaton-dp.md#matching-state)と同じ構造で、上の桁から状態機械を動かす
- 桁数自体が $10^{18}$ のように大きく、「$N$ 以下」ではなく「ちょうど $N$ 桁」を数えるなら、桁ごとの遷移を行列にして[行列累乗](../math/matrix-power.md)やダブリングで速くする
- 未満の状態から先が単純な数え上げになるなら、DP の代わりに式で数えてもよい（0 でない桁が $k$ 個なら、残り $n$ 桁から $\binom{n}{k} 9^k$ 通り）
