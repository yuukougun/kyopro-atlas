!!! abstract "要点"
    - **何のページか**：手法の名前・別名・英語名から、そのページを五十音順と ABC 順で引ける。全ページの題名と別名から生成するので、サイト内検索の結果に左右されない入口として使える。
    - **使い方**：ページの上の欄に語を入れると、その語を含む行だけが残る（語の一部でもよい）。並びから探すなら、最初の字がかななら[五十音順](#kana)、英字か数字なら[英字の名前](#latin)の節を見る。漢字や記号で始まる語は五十音順の節の最後にあり、`_GLIBCXX_DEBUG` のような `_` で始まる C++ の名前も記号の側にある。
    - **ほかの入口**：語の意味は[用語集](glossary.md)、問題文の言い回しからは[逆引き辞典（言い回しから）](reverse-index-signs.md)、制約からは[逆引き辞典（制約・計算量から）](reverse-index-constraints.md)で引く。

用語の索引は、各ページの題名・別名（略称・英語名を含む）と、ページで使う ACL の名前を 1 語 1 行に並べ、その語を持つページへつないだものである。名前は知っているがどのページにあるか分からないときや、サイト内検索で目当てのページが出てこないときに使う。行はすべて各ページの題名・別名・ACL の名前から自動で作るので、ページや別名が増えると索引も増える。

## 引き方 {#how-to-read}

行は次の 2 つの形をとる。

- 矢印のない行（例：「[いもす法](../basics/imos.md)」）は、その語がページの題名そのものであることを表す。
- 「語 → ページ」の行は、語がそのページの別名であることを表す。「セグ木 → セグメント木」のような略称、「DSU → Union-Find」のような英語名、「lazy_segtree → 遅延セグメント木」のような ACL の名前がこの形になる。ACL の名前は、それを使うページのうち、その機能を中心に説明する 1 ページだけへつなぐ。

行き先はページの先頭で、節には分けていない。ページを開いたら、冒頭の要点と目次で目当ての節を探す。別名には「二分探索と DP → 答えで二分探索」のように、手法を組み合わせた語や問題の型の名前も入っている。語が別のページの題名に似て見えても、行き先は矢印の先で確かめる。

語は最初の字の種類で 3 つに分けて並べる。

- **かなで始まる語**は[五十音順](#kana)の節に、あ行からわ行までの見出しを分けて並べる。カタカナはひらがなと同じに扱い、長音「ー」は飛ばして読む（「セグメント木」は「せぐめんと木」として並ぶ）。濁音・半濁音で始まる語は、清音の語のすぐ後に来る（「が」で始まる語は「か」の語の後、「き」の語の前）。2 字目からも文字コードの順で比べるので、語の途中の漢字はどのかなよりも後に来る（「クエリ先読み」は「クエリを逆順に処理」の後）。
- **漢字・記号で始まる語**は、読みの順には並べられないので、五十音順の節の最後の[漢字・記号で始まる語](#terms-kanji)に、最初の字の文字コードの順で集めてある。「二分探索」や「遅延セグ木」はここにあり、な行・た行にはない。記号で始まる C++ の書き方やコンパイラのオプション（`#define int long long`・`-fsanitize=address` など）もこの見出しの先頭にある。`_GLIBCXX_DEBUG`・`__int128` のような `_` で始まる名前と、Σ・φ などのギリシャ文字で始まる語も同じ並びにある。この見出しの語は、ページの上の欄に語を入れて絞り込むのが速い。JS が動かない環境では欄が出ないので、ブラウザのページ内検索（パソコンでは Ctrl+F、スマートフォンではブラウザのメニューにある項目）で探す。
- **英字・数字で始まる語**は[英字の名前](#latin)の節に、大文字と小文字を区別せずに ABC 順で並べる。数字で始まる語（01-BFS・2-SAT など）は英字の語より前に来る。全角の英数字は半角と同じに扱う。

ページの上の欄は、語を含む行と、その行の見出しだけを残す。大文字と小文字・全角と半角・カタカナとひらがな・空白や「-」の有無の違いは問わないので、「だいくすとら」でも「union find」でも当たる。「セグ木」と「セグメント木」、「最大公約数」と「gcd」のような少数の言い換えは両方の語で探す。空白で区切った語は、すべてを含む行だけが残る。

目当ての語が見つからないときは、次の順に確かめる。

<!-- textlint-disable prh -->

- **表記の揺れ**：索引に載るのは題名と別名に書いた表記だけである。「ダイクストラのアルゴリズム」で見つからなければ「ダイクストラ」で始まる行を見るように、語の頭だけで探し直す。本文で使う書き方（正規形）と、よくある別の書き方の対応は[用語集の表記の正規形と別名の対応表](glossary.md#canonical-forms)にある。
- **手法の名前でない語**：[状態](glossary.md#state)・[単位元](glossary.md#identity-element)・[単調性](glossary.md#monotonicity)のように、くり返し出てくるがページを持たない語は索引に載らない。[用語集](glossary.md)の項を引く。
- **名前が分からない**：問題文の言い回しや立てた式の形からは[逆引き辞典（言い回しから）](reverse-index-signs.md)、$N$ の上限からは[逆引き辞典（制約・計算量から）](reverse-index-constraints.md)で引く。C++ の書き方やコンパイルエラーからは[C++ の逆引き](../cpp/cpp-reverse-index.md)、手法どうしの前提の関係からは[知識マップ](knowledge-map.md)で引く。

<!-- textlint-enable prh -->

サイト内検索はページの本文から索引を作り、語を短い断片に区切って照合する。そのため、ひらがなの専門語（いもす法など）や、「木」「法」のような短い断片に区切られる語は、その断片を含む別のページが上に出ることがある。また、別名にだけあって本文に出てこない語は、検索では見つからない。この索引は語の文字そのもので並べてあるので、検索の結果が怪しいときの確かめに使える。

## 複数のページに当たる語 {#shared-terms}

同じ語が 2 つ以上のページの題名か別名にあるとき、その語と行き先のページの組をここに並べる。別名はなるべくページどうしで重ならないように付けているので、組は少ない。組が載ったときは、行き先のページの冒頭の要点を見比べ、問題に合う方を開く。

表記が近くて取り違えやすい語も、ここに手で書き添える。

- **「クエリの平方分割」と「クエリ平方分割」**：前者は[平方分割](../ds/sqrt-decomposition.md#query-buckets)の節の方法で、更新と質問が混ざったクエリを $\sqrt{Q}$ 個ずつのかたまりに分け、かたまりの切れ目でデータ構造を作り直す。後者は [Mo's algorithm](../ds/mo-algorithm.md#what-it-does) の別名で、区間クエリを先に全部読み、答えやすい順に並べ替えて区間の両端を 1 つずつ動かす。クエリの間に更新が挟まるなら前者、更新がなく 1 要素の出入りで答えを直せるなら後者から読む。更新のある区間クエリを Mo で扱う変形は、後者のページの[時間付き Mo](../ds/mo-algorithm.md#variants)にある。
