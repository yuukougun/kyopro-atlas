出典と AI 利用の方針は、この教材を誰がどのように書いて確かめ、何を資料にし、資料をどう示しているかの説明である。参考にされた記事の著者や読者が問題に気づいたときの連絡先と、連絡を受けたときの対応も示す。読者が claude.ai に解説を頼むときの約束は、[claude.ai での解説の頼み方](how-to-use.md#claude)にある。

## AI で書いていることと確かめ方 {#ai-writing}

この教材の本文は、作者の指示のもとで AI（Anthropic の Claude）が書いている。制作には手元で動かす Claude Code を使い、ページを分けて執筆の担当を立て、並行して書かせた。図・コード片と、索引や一覧を作るサイトの仕組みも、同じように AI が作った。

作者は、教材の目的・読者・範囲と、次の制作の約束を決めた。

- 事実（問題番号・計算量・定理など）は、確かめてから書く。
- 他者の文章を転載せず、参考にした資料を出典として残す。
- AI の利用を断る指定のあるサイトを資料にしない。

<!-- 作者が確かめる：1・2 つ目の約束は要件定義（planning/requirements.md §8 の注意点）にある。3 つ目は、作者の決定として記録にあるのは AtCoder の noai の尊重（planning/decisions.md 2026-10-21）で、ほかのサイトへの広げ方は CLAUDE.md と調査の手引き §3 の 8 にある。3 つとも「作者が決めた」と書いてよいかを確かめる -->

ページの分け方・レベル・構成などの設計は、AI がまとめた案を作者が確かめてから進めた。

書いたページは、次の 3 段で確かめている。

1. **別の担当による検証**：書いた担当とは別の AI の担当が、事実・コード・図・分かりやすさの 4 つの観点で読み、指摘を直した。書いた担当には、自分のページを検証させない。
2. **機械の検査**：問題の番号・題名・difficulty を、AtCoder Problems の公開データから作った問題の台帳と照らす。コード片は完全なプログラムにして GCC 15.2 でコンパイル・実行し、期待どおりに動くかを確かめる。表記は textlint で検査する。これらの検査は、変更を push するたびに GitHub Actions でも動く。
3. **全体の検証**：全ページを書き終えた後（2026-10-22）、全体の検証を 2 巡行った。1 巡目は構成・ページどうしの関係・事実・図・共有のファイルの 5 つの観点で全ページの問題点を洗い出して直し、2 巡目は残った点を直した。どちらも直した結果を別の担当が検証し、全ページの段階を「検証済み」にした。

ページの段階は次の 4 つで、作者が目を通したページから順に「完成」にしていく。

- **準備中**：本文がまだなく、冒頭の要点だけがある。
- **本文あり・未検証**：AI の担当が書き、まだ検証していない。
- **検証済み**：別の AI の担当が検証し、指摘を直した。
- **完成**：作者が目を通し、よいと判断した。

2026-10-29 の時点で、このページのほかの 353 ページはすべて「検証済み」で、「完成」のページはまだない。いま読めるページは AI が書いて AI が検証したもので、作者がすべてを確かめたものではない。段階は、いまは「準備中」のときだけページの上に帯で出る（[ページの段階と「準備中」の帯](how-to-use.md#stub)）。

AI の書いた文章には、検証をすり抜けた誤りが残ることもある。誤りに気づいたら、[掲載内容についての連絡と対応](#contact)の方法で知らせてほしい。

## 他者の記事を転載しない {#no-copying}

この教材は、競技プログラミングの解説記事やライブラリの文書などを参考にして書いている。資料は内容を理解し、事実を確かめるために読む。文章・図・コードは写さずに、この教材の言葉と図で書き直している。

- **文章**：自分の言葉で書く。検証の担当は、参考にした資料と本文を並べて読み、文の並び・言い回し・例（数値や図の形）がそのままになっていないかを確かめる。
- **図**：この教材のために作った SVG の図・Mermaid の図・動く図（ステップ送りの図）だけを載せている。ほかのサイトの画像は載せていない。
- **コード**：本文のコード片は、この教材のために書いた完全なプログラムから取り込んだものである。
- **問題文**：AtCoder の問題文と入出力例は載せない。問題は、リンクと、問いだけを自分の言葉にした要約で示す（[問題の表示](how-to-use.md#problems)）。コード片を確かめる入力にも、問題の入出力例は使わない。

<!-- 作者が確かめる：「他者のコードを写さない」は、執筆の手引き（planning/style-guide.md）に明記がない。文章は §2.6・§11、例と図の形は planning/checklists/fact.md の F8 にある。上の「コード」の行を方針として書いてよいかを確かめる -->

規約やライセンスで使い方に条件のある資料は、条件に合わせて使い方を狭めた。

- **USACO Guide**：書面の許可のない使用・複製・再配布を規約で禁じているので、文章は使わず、ページの構成の参考にだけした。
- **cp-algorithms と OI Wiki**：ライセンスは、cp-algorithms が CC BY-SA 4.0、OI Wiki が CC BY-SA 4.0 と SATA である。文章と図は使わず、考え方や計算量を確かめる資料として読んだ。さらに学ぶための資料として挙げることもある。
- **問題文を載せている解説**：コンテストの記録や個人の解説のリポジトリのうち、問題文（英訳を含む）を引用して載せているものは、問題文の部分を読まず、解法の部分だけを参照した。

<!-- 作者が確かめる：USACO Guide の規約は、使用（used）も書面の許可なしには禁じている。構成の参考にしたこと（「この教材の使い方」の参考にも挙がっている）を、このまま書いてよいかを確かめる -->

リポジトリには、他者の作ったソフトウェアも同梱している。コード片が呼び出す AtCoder Library（ACL。CC0）と、サイトの表示に使う KaTeX・Cytoscape.js・cytoscape-dagre（どれも MIT ライセンス）で、それぞれのライセンスの文書も一緒に置いている。これらは教材の文章ではなく、道具として使っている。

## 参考にした資料の示し方 {#citations}

各ページの末尾には「参考」の節があり、そのページで参考にした資料を 1 行に 1 件ずつ並べている。1 行には、著者・題名・URL と、その資料のどこを参考にしたかを書く。

- 例題・練習問題の方針を確かめるために読んだ解説も、参考に入れる。
- ACL の使い方は、GitHub にある ACL の公式の文書（document_ja）を参考に挙げる。
- 発展の概要のページでは、さらに学ぶための資料を「学ぶための資料」の節にも並べる。
- 参考の節は、各分野のページのうち、用語集と用語の索引を除くすべてにある。トップページと、自動で作るページ（分野の入口・一覧・詳細索引）にはない。

問題（例題・練習・力試し）について、何を問い、どう解けるかは、解説で確かめた。使った解説の多くは、第三者の書いたものである。典型90問・鉄則本・アルゴリズムと数学・ACL Practice では、出題者が GitHub に公開している解説や解答例も使い、それだけで確かめた問題もある。確かめた解説の URL は、リポジトリの[問題の台帳](https://github.com/yuukougun/kyopro-atlas/blob/main/data/problems.yaml)に、問題ごとの記録として残している。裏付けの取れない問題は載せない。

<!-- 作者が確かめる：出題者の資料は、解説と解答例のほかに問題文も使っている。台帳では典型90問の 4 問（typical90_bc・bg・bk・bt）の evidence に出題者のリポジトリの問題文（problem/・problem-txt/）があり、参考でも docs/basics/complexity-estimation.md（055・072 の問題の画像で制約を確かめた）と docs/string/hash-safety.md（047 の「問題文も参照」）が挙げている。上の文と、「他者の記事を転載しない」の節の「問題文を載せている解説」の行に書き足すかを決める（手引き §15-6 の「問題文を読まない」に出題者のリポジトリが入るかと合わせて） -->

参考には、atcoder.jp と codeforces.com の URL を入れない。制作では、これらのページを AI で開かない約束にしている（例外とあわせて[AI の利用を断るサイトを資料にしない](#noai)で述べる）。atcoder.jp にある AtCoder の公式の解説も、資料にしていない。ただし、出題者が GitHub に公開している解説や解答例（上の問題集のもの）は資料にし、参考にも挙げている。典型90問では、この出題者の解説が公式の解説にあたる。問題の行のリンクは atcoder.jp の問題ページを指すが、これは読者が問題を開くためのものである。

## AI の利用を断るサイトを資料にしない {#noai}

Web のサイトには、AI による利用を断る指定を置いているものがある。この教材は、そうしたサイトを資料にしない。

資料にしたドメインは、次の 2 か所に noai・noimageai の指定がないことを確かめている。確かめるプログラムは、リポジトリの [tools/check_noai.py](https://github.com/yuukougun/kyopro-atlas/blob/main/tools/check_noai.py) である。

- ページの HTML にある robots の meta タグ（`<meta name="robots" content="noai">` の形。クローラの名前を指定したものも含む）
- HTTP の応答の X-Robots-Tag ヘッダー

新しいドメインは、資料として使う前に確かめる。利用規約などで AI の利用を断っていると分かったサイトも、資料にしない。はてなブログ・Scrapbox・note のように書き手ごとに設定や条件の違うサービスは、書き手・プロジェクト・記事ごとに確かめる。確かめたドメインは、確かめた日とともに[執筆の手引き](https://github.com/yuukougun/kyopro-atlas/blob/main/planning/style-guide.md)の付録 B に記録している。

<!-- 作者が確かめる：robots.txt での AI 向けのクローラ（GPTBot・ClaudeBot など）の拒否は、今の判定に入れていない（check_noai.py の robots オプションで表示するだけ）。「断る指定」に含めるかを決めて書く -->

AtCoder の問題ページと解説ページには noai と noimageai の指定があり、Codeforces のページにも同じ指定がある。制作の始め（2026-10-21）にこれらの指定を確かめてからは、atcoder.jp（サブドメインを含む）と codeforces.com のページを AI で開いていない。問題の題名と difficulty は AtCoder Problems の公開データで確かめ、問いと解き方は第三者や出題者が公開している解説や解答例で確かめた（[参考にした資料の示し方](#citations)）。

例外として、AtCoder のコンパイラとオプションの記述（[AtCoder と手元の C++ 環境の参考](../cpp/cpp-environment.md#references)）は、AtCoder の公式の言語の一覧によっている。この一覧は img.atcoder.jp にあり、制作の始めに noai の指定がないことを確かめて読んだ。

<!-- 作者が確かめる：記録（planning/decisions.md の 2026-10-21「質問の前に確認した事実」）では、決まりを作る前に、AI が AtCoder の問題・解説ページの meta、robots.txt と利用規約、言語の一覧（img.atcoder.jp）を確かめ、C++ の環境も同じ所に記録した。Codeforces の指定は、調査 00 が同じ日に https://codeforces.com/edu/courses を開いて確かめた。次の 2 つは記録にない。(1) decisions.md の GCC 版のオプションの一覧を、言語の一覧から読んだか（b5 で cpp-environment の担当が確かめられず、メインへの提案に回した点）。(2) AtCoder生成AI対策ルール（20261014 版）の中身をどこで読んだか（atcoder.jp で読んだのなら、上の例外に足す）。2 つを確かめ、例外の書き方を決める -->

読者が claude.ai に解説を頼むときも、Claude にこの 2 つのサイトを開かせない約束にしている（[claude.ai での解説の頼み方](how-to-use.md#claude)）。開催中のコンテストの問題に使わない約束は、[AtCoder生成AI対策ルールの版](how-to-use.md#ai-rule-version)にある。

## 掲載内容についての連絡と対応 {#contact}

掲載内容に問題があれば、GitHub の [kyopro-atlas の Issue](https://github.com/yuukougun/kyopro-atlas/issues) で知らせてほしい。たとえば次のような場合である。

- 自分の記事の文章・図・コードが、この教材に写されている、または近すぎると感じたとき
- 参考の行の著者・題名・URL が違うとき、または自分の記事を参考に挙げないでほしいとき
- AI の利用を断っているサイトが資料になっているとき
- 事実の誤り（計算量・定理・問題の内容など）や、分かりにくいところに気づいたとき

知らせるときは、ページの URL（節が分かれば節の名前も）と、何が問題か、どうしてほしいかを書いてほしい。参考にされた記事の著者であれば、その記事の URL も添えてほしい。Issue を立てるには、GitHub のアカウントが要る。

<!-- 作者が確かめる：GitHub のアカウントがない人や、公開の Issue に書きにくい連絡（権利についての申し出など）の受け口を用意するか。用意するならここに書く（#10 の「報告の受け口」と案内をそろえる） -->

連絡を受けたら、次のように対応する。

1. 内容を確かめ、Issue に返事を書く。
2. 文章・図・コードが資料に近すぎると確かめたら、その箇所を書き直すか削除する。
3. AI の利用を断るサイトだと分かったら、そのサイトを資料から外し、そのサイトを参考にした箇所を、ほかの資料で確かめ直して書き直す。
4. 参考の行の誤りは直す。参考に挙げないでほしいという申し出には、その資料に基づく記述をほかの資料で書き直してから、参考の行を外す。
5. 事実の誤りは、ほかの直しと同じく、別の担当の検証を経て直す。

直した内容はリポジトリの commit の履歴に残り、誰でも見られる。
