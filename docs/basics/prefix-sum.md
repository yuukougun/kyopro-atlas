!!! abstract "要点"
    - **何ができるか**：$S_0 = 0$、$S_{i+1} = S_i + a_i$ と前計算すると、区間 $[l, r)$ の和が $S_r - S_l$ で $O(1)$ で求まる。引き算できない演算（gcd・max）は、左からの累積と右からの累積を組み合わせて「1 つ除いた値」を作る。
    - **いつ使うか**：
        - 区間の和を何度も聞かれる。
        - 1 つだけ除いた（変えた）ときの値を、すべての位置について求める。
        - 円環上の区間の和を扱う。
        - $Q \le 2 \times 10^5$ 個の区間和のクエリがあり、値の更新がない。
    - **計算量**：前計算 $O(N)$、区間の和の取得 $O(1)$。左右からの累積も前計算 $O(N)$ で、1 つ除いた値は演算 1 回で求まる。
    - **前提**：なし

累積和は、列の先頭から順に足した値を前計算しておき、区間の和を 2 つの値の引き算で答える方法である。$Q$ 個の区間の和を毎回足し直すと $O(NQ)$ かかるが、累積和なら前計算 $O(N)$ と 1 回 $O(1)$ の合計 $O(N + Q)$ で済む。考え方は和に限らず、XOR・gcd・max など、前から順に積み上げられる演算に広がる。

## 半開区間と、先頭に 0 を置く約束 {#half-open}

累積和の添字は、$S_k$ を「先頭 $k$ 個の和」と決めると迷わない。実装では列を 0-indexed で $a_0, \dots, a_{N-1}$ と持ち、次のように定める。

$$
S_0 = 0, \qquad S_{k+1} = S_k + a_k \qquad (0 \le k < N)
$$

$S$ は長さ $N + 1$ の配列になる。$S_k$ は「境界 $k$ より左にある要素の和」と読める。境界 $k$ は $a_{k-1}$ と $a_k$ の間の切れ目で、境界 0 は列の左端、境界 $N$ は右端である。

![上は a = (3, 1, 4, 1, 5, 2) の棒グラフで、a[2]・a[3]・a[4] の 3 本を網掛けにしている。下は境界 0〜6 での S の値 0・3・4・8・9・14・16 の折れ線で、S[5] − S[2] = 14 − 4 = 10 が網掛けの和に等しい](../img/prefix-sum/half-open.svg)

区間は[半開区間](../guide/glossary.md#half-open-interval) $[l, r)$（$a_l$ から $a_{r-1}$ まで）で表す。境界 $r$ より左の和から境界 $l$ より左の和を引けば、境界 $l$ と $r$ の間だけが残る。

$$
a_l + a_{l+1} + \dots + a_{r-1} = S_r - S_l
$$

図の例では $[2, 5)$ の和は $4 + 1 + 5 = 10$ で、$S_5 - S_2 = 14 - 4 = 10$ と一致する。半開区間と $S_0 = 0$ を組み合わせると、次の 2 つが場合分けなしで成り立つ。

- **先頭からの区間**：$l = 0$ でも $S_r - S_0 = S_r$ となり、$S_{-1}$ のような範囲外を読まない
- **空区間**：$l = r$ なら $S_r - S_l = 0$ で、空の和として正しい

問題文が 1-indexed の閉区間 $[L, R]$ で与えるときは、$l = L - 1$、$r = R$ に直す。1-indexed のまま書くなら答えは $S_R - S_{L-1}$ で、同じ式である。

累積和の応用は、「区間の量を、両端の境界での値の差に直す」という見方にまとまる。たとえば「区間に含まれる条件を満たす要素の個数」なら、条件を満たす位置を 1、それ以外を 0 にした列の累積和を取ればよい。数える対象が 2 文字にまたがる（"AC" の出現など）ときは、どの位置に 1 を置くかを先に決める（[例題](#abc122_c)）。

??? question "確認問題：閉区間のまま書くと"

    ??? success "答え"
        $l = 0$ のとき $S'_{-1}$ を読むことになり、場合分けが要る（C++ の `vector` なら範囲外の読み出しで未定義動作になる）。$S_0 = 0$ を置く半開区間の定義なら、この場合も $S_r - S_0$ で済む。

## 左右からの累積（1 つ除いた gcd・max） {#left-right}

累積和で区間の和が引き算で求まるのは、足し算に逆の操作（引き算）があるからである。gcd・max・min には逆の操作がない。$\gcd(a_0, \dots, a_{r-1})$ と $\gcd(a_0, \dots, a_{l-1})$ が分かっても、$[l, r)$ の gcd は求まらない。

それでも「1 つだけ除いた値」なら求まる。$a_i$ を除いた残りは、左の $[0, i)$ と右の $[i + 1, N)$ の 2 つの区間に分かれる。どちらも端を含む区間なので、左から積み上げた値と右から積み上げた値で表せる。

$$
\mathrm{pre}_i = \gcd(a_0, \dots, a_{i-1}), \qquad \mathrm{suf}_i = \gcd(a_i, \dots, a_{N-1})
$$

とすると、$a_i$ を除いた gcd は $\gcd(\mathrm{pre}_i, \mathrm{suf}_{i+1})$ である。空の範囲には演算の[単位元](../guide/glossary.md#identity-element)を置く。gcd なら $\gcd(0, x) = x$ なので 0、max なら $-\infty$（すべて 0 以上なら 0）、和なら 0 である。こうしておけば $i = 0$ と $i = N - 1$ も場合分けが要らない。

前計算は左右それぞれ $O(N)$ 回の gcd で、各 $i$ の値は gcd 1 回で求まる（gcd 1 回は値の上限を $V$ として $O(\log V)$）。素朴に「$a_i$ を除いて全体を計算し直す」と $O(N^2)$ 回の演算になる。

この形が使える合図は、「1 つを除く」「1 つを好きな値に変える」「ある位置で列を左右に分ける」である。

- **1 つを好きな値に変える**：gcd を最大にしたいなら、変える値は残りの gcd にするのがよい。だから「1 つ除いた gcd」の最大を求めればよい
- **位置で左右に分ける**：位置 $i$ を境に、左側では条件 A を、右側では条件 B を数える問題では、左からの累積と右からの累積を別々に持つ。和なら 1 本の累積和からも求まるが、2 本にすると式の向きを取り違えにくい
- **左右で別の量を最小にする**：左側の区間の最小と右側の区間の最小を組み合わせるなら、累積 min を左右から作る

??? question "確認問題：1 つ除いた最大値"
    $N$ 個の値について、各 $i$ で「$a_i$ を除いた残りの最大値」を求めたい。累積和のように「全体の最大から $a_i$ を引く」ことはできない。なぜか。また、左右からの累積を使わずに済ませる方法はあるか。

    ??? success "答え"
        max には逆の操作がないので、全体の最大から $a_i$ の分だけを取り除けない。たとえば $(5, 5)$ と $(5, 3)$ はどちらも全体の最大が 5 で、5 を除いた残りの最大は 5 と 3 で違う。全体の最大だけでは区別できない。左右からの累積の代わりに、最大と 2 番目の最大（同じ値が 2 つあれば両方）を覚えておく方法もある。$a_i$ が最大の要素そのものなら 2 番目を、そうでなければ最大を答えればよい。gcd にはこの方法が使えないので、左右からの累積の方が広く使える。

## 円環は 2 周分に伸ばす {#circular}

円環に並んだ $N$ 個の値で、位置 $i$ から時計回りに $k$ 個（$1 \le k \le N$）の和を求めたいとする。$i + k > N$ だと区間が末尾から先頭へ回り込み、1 本の累積和では引き算 1 回で書けない。

列を 2 周分に伸ばすと、回り込む区間も普通の区間になる。$b_j = a_{j \bmod N}$（$0 \le j < 2N$）として $b$ の累積和 $T$（長さ $2N + 1$）を作れば、位置 $i$（$0 \le i < N$）から $k$ 個の和は $T_{i+k} - T_i$ である。$i + k \le 2N - 1$ なので、範囲外は読まない。

伸ばさずに書くこともできる。回り込む場合（$i + k > N$）は、末尾までの $[i, N)$ と先頭からの $[0, i + k - N)$ の 2 つに分けて $(S_N - S_i) + S_{i+k-N}$ とすればよい。ただし、2 周分に伸ばすと次の節の二分探索・尺取りがそのまま使える。回り込みの場合分けを書き間違えることもないので、伸ばす方が安全である。

円環を「切れ目」で考える問題も、この形に直せる。円形のケーキを切れ目で分けて、連続するピースの和をちょうど全体の $1/10$ にできるか判定する型がその例である。全体の和が 10 で割り切れなければ不可能である。割り切れるなら、伸ばした累積和の上で、各始点 $i$ について $T_j = T_i + (\text{全体の和}) / 10$ となる $j$ を二分探索すればよい。

## 累積和の上で二分探索・尺取り {#with-binary-search}

すべての $a_i$ が 0 以上なら、累積和 $S$ は単調に増える（減らない）。この単調性を使うと、「和が $K$ 以上になる最短の区間」「和が $K$ 以下になる最長の区間」のような、区間の端を探す問題を速く解ける。

**二分探索**：左端 $l$ を決めると、$S_r - S_l \ge K$ を満たす最小の $r$ は、$S_r \ge S_l + K$ を満たす最小の $r$ である。$S$ は単調なので、[二分探索](../basics/binary-search.md)（`lower_bound`）で $O(\log N)$ で見つかる。

```text
for l in 0 .. N-1:
    r = lower_bound(S, S[l] + K)   # S[r] >= S[l] + K となる最小の r
    if r <= N: 区間 [l, r) の長さ r - l を答えの候補にする
```

**尺取り**：$l$ を 1 つ右へ動かすと $S_l$ は減らないので、条件を満たす最小の $r$ も左へは戻らない。だから $r$ を前回の位置から右へ進めるだけでよく、全体で $O(N)$ になる（[尺取り法](../basics/two-pointers.md)）。

2 つの列から先頭の何個かずつを選ぶ問題も同じ形である。一方から先頭 $i$ 個を選ぶと決めると、もう一方から選べる個数の最大は、累積和の上の二分探索で求まる。$i$ を増やすともう一方の最大は減るだけなので、尺取りでもよい（[練習](#practice)の ABC172 C）。

負の値があると $S$ は単調でなくなり、二分探索も尺取りも正しくない。「和がちょうど $K$ の区間の個数」のような等式の条件なら、$S_r - S_l = K$ となる $l$ の個数を連想配列で数える（[累積和と連想配列で区間を数える](../basics/prefix-sum-counting.md)）。

??? question "確認問題：負の値があると"
    $a = (3, -3, 1)$、$K = 3$ で、$l = 0$ から始まり和が $K$ 以上になる最短の区間を、`lower_bound` で $S_r \ge S_0 + K = 3$ となる最小の $r$ として探した。何が起きるか。

    ??? success "答え"
        $S = (0, 3, 0, 1)$ で単調でない。`lower_bound` は中央の $S_2 = 0 < 3$ を見て、$r \le 2$ をまとめて捨てる。続けて $S_3 = 1 < 3$ も不可なので「見つからない」と返す。実際には $r = 1$（区間 $[0, 1)$ の和 3）が条件を満たす。`lower_bound` はソートされた列を前提にするので、負の値があるときは単調性に頼らず、区間の数え方を変える。

## 落とし穴 {#pitfalls}

累積和のバグの多くは、型のあふれと添字の 1 つのずれである。

**累積和は int に収まらない**。$N = 2 \times 10^5$ 個の $10^9$ 以下の値を足すと、最大 $2 \times 10^{14}$ になる。`int`（約 $2.1 \times 10^9$ まで）ではあふれるので、`vector<long long>` で持つ。入力の $a_i$ が `int` で収まっても、$S$ は `long long` にする（[整数のオーバーフロー](../cpp/cpp-integer-overflow.md)）。

**`accumulate` の初期値の型**。`accumulate(a.begin(), a.end(), 0)` は初期値 `0` の型（`int`）で足し続けるので、要素が `long long` でもあふれる。初期値は `0LL` と書く。

**`partial_sum` は $S_0$ を作らない**。`partial_sum` や `inclusive_scan` の結果は先頭 1 個からの和で始まり、先頭に 0 を置かないので、そのまま $S$ として使うと添字が 1 つずれる。長さ $N + 1$ の `s` に `s[0] = 0` を置き、`partial_sum(a.begin(), a.end(), s.begin() + 1)` と書けば $S$ になる。

**長さ $N + 1$ を忘れる**。$S$ は $S_0$ から $S_N$ までの $N + 1$ 個である。`vector<long long> s(n)` と書くと $S_N$ を範囲外に書き込む。

**閉区間の変換**。問題文の $[L, R]$（1-indexed）は、0-indexed の半開区間では $[L - 1, R)$ である。答えは $S_R - S_{L-1}$ で、「$S_R - S_L$」や「$S_{R+1} - S_L$」と書く誤りが多い。変換は入力を読んだ直後の 1 か所にまとめ、以降は半開区間だけで考える。

**余りの累積和の引き算**。和を $m$ で割った余りで累積したとき、$S_r - S_l$ は負になりうる。C++ の `%` は負の数に負の余りを返すので、`((s[r] - s[l]) % m + m) % m` で 0 以上に直す。

**2 本の累積和の向き**。左右からの累積で $\mathrm{pre}_i$ を「$i$ を含まない」、$\mathrm{suf}_i$ を「$i$ を含む」と決めたら、除くときは $\mathrm{pre}_i$ と $\mathrm{suf}_{i+1}$ を組み合わせる。定義をコメントで書いておかないと、$\mathrm{suf}_i$ と取り違えて $a_i$ を除けなくなる。

## 値が更新されるなら BIT、静的な区間 min なら Sparse Table {#next-tools}

累積和は、列が途中で変わらず、引き算できる演算に使う道具である。前提が崩れたときに使う手法と、累積和の考え方が広がる先をまとめる。

| 状況 | 使う手法 | 計算量 |
| --- | --- | --- |
| 値の更新と区間の和が交互に来る | [BIT](../ds/fenwick-tree.md) | 更新・取得 $O(\log N)$ |
| 更新がなく、任意の区間の min・max | [Sparse Table](../ds/sparse-table.md) | 前計算 $O(N \log N)$、取得 $O(1)$ |
| 更新があり、演算が min・gcd など | [セグメント木](../ds/segment-tree.md) | 更新・取得 $O(\log N)$ |
| 区間に一律に足し、最後に全体を読む | [いもす法](../basics/imos.md) | $O(N + Q)$ |

累積和は、1 点の更新があると更新した位置より後ろの $S$ をすべて直すことになり、1 回 $O(N)$ かかる。更新と区間の和が混ざるなら BIT を使う。min・max は 1 つ除くだけなら左右からの累積で足りるが、任意の区間 $[l, r)$ を聞かれるなら Sparse Table を使う。min・max は同じ要素を 2 回数えても結果が変わらないので、重なる 2 つの区間を合わせて $O(1)$ で答えられる。

演算によっては累積和と同じ引き算が使える。XOR は $x \oplus x = 0$ なので、自分自身が逆の操作になる。$P$ を累積 XOR とすると、$[l, r)$ の XOR は $P_r \oplus P_l$ で求まる。積は逆元があれば割り算で戻せる。ただし 0 を含むと割れない。mod の積は、1 つ除いた積なら左右からの累積で求め、任意の区間の積ならセグメント木を使う。

累積和の考え方は、次のページで広がる。

- **区間の個数を数える**：「区間の和が $K$」「$M$ の倍数」を $S_r$ と $S_l$ の関係に直して数える（[累積和と連想配列で区間を数える](../basics/prefix-sum-counting.md)）
- **差分との往復**：いもす法は、差分の列を作ってから累積和で元に戻す。累積和と差分は互いに逆の操作である（[いもす法](../basics/imos.md)）
- **2 次元**：長方形の和は 4 つの累積和の足し引きで求まる（[2 次元累積和](../basics/prefix-sum-2d.md)）
- **DP の遷移**：$\mathrm{dp}[i]$ が直前の区間の $\mathrm{dp}$ の和で決まるとき、$\mathrm{dp}$ の累積和で遷移を $O(1)$ にする（[累積和・いもす法による DP の高速化](../dp/dp-prefix-sum.md)）

## 上位の手法へのつながり {#next-steps}

このページの累積和は、次の手法の部品になる。

- **区間の和の条件で数える**：和がちょうど $K$ の区間や、和が $M$ の倍数の区間の個数を、$S_r$ と $S_l$ の関係に言い換えて連想配列で数える（[累積和と連想配列で区間を数える](../basics/prefix-sum-counting.md#equal-k)）
- **2 次元の累積和**：長方形の和を 4 項の足し引きで $O(1)$ にする（[2 次元累積和](../basics/prefix-sum-2d.md#formula)）
- **区間に加算する**：累積和の逆の操作として、区間への加算を両端の印に直して最後に累積する（[いもす法](../basics/imos.md#imos-1d)）
- **DP を速くする**：遷移元が連続した範囲の和になる DP を、前の段の累積和で 1 回 $O(1)$ にする（[累積和・いもす法による DP の高速化](../dp/dp-prefix-sum.md#pull-and-push)）
- **更新のある列・引き算できない演算**：値が更新されるなら [BIT](../ds/fenwick-tree.md#what-it-does)、静的な区間の min なら [Sparse Table](../ds/sparse-table.md#what-it-does) に進む（[値が更新されるなら BIT](#next-tools)）

## 例題 {#examples}

### ABC122 C. GeT AC {#abc122_c}

<div class="kp-problems" data-role="example" markdown>

- [ABC122 C. GeT AC](https://atcoder.jp/contests/abc122/tasks/abc122_c)（diff 700）：文字列の区間ごとに、部分文字列 AC が何回現れるかを答えるクエリに答える。

</div>

クエリごとに区間を調べ直すと $O(NQ)$ で間に合わないので、累積和で 1 回 $O(1)$ にする。要点は、2 文字にまたがる "AC" を 1 つの位置に割り当てることである。"AC" を A の位置で数えると決める。区間に収まる "AC" は、A が区間の中にあり、しかも区間の最後の文字ではないものである。

??? note "解法の詳細"
    - 0-indexed で、文字列を $s$ として、$t_i = 1$（$s_i = \text{A}$ かつ $s_{i+1} = \text{C}$ のとき）、それ以外は $t_i = 0$ とする（$0 \le i < N - 1$）。$t$ の累積和を $T$ とする（$T_0 = 0$）。
    - 1-indexed の閉区間 $[L, R]$ に収まる "AC" は、A の位置（0-indexed）$j$ が $L - 1 \le j$ かつ $j + 1 \le R - 1$ を満たすもの、すなわち半開区間 $[L - 1, R - 1)$ に $j$ があるものである。
    - 答えは $T_{R-1} - T_{L-1}$。A が区間の左の外にある "AC" は $j = L - 2$ で引かれ、C が区間の右の外にある "AC" は $j = R - 1$ で含まれない。$L = R$ なら 0 になる。
    - 前計算 $O(N)$、クエリ 1 回 $O(1)$。

## 練習問題 {#practice}

<div class="kp-problems" data-role="practice" markdown>

- [ARC098 C. Attention](https://atcoder.jp/contests/arc098/tasks/arc098_a)（diff 635）：一列に並んだ人のうち 1 人をリーダーに選ぶとき、向きを変える人数の最小値を求める。
- [ABC172 C. Tsundoku](https://atcoder.jp/contests/abc172/tasks/abc172_c)（diff 930）：2 つの机に積まれた本を上から読むとき、K 分以内に読める最大の冊数を求める。
- [ABC125 C. GCD on Blackboard](https://atcoder.jp/contests/abc125/tasks/abc125_c)（diff 1197）：1 つだけ好きな値に書き換えたときの、全体の最大公約数の最大値を求める。
- [典型90 076. Cake Cut（★3）](https://atcoder.jp/contests/typical90/tasks/typical90_bx)（diff —）：円環に並んだケーキのピースから連続する部分を取り、和をちょうど全体の 1/10 にできるかを判定する。

</div>

??? note "練習の方針"
    - **ARC098 C**：リーダーを $i$ に決めると、向きを変えるのは左側で西を向いている人と、右側で東を向いている人である。左からの W の個数と右からの E の個数を前計算し、各 $i$ を $O(1)$ で調べる
    - **ABC172 C**：机 A から読む冊数 $i$ を全探索し、残り時間で机 B から読める最大の冊数を、B の累積和の上の二分探索で求める。$i$ を増やすと B の冊数は減るだけなので尺取りでもよい。累積和は最大 $2 \times 10^{14}$ 程度になるので `long long` にする
    - **ABC125 C**：書き換える値は残りの gcd にするのが最もよいので、「1 つ除いた gcd」の最大が答えである。左右からの累積 gcd で各 $i$ を gcd 1 回で求める
    - **典型90 076**：[円環は 2 周分に伸ばす](#circular)の型そのものである。全体の和が 10 で割り切れなければ不可能。割り切れるなら、2 周分に伸ばした列の累積和の上で、各始点から和が全体の $1/10$ になる終点を二分探索で探す
