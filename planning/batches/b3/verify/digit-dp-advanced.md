## 指摘

1. **直すべき**｜F2 定理・性質の主張｜#challenge の「力試しの方針」ABC138 F｜「$y \bmod x = y - x$ になるのは $y < 2x$ のときで、これは $x$ と $y$ の最上位 bit が同じことと同値である」は誤り。最上位 bit が同じなら $y < 2x$ だが、逆は成り立たない。反例：$x = 3$（11）・$y = 5$（101）は $5 < 6$ だが最上位 bit が違う（このとき $y \bmod x = 2$、$y \oplus x = 6$）。正しくは「最上位 bit が違えば $y \oplus x \ge 2^{\text{msb}(y)} > x > y \bmod x$ なので条件を満たさない。同じなら $x \le y < 2x$ で $y \bmod x = y - x$」の 2 段である｜Python で 1 ≤ x ≤ y < 64 を調べ、(y < 2x) と (最上位 bit が同じ) が食い違う組 (3,4)・(3,5)・(5,8)… を確認。条件全体「y mod x = y xor x ⇔ 最上位 bit が同じ かつ x ⊆ y」は 1 ≤ x ≤ y < 200 で成り立つことを確認。kmjp の記事も「最上位 bit が同じ → y < 2x」の向きだけを述べる｜該当の 2 文を「最上位 bit が違うと、$y \oplus x$ は $y$ の最上位 bit を持つので $x$ より大きく、$x$ 未満の $y \bmod x$ と等しくなれない。最上位 bit が同じなら $y < 2x$ なので $y \bmod x = y - x$ である。」のように、必要の向きと十分の向きを分けて書く

2. **直すべき**｜G5 静的な図の内容・F3｜multiple-numbers.svg（#multiple-numbers）｜節は $x \text{ AND } y = 0$ の組を数える DP だが、図の組 $x = 1010$・$y = 1001$ は bit 3 で両方が 1 で、$x \text{ AND } y = 1000 \ne 0$。本文の遷移では bit 3 の時点で捨てられる組であり、読者が「この DP で数える組」の例として読むと遷移の説明と矛盾する｜SVG のソースと 720px の PNG で x・y の bit を確かめた｜条件を満たす組に替える。例：$A = 1101$、$B = 0111$、$x = 1010$（bit 2 で未満）、$y = 0101$（bit 3・2 は一致、bit 1 で未満）。フラグの切り替わる位置は本文 53 行の「x は bit 2、y は bit 1」のままで、$x \text{ AND } y = 0$ になる。図の題も「x ≤ A、y ≤ B、x AND y = 0 を…」とするとよい。代替テキストはそのままでよい

3. **直すとよい**｜U3 飛躍・F7 記法｜#multiple-numbers の遷移の行（60 行）｜「$t_x' = (t_x \land b_x = A \text{ の bit})$」は演算の結び付きが読めず、$(t_x \land b_x) = \dots$ とも読める。「A の bit」に記号もない｜コード片では `ntx = (tx && bx == la)`｜「上の bit から $k$ 番目の $A$ の bit を $a_k$ として、$t_x' = t_x \land (b_x = a_k)$」のように記号を置き、かっこで結び付きを明示する。落とし穴の `ntx = tx && bx == la` とも対応が付く
