## 指摘

1. **直すべき**｜F1 計算量｜要点の「計算量」（49 行）と front matter の `complexity`｜「位数と原始根は、φ(m) の素因数分解に O(√m)、その後の累乗に O(log² m)」とあるが、原始根は候補 g = 2, 3, … を順に試すので、累乗の手間は「候補 1 個あたり O(ω(φ(m)) log m)」×「試す候補の数」である。試す候補の数は O(1) とは言えない（実際の素数では小さいが、最小の原始根の上界は多項式の対数では示されていない）。位数だけなら O(log² m) で正しい｜order.cpp の primitive_root の二重ループ。本文の primitive-root の節も「実際の素数では小さい g ですぐ見つかる」と書いており、要点だけが条件なしの O(log² m) になっている｜要点と complexity を「位数は φ(m) の素因数分解に O(√m)、その後 O(log² m)。原始根は候補 1 個の判定が O(log² m) で、実際には小さい候補で見つかる」のように直す

2. **直すとよい**｜U4・F2｜bsgs の節の「応用の型」（173 行）｜表を a^j の側に作り giant step で b·a^{−in} を引く形では x = in + j になり、最小の解には**小さい j を残す**（上書きしない）必要がある。ページは本節と落とし穴で「大きい j を残す」を強調しているので、ARC042 D の練習の方針（「表を使い回す形にする」）に従って実装した読者が逆の規則を当てはめやすい。また i は 0 から始める（x = j の解を拾う）点も書かれていない｜x = in + j の形から、同じ i では j が小さいほど x が小さい｜「この形では x = in + j なので、表には小さい j を残し、i = 0 から引く」と 1 文足す

3. **直すとよい**｜U3｜count-by-order の節の「届くかどうかは位数の割り切りで決まる」（119 行）｜「x の累乗はどれも y^d ≡ 1 を満たし」と、判定したい y を方程式の未知数の名前にも使っていて、読者は「どの y の話か」で止まる。また最後の「解の全体が x の累乗にちょうど一致する」から「y が累乗で書ける ⇔ y^d ≡ 1 ⇔ ord(y) | d」への最後の一歩が書かれていない｜本文の文と、Python で確かめた主張（向きは正しい）｜「z^d ≡ 1 を満たす z の全体が x の累乗に一致する。よって y が x の累乗で書けることは y^d ≡ 1、すなわち ord(y) | d と同じである」のように、未知数を z に変え、結論の 1 文を足す
