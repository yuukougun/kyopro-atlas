## 指摘

1. **直すべき**｜F2 主張の誤り｜#pitfalls「行けない組に二項係数を使う」の 1 文目「$\binom{dr + dc}{dr}$ をそのまま計算すると、$dc < 0$ でも $dr + dc \ge 0$ なら 0 でない値になる」｜$dc < 0$ なら $dr > dr + dc$ なので、$k > n$ で 0 を返す普通の二項係数の関数なら正しく 0 になる（drken の記事の COM も `if (n < k) return 0`）。$dr < 0$ でも $k < 0$ で 0 になる。実際に起きる誤りは、階乗の式 `fact[dr + dc] * ifact[dr] * ifact[dc]` を範囲の確かめなしに使い、負の添字で表の外を読むこと（未定義動作）である｜$\binom{n}{k}$ で $n = dr + dc$、$k = dr$ とおくと、$dc < 0 \Leftrightarrow k > n$、$dr < 0 \Leftrightarrow k < 0$。コード片の paths も dr・dc の符号を先に確かめている｜「$j$ から $i$ へ列が戻る組で、階乗の式 $\mathrm{fact}[dr + dc] \cdot \mathrm{ifact}[dr] \cdot \mathrm{ifact}[dc]$ をそのまま使うと、負の添字で表の外を読む。差のどちらかが負なら 0 を返す関数にしておく（$k < 0$ か $k > n$ で 0 を返す二項係数の関数でもよい）」のように直す

2. **直すべき**｜F2・F7 用語の誤り｜#count-violations の最後の応用の型「$r_k (N - k)!$（少なくとも $k$ 個）の表から二項係数で戻せる」｜$r_k (N - k)!$ は「$k$ 個の位置の組を指定して数えた数の和」で、ちょうど $t$ 個破る順列を $\binom{t}{k}$ 回数える。「少なくとも $k$ 個の位置で破る順列の数」ではない。読者がこれを「少なくとも」の数と思うと、差を取って「ちょうど」を出す誤った戻し方をする｜N = 6・X = 2 で全探索：$r_k (N-k)!$ = 720, 1920, 2208, 1404, 526, 114, 13、少なくとも k 個破る順列の数 = 720, 691, 587, 380, 200, 49, 13（k = 1 で 1920 は全体の 720 を超える）。$e_t = \sum_k (-1)^{k-t} \binom{k}{t} r_k (N-k)!$ で「ちょうど」に戻ることは確かめた｜「（少なくとも $k$ 個）」を「（$k$ 個の位置を指定して数えた数の和。ちょうど $t$ 個破るものを $\binom{t}{k}$ 回数える）」に替え、戻す式 $e_t = \sum_{k \ge t} (-1)^{k - t} \binom{k}{t} r_k (N - k)!$ を添える。本文 121 行の「$N(S)$ は『少なくとも $S$ を破る』数」は集合 $S$ についての言い方なので正しく、そのままでよい

3. **直すとよい**｜U4 実装の粒度｜#equal-blocks の単調スタックの段落と #tree の DP｜(a) スタックの段落は「$A_{i-1}$ 以上の組を取り出してまとめ直す」とあるが、新しく加わる $j = i - 1$（$\min = A_{i-1}$、重み $h[i-1]$）をまとめた組に足すことと、全体の $\sum$ の更新の順（取り出した組の値 × 和を引き、まとめた組の $A_{i-1}$ × 和を足す）が書かれておらず、擬似コードを書くと迷う。(b) #tree で $\mathrm{dp}[v]$ の初期値（子をまとめる前は $\mathrm{dp}[v][1] = 1$）が書かれていない｜本文だけで擬似コードを書いて確かめた（初期値は自分の Python の木 DP で `{1: 1}` が要った）｜(a)「$i$ を進めるたびに、$A_{i-1}$ 以上の組を取り出し、それらの $h$ の和に $h[i-1]$ を足して $(A_{i-1}, \text{和})$ の組を 1 つ積む。$\sum$（値 × 和）は、取り出した分を引き、積んだ分を足して保つ」と 1〜2 文足す。(b)「子をまとめる前は $v$ だけの成分なので $\mathrm{dp}[v][1] = 1$ から始める」と足す
