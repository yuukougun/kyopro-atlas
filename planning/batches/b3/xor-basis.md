| 語 | anchor | 定義 |

| 独立（XOR の） | linear-independence | 整数の集合で、空でないどの組を選んで XOR しても 0 にならないこと。最上位 bit が互いに違う整数の集合は独立である |
| ランク | rank | 整数の集合（または行列の行）から作れる値の全体を表すのに要る、独立な要素の個数。XOR なら作れる値は 2^ランク 種類ある |
| マトロイド | matroid | 「独立な集合」の族で、独立な集合の部分集合も独立、大きさの違う 2 つの独立な集合があれば小さい方に大きい方から 1 つ足して独立にできる、を満たすもの。重みの小さい順に独立を保つものだけ取る貪欲が最適になる |

## 検証の指摘への対応（2026-10-22）

指摘 1〜7 をすべて直した。採らなかったものはない。

1. #min-cost の冒頭を「各整数に $0$ 以上のコストがあり」とし、負のコストは先に全部選んでから残りに貪欲をかける、と 1 段落足した。証明の冒頭に「$O$ が $g_1, \dots, g_r$ をすべて含むなら、ほかの要素のコストは 0 以上なので貪欲も最適」を足した
2. #xor-walk の箇条書きに句点を足した
3. xor-walk.cpp の注釈を「スタックで訪ねてできる全域木（木の形は問わない）」に、yaml の注釈を「コードが作る木は図と違うが、答えは同じ」にした。本文のコードの後に、コードの木は図と違ってよい（図のグラフでは 1–3 が木の辺になる）こと、確認問題へのリンクを足した。「DFS と挿入」は「探索と挿入」にした
4. insert.svg は「できた基底」の段を外し（本文 76 行に基底と $2^3$ 種類を足した）、文字を 19〜22px に上げた（幅 634）。xor-walk.svg は右の式の欄を外してグラフだけにし（幅 480、文字 18〜20px）、閉路の値 $0 \oplus 6 \oplus 4 = 2$ は本文に移した。代替テキストも図に合わせた。360px と 720px の PNG で確かめた
5. 導入を「個数と最大値を $O(B)$ で、K 番目を前計算 $O(B^2)$ の後に 1 回 $O(B)$ で」にした
6. ラムダ `min_walk` をやめ、`xb.reduce(d[u] ^ d[v])` を直接書いた
7. 「頂点の組を数えるときの性質」を主張・理由・Binary Trie への帰着の 3 段落に分け、理由では条件を「基底の最上位 bit の位置がすべて 0」と言い直した。長い文も 2 つに分けた
