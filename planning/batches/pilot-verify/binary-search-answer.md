## 指摘

### 1. 直すべき｜事実・分かりやすさ｜#monotonicity 第 4 段落（67 行）

- **問題**：「ちょうど K 回切って、すべて x 以上」は x を小さくすると「ちょうど」を守れなくなる心配があり、単調か分かりにくい、と書いているが誤り。x で通る K か所の切り方はそのまま x' < x でも通るので、この判定は最初から単調である。「K 以上に緩める」理由は単調性ではなく、判定を貪欲で作ると「作れるピースの最大数」が出るので、「ちょうど K + 1 個」より「K + 1 個以上」の方が判定しやすい（多い分はくっつけて減らせる）ことにある。本当に単調でないのは、確認問題のような「（x で決まる量）がちょうど K」の形の条件で、本文はこの 2 つを混ぜている。節の題名の主題なので、読者に誤った理由を教えることになる
- **根拠**：同じ切り方が小さい x でも条件を満たす（本文 65 行の論法そのもの）。総当たりでも「ちょうど K か所」の可否は全件で x について単調だった
- **直し方**：段落を 2 つに分ける。(a) 「x 以上の要素がちょうど K 個」「和がちょうど S」のように、x で決まる量が K に等しいかを問う判定は両側で不可になり単調でない。「K 個以上」に直す（確認問題へつなぐ）。(b) 「ちょうど K か所切る」のように選び方の個数が決まっている場合は、判定自体は単調だが、貪欲で数えやすいように「K + 1 個以上作れるか」に緩め、余分をくっつけても条件が壊れないことで同値を示す。例題の方針（182 行）の書き方は (b) と合っているので、そのままでよい

### 3. 直すとよい｜事実｜#next-steps「平均・比・中央値」（164 行）

- **問題**：「中央値 ≥ x」⇔「x 以上を +1、未満を −1 にした和が正」は、要素数が奇数か、偶数で下側の中央値（N/2 番目）と定めたときだけ成り立つ。上側の中央値（N/2 + 1 番目）なら「和が 0 以上」になる。「常に」と読める
- **根拠**：N = 4 で並べた b1 ≤ … ≤ b4 とし、x 以上の個数を c とすると和は 2c − 4。b2 ≥ x ⇔ c ≥ 3 ⇔ 和 > 0、b3 ≥ x ⇔ c ≥ 2 ⇔ 和 ≥ 0
- **直し方**：「（中央値の定め方で、正か 0 以上かが変わる）」と一言添え、詳細は fractional-binary-search に任せる

### 4. 直すとよい｜事実・分かりやすさ｜#pitfalls 第 1 段落（127 行）

- **問題**：最大値の最小化の ng を「0 や −1」とするが、答えが 0 になりうる問題では 0 は ng に置けない。直後の「答えになりうる値を ng に置くと漏れる」と食い違う。また「迷ったら制約から分かる最大値より 1 大きい値を使う」は、ng が上側にあるとき（最小値の最大化・最大の N を求める）にだけ当てはまり、この段落が例にしている最大値の最小化（ng は下側）とは向きが逆
- **直し方**：「ng は答えの取りうる範囲の 1 つ外側（下側なら最小値 − 1、上側なら最大値 + 1）」と向きを区別して書く

### 5. 直すとよい｜分かりやすさ｜#pitfalls「答えが存在しない場合を忘れる」（129 行）
