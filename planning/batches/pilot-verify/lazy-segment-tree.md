## 指摘

1. **直すべき｜事実｜#acl-conventions 170 行・#boundaries 179 行「INF への加算」・#invariants 348 行**
   - 問題：「ACL は余りの葉にも push で `mapping` を施すので、`mapping(f, e())` が答えを壊さないよう作る」「`e()` を `LLONG_MAX` にすると、push で余りの葉へ加算が届いた瞬間にオーバーフローする」は誤り。余りの葉に届くのは `id()` だけである
   - 根拠：ACL の `apply(l, r, f)` が `all_apply` するのは $[l, r) \subseteq [0, N)$ にすっぽり入るノードだけで、保留が id 以外になるのはそういうノードだけ。push はその子（やはり $[0, N)$ の中）へ降ろすだけなので、余りの葉を含むノードの保留はずっと `id()` のままである。`mapping(id(), e()) = e()` は条件 1 から出るので、追加の要件はない。pad.cpp で id 以外が届く回数 0・UB の報告なしを確かめた。本当に `e()` に加算が届くのは、`seg(n)` で作って実の要素がすべて `e()` のとき（または初期値に INF を入れたとき）である
   - 直し方：170 行の段落は削るか、「余りの葉には id しか届かないので気にしなくてよい」に替える。179 行は理由を「`seg(n)` で作ると実の要素も `e()`（INF）なので、そこへ区間加算が届くと `LLONG_MAX` ではあふれる。初期値に INF を入れる問題も同じ」に直す（`1LL << 60` を勧めるのはそのままでよい）。348 行も同じく直す。170 行の「区間和の $(0,0)$ が $(0,0)$ のまま」の例は、`seg(n)` の話として 176 行の「葉の長さは 1」に寄せる

2. **直すべき｜事実｜#dual-segment-tree 193 行**
   - 問題：「区間作用の前に、区間の両端へ向かう経路の保留を上から push しておけば、上ほど古い作用という順序が保たれる」は向きが逆。保たれるのは「上ほど新しい（下ほど古い）」である
   - 根拠：新しい作用を置くノードの祖先は直前の push で保留が空になっているので、新しい作用より上に古い作用は残らない。一方、そのノードの子孫（両端の経路から外れた部分）には古い保留が残る。dual.py で、「上ほど新しい」として葉から根へ順に施すと誤り 0、逆にすると誤りが出ることを確かめた
   - 直し方：「…上ほど新しい作用という順序が保たれる。一点の値は、初期値に葉に近い保留から順に（根の保留を最後に）施して求める」とする。185 行の「経路の保留を合成して初期値に施せば求まる」にも、可換でないときは施す順が要ることを添えると、節だけ読んでも通じる
