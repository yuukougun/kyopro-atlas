## 確かめたこと

### G1 状態の列の正しさ

- `node --test tests/viz/euler-tour.test.mjs`：7 件すべて通る。試験は各状態の性質（入る順が行きがけ順、in が 0, 1, 2, … と振られる、exit で out = timer、stack が根から cur までの道、subtree の members が区間 [in, out) の頂点かつ子孫の集合）と、最後の値を素朴な再帰 DFS と比べている。状態の数だけを見る試験ではない
- 自分で別の実装を書いて突き合わせた（scratchpad の `et/check.cjs`。リポジトリには置いていない）。再帰の DFS で「start → 入る・出る 2n 個 → built → select ごとの subtree」の事象の列を作り、各状態の phase・cur・stack・tin・tout・ord・timer・range・members を比べた。入力は (a) n ≤ 6 のすべての親配列のうち木になるもの（番号の順でない親を含む）で select に全頂点、(b) n ≤ 10・葉 6 個以下のランダムな木 5000 個（select はランダムな長さ 0〜10、重複あり）。計 6425 本の木で食い違い 0
- caption の数字も同じスクリプトで照らした：enter の「頂点 p の子 v」「in[v] = t」「timer は t+1」、exit の「次の番号 out[v]」と葉のときだけ「子がない」、subtree の「（部分木の頂点を列の順に）」と「= 長さ は部分木の頂点数」、built の列。食い違い 0
- 本文の例を手で追った：入る順 0, 2, 3, 6, 1, 5, 4、in = [0, 4, 1, 2, 6, 5, 3]、out = [7, 5, 5, 3, 7, 7, 5]、部分木 2 → [1, 5)、5 → [5, 7)、6 → [3, 5)、0 → [0, 7)。本文 82・88 行目と一致する。1 ステップに 2 つの変化が混ざる状態はない（入る・出るを 1 事象ずつ）
- 境界：n = 1（start・enter・exit・built・subtree の 5 状態、[0, 1)）、パス状 n = 10、星、select の省略・空・null（省略と同じ扱い）・重複を試した
