# 動く図 lca（深さをそろえてから同時に跳ぶ）

## 作ったもの

- `overrides/assets/js/viz/lca.js`：ダブリングで LCA を求める動く図。見本（binary-search・lazy-segment-tree）と同じ形で、`states(config)` は DOM を使わない純粋な関数、`render(svg, state, config, h)` が描く。`viewBox` は木の最大の深さと表の段数 L で決まり、ステップによらない（幅は 380 以上）
- `tests/viz/lca.test.mjs`：試験 8 件
- `docs/tree/lca.md`：div（config は執筆者のまま）の後の案内の段落を直した。元の文「左に木、右に up[k][u] と up[k][v] の表を並べ」は、幅 360 で読めるよう木を上・表を下に積んだ図と食い違うので、「上に木、下に表を置く。① では深さの差の 2 進数の桁ごとに u を上げ、② では k を大きいほうから 1 段ずつ試して up[k][u] と up[k][v] を表に書く。比べている 2 頂点は破線の輪で示す。跳ぶのは 2 つの値が違う段だけであることを確かめてほしい。」にした。div の前の段落はそのまま

## config

`{"n": 12, "parents": [-1, 0, 0, 1, 1, 2, 3, 4, 6, 7, 5, 8], "query": [11, 9]}`（執筆者の仮のものから変えていない）

- `n`：1〜16 の整数。頂点は 0-indexed で根は 0
- `parents`：長さ n。`parents[0] = −1`、ほかは 0 以上 n 未満の整数で、親をたどると根に着く（自己ループ・閉路は誤り）。番号の順に並んでいなくてよい
- `query`：0 以上 n 未満の 2 頂点 `[u, v]`
- 表の段数 L は本文のコード（`snippets/lca/lca.cpp:build`）と同じく「2^L ≥ n の最小、ただし 1 以上」。根の親は根自身
- 誤りは見本と同じく Error を投げ、viz.js が「図を表示できなかった：…」と出す（data-config がない・n の範囲・parents の長さと値・根・自己ループ・閉路・query）

## 描き方とステップ（本文の例で 9 状態）

- 上から、見出し（「lca(11, 9)：① 深さをそろえる」「② 同時に跳ぶ」「答え 1」）、木（左に「深さ d」の目盛り。深さごとに段をそろえ、葉を番号の順に左から並べる）、表の見出し、表
- 表：① の間は「k・2^k・d の桁・up[k][u]・結果（上げる／そのまま）」、② の間は「k・2^k・up[k][u]・up[k][v]・結果（跳ぶ／跳ばない）」。行は k = L−1 から 0 の順で、いま試している段は太枠と太字
- 状態：初め（入れ替えがあれば書く）→ ① の 1 の桁ごとに「u を 2^k 個上げる」（本文のコードと同じく k の小さいほうから）→「深さがそろった」→ ② の k ごとに「比べる」（違えば続けて「跳んだ」）→ 答え。① で u = v になったら ② をせずに答え
- 本文の例：11 → 8（k = 0）、k = 3・2 はどちらも 0 で跳ばない（k = 3 は「根より上は根 0 で止まる」と書く）、k = 1 は 3 と 4 で違うので跳んで u = 3・v = 4、k = 0 はどちらも 1 で跳ばない、答えは up[0][3] = 1。前後の文章と静的な図 jump.svg と同じ
- caption の例：「② k = 2：u = 8 の 4 個上と v = 9 の 4 個上はどちらも 0。同じなので跳ばない（跳ぶと LCA を通り過ぎるかもしれない）。」「すべての k を試した。u = 3、v = 4 は LCA のすぐ下の子にいるので、答えは up[0][3] = 1 である。」
- 色だけに頼らない：u・v は名札の文字（u は左、v は右）と太枠、比べる 2 頂点は破線の輪、跳んだ動きは矢印、答えは塗り＋外側の輪＋「LCA」の文字、表の結果は文字で書く

## 未解決の点

- 執筆者の仕様の追加の候補（u が v の祖先になる例 `query: [8, 3]`）は、図は対応して試験もしたが、本文に 2 つ目の div は足していない。本文の ① の文（「上げた結果が v と一致したら … v が答え」）を図でも見せたいなら、同じ木で `[8, 3]` の div（4 状態）を足すことを提案する
- ① は本文のコードと同じく k の小さいほうから上げる。② は大きいほうから。表の行はどちらも k = L−1 が上なので、① では注目の行が下から上へ動く
- 線の色は dp-tree-table・union-find と同じく、kp.css に線用の class がないので `style` に Material の CSS 変数を直接書いた
- caption の長さが状態ごとに違うので、幅 360 では操作のボタンの位置が 1 行分上下する（ほかの図と同じ）

## 検証の指摘への対応（verify-lca.md）

直すべきは 0 件。直すとよい 3 件はすべて直した。

- 指摘 1（葉の多い木で幅 360 では読めない）：validate で葉（子のない頂点）が 7 個以上なら「葉（子のない頂点）が … 個ある。幅 360 で読めるよう 6 個までにする」と Error にした（MAX_LEAVES = 6。葉 6 個で viewBox の幅 472、幅 360 で約 0.7 倍）。冒頭の注釈にも書いた。試験：16 頂点の星と葉 7 個の木で Error、葉 6 個は通る、葉 6 個の幅が 480 以下。ランダムな木の試験は、葉 6 個以下の木だけを使う（親を直前の数個から選んで深い木も作る）
- 指摘 2（同じ頂点どうしの caption）：q0 = q1 のときは「u = v = 5 で同じ頂点なので、答えは 5 である。」、祖先のときは「u = v = 3 になった。v = 3 は u = 8 の祖先だったので、答えは 3 である。」と書き分けた。試験を足した
- 指摘 3 (a)（「LCA」の文字が親への辺に重なる）：親への辺と反対の側の斜め上に置く（親が右なら左上、親が左・真上・根なら右上）。試験：頂点の真上（同じ x）に置かない
- 指摘 3 (b)（同じ頂点を比べると破線の輪が 1 つに見える）：2 つ目の輪が 1 つ目と同じ頂点なら半径を R + 11 にして二重の破線にした。試験：本文の 4 番目の状態（k = 3、どちらも 0）で輪が 2 つ、中心が同じで半径が違う

採らなかったもの：なし。未解決の点の `[8, 3]` の 2 つ目の div は、検証の意見どおり必須でないので足していない（メインの判断に任せる）。
