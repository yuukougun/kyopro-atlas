## 指摘

### 1. 直すべき｜例 2（#negative-edges）の 4 番目の caption｜G1・C3

- **場所**：`overrides/assets/js/viz/dijkstra.js` 224〜229 行（`bad.forEach` の caption）。表示は「(3, b) を取り出す。b を確定する。b → a で 3 − 2 = 1 < 2 となり、確定済みの a の距離が 2 から 1 に縮む。入れ直す書き方なので (1, a) を入れて a は 1 に直るが、**done[v] で捨てる書き方なら 2 のまま誤る**。」。本文 136 行の「確定済みの印 `done[v]` で 2 回目以降を捨てる書き方なら、$a$ は 2 のまま誤る」も同じ主張である
- **問題**：本文 104 行が説明する `done[v]` の書き方は「取り出したときに確定済みなら捨てる」で、緩和（`d + w < dist[to]` なら更新）は行き先が確定済みでも止めない。この書き方では b を処理したときに dist[a] は 1 に更新され、(1, a) を取り出して捨てるだけなので、**この例の答えは 0、1、3 で合う**。誤るのは「a から出る辺が見直されない」ことで、a から先に辺があるときだけである。「2 のまま誤る」は、緩和でも `!done[to]` を見て確定済みへの更新を止める別の書き方でしか起きない
- **根拠**：作業用の場所に C++ で 2 通りを書いて（g++-15）この 3 頂点の例を動かした。取り出し側だけ `if (done[v]) continue;` → `0 1 3`（正しい）。緩和にも `!done[to]` を足す → `0 2 3`（誤り）
- **直し方**：どちらか。
    - (a) 例に a から出る辺を 1 本足す（例：頂点 c を足し a → c に重み 1。入れ直す書き方は c = 2、`done[v]` で捨てる書き方は (1, a) を捨てるので c = 3 のまま誤る）。図の caption は「done[v] で捨てる書き方なら (1, a) を取り出しても読み飛ばすので、a から出る辺が見直されず、c は 3 のまま誤る」のように、誤るのが a の先であることを言う。本文 136 行と静的な図 negative.svg、試験の PAGE2 も合わせて直す
    - (b) 例は変えず、caption を「done[v] で捨てる書き方では (1, a) を取り出しても読み飛ばすので、a から出る辺は見直されない（a から先に辺があれば、その先の距離が誤る）」にし、本文 136 行も同じ趣旨に直す
  - 本文 136 行はメインの判断（図の担当の範囲の外）。caption の文は `wasDone` の更新すべてに出るので、(a)(b) どちらでも一般の config で正しい言い方にする

### 2. 直すとよい｜横に置いた暫定距離が取り出しの輪に接する｜G3

- **場所**：`dijkstra.js` 409 行 `var off = dir[1] !== 0 ? R + 14 : R + 8;`
- **問題**：距離を左右に置くとき、文字の端は中心から R + 8 = 25 で、取り出しの輪（半径 R + 5 = 22 に線の太さ）とほぼ接する。例 1 の最後のステップ（(7, 4) を取り出す）で、頂点 4 の右の「7」が輪に触れて見える（幅 800 のスクリーンショット）。頂点 0 の左の「0」も 2 番目のステップで同じ形になる
- **根拠**：幅 800・ライトの例 1 の 8/8 の画像で目視
- **直し方**：左右のときの間隔を R + 12 程度に広げる（輪がある頂点だけ広げてもよい）

### 3. 直すとよい｜すぐ上の静的な図と「太い実線」の意味が違う｜G5・G7

- **場所**：`docs/graph/dijkstra.md` 66 行（graph.svg の説明「太い実線は…最短路の木」）と 82 行（動く図の前置き）、`dijkstra.js` 凡例
- **問題**：直前の静的な図では太い実線が最短路の木だが、動く図では太い実線が「今回更新」で、最短路の木は細い実線（凡例「距離を与えた辺」）である。凡例はあるが、同じグラフを続けて見せるので読み違えやすい。最後の caption も最短路の木に触れない
- **直し方**：最後の状態の caption に「細い実線の辺が最短路の木（0-2-1-3-4）である」の 1 文を足す（`prev` から作れる）か、82 行の前置きに「動く図では、太い実線がそのステップで更新に使った辺である」と書く
