## 指摘

### 1. 直すとよい：許された config の範囲で、箱の中の分数が箱からはみ出して重なる

- **場所**：`expected-value-dp.js` の `shortText`（箱に書く文字列）と、`validate` の範囲（`MAX_HP = 7`・`MAX_DEN = 100`）
- **問題**：config の説明では n ≤ 7・分母 ≤ 100 を正しい入力としているが、その範囲で箱（幅 54）に入らない分数ができ、隣の箱の文字と重なって読めない。本文の config では起きない
- **根拠**：ブラウザで `{"hp":{"n":7,"p":"1/100"}}` の最後のステップを開くと、`6940496029801/1000000000000`（幅 235）などが箱の外へはみ出し、左端は viewBox の外（x = −77）に出た。`{"hp":{"n":7,"p":"1/3"}}` でも `3964/729`・`1139/243`（幅約 66 > 54）がはみ出す。すべての HP の config（b ≤ 100）で箱の文字列は最長 27 文字。すごろくの最長は `1197/256` などの 8 文字で、こちらも 54 にぎりぎり
- **直し方**：箱に入らない長さ（たとえば 6 文字を超える）なら、箱には小数の近似（`≈5.44` か `5.438`）を書き、分数は caption だけにする。あわせて、範囲を狭める（分母 ≤ 12 など）か、config の説明に「箱に入る値になる p を使う」と書く。試験に「`eShort` の長さが上限以下」を足すとよい

### 2. 直すとよい：すごろくの凡例「上の矢印」が、隣のマスへの直線の矢印に合わない

- **場所**：`render` の凡例（`"上の矢印：1〜A_i の目で進む"`）
- **問題**：隣のマスへ進む矢印（1 の目）は箱の横の直線で描かれ、上の弧ではない。凡例の言葉だけを読むと、横の直線が何の矢印か分からない。本文の config でも、マス 0→1・1→2・2→3 の矢印は直線である
- **根拠**：360px・800px のスクリーンショット（ステップ 10・15・16）。`edge` は span 1 の実線を直線で描く
- **直し方**：凡例を「右向きの矢印（横と上）：1〜A_i の目で進む」などにする

### 3. 直すとよい：p = 0 か p = 1 のとき、描かれない矢印を凡例と caption が述べる

- **場所**：`render` の HP の凡例、`states` の fill の caption（`where`）
- **問題**：p = 0 では破線を描かないが、凡例に「破線：2 減る（確率 p = 0）」が残る。fill の caption も「矢印の先の HP t2 と HP t1 の値はもう決まっている（確率の和 0 + 1 = 1）」と、描かれていない側の矢印の先を挙げる（p = 1 では実線について同じ）。値は正しい（E[h] = h、⌈h/2⌉）
- **根拠**：`{"hp":{"n":3,"p":0}}` の最後のステップのスクリーンショット。式の部分は `isZero` で項を省いているが、`where` と凡例は省いていない
- **直し方**：p = 0 なら凡例の破線の行と caption の HP t2 を省き、p = 1 なら実線の側を省く。本文の config（p = 1/2）には関わらないので、急がない

### 4. 直すとよい：終状態の近くで矢じりと弧が重なる

- **場所**：`render` の `edge`（弧の端を `5 * span` だけずらす処理）
- **問題**：HP の部では HP 1 → HP 0 と HP 2 → HP 0 の破線の矢じりが HP 0 の上で重なる。すごろくの部ではマス 0 → 2 と 0 → 3 の弧が出だしでほぼ重なり、マス 3（ゴール）の上で 0 → 3 と 1 → 3 の矢じりが重なる。本文の config では読めるが、矢印の本数を数えにくい。A = 6, 5, 4, 3, 2, 1 のような config では、ゴールの上に矢じりが 6 つ重なって数えられない
- **根拠**：800px・360px のスクリーンショット（ステップ 3・7・10・15・16 と、上の config の最後のステップ）。執筆者の報告の「未解決の点」にも挙がっている
- **直し方**：弧の終点を、入ってくる矢印の数に応じて箱の上辺に沿って均等にずらす（終点ごとに何本目かを数えて x をずらす）。始点も同じようにずらすと、出だしの重なりも減る
