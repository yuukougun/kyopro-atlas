# 動く図 imos の検証

対象：`overrides/assets/js/viz/imos.js`・`tests/viz/imos.test.mjs`・`docs/basics/imos.md`（#imos-1d に足した 1 段落と div）。報告 `planning/batches/viz/imos.md`。観点は `planning/checklists/figure.md`（G1〜G7）と `code.md`（JS に当てはまる範囲）。

## 結論

直すべき指摘は 0 件、直すとよい指摘は 5 件。状態の列は手法として正しく、本文の例の値（D = [0, +1, 0, +2, 0, −1, 0, −2, 0]、A = 0, 1, 1, 3, 3, 2, 2, 0）・静的な図 imos-1d.svg・コード片 imos-1d.cpp の変数（`d`・`cur`・`a`）と食い違わない。ブラウザで図が描かれ、ステップ送りで進むことを目で確かめた。

## 確かめたこと

- `node --test tests/viz/imos.test.mjs`：6 件すべて通る
- 別に書いた突き合わせ（作業用の場所の `vimos/` と `v/chk.cjs`。リポジトリには置いていない）：試験とは別の乱数（Park–Miller）で、`n` 1〜12、操作 1〜4 個、`l`・`r` は 0〜n から 2 つ選んで並べ替え（`r = N` や `l = 0` を多く含む）、`x` は −99〜99 の 18765 通り。自分で作った状態の列（D を 1 か所ずつ書き換えた列、素朴に塗った A を 1 マスずつ見せる列）と、全ステップの `d`・`a`・`focusD`・`cur` が一致した。最後の D が A の隣接差（`D[i] = A[i] − A[i−1]`、`D[N] = −A[N−1]`）になることも確かめた。全ステップで `render` を偽の `h` で呼び、座標に NaN・Infinity が出ないこと、累積の caption の値が `cur` と一致することも確かめた
- caption：本文の例の 14 状態と、`{n: 3, ops: [[0,3) に −5, [0,3) に +5]}`（番兵への書き込み・印の打ち消しで 0）を全部読んだ。1 ステップに変化は 1 つずつで、caption と描かれた値がそろう
- 誤った config：試験の 16 通りに加え、`n: "8"`・`ops: {}`・`x` なし・`l: "0"`・`x: −100`・配列の要素が配列・`n: Infinity`・`x: 1e300` がすべて Error になる（余分なキーは無視する。見本と同じ扱い）
- `python3 tools/check_pages.py`：エラー 0・警告 0
- `npx textlint docs/basics/imos.md`：エラー 0・警告 43。行 65〜69 で出るのは 66 行目（前からある図の代替テキスト）だけで、足した 68 行目には出ない
- ブラウザ：`uv run mkdocs build -d <scratchpad>/site-imos`（警告は Material の告知だけ）を `python3 -m http.server` で配り、`~/.cache/puppeteer` の chrome-headless-shell 146（日本語は font_env と同じ fontconfig で `/mnt/c/Windows/Fonts` を足す）を CDP で動かした。幅 900（ライト）・360（ライト・ダーク `slate`）で、「最初へ」の後に「次へ」を 0・2・4・5・9・13 回押して撮った。カウンタ 1/14〜14/14、caption、D の印・帯・cur の三角が進み、最後で「次へ」「最後へ」が無効になる。JS の例外・console.error は 0。幅 360 で `document.documentElement.scrollWidth` は 360（はみ出しなし）、SVG は 306.8px（viewBox 366×190、約 0.84 倍）、ボタンは 44×44
- 色だけに頼らないか：注目は太い枠（3.5）、番兵は点線、未計算は「?」、累積の位置は三角と「cur = …」、いまの操作の帯は太さと文字色で、ほかの操作の帯は細い灰色。累積に入れ終えた D の薄い塗りは色だけだが、三角の位置と埋まった A でも分かるので問題にしない
- 本文との一致：足した段落（「同じ例で D に印を 1 か所ずつ書き込み … cur はカーソルまでの D の和」）は図の動きと合う。帯のラベル「[1, 5) に +1」は本文の半開区間の書き方と同じ。番兵の説明（D[N] は累積に使わない）は本文の箇条書きと同じ

## 気づいたこと（指摘にしない）

- `n = 12` では viewBox の幅が 518 になり、幅 360 の画面で約 0.59 倍（枠の数字は約 9.5px、添字は約 7px）。読めることを撮って確かめた（`vimos/shots2/t-slate-12.png`）。見本の two-pointers も `MAX_N = 12` なので同じ程度とみなした。試験の「幅 ≤ 440」は本文の config だけを見ている
- 余分なキー（`{"l":0,"r":1,"x":1,"extra":1}`）は黙って無視する。binary-search などと同じ扱いなので問題にしない
- 作業用の場所 `scratchpad/v/` はほかの検証役と共有されていて、途中で `shot.mjs` が上書きされた。この検証の撮影は `scratchpad/vimos/` の自前の道具で撮り直している
