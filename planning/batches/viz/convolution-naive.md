### 図の形

- 段は上から：いまの段階の 1 行、a の段（添字 i をマスの上に）、反転した b の段（添字 j をマスの下に）、積の段、和の式の行、c の段（添字 k をマスの下に）。左の列に行の名前（i・a・b と「反転」・j・積・c・k）
- 列：反転した b は a の左右に最大 M − 1 マスはみ出すので、列 −(M − 1)〜N + M − 2 の N + 2M − 2 列にする。ずらし幅 k では b_0 を列 k に置き、b_j は列 k − j（a_{k−j} の真下）に来る。c_k のマスも列 k に置くので、c_k はいつもそのずらし幅の b_0 の真下にある
- 重なった列：a と b のマスを塗り（`is-yes`）、上下の間に「×」、添字 i・j を色付きの太字にし、真下の積の段にその積を出す。重ならないマス（a の外にはみ出した b、b と重ならない a）は薄い細枠と薄い字。和の式の行に「c₂ = 6 + 10 + 12 = 28」（添字は tspan を dy で下げる。baseline-shift は使わない）。いまの c_k は濃い塗り（`is-answer`）、求めた c は普通のマス、まだのものは点線の空のマス
- 色だけに頼らない：重なりは「×」・積のマス・添字の太字でも分かり、重ならないマスは細い薄い枠、まだの c は点線で区別する。色は kp.css の `.kp-v-*` の class と、z-algorithm と同じく Material の CSS 変数を使う inline の style だけで付けた（色の直書きは 0 件）。CSS・viz.js は変えていない

### ステップ（本文の例で 7 状態。一般に N + M + 1）

1. start：a を上の段に、b を反転して 6, 5, 4 の順に b_0 が a_0 の真下に来るように置く。c の段は空。和の式の行に定義「c_k = Σ a_i b_j（i + j = k）」、b_0 の右に「右へずらす →」（ずらすとき・入る幅があるときだけ）
2. step（ずらし幅 k = 0〜N + M − 2 に 1 状態ずつ）：caption は次の形

    > ずらし幅 k = 1。下の段を右へ 1 つずらし、b_0 が a_1 の真下に来た。重なるのは a_0 と b_1、a_1 と b_0 の 2 組で、どれも i + j = 1 である。c_1 = 1 × 5 + 2 × 4 = 5 + 8 = 13 である。

    k = 0 では「b_0 は a_0 の真下にあり、b_1 と b_2 は a の左にはみ出している」、k ≥ N では「b_0 は a の右端より右に出た」、最後のずらし幅では「これより右へずらすと重なる組がなくなるので、ずらし幅はここまでである」を添える
3. done：c がそろう（全部を `is-yes`）。積の段に「掛け算は全部で N × M = 9 回」、和の式の行に「c = (4, 13, 28, 27, 18)」、b の段は最後の位置に薄く残す。caption は「ずらし幅 0〜4 の N + M − 1 = 5 通りを終え、c = (4, 13, 28, 27, 18) が求まった。どの組 (i, j) も、ずらし幅 i + j のときにちょうど 1 回だけ重なるので、掛け算は全部で N × M = 9 回である。素朴な方法が O(NM) かかるのはこのためである。」

caption の添字は fenwick-tree と同じく `a_0` の形で書いた（caption は textContent なので下付きにできない）。図の中は下付きの tspan。

## 未解決の点・提案

- 値は 0〜9 の整数に限った。負の値（abc196_f の ±1 の置き換えなど）や 2 桁の値を見せたくなったら、マスの幅と caption の括弧（「1 × (−1)」）を足す必要がある。いまの置き場では要らない
- start と k = 0 の状態は b の位置が同じ（start は置き方の説明だけで、k = 0 で重なりと積が出る）。done では b の段を最後の位置に薄く残した。消す案もあるが、ものが急に消えると見えるのでやめた。どちらが読みやすいかは検証で判断してほしい
- 静的な図 anti-diagonal.svg（積の表を斜めに足す）とは見せ方が違い、補い合う：表は「i + j が同じマスをまとめる」、動く図は「反転してずらすと i + j = k の組がちょうど重なる」。重複ではない
- メインへ：Issue #51 の検査（data-viz の名前に対応する JS があるか）を足す担当がいれば、convolution-naive.js はこれでそろう。gen_site.py の作り直しが要る（上の --check の 3 ファイル）

## 検証の指摘への対応（verify-convolution-naive.md）

直すべき指摘は 0 件で、直すとよい指摘 2 件をどちらも直した。直したのは JS と試験だけで、本文は変えていない。作者の「未解決の点」への判断（start と k = 0 で b の位置が同じ、done で b を薄く残す、値は 0〜9）はそのとおりにし、変えていない。

1. **k ≥ N + 1 の caption**（`convolution-naive.js` の states の where）：k = N は前のまま「b_0 は a の右端より右に出た。」とした。k > N では、右に出ている b_j（列 k − j ≥ N、つまり j = 0〜k − N）を言う。2 個なら「b_0 と b_1 は a の右端より右に出ている。」、3 個以上は「b_0〜b_{k−N} は a の右端より右に出ている。」になる。本文の例の 6/7（k = 4）は「下の段を右へ 1 つずらし、b_0 と b_1 は a の右端より右に出ている。」になる
    - 試験：`checkStates` で、許すすべての大きさ・ずらし幅についてこの言い方を確かめる（k < N では「右端より右」を言わない）。本文の例の k = 4 と、a が 1 個・b が 5 個のときの k = 2〜4（b_0 と b_1、b_0〜b_2、b_0〜b_3）の assert も足した
2. **render の試験で b の反転を確かめる**：描いた図を位置だけで読み直す試験「render を位置で読み直す」を足した（`readBack`。states の pairs・c は使わない）
    - 読み方：マスの段（a・b・積・c）を y で決め、列の番号を c の段のマスの x で決める。マスの中の文字と、b のマスの下の添字は位置で引く
    - config は 8 つ：本文の例、1 個どうし、列の数が上限の 3 つ、値が同じ並び、b の値がすべて違う 2 つ（[5, 9, 2, 6]・[1, 8, 2]。足した）。その全状態で次を確かめる
    - a：列 0〜N − 1 に a_i がある
    - b：左から添字 M − 1, …, 0 の順に並ぶ（反転）。値 b_j のマスは列 shift − j にある（start なら列 −j）
    - c の段：k までは定義どおりの値（定義の畳み込みと比べる）で、残りは空。濃い塗りはいまの c_k だけ
    - step：a と b の両方がある列は、ちょうど 0 ≤ i < N かつ 0 ≤ k − i < M の i である。a_i の真下の b のマスは b_{k−i}、その下の添字は k − i で、どちらも塗られている。重ならないマスは塗らない
    - 積の段：重なる列の真下にだけ a_i × b_{k−i} があり、その和が c_k になる
    - 試験で穴がふさがったか：作業用の写しで、検証の写しと同じく render の b の列を `s.shift - (M - 1) + j`（反転しない）に変えた。足した試験だけが、最初の状態で「b が反転して並ばない」（左からの添字が 0, 1, 2）と落ちる。caption を前の言い方に戻した写しでは、caption の試験 3 件が落ちる。写しは消した
- 確かめたこと：`node --check`、`node --test tests/viz/convolution-naive.test.mjs` は 9 件、`node --test "tests/viz/*.test.mjs"` は 215 件ですべて通る（ほかの担当の試験を含む）
