# 動く図 segment-tree（非再帰の prod が両端から拾うノードと、set が作り直す経路）

## 作ったもの

- `overrides/assets/js/viz/segment-tree.js`：セグメント木の動く図。見本（binary-search・lazy-segment-tree・fenwick-tree）と同じ形で、`states(config)` は DOM を使わない純粋な関数、`render(svg, state, config, h)` が描く。`viewBox` は葉の数だけで決まり、ステップによらない（8 葉で 416 × 388）
- `tests/viz/segment-tree.test.mjs`：試験 9 件
- `docs/ds/segment-tree.md`：div の config は執筆者の案のまま。後ろの段落に、図の読み方（縦の棒が l・r、積んだノードに「sL へ」「sR へ」、作り直したノードは点線の枠）を 2 文足した（検証の後、点線と太枠の使い分けを書いた 3 文に直した）

## config

`{"array": [5, 3, 7, 2, 6, 4, 8, 1], "op": "min", "ops": [{"type": "prod", "l": 1, "r": 7}, {"type": "set", "p": 5, "x": 0}, {"type": "prod", "l": 1, "r": 7}]}`（執筆者の案から変えていない）

仕様（添字は 0-indexed、区間は半開区間）：

- `array`：1〜8 個の整数（絶対値 99 以下）。長さが 2 の冪でなければ余りの葉を単位元で埋める
- `op`：`"min"`（単位元 ∞）・`"max"`（−∞）・`"sum"`（0）。省略すると min
- `ops`：1〜6 個。`{"type": "prod", "l", "r"}`（0 ≤ l ≤ r ≤ N。l = r の空区間も可）か `{"type": "set", "p", "x"}`（0 ≤ p < N、x は絶対値 99 以下）
- 誤りは見本と同じく Error を投げ、viz.js が「図を表示できなかった：…」と出す

## 描き方とステップ（本文の例で 13 状態）

- 本文の擬似コード（ACL と同じ配置。根 1、子 2k・2k+1、葉 i はノード size + i）と同じ順に進める
- 各ノードの箱に、上にノードの番号（小さく）、中に値。葉の下に a0〜a7、その下に今の操作の区間の帯（set なら位置の三角）と「[1, 7) の最小値　sL = 2　sR = 4　答え 2」のような途中の値
- prod：「始め」（l ← l + size、r ← r + size）→ ループ 1 回ごとに 1 状態 →「終わり」。l・r はその段の境目に縦の棒と「l = 9」「r = 15」（等しければ「l = r = 3」）で示す。文字は背景の色で縁取り、辺と重なっても読める。caption は「l は奇数（右の子）で親は左にはみ出すので、ノード 9（[1, 2)）の値 3 を sL の右に積み（sL = 3）、l を 10 に進める。r は奇数で、r − 1 = 14 は左の子なので親は右にはみ出す。…l・r を半分にして親の段へ上がり、l = 5、r = 7 になる。」の形。終わりは答えの式と、使ったノード（左から 9・5・6・14）が区間ちょうどになること。根を使う場合（l = 1）は「根で、区間はこのノードの全体」と書き、根より上の段で止まるときは棒を描かない
- set：葉の書き換え → 親の作り直し 1 回ごとに 1 状態（「min(6, 0) = 0。値は 4 から 0 に変わる」／変わらなければ「変わらない」）。最後の状態で書き換えたノード 13・6・3・1 を挙げる
- 色だけに頼らない：このステップで使った・書き換えたノードは太枠、積んだノードには文字で「sL へ」「sR へ」、取得の終わりは使ったノードを塗りつぶし、set で作り直し済みのノードは点線の枠

## 未解決の点

- 幅 360 では 12px の文字（ノード番号・「sL へ」・a0〜a7）が約 10px になる。lazy-segment-tree・fenwick-tree と同じ程度なので、そのままにした
- 最初の版では l・r の名前が辺と重なって読みにくかったので、文字を背景の色（`--md-default-bg-color`）で縁取った（inline の style。kp.css に class を足す案もあるが、担当外のファイルなので触っていない）
- 再帰型の prod（§再帰型と非再帰型）は図にしていない。必要なら `"mode": "recursive"` を足せる
- 演算は min・max・sum の 3 つだけ。可換でない演算（1 次関数の合成など）は箱に収まらないので載せていない。sL・sR の左右の順序は caption の「右に積む」「左に積む」と試験で確かめている

## 検証の指摘への対応（verify-segment-tree.md）

直すべきは 0 件。直すとよい 6 件はすべて直した。

1. 根の段（l = 1、r = 2）の r の側は「r − 1 = 1 は根で、l の側で使ったので、r の側で使うノードはない。」にした。試験を 1 件足した
2. `expr` は値が単位元と等しいかでは省かず、引数で「まだ何も積んでいない sL・sR」と「余りの葉」の側だけを省くようにした。sum で 0 の子があっても「5 + 0 = 5」と出る。試験を 1 件足した
3. 長さ 1 の set は、leaf の caption の「次に、親を根まで…」を「葉がそのまま根なので、作り直すノードはない。」に差し替えた（後から足すのをやめた）。試験を 1 件足した
4. caption の「a_5」を図の添字に合わせて「a5」にした（図の葉の下と下の行が「a5」なので、詰まらないほうにそろえた）
5. 本文の図の読み方の文を「一点更新では、今のステップで書き換える・作り直すノードを太枠にし、書き換え済みの葉と作り直し済みのノードを点線の枠で囲む。」に直した
6. 「作ったもの」の viewBox を 416 × 388 に直した
