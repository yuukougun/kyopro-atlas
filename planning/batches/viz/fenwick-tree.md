# 動く図 fenwick-tree（BIT の sum と add がたどる箱）

## 作ったもの

- `overrides/assets/js/viz/fenwick-tree.js`：BIT の動く図。見本（binary-search・lazy-segment-tree・imos）と同じ形で、`states(config)` は DOM を使わない純粋な関数、`render(svg, state, config, h)` が描く。`viewBox` は N と段の数だけで決まり、ステップによらない
- `tests/viz/fenwick-tree.test.mjs`：試験 7 件
- `docs/ds/fenwick-tree.md`：#invariants の、コメントで置いてあった div を本物にし、前に案内の 1 段落を足した（同じ N = 8 に値 3・1・4・1・5・9・2・6 を入れ、sum(7) は t[7]・t[6]・t[4] で 2 + 14 + 9 = 25、add(3, +2) は t[3]・t[4]・t[8] を直す。次の i への移り方は #operations で述べる）。静的な図 boxes.svg と前後の文章はそのまま

## config

`{"a": [3, 1, 4, 1, 5, 9, 2, 6], "ops": [{"type": "sum", "i": 7}, {"type": "add", "i": 3, "x": 2}]}`

執筆者の仮の config（`{"n": 8, "ops": [{"type": "sum", "i": 7}, {"type": "add", "i": 3}]}`）から、次の 2 点を変えた。

- `n` の代わりに列の値 `a` を持たせた（N = a の長さ）。箱の値と s の途中の値を見せ、「sum が接頭辞の和に一致する」ことを数で確かめられるようにするため
- add に足す値 `x` を足した

仕様（添字は本文の「保つ性質」の節と同じ 1-indexed）：

- `a`：1〜12 個の整数（絶対値 99 以下）
- `ops`：1〜4 個。`{"type": "sum", "i"}`（0 ≤ i ≤ N。sum(0) はループに入らず 0）か `{"type": "add", "i", "x"}`（1 ≤ i ≤ N。i = 0 は「止まらない」と書いた Error。x は 0 でない整数で絶対値 99 以下）
- 箱の値と sum の途中の値が絶対値 999 を超える列と操作は、枠からはみ出すので Error
- 誤りは見本と同じく Error を投げ、viz.js が「図を表示できなかった：…」と出す

## 描き方とステップ（本文の例で 11 状態）

- 長さ 2^k の箱を段 k に置き、長い段を上に描く（boxes.svg と同じ向き）。各箱に「t[i]」と値。下に a の行、添字、添字の 2 進数（N に合わせた桁数）。上の行に「sum(7)　i = 4　s = 25」のような今の操作と変数
- 初期状態 → 操作ごとに「始め」「ループ 1 回ごと」「止まった」。ループ 1 回ごとの caption は「i = 7（2 進で 0111）、lowbit(i) = 1。s += t[7]（a_7 = 2）で s = 2。次は i − lowbit(i) = 7 − 1 = 6（0110）で、最下位の 1 が消える。」の形（add は「t[i] に x を足して 旧 → 新。次は i + lowbit(i) = …で、最下位の 1 の桁で繰り上がる。」）。sum の終わりは通った箱と、直接足した和（一致する）を書き、add の終わりは「i = 16 > N = 8 になったので止まる。a_3 を含む箱は t[3]・t[4]・t[8] の 3 つ」
- 色だけに頼らない：今の箱は太枠、この操作で通った箱は点線の枠、今の i は添字と 2 進数を太字にして下に三角の印。sum では足し終えた箱が覆う a を塗り、add では足した a_i を太枠にする

## 確かめたこと

- `node --test tests/viz/fenwick-tree.test.mjs`：7 件すべて通る。本文の例で、初期の t = [3, 4, 4, 9, 5, 14, 2, 31]（1-indexed）、sum(7) が 7 → 6 → 4 と通って s = 2, 16, 25、add(3, +2) が 3 → 4 → 8 と通って 16 で止まり、t = [3, 4, 6, 11, 5, 14, 2, 33]（本文の「t[7]・t[6]・t[4]」「t[3]・t[4]・t[8]」「7 → 6 → 4 → 0」「3 → 4 → 8」と一致）。caption の 2 進数と式。端の場合（sum(0)、sum(N)、N = 1、N = 12 で 2 の冪でない場合の sum(12) = t[12]・t[8] と add(5) = t[5]・t[6]・t[8]、add(N)、負の x、add の後の sum）。ランダム 3000 件で、各ステップの s・通る箱が定義どおりで、sum が素朴な和と一致し、add が a_i を含む箱をちょうど通り、add の後の t が定義どおり。入力を書き換えない。誤った config 23 通り。viewBox の大きさ。偽の h で render を呼び、太枠・点線・三角の印が付くこと
- `python3 tools/check_pages.py`：エラー 1 件は graph/degree-sqrt.md の用語集の anchor（このページとは無関係、別の作業のもの）。fenwick-tree には警告もない
- `npx textlint docs/ds/fenwick-tree.md`：エラー 0。足した段落（85 行目）には警告なし（最初の版で読点の数の警告が出たので文を分けた）
- ブラウザ：`uv run mkdocs build -d <scratchpad>/site-fenwick-tree` でビルドし、http サーバー経由で chrome-headless-shell（日本語は font_env と同じ fonts.conf）で開いた。幅 800（ライト）で 11 状態すべて、幅 360（ライト・ダーク）で 1・5・6・9・11 番目を「次へ」で送って撮り、図が描かれ、カウンタ 1/11〜11/11 と caption が進み、最後で「次へ」「最後へ」が無効になることを目で確かめた。幅 360 で横のはみ出しなし（scrollWidth 360）、箱の「t[i]」と値、2 進数が読める。JS の例外なし

## 未解決の点

- catalog の visual にある「添字を 2 進数で並べる」は満たしたが、BIT 上の二分探索（lower_bound）は図にしていない。必要なら操作の種類 `lower_bound` を足せる
- 幅 360 では 12px の文字（t[i] の名前と 2 進数）が約 10px になる。imos・lazy-segment-tree と同じ程度なので、そのままにした
- N = 12 は幅 504 になり、幅 360 では約 0.65 倍に縮む。本文は N = 8 なので問題はないが、ほかのページで N を大きくするときは注意

## 検証の指摘への対応（verify-fenwick-tree.md）

直すべきは 0 件。直すとよいの 3 件はすべて直した。採らなかったものはない。

- 1（幅 1 の枠に 4 文字の値）：`validate` で、add の後の a の値（奇数の i の t[i] は a_i と同じ値）が −99〜999 に収まるかを確かめ、外れたら「幅 1 の枠に描く a の値（奇数の i の t[i] も同じ値）は add の後も −99〜999 にする」の Error にした。描画で文字を縮める案は、同じ図の中で文字の大きさがそろわなくなるので採らなかった。試験に `a_1 = −100` になる場合と、指摘の `{a: −99 を 12 個, ops: add(9, −99) を 4 回}` を足した。幅 2 以上の箱は「−999」の 4 文字が入るので、絶対値 999 の制限のままにした
- 2（sum の始めの「a_1 + … + a_1」）：i = 1 は「a_1 を求める」、i = 2 は「a_1 + a_2 を求める」、i ≥ 3 は今のまま
- 3（add の終わりで箱が 1 つ）：「a_12 を含む箱は t[12] だけで、それを直した。」にした
- 試験に「caption は項や箱の数が少ないときも自然に書く」を足して 8 件。`node --test` は 8 件すべて通る。`check_pages.py` はエラー 0・警告 0、`npx textlint docs/ds/fenwick-tree.md` はエラー 0（警告 18 は足した段落の外）。本文は変えていない
- ブラウザ：作業用の場所に `mkdocs build`（-q なし）でビルドし直し、chrome-headless-shell（font_env と同じ fonts.conf）で幅 800（ライト）の 11 状態すべてと幅 360（ライト・ダーク）の 1・5・6・9・11 番目を「次へ」で送って撮った。カウンタ 1/11〜11/11 と caption が進み、「a_1 + … + a_7 を求める」「3 つで、すべて 1 回ずつ直した」のとおり本文の例の表示は変わらない。横のはみ出しなし（scrollWidth 360）
