# 動く図 two-pointers（尺取り法）

## 作ったもの

- `overrides/assets/js/viz/two-pointers.js`：尺取り法で、各左端 l に対する右端 r(l) を、r を戻さずに求める図
  - 上段：列のマス（添字つき）と区間 [l, r) の太い枠。r は枠の上の下向きの三角、l は添字の下の上向きの三角で、どちらも斜体の文字を付けて境目（マスの間）を指す。出した要素は薄く、入れられなかった要素は破線の枠と × で示す。その下に「[l, r)　和 s ≤ K」の文字
  - 下段：決まった r(l) の折れ線。横はマスと同じ列（l）、縦は r（0〜N）。点の上に値の数字を書くので色に頼らない。いま決めた点は大きく強調する
  - 状態の phase：start・extend（r を伸ばす）・decide（伸ばせないので r(l) を決める）・advance（a[l] を出して l を進める。空区間なら r も一緒に進める）・none（at-least で r = N でも足りない）・done。各状態にだ・である調の caption を付けた
  - mode "at-least"（和が K 以上・各 l で最小の r）も実装した（執筆者が将来の余地として置いたもの。本文ではまだ使っていない）
- `tests/viz/two-pointers.test.mjs`：8件
  - 本文の例で r(l) = 3, 3, 4, 5, 7, 7, 7、区間の数 15、状態 22（伸ばす 7・決める 7・進める 6）、× の位置
  - mode の省略、at-least の例（3, 4, 4, 5, 7, なし, なし）
  - 端の場合：K = 0 で l と r が一緒に進む、0 の要素、1 要素、全体でも K に届かない（打ち切り）、全体が K 以下
  - ランダム 3000 通り × 2 mode で全探索の r(l)・区間の数と一致。どの状態でも和が区間の中身と一致し、l ≤ r、端が戻らない、at-most では和 ≤ K
  - 決定的であること・入力を書き換えないこと・入力の誤り（data-config がない・array の長さ/値・K・mode）・viewBox

## config

`{"array": [1, 2, 1, 3, 1, 1, 2], "K": 4, "mode": "at-most"}`（執筆者の仮のまま変えていない）

- array：0〜99 の整数を 1〜12 個。K：at-most は 0 以上、at-least は 1 以上の整数。mode：省略時 "at-most"
- N = 7 で viewBox の幅は 360（スマホの幅で縮まない）

## 本文の変更

`docs/basics/two-pointers.md` の div の直後の段落に、r(l) を決めてから l を進めること、下の折れ線に r(l) を 1 点ずつ足すこと、最後に r(l) が静的な図の帯の右端と一致し、和が 4 以下の空でない区間が $\sum_l (r(l) - l) = 15$ 個であることを足した（15 は試験で全探索と照合済み）。

## 未解決の点

- 幅 1000 では図が横いっぱいに広がり大きく見える（viz.js と kp.css の共通の振る舞いで、binary-search と同じ。この図の範囲では直していない）
- caption の中の l は本文の数式と違い立体で、字形によっては I と紛らわしい（図の中の l・r は斜体にした）

## 検証の指摘への対応（verify-two-pointers.md）

直すべき指摘は 0 件。直すとよい指摘 5 件はすべて直した。

1. 本文の「上の図の帯の右端」を「前の静的な図（各 $l$ の区間を帯で示した図）の帯の右端」にした
2. at-least で打ち切ったときの done の caption を「r(l) は l = 0〜4 で 3, 4, 4, 5, 7 と決まった。左端 l = 5 以降は条件を満たす右端がない。…」とした（試験を足した）
3. caption の l・r に「左端」「右端」を添えた（「左端 l = 0 から始まる」「左端 l を 3 に進める」「右端 r を 4 に伸ばす」など）。r(l) の記号はそのまま
4. 状態に skipped（入れずに l と r を一緒に越えた位置）を持たせ、その要素は薄い塗りでなく破線の枠のまま描くようにした（試験を足した。A = (5, 0, 7)・K = 0 で a[0] が破線になることをブラウザで確かめた）
5. MAX_N を 12 から 8 にした（viewBox の幅 404、幅 360 の画面で 0.76 倍ほど）。試験の乱数も N ≤ 8 にし、N = 9 で Error になることと、N = 8 で 0.75 倍以上に収まることを試験した

直したあとの確認：試験 8 件が通る、check_pages で two-pointers の指摘 0、textlint はエラー 0・警告 25（変更前と同じ）、scratchpad へのビルドで警告なし。ブラウザ（幅 360 ライト・幅 1000 ダーク）で図が描かれ「次へ」で状態が進むこと、at-least の最後・K = 0・N = 8 の図、N = 9 の誤りの文を目で確かめた。
