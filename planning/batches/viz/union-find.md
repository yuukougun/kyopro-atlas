# 動く図 union-find（union by size の併合と find の経路圧縮）

## 作ったもの

- `overrides/assets/js/viz/union-find.js`：Union-Find の動く図。見本（binary-search・lazy-segment-tree）と同じ形で、`states(config)` は DOM を使わない純粋な関数、`render(svg, state, config, h)` が描く。`viewBox` は n と全ステップの森の最大の深さで決まり、ステップによらない
- `tests/viz/union-find.test.mjs`：試験 11 件
- `docs/ds/union-find.md`：div（config は執筆者のまま）の前の案内の段落を直した。元の文の「小さい木の根が大きい木の根の下につく様子」は、この ops ではすべての併合が同じ大きさどうし（そうでないと深さ 3 と最後の par が静的な図と合わない）なので起きず、図と食い違っていた。「根どうしがつながるたびに根の par が −(大きさ) に変わる様子と、最後の find(7) で深さが縮む様子を確かめられる。この順では、併合する 2 つの木がいつも同じ大きさになる。」にした。div の後の段落（a 側の根を残す・深さ 2 → 3）はそのまま

## config

`{"n": 8, "ops": [{"type": "merge", "a": 0, "b": 1}, {"type": "merge", "a": 2, "b": 3}, {"type": "merge", "a": 0, "b": 2}, {"type": "merge", "a": 4, "b": 5}, {"type": "merge", "a": 6, "b": 7}, {"type": "merge", "a": 4, "b": 6}, {"type": "merge", "a": 0, "b": 4}, {"type": "find", "x": 7}]}`（執筆者の仮のものから変えていない）

仕様：

- `n`：1〜10 の整数（幅 360 で節の番号が読める上限）
- `ops`：1〜24 個。`{"type": "merge", "a", "b"}` か `{"type": "find", "x"}`（どれも 0 以上 n 未満の整数）。a = b や同じグループどうしの merge も受け付ける
- 誤りは見本と同じく Error を投げ、viz.js が「図を表示できなかった：…」と出す（data-config がない・n の範囲・ops の個数・type・添字の範囲と整数か）

## 描き方とステップ（本文の例で 21 状態）

- 上から、見出し（「merge(0, 4)：根どうしをつなぐ（グループ 1 個）」の形）、配列 par（添字の行と値の行。負の数は −）、凡例、森。森は根を番号の順に並べ、子から親へ矢印を引く。森の高さはステップで変わるので、余白が下に来るよう配列を上に置いた
- 状態：初め → merge ごとに「根を求める（たどった道を太線、2 つの根を太枠）」→ merge の中の find で親が変わったときだけ「経路圧縮」→「根どうしをつなぐ」（同じ根なら「何もしない」）→ find ごとに「始め」「親へ 1 段ずつ（最後の段で根に着いたと書く）」→ 親が変わるときだけ「経路圧縮」→ 終わり（グループの数と par）
- caption の例：「大きさが同じ（4）なので、a 側の根 0 を残し、根 4 をその下につなぐ。par[4] = 0、par[0] = −4 + (−4) = −8 にする。グループは 1 個になった。」「par[4] = 0 なので 0 へ進む（3 回目）。par[0] = −8 < 0 なので 0 が根である。find(7)：7 → 6 → 4 → 0 と 3 回たどって根 0 を見つけた。」「帰りがけに、通った 7 と 6 の親を根 0 に書き換えた（経路圧縮）。4 はもともと根の子である。…」。大きさが違うときは「小さい方の根 y（大きさ …）を、大きい方の根 x（大きさ …）の下につなぐ」、b 側が大きいときは「入れ替え」と書く
- 色だけに頼らない：根は二重の輪、いま注目する節は太枠と太字、たどった矢印は太線、書き換えた矢印は太い破線、値が変わった par のマスは太枠と太字。凡例に線の形と二重の輪を示した

## 未解決の点

- 森の配置は状態ごとに作り直すので、併合のたびに節の位置が動く（たとえば merge(0, 1) のあと 1 が 0 の下に移り、2〜7 が左へ詰まる）。どの節がどこへ行ったかは番号で追える。位置を固定したいなら、最終状態の配置を全ステップで使う方法がある
- 線の色は dp-tree-table・expected-value-dp と同じく、kp.css に線用の class がないので `style` に Material の CSS 変数を直接書いた
- 本文の ops では「小さい木の根が大きい木の根の下につく」場面がない（静的な図と最後の形をそろえるため）。この場面を見せたいなら、別の div（たとえば merge(0, 1)・merge(0, 2)・merge(3, 0)）を足すことを提案する
- `same` と `size` の操作は作っていない。必要なら type を足せる

- 指摘 1（直すべき）：直した。本文の config は変えず、div の後の段落の次に 2 つ目の div（6 要素、merge(0, 1)・merge(2, 3)・merge(0, 2)・merge(4, 3)・merge(5, 1) の 13 状態）と前後の文を足した。merge(4, 3) で find(3) の経路圧縮と「根 4 の方が小さいので入れ替え」、merge(5, 1) でもう一度小さい方の根を大きい方の根の下に入れる場面が出る。後の文は「深さが 1 増えるのは小さい方の木の要素だけ」とし、#complexity へつないだ
