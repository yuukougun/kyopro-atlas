# 動く図 digit-dp-tight（桁 DP の一致フラグ）

## 作ったもの

- `overrides/assets/js/viz/digit-dp-tight.js`：桁 DP の「N と一致しているか」のフラグの動く図。見本（binary-search・lazy-segment-tree）と同じ形で、`states(config)` は DOM を使わない純粋な関数、`render(svg, state, config, h)` が描く。`viewBox` は桁数だけで決まり、ステップによらない
- `tests/viz/digit-dp-tight.test.mjs`：試験 6 件
- `docs/dp/digit-dp.md`：変えていない。div・config・図の前後の文章（図の説明と、図の流れを追う箇条）は、図の内容とそのまま合う

## config

`{"digits": "253", "base": 10}`（本文と同じ。変えていない）

- `digits`：N を base 進で書いた数字の文字列（1〜6 文字）。先頭は 0 にしない（N = 0 の `"0"` だけは可）
- `base`：2〜10 の整数（省略すると 10）。`{"digits": "1101", "base": 2}` のように 2 進の節にも使える
- 誤りは見本と同じく Error を投げ、viz.js が「図を表示できなかった：…」と出す（`"0253"` で表示を確かめた）

## ステップ（本文の例で 5 状態。一般に桁数 + 2）

1. start：N の桁を横に並べ、一致の道の始点（何も決めていない数）だけを示す
2. 桁ごとに 1 状態：その桁の N の数字を強調し、一致の道を太線で 1 段伸ばす（線の上に「2 を置く」）。始点のノードから未満の枝を分け、箱に置ける数字（0・1、0〜4 など）・「残り k 桁自由」・「2 × 100」を書き、下に「= 200」。数字が 0 の桁は点線の箱「枝なし」。caption は「百の位を決める。N の数字は 2 である。0・1 を置くと…残りの 2 桁は 00〜99 の 100 通りを自由に選べるので、2 × 100 = 200 個になる。2 を置けば一致のまま次の桁へ進む。」の形
3. done：一致の道の終点の右に「N 自身 1 個」を塗り、下に「合計 254 個（0〜253 の個数）」。caption は「合計は 2 × 100 + 5 × 10 + 3 + 1 = 254 で、0 から 253 までの整数の個数 254 と一致する」（本文の式と同じ書き方）

色だけに頼らないよう、行の左に「一致」「未満」と文字で書き、一致の道は太線と塗ったノード、まだの所は細い破線と点線のノード、いまの桁は太い枠、枝のない桁は点線の箱と「枝なし」で区別した。色は kp.css の既存の class（kp-v-cell・kp-v-text・kp-v-ptr・kp-v-mark）だけで付け、CSS は足していない。

## 確かめたこと

- `node --test tests/viz/digit-dp-tight.test.mjs`：6 件すべて通る。本文の config で枝が [2 × 100, 5 × 10, 3 × 1]、合計 254、最後の caption に本文と同じ式「2 × 100 + 5 × 10 + 3 + 1 = 254」、各ステップの caption が本文の箇条（0・1 → 00〜99 の 100 通り、0〜4、0〜2、N 自身）と合う。全探索（0〜N の各 X を桁数にそろえ、初めて N と異なる桁ごとに数える）と枝ごとの個数が一致：10 進の N = 0〜1200、2 進の 0〜63、3 進の 0〜242、999999・100000・8 進 777777。端の場合（N = 0、数字 0 を含む N = 100、2 進 1101）、caption が句点で終わる、入力を書き換えない、誤った config 10 通りで Error、viewBox の大きさ
- `python3 tools/check_pages.py`：エラー 0・警告 0
- `npx textlint docs/dp/digit-dp.md`：エラー 0（警告 1 は執筆者の報告にある 2 進の節の max-comma の誤検出で、以前からのもの）
- ブラウザ：`uv run mkdocs build -d <scratchpad>/site-digit-dp-tight` でビルドし、chrome-headless-shell（CDP を Node の WebSocket で操作、日本語は render_svg.py の font_env と同じ fontconfig で Windows のフォント）で幅 360px と 900px で開いた。図が取り付けられ、「次へ」のクリックで 1/5 → 5/5 と状態が進み、caption とカウンタが変わることを各ステップのスクリーンショットで目で確かめた。360px でも数字・ラベル・箱の文字が読める。config を替えた写し（2 進 1101・N = 0・6 桁 905017・誤りの 0253）も表示を確かめた

## 未解決の点

- 6 桁（上限）のときは横幅が 706 になり、360px では箱の中の小さい文字（12px 相当）が約 6px まで縮む。本文の 3 桁では問題ない。2 進の節で使うなら 4〜5 桁にとどめるとよい
- 2 進の節にこの図を置くかはメインの判断（今は tight-flag の節の 1 か所だけ）
- ビルドの途中、別の担当の http.server がポート 8765 で site-imos を出していたため、最初の撮影はそちらのビルドを見ていた（そのビルドにもこの JS が入っていたので結果は同じ）。並行で撮るときはポートを分けるとよい

## 検証の指摘への対応（verify-digit-dp-tight.md）

直すべき指摘は 0 件。直すとよい 4 件はすべて直した。採らなかったものはない。

1. 一致の道の「まだの所」のコメントを「細い破線（短い線分を並べる）」に直した
2. 6 桁目の位の名前を「10 万」から「十万」にした。試験に「10 進の位の名前はすべて漢数字（905017 で十万〜一の位）」を足した（7 件）
3. 冒頭のコメントに「幅 360px で読めるのは 4 桁ぐらいまでなので、本文では 4 桁以下にする」と書いた。`MAX_LEN` は 6 のまま（900px 以上なら 6 桁でも読め、試験の全探索も 6 桁を使うため）
4. 枝なしの箱がいまの桁のときは `is-sentinel` の代わりに `is-no` を付け、`is-focus` の太い accent の枠が見えるようにした（CSS は足していない）。いまの桁でなくなれば点線の箱に戻る

確かめたこと：`node --test` 7 件通過、`check_pages.py` で digit-dp は 0 件、textlint はエラー 0（警告 1 は以前からの 2 進の節）。scratchpad の site-digit-dp-tight にビルドし、chrome-headless-shell で本文の config を 360px・900px・900px ダークで 1/5 → 5/5 まで送って確かめた。905017 に差し替えた写しで「十万の位」と、いまの桁の枝なしの箱が太い accent の枠になり、次のステップで点線に戻ることを確かめた
