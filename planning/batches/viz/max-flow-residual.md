## config

`{"n": 4, "labels": ["s", "a", "b", "t"], "edges": [[0, 1, 1], [0, 2, 1], [1, 2, 1], [1, 3, 1], [2, 3, 1]], "s": 0, "t": 3, "paths": [[0, 1, 2, 3], [0, 2, 1, 3]]}`（b3 の仕様のとおり）

仕様：

- `n` は 2〜8。`edges` は 0〜12 本の有向の辺 `[u, v, c]` で、容量 c は 1〜99 の整数。`s`・`t` は省略時 0 と n−1 で、s ≠ t。`labels` は省略可（n 個の 1〜3 文字で重複なし）。`pos` は省略可（単位は任意で、枠に合わせて拡大・縮小する）
- `pos` を省くと、s を左端、t を右端に置き、ほかの頂点を番号の順に上の弧（左から）、続けて下の弧（左から）に並べる
- `paths`：流す増加路を頂点の列 `[s, …, t]` で順に並べた配列（省略可、20 本まで）。各道は同じ頂点を 2 度通らず、その時点の残余グラフで容量が正の辺だけを通ること。渡した道を流し終えても増加路が残れば、続きは DFS で探して最大まで流す。`paths` を省けば、はじめから DFS で探す（b3 の仕様の「自動で探す版にしてもよい」を、渡した道の後の続きにも使った）
- DFS は、各頂点で元の辺の番号の順に（ACL の mf_graph が順辺と逆辺を `add_edge` の順に持つのと同じ）、容量が正で未訪問の頂点へ進み、最初に t に着いた道を選ぶ。本文の config で `paths` を省いても、1 本目に s→a→b→t、2 本目に s→b→a→t を選び、同じ列になる（試験で確かめる）
- Error にするもの：自己ループ、同じ 2 頂点を結ぶ 2 本目の辺（逆向きも。順辺と逆辺の組が重なるため）、容量が 1〜99 の整数でない、`paths` の道が s から始まらない・t で終わらない・同じ頂点を 2 度通る・辺のない組を通る・その時点で容量 0 の辺を通る、`pos` の頂点が同じ位置か近すぎる（中心の間隔 60 未満）、増加路が 99 本を超える、ほか形の誤り。viz.js が「図を表示できなかった：…」と出す（例：「paths の 2 本目：s → a の残りの容量が 0 なので、増加路にならない」）

## 動きとステップ

- 状態の列は「元のグラフ」→ 増加路 1 本ごとに「道を選び、最小の容量 d を示す」「d を流す」→「最後」。本文の config は 6 状態
- 状態の項目：`phase`（init / path / push / end）・`flow`（元の辺ごとの流量）・`total`（流量）・`path`・`arcs`（増加路の辺 `{edge, rev, from, to, cap}`。rev は逆辺か）・`d`・`auto`（DFS で見つけた道か）・`before`（push の前の flow）・`reach`（s から届く頂点）・`cut`（届く側から外へ出る元の辺）・`back`（外から届く側へ入る元の辺）・`last`・`caption`
- 本文の例の流れ：1 本目 s→a→b→t（d = 1）で流量は [1, 0, 1, 0, 1]、2 本目 s→b→a→t は逆辺 b→a を通り（d = 1）、a→b の 1 が打ち消されて [1, 1, 0, 1, 1]、流量 2。最後は s だけが届き、カットは s→a・s→b（容量の和 2）。本文の静的な図の (1)〜(3) と一致する
- caption の例
    - 4/6：「増加路 s → b → a → t を選ぶ。b → a は逆辺で、a → b に流している 1 まで押し戻せる。道の上の残りの容量は 1、1、1 で、最小の d = 1 だけ流せる。」
    - 5/6：「d = 1 を流す。通った辺 s → b・b → a・a → t の容量が 1 減り、逆向きの辺 b → s・a → b・t → a の容量が 1 増える。b → a は逆辺なので、元の辺 a → b の流量が 1 から 0 に減る（押し戻す）。流量は 1 + 1 = 2 になる。」
    - 6/6：「s から t への増加路はもうない。残余グラフで容量が正の辺だけをたどって s から届く頂点（塗った頂点）は s だけで、t には届かない。塗った頂点から外へ出る元の辺 s → a・s → b はどれも容量いっぱいに流れていて、容量の和 1 + 1 = 2 が今の流量に等しい。これが最小カットで、流量 2 が最大である。」
    - 順辺だけの道を流すステップは「通った順辺 … の容量が d 減り、その逆辺 … の容量が d 増える」と言う。外から届く側へ入る辺があれば、最後に「… の流量は 0 である」も言う
- 描画（色だけに頼らない）
    - 残余グラフ：元の辺ごとに、順辺（実線）と逆辺（破線）を、それぞれ進む向きの左側に 5 ずらして並べ、矢じりを付ける。数は線の外側に置き、左右に寄る辺は文字の端を線にそろえて、ステップで文字の幅が変わっても位置が動かないようにした
    - 容量 0 の辺は細く薄い線と薄い数。選んだ増加路は太線（逆辺は太い破線）と太字の数。流したステップは、両向きの数を「1→0」「0→1」の形の太字にし、線は流した後の容量で描く（使い切った順辺が薄くなり、逆辺が濃くなる）
    - 最後のステップは、s から届く頂点を塗り（文字は太字の白）、カットの辺に届く側の寄りで横切る短い太線の印を付ける
    - 図の下に「増加路」「流す量（d = min(1, 1, 1) = 1）」「流量（0 + 1 = 1 など）」の行と、最後だけ「カット（s → a・s → b（容量の和 2））」の行。凡例は 2 行（順辺・逆辺・容量 0／増加路・s から届く頂点・カットの辺）
    - 色は kp.css の `.kp-v-*` の class で付けた（下の「未解決の点」1）
