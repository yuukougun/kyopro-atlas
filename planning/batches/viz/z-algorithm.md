## 未解決の点

- 箱を取り替えるステップでは、図の括弧は z[i] を決めるのに使った古い箱のままで、新しい箱は caption にだけ出る（次のステップで括弧が新しい箱になる）。ステップを分けるか、新しい箱を別の線で描くかは検証で判断してほしい
- 場合 2 で箱の内側にある食い違い（S[i + z[i − l]] ≠ S[z[i − l]]）には印を付けていない（caption に「食い違いも箱の内側で起きる」とだけ書く）
- 仕様にある palindrome（Manacher）の図との部品の共有はしていない（Manacher の動く図がまだないため）。箱の括弧・矢印は render の中の短い処理なので、作るときに写せばよい
- 誤った config の表示（「図を表示できなかった：…」）は Node の試験で Error を投げることだけ確かめ、ブラウザでは試していない（viz.js の共通の処理）

## 検証の指摘への対応（verify-z-algorithm.md）

直すべき 0 件。直すとよい 4 件はすべて直した。

1. 箱を取り替えるステップ：一番上に行を足し、新しい Z-box を破線の括弧と「新しい Z-box [l, r)」の文字で描く（空の箱は破線の短い縦線と「（空）」）。古い箱の実線の括弧はそのまま残すので、z[i] を決めるのに使った箱と取り替えた後の箱が同時に見える。図の高さは 256 → 282
2. 空の箱：boxText で l = r > 0 のとき「Z-box [l, r)（空）」と書く。図では位置 l の左の境目に短い縦線と「l = r」を描く。試験に abcab の i = 3 の caption を足した
3. 先頭の行の調べなかった文字：塗りをやめ、細い薄い枠と薄い字にした（写した部分の灰色の塗り＋破線と、塗りでも区別できる）
4. 場合 2：箱の内側で分かる食い違いの位置（S の行の i + z[i − l] と先頭の行の k = z[i − l]）を点線の枠と右上の小さな「≠」で示し、caption を「S[i + k] ≠ S[k] も、箱の内側の対応 S[i − l + k] ≠ S[k] から分かっている」と位置で書く。比較の数は変えない。試験に i = 4 の caption（S[5] ≠ S[1]、S[2] ≠ S[1]）を足した

本文の div の直前の段落に、場合 2 の「≠」の印と、新しい Z-box の破線の括弧の説明を 2 文足した。
