# 動く図 bfs-layers（幅優先探索の距離の層とキュー）

## 作ったもの

- `overrides/assets/js/viz/bfs-layers.js`：BFS で、先頭を 1 つ取り出すたびに隣を見つけて距離の層が育つ様子を描く図
  - 上段：頂点を最後に決まる距離ごとの列（層の帯）に並べる。列の中は見つけた順に上から置く（静的な図 layers.svg と同じ並び）。始点から届かない頂点は右端の「届かない」の列に置く。同じ列で間に頂点がある辺は右へふくらむ弧で描く
  - 帯：まだ誰も見つけていない層は破線、見つけた層は実線、いまキューにある距離の層は塗り＋見出しを強調。これでキューの距離が d と d+1 の 2 層だけであることが帯でも見える
  - 頂点：未発見は破線の円と「−1」、キューの中は白い円、取り出し済みは塗りの円。取り出した頂点は外側に輪。距離の数字は辺から離れた向き（上・下を優先し、枠の端では横に置かない）に書き、このステップで見つけた頂点は「−1→d」と強調して、push のときに距離を書くことを示す
  - 辺：親への辺（par）は太い実線、このステップで見た辺は強調色、ほかは細い破線。最後に太い辺が最短路の木になる（path-restoration へのつながり）
  - 下段：「取り出した頂点」（距離と見つけた頂点の名前）と、キュー（左が先頭、下に距離、距離が変わる所に縦線）。凡例 2 行
  - 状態の phase：init・pop（1 回の取り出しで 1 状態）・done。caption はだ・である調で、飛ばした隣・見つけた隣・「キューの中の距離は前から 1, 2 で、1 と 2 の 2 種類である」を毎回書く。done は全頂点の距離と、届かない頂点の名前を書く
  - 色だけに頼らない：未発見・キューの中・取り出し済みは円の線種と塗り、距離は数字、辺は太さと破線、キューの距離の境目は縦線で区別する
- `tests/viz/bfs-layers.test.mjs`：6 件
  - 本文の config：状態 8 個、最後の距離 0, 1, 1, 2, 2, 3、親 [−1, 0, 0, 1, 2, 3]、太い辺の番号 0・1・3・5・7、取り出す順 s〜e、各取り出しの後のキュー（[a,b]・[b,c]・[c,d]・[d,e]・[e]・[]）と見つけた頂点、caption の要点
  - 端の場合：頂点 1 個で辺なし、届かない頂点がある（始点が 0 でない）
  - ランダム 2000 通り（n ≤ 8、辺 ≤ 14、始点もランダム）：距離が別に書いた BFS と一致。どの状態でも、書いた距離は真の距離と一致、キューの距離は単調で差 1 以下、同じ頂点が 2 回入らない、親の距離 + 1、1 ステップで 1 頂点を取り出す、各頂点の push は 1 回、caption がだ・である調
  - 決定的であること・入力を書き換えないこと・入力の誤り（data-config・n・labels の数/重複/長さ・n と labels の食い違い・source・辺の端・自己ループ・多重辺・辺の形・辺の数）

## config

`{"labels": ["s", "a", "b", "c", "d", "e"], "edges": [[0, 1], [0, 2], [1, 2], [1, 3], [2, 3], [2, 4], [3, 4], [3, 5], [4, 5]], "source": 0}`（執筆者の仮のまま変えていない）

## 未解決の点

- 層の列は最後に決まる距離で先に並べるので、未発見の頂点の置き場所が答えを先に見せている（静的な図と同じ並びにするためにそうした。帯は破線、距離は −1 で、見つかるまで層として扱わない）
- 有向グラフは扱っていない（有向だと層を 2 つ以上戻る辺がほかの頂点の上を通るため）。本文の例は無向なので足りている
- 幅 1000 では kp-viz__svg の max-height で図が中央に小さめに描かれる（共通の振る舞い）

## 検証の指摘への対応（verify-bfs-layers.md）

直すべき 0 件・直すとよい 5 件。5 件とも直した（採らなかったものはない）。

1. 距離の文字が同じ列の隣の頂点の文字と重なる：向きを列ごとに上から順に決める `labelDirs` を足し、すぐ上の頂点が文字を下に置いたときは上に置かない。あわせて、横に置く向きの近くに別の頂点（とその上下の文字）があれば横に置かない（隣の列が近いとき、横の文字が隣の頂点の文字に触れる例が乱数で見つかったため）。上下の離れは R + 14 → R + 12 にして、文字が自分の頂点の側に寄るようにした
2. 右端の列の弧がはみ出す：`bulge` を `2 × (W − 6 − x)` で頭打ちにした（2 次ベジエの一番右は制御点までの半分）
3. 今見た親への辺が色だけで区別される：今見た辺が親への辺でもあるときは、太い線の中に背景色の細い破線を重ねる（`data-focus-tree`）。凡例は 3 行にし、「今見た辺」に細い破線と、破線を重ねた太い線の 2 つの見本を並べて「（太いものは親への辺でもある）」と書いた
4. 横の距離の文字が取り出しの輪に接する：横の離れを R + 7 → R + 10 にし、枠の端の判定も同じ値を使う
5. labels を省いたときの caption：caption の中だけ頂点を「頂点 k」と書く（図の中の名前は短いまま）。コメントに、本文では labels を書くのがよいと 1 行足した

試験は 6 → 9 件：偽の `h` で描いて、距離の文字の箱どうしが重ならないこと・弧の一番右が枠の中にあること（本文の config・指摘の 2 例・乱数 3000 件の全状態）、今見た親への辺だけに重ねの印があること、labels を省いたときの caption。

確かめたこと：`node --test` 9 件通る、`check_pages.py` エラー 0（警告 1 は comb/expectation-tail-sum.md でこの図と関係ない）、`npx textlint docs/graph/bfs.md` エラー 0・警告 6（変更前と同じ）、`mkdocs build`（scratchpad の site-bfs-layers）で bfs の警告なし。chrome-headless-shell で本文の図（幅 360 ライト・ダーク、幅 800）と、ページの写しに足した指摘の 3 つの config を撮り、1/8 → 8/8 と進むこと、重ねの破線と凡例、文字の重なりがないこと、弧が枠に収まること、横のはみ出しなし（scrollWidth = 画面幅）、JS の例外なしを目で確かめた。
