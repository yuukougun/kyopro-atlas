## 指摘

### 1. 直すとよい｜段の中の更新の並びが、本文の箇条書きと図で違う｜G1・G7

- **場所**：`docs/graph/warshall-floyd.md` 80〜81 行（k = 2・k = 3 の箇条書き）。図の段の最後の caption（`warshall-floyd.js` 221〜223 行）
- **問題**：図はマスを行の順に送るので、k = 2 では d[3][0] → d[3][1]、k = 3 では d[0][1] → d[0][2] → d[1][2] の順に更新し、caption も「d[3][0]・d[3][1]」「d[0][1]・d[0][2]・d[1][2]」と書く。本文は「d[3][1] = 2、d[3][0] = 4」「d[0][2] = 2、d[0][1] = …、d[1][2] = 4」の順である。値は一致するので誤りではないが、図を送りながら読むと、本文の 1 つ目の更新が図では 2 つ目に来る。執筆の報告の「本文の箇条書き…に一致する」は値の一致の意味である
- **根拠**：`vwf/cap.mjs` で 29 状態を書き出し、21・22 番目（k = 2）と 24・25・27 番目（k = 3）を本文と比べた
- **直し方**：本文の 2 行を行の順（k = 2：d[3][0] = 4、d[3][1] = 2。k = 3：d[0][1]、d[0][2]、d[1][2]）に並べ替える。本文が d[3][1] を先に書くのは 84 行の「d[3][1] = 2 が先にできていた」へつなぐためなので、並びを変えずに残すなら直さなくてよい（メインの判断）

### 2. 直すとよい｜頂点の印「i」「j」「k」が、比べる頂点の輪に触れる｜G3

- **場所**：`warshall-floyd.js` 431 行 `var off = R + 11;`（輪は 421 行で半径 R + 4）
- **問題**：印の文字の中心が頂点の中心から 26 で、輪（半径 19 に線の太さ）との間が文字の半分（約 7）しかない。斜めに置くと文字の端が輪に重なる。幅 800 の図 1 の 4 番目で頂点 3 の左下の「j」、24 番目で頂点 0 の左上の「i」と頂点 1 の右上の「j」、幅 360・ダークの 22 番目で頂点 1 の「j」と頂点 3 の「i」が輪の線に触れて見える
- **根拠**：`vwf/shots/w800-light-v0-s4.png`・`w800-light-v0-s24.png`・`w360-dark-v0-s22.png` を目視
- **直し方**：輪がある頂点では `off` を R + 15 程度に広げる（例：`var off = isEnd ? R + 15 : R + 11;`）。広げた後に頂点 0・1 の上の印が viewBox の上端や重みの「2」と重ならないかを撮って確かめる

### 3. 直すとよい｜幅 360 で ijk の「×」と「正 3」が小さい｜G3・G4

- **場所**：`warshall-floyd.js` 492〜497 行（× は 15px、「正 3」は 10px）、凡例 541 行
- **問題**：確認問題の図の結論（どのマスが誤りか）を色以外で示すのは × と「正 3」だけで、誤りのマスの塗り `is-no` はライトでは普通のマスの塗りとほとんど区別できない。幅 360 では viewBox が約 0.68 倍に縮み、× が約 10px、「正 3」が約 7px になる。読めなくはないが、図の一番の結論としては目立たない（執筆の報告の未解決の点と同じ観察）
- **根拠**：`vwf/shots/w360-dark-v1-s13.png`・`w800-light-v1-s13.png` を目視
- **直し方**：誤りのマスに太い破線の枠か二重の枠を足す（比べるマスの太い実線・足すマスの細い破線と別の線にする）か、「正 3」を 12px 程度にして値を少し上へ寄せる。凡例の見本も同じ線にする

### 4. 直すとよい｜ijk の caption が、k = i・k = j を候補から除く理由を言わない｜G1・C3

- **場所**：`warshall-floyd.js` 248〜255 行（ijk の caption）
- **問題**：式は `d[0][1] = min(5, ∞ + 1, 1 + ∞)` で k = 2, 3 だけを並べ、caption は「k を内側で回して…と比べる。候補は k = 2 で…」とだけ言う。kij の段の始まりは「k 行目と k 列目は変わらない」と飛ばす理由を言うが、ijk にはそれに当たる文がなく、読者は k = 0, 1 がどこへ行ったか迷う。確認問題の答えの文章も k = 2, 3 だけを述べるので、本文と食い違いはない
- **根拠**：`vwf/cap.mjs` の出力の ijk の 2 番目。実際の i, j, k のループでは k = i, j の候補は d[i][i] + d[i][j] = d[i][j] などで値を変えない（独立の突き合わせで対角が 0 のままであることも確かめた）
- **直し方**：ijk の最初のマスの caption（または初期状態の caption）に「k = i と k = j の候補は d[i][j] そのものなので除く」の 1 文を足す
