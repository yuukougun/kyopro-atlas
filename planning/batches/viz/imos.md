# 動く図 imos（1 次元のいもす法）

## 作ったもの

- `overrides/assets/js/viz/imos.js`：1 次元のいもす法の動く図。見本（binary-search・lazy-segment-tree）と同じ形で、`states(config)` は DOM を使わない純粋な関数、`render(svg, state, config, h)` が描く。`viewBox` は列の数と操作の数だけで決まり、ステップによらない
- `tests/viz/imos.test.mjs`：試験 6 件
- `docs/basics/imos.md`：#imos-1d の図（imos-1d.svg）と div の間に、動く図の案内の 1 段落を足した（「同じ例で D に印を 1 か所ずつ書き込み、左から累積して A を 1 マスずつ埋める。cur はカーソルまでの D の和」）。div の config は執筆者のまま

## config

`{"n": 8, "ops": [{"l": 1, "r": 5, "x": 1}, {"l": 3, "r": 7, "x": 2}]}`（本文と同じ。変えていない）

- `n`：列 A の長さ（1〜12）。D は長さ n + 1 で、D[n] は番兵（点線の枠）
- `ops`：1〜4 個の `{l, r, x}`。半開区間 [l, r)、0 ≤ l < r ≤ n、x は 0 でない整数で絶対値 99 以下
- 誤りは見本と同じく Error を投げ、viz.js が「図を表示できなかった：…」と出す

## ステップ（本文の例で 14 状態）

1. init：D をすべて 0、A は「?」の枠
2. 操作ごとに plus（D[l] += x：l から先の A がすべて x 増える）と minus（D[r] −= x：r から先は打ち消して元に戻る）。いまの操作の帯を太く強調し、ほかは細い灰色。同じ位置に前の印があれば「前の印と合わせて D[k] = …」、r = N なら「番兵に書く」と caption に書く
3. sweep：i = 0〜N − 1 で「cur = 前の cur + D[i] = …。A[i] = cur = D[0] + … + D[i] = …」。累積に入れ終えた D を塗り、A の下に三角の印と「cur = …」
4. done：A を答えの色で塗り、「A = 0, 1, 1, 3, 3, 2, 2, 0。番兵の D[8] は累積に使わない」

色だけに頼らないよう、注目の枠は太い線、番兵は点線、未計算は「?」、累積の位置は三角と文字、帯は太さと文字で区別した。

## 確かめたこと

- `node --test tests/viz/imos.test.mjs`：6 件すべて通る。本文の例で D = [0, +1, 0, +2, 0, −1, 0, −2, 0]、A = [0, 1, 1, 3, 3, 2, 2, 0]（本文の図の説明と一致）。端の場合（l = 0、r = N で番兵に書く、N = 1、接する区間で印が打ち消して 0、負の x、同じ区間のくり返し、1 要素の区間）、ランダム 3000 件で素朴に塗った答えと一致、各ステップの D・cur・A の不変条件、入力を書き換えない、誤った config 16 通りで Error、viewBox の大きさ
- `python3 tools/check_pages.py`：エラー 0・警告 0
- `npx textlint docs/basics/imos.md`：エラー 0（警告 43 は以前からのもの。足した 68 行目には警告なし）
- ブラウザ：`uv run mkdocs build -d <scratchpad>/site-imos` でビルドし、chrome-headless-shell（日本語は font_env と同じ方法）で http 経由で開いた。「次へ」ボタンを 0・2・4・5・9・13 回押した状態を幅 360 と 900 で撮り、図が描かれ、ステップが進み（カウンタ 1/14〜14/14、caption も対応）、最後で「次へ」「最後へ」が無効になることを目で確かめた。幅 360 でも枠の数字と帯の文字は読める（viewBox 366×190、表示で約 0.84 倍）

## 未解決の点

- 2 次元（imos-2d）は作っていない。執筆者の提案どおり別の名前（`imos-2d`、config は `h`・`w`・`rects`）にするのがよいと考えるが、メインで決めてほしい
- 幅 360 では添字の数字（12px の is-sub）が約 10px になる。見本の lazy-segment-tree と同じ程度なので、そのままにした
- file:// で開くと viz.js が動かない（KaTeX も動かない）ため、確認は http サーバーを立てて行った。サイトの公開には影響しない

## 検証の指摘への対応（verify-imos.md）

直すべきは 0 件。直すとよい 5 件のうち 1〜4 を直し、5 はメインの判断に回した。

- 指摘 1（値の桁あふれ）：直した。`validate` で印を書き込む途中の D と累積した A を計算し、絶対値 99 を超えたら「D と A の値が絶対値 99 を超えない操作にする」の Error を投げる。最後の D だけでなく途中の D も見る（途中で一時的に大きくなる印も枠に描かれるため）。試験に、`[0, 2) に −99` を 4 回・A が 120 になる・D[2] が −120 になる の 3 件と、打ち消して 0 になる範囲内の 1 件を足した
- 指摘 2（r = N の caption）：直した。r = N のときは「r = N なので、A の外にある番兵の D[N] に書く（累積には入らないので、打ち消す相手はない）。」だけを出し、「位置 N から先は打ち消して元に戻る」は出さない。試験で確かめる
- 指摘 3（項の少ない和の「…」）：直した。i = 0 は「D[0]」、i = 1 は「D[0] + D[1]」、i ≥ 2 は「D[0] + … + D[i]」。試験で確かめる
- 指摘 4（番兵に書くステップの強調）：直した。注目している番兵には `is-sentinel` を付けず `is-yes is-focus` を付け、点線は `stroke-dasharray="4 3"` の属性で描く。kp.css は変えていない。偽の `h` で render を呼ぶ試験を 1 件足した（試験は 7 件）
- 指摘 5（catalog の visual の「2 次元は 2 段」）：採らなかった（この担当では直せない）。catalog は凍結されており、2 次元の動く図を作るか静的な図で足りるとするかはメインが決める。案は上の「未解決の点」と同じ（作るなら別の名前 `imos-2d`）

確かめたこと（直した後）：`node --test tests/viz/imos.test.mjs` 7 件すべて通る。`python3 tools/check_pages.py` エラー 0・警告 0。`npx textlint docs/basics/imos.md` エラー 0（警告 43 は以前からのもの。ページは変えていない）。ブラウザ：作業用の場所に `mkdocs build -d` でビルドし、chrome-headless-shell（日本語は font_env と同じ方法）で幅 900（ライト）・360（ダーク）の本文の例を 14 状態すべて送り、caption（i = 0・1 の和の書き方を含む）とカウンタ 1/14〜14/14 が進むこと、JS の例外が 0、幅 360 ではみ出しがないことを確かめた。r = N の場合はビルド結果のコピーで config を `{"n": 4, "ops": [[0, 4) に +3]}` に替えたページを開き、番兵 D[4] がアクセント色の太い点線と薄い塗りで強調され、caption が新しい文になることを目で確かめた
