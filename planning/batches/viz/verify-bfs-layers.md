## 指摘

### 1. 直すとよい｜距離の文字が同じ列の隣の頂点の文字と重なる config がある｜G3

- **場所**：`bfs-layers.js` 242〜265 行 `labelDir` と 342〜343 行（`off = R + 14`）
- **問題**：向きは「その頂点の辺から離れた向き」だけで選び、同じ列の上下の頂点の文字を見ない。列の頂点の間隔は SP = 64 で、上下の文字は中心から 30 なので、上の頂点が下に、下の頂点が上に文字を置くと 4 px しか離れず重なる。例：`{"n":5,"edges":[[0,3],[1,2]],"source":0}` は届かない列に 1・2・4 が並び、2 は辺 1-2 を避けて下に、4 は辺がないので上に置いて重なる。星形 `{"n":8,"edges":[[0,1],[0,2],…,[0,7],[1,7],[2,6]]}` の 2/10 では「−1→1」が 1 と 2・2 と 3 の間などに並び、どの頂点の距離か読み取りにくい（幅 390 の画像で目視）
- **根拠**：作業用の場所で乱数の 5000 件を全状態描き、距離の文字の箱（1 文字 8 px・高さ 14 px と見積もる）が互いに交わる config を数えると 315 件（約 6%）。本文の config は 0 件
- **直し方**：`labelDir` の候補ごとに、同じ列で 1 つ上（下）の頂点がある向きに罰を足す（上の頂点がすでに下に置くなら上を避ける、など、列の上から順に決める）。または列の中の頂点の間隔 SP を文字 2 つ分（例：72 以上）に広げる。届かない列は辺が少ないので、上下を交互に決めるだけでも足りる

### 2. 直すとよい｜右端の列の弧が枠から少しはみ出す｜G3

- **場所**：`bfs-layers.js` 312〜317 行（同じ列で間に頂点がある辺を右へふくらませる弧）
- **問題**：右端の列（x = 384）で行の差が 4 の弧は、ふくらみ 34 × 3.5 = 119 で、曲線の一番右が x = 443.5 になり、viewBox の幅 440 を超えて端が切れる
- **根拠**：乱数 30000 件で 8 件。例：`{"n":8,"edges":[[0,1],[1,2],[3,4],[3,7],[4,5],[5,6]],"source":0}`（届かない列に 3〜7、辺 3-7）。幅 390 の画像では弧は収まって見えるが、計算上は線の太さを含めて 4〜5 px 外に出る
- **直し方**：右端の列ではふくらみを左へ向けるか、`bulge` を `W - 4 - x` の 2 倍で頭打ちにする（2 次ベジエの頂点は制御点までの半分なので）

### 3. 直すとよい｜このステップで見た親への辺と、前からの親への辺が色だけで区別される｜G4

- **場所**：`bfs-layers.js` 304〜307 行と 397〜399 行（凡例）
- **問題**：見た辺が親への辺でもあるとき（今 push した頂点への辺や、取り出した頂点の親への辺）、太い実線のまま class だけ `is-focus` になり、前からの太い辺（`is-answer`）とは色の濃さしか違わない（幅 360 の 3/8 で s-a と s-b、幅 1000 の 6/8 で b-d とほかの太い辺。ダークでは青どうし）。凡例の「今見た辺」は破線だけを見せるので、太い実線の「今見た辺」が凡例にない
- **根拠**：幅 360 ライト・ダークと幅 1000 ライトの画像で目視
- **直し方**：今見た辺は太さ・実線か破線を親への辺かどうかで決めたまま、線種でも分かる印を足す（例：今見た辺に細い白の破線を重ねる、または今見た辺の取り出した頂点の側に小さな矢じりを付ける）。少なくとも凡例を「今見た辺（太いものは親への辺）」のようにして、太い強調色の線が何かを書く

### 4. 直すとよい｜横に置いた距離の文字が取り出しの輪に接する｜G3

- **場所**：`bfs-layers.js` 343 行 `var off = dir[1] !== 0 ? R + 14 : R + 7;`
- **問題**：左右に置くときの文字の端は中心から R + 7 = 23 で、取り出した頂点の輪（半径 R + 5 = 21、線の太さ込みで 22 程度）とほぼ接する。星形の 2/10 で頂点 0 の左の「0」が輪に触れて見える。本文の config では横に置く頂点がないので出ない
- **根拠**：幅 390 の画像で目視（dijkstra の検証の指摘 2 と同じ形）
- **直し方**：横の `off` を R + 10 程度にする（枠の端の判定 253 行の `R + 7 + 40` も合わせる）

### 5. 直すとよい｜labels を省いたときの caption が数と頂点の名前で紛らわしい｜G1（caption）

- **場所**：`bfs-layers.js` 55 行（名前を `String(k)` にする）と caption を作る 157〜178 行
- **問題**：labels を省くと頂点の名前が 0〜n−1 になり、caption が「先頭の 1（距離 1）を取り出す。隣の 0 はもう距離が書いてあるので飛ばす。2 は −1 なので、見つけたこの場で距離 2 と親 1 を書き」「距離は 0: 0、1: 1、2: 2、3: −1」のように、頂点の番号と距離の数が並んで読みにくい。本文の config は labels を使うので出ない
- **根拠**：ページの写しに n = 8 の config を入れて caption を読んだ
- **直し方**：labels を省いたときは caption の中だけ「頂点 1」と書く（`names` と `L[u]` を通す所で名前が数なら「頂点 」を前に付ける）か、コメントの「本文での書き方」に labels を書くことを勧める 1 行を足す
