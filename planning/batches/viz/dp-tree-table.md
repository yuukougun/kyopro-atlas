# 動く図 dp-tree-table の報告

## 作ったもの

- `overrides/assets/js/viz/dp-tree-table.js`：足場の例（Frog 1）で、全探索の木と DP の表を並べる図。上に木、下に表を置く（横に並べると 360px で文字が小さくなりすぎるため）。3 つの部分を順に見せる
  - 前半（tree）：足場 N−1 から逆向きに分岐する素朴な再帰 f(i) → f(i−1), f(i−2) の木（N = 6 で 20 節・葉 8）。帰りがけ順（f(i−1) を先に呼ぶ）に進める。足場 i の呼び出しが初めて返ったら、節を塗り、表の dp[i] へ実線を引いて値を書く。caption に `dp[i] = min(dp[i−1] + |h_i − h_{i−1}|, dp[i−2] + |h_i − h_{i−2}|)` の数を入れた式を出す。同じ足場の呼び出しがもう一度現れたら、その部分木をまとめて 1 ステップで灰色・破線の枠にし、表の dp[i] へ破線を引く（「ここから k 回の呼び出しをやり直すが、値は表と同じ」）。見出しに「呼び出し k / 20」を出す
  - 後半 1（pull）：同じ表で dp[0] = 0 から、dp[i] へ i−1・i−2 から実線の矢印を集めて 1 マスずつ決める。いま使う辺は太く、コスト（+6 など）を弧の上に書く。使い終えた辺は細い実線、まだ使っていない辺は薄い点線。caption で「使った辺は k / 9 本」と数える
  - 後半 2（push）：dp[0] = 0・ほかは ∞ から、確定した dp[i] から i+1・i+2 へ破線の矢印を出す。送り先の更新を表の下の「更新」の行に「8→6」「∞→3」と書き、caption に `min(8, 1 + 5) = 6` の形で出す。最後に、どちらの形も各辺を 1 回ずつ使い同じ表になることを書く
  - 仕様からの変更：執筆者の仕様は「木の節を 1 つずつ」だったが、呼び直しの部分木は 1 ステップにまとめた（初めて返る 6 ステップと呼び直し 4 ステップが交互に来る）。20 ステップに分けると灰色の節が 1 つずつ増えるだけの手順が長く続き、「部分木ごと同じ計算をやり直す」ことが見えにくいため。呼び出しの回数は見出しと caption で数える
  - 色だけに頼らない工夫：木の節は 未計算＝白抜き・計算した＝塗り＋太字・呼び直し＝灰色＋破線の枠。表を書く線は実線、引く線は破線。表のマスは 確定＝実線の枠、未確定＝破線の枠と「?」「∞」、答え＝塗りつぶし。貰う形は実線・配る形は破線で、見出しにも言葉で書く。使っていない辺は点線
  - 狭い幅：viewBox は本文の config で 408 × 365（どのステップでも同じ）。360px の画面で約 0.76 倍。補助の文字は 14px にした（expected-value-dp と同じ）
- `tests/viz/dp-tree-table.test.mjs`：9 件
  - 本文の config で、表 (0, 7, 1, 6, 3, 6)・答え 6・呼び出し 20 回・辺 9 本。木の手順が dp[0]・dp[1]・(0 の呼び直し)・dp[2]・(1)・dp[3]・(2)・dp[4]・(3)・dp[5] の順で、呼び出しの累計が 1, 2, 3, 4, 6, 7, 11, 12, 19, 20。呼び直しの部分木の大きさが C(i)。caption の比べ方（min(7 + 6, 0 + 1) = 1 など）が本文と合う。配る形で dp[3] が 8 → 6、dp[4] が ∞ → 3（push-pull.svg と同じ）、dp[5] が 10 → 6
  - 貰う形と配る形で使う辺がどちらも 2N − 3 本で重複がなく、同じ集合（N = 2〜6）
  - 配る形で辺を使うとき、遷移元の値は確定している
  - ランダムな高さ 500 通り（N = 2〜6）で、3 つの部分の最後の表が跳び方の全列挙の最小と一致し、呼び出しの総数が再帰の回数と一致する。確定したマスの値はいつも正しい
  - 端の場合：N = 2（呼び直しなし・辺 1 本、まとめの caption も変わる）、N = 3、高さがすべて同じ、parts を絞る（push だけなら「どちらの形も」と書かない）
  - 同じ入力から同じ列ができ、入力を書き換えない。誤った config 13 通りで Error。viewBox。render を偽の h で全ステップ呼び、座標に NaN が出ない
- `docs/dp/dp-basics.md`：図の前の文を「上に全探索の木、下に DP の表を並べたもの」にし、木の数字が足場の番号であることと、呼び直しを破線の枠で灰色にすることを足した。図の後の段落に、後半で同じ表を貰う形（実線）と配る形（破線）で埋め、どちらも 9 本の遷移を 1 回ずつ使って同じ表になることと、#dp-push-pull へのリンクを足した

## config

```
<div class="kp-viz" data-viz="dp-tree-table" data-config='{"h": [8, 1, 7, 2, 9, 6]}'></div>
```

- `h`：足場の高さ（2〜6 個の 0〜99 の整数）。N = 7 では呼び出し 33 回・葉 13 個になり、狭い幅に収まらないので 6 までにした
- `parts`：省略可。`"tree"`・`"pull"`・`"push"` から選ぶ配列（既定は 3 つ。並びはいつもこの順）。本文では使っていない
- 本文の config は執筆者の改訂（`{"h": [8, 1, 7, 2, 9, 6]}`）のまま変えていない。状態は 24（tree 12・pull 6・push 6）

## 未解決の点・提案

- 線の色は expected-value-dp と同じく、kp.css に線用の class がないので `style` に Material の CSS 変数を直接書いた（その報告の提案 `.kp-v-edge` などがあれば置き換えられる）
- 呼び直しの破線は、木の右側の節から表のマスへ斜めに引くので、途中の灰色の節の上を通る（図 10/24 の足場 3 など）。読めるが、気になるなら線を節の下から折れ線で引く
- 後半（pull・push）では木を描かないので、表の上に余白がある（viewBox をステップで変えないため）。弧を高くして余白を少し使った
- catalog の visual は「配ると貰うを色違いで」だが、色に加えて実線と破線で区別した（静的な図 push-pull.svg と同じ区別）

## 検証の指摘への対応（verify-dp-tree-table.md）

- 1（弧のコストの文字に別の弧が重なる）：直した。弧の上のコストの文字に背景色の縁取り（`paint-order:stroke`）を付けた。ステップ 15・17・22 で、交わる太い弧の上でも数字が読めることを幅 360（ライト・ダーク）・800 のスクリーンショットで確かめた
- 2（「呼び出し k / 20」が返った呼び出しの数）：直した。見出しを「素朴な再帰の木（返った呼び出し k / 20）」に、caption を「返った呼び出しはここまで k 回」にした（本文の caption の「初めて返る」と言葉を揃えた）。見出しが 360px で収まるよう「と dp の表」は外した（表には「dp」の行の名前がある）。試験に、caption が calls と同じ数を「返った呼び出しはここまで k 回」と書くことの照合を足した
- 3（本文の「全探索の木」と図の木の向き）：直した。図の前の文に「図の木は足場 5 から『どこから来たか』を逆にたどる向きなので、足場 3 の節は $5 \to 4 \to 3$ と $5 \to 3$ の 2 か所に現れる」を足した。l.56 の前向きの例は状態の説明として残した
- 4（呼び直しの破線が途中の節の近くを通る）：採らなかった。折れ線にすると、足場 3 の節の真下にはその部分木があるので、下ろした線が呼び直した節の上を通り、かえって読みにくい。木の間の隙間を通す経路は幅 360 では節の間隔が狭く取れない。検証でも「誤読にはつながらない」とされ、caption が言葉で補っており、線の先の矢じりと太枠のマスでどのマスを引くかは分かるため、いまの直線のままにした
