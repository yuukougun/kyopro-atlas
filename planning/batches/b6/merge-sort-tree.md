## 候補

### abc379_f（新規。台帳になし）

- 問題ID：abc379_f
- 題名：F. Buildings 2
- difficulty：1659（青）
- 役割：practice
- 要約：高さが相異なる N 棟のビルが一列に並び、l < r の組の質問ごとに、r より東にあるビルのうち l と r の両方から見える（間のビルがすべてそれより低い）ものの数を答える。
- 方針の要点：r より東では l から見えるビルの集合は r から見えるビルの集合に含まれるので、ビル j の左で最も近い高いビルの位置を p(j) とすると答えは「区間 (r, N] の中で p(j) ≤ l の j の個数」になり、列 p にマージソート木を作れば 1 回 O(log^2 N) で答えられる。
- 裏付け：
    - https://www.cnblogs.com/RomanLin/p/18677191 （問題の設定（高さは 1〜N の相異なる値、1 ≤ l < r ≤ N）と、「l から見えるものは r から見えるものの部分集合なので [r+1, n] の中だけ考えればよい」という観察を確かめた。解き方はクエリを l の順に並べ、右から単調スタックを保って二分探索で r より右の個数を数えるオフラインの方法）
    - https://qiita.com/yuu_kyopro/items/51ad67c3c980bf91c5a6 （マージソート木の「使える問題」に挙げている。説明はない）
- p(j) ≤ l という形への言い換えは執筆者の判断（j が l から見えるのは、l と j の間にある j より高いビルがないとき、つまり p(j) ≤ l のときである）
- 台帳への追加の提案：pages に {id: merge-sort-tree, role: practice}。オフラインの単調スタック（monotonic-stack）や先読みの BIT でも解けるので、本文では「先読みすれば offline-queries でも解ける」と添えるとよい

### abc405_f（新規。台帳になし）

- 問題ID：abc405_f
- 題名：F. Chord Crossing
- difficulty：1588（水。青の帯の下端に近い）
- 役割：practice
- 要約：円周上の 2N 個の点の間に互いに交わらない M 本の弦が引かれていて、質問ごとに 2 点を結ぶ弦が与えられ、既存の弦のうちそれと交わるものの本数を答える。
- 方針の要点：円を 1 か所で切って点を一列に並べると、答えは「質問の区間の中に端点がちょうど 1 つある弦の本数」になるので、各端点に相手の端点の位置を書いた列にマージソート木を作り、区間 (C, D) の中で相手が C 未満か D より大きいものの個数を数える。
- 裏付け：
    - https://merom686.hatenablog.com/entry/2025/05/11/021302 （線分の番号を一列に並べると 1〜M が 2 個ずつ入った列になり、「クエリの区間内にちょうど 1 個入っている数が何個あるかが答え」と書いている。解き方は括弧列として見てセグメント木に乗せる別の方法）
    - https://qiita.com/yuu_kyopro/items/51ad67c3c980bf91c5a6 （マージソート木の「使える問題」に挙げている。記事中の題名は「ABC405-E Chord Crossing」だが、リンク先は abc405_f で、題名 Chord Crossing は ap.py の abc405_f と一致する）
- 「区間にちょうど 1 個ある数」を「相手の端点が区間の外にある端点」と読み替え、相手の位置の列でしきい値の個数を数える形は執筆者の判断
- 制約（N・M・Q の上限）は第三者の解説で確かめられなかった。w.atwiki.jp の解法メモ（https://w.atwiki.jp/sport_programming/pages/80.html 、check_noai では noai・noimageai の指定なし、2026-10-22）は WebFetch で HTTP 403 になり読めなかった
- 台帳への追加の提案：pages に {id: merge-sort-tree, role: practice}

### abc174_f（台帳にあり。merge-sort-tree の役割はなし）

- 問題ID：abc174_f
- 題名：F. Range Set Query
- difficulty：1495（水）
- 役割：practice
- 要約：長さ N の列について、区間 [l, r] に含まれる値の種類数を Q 個の質問に答える。
- 方針の要点：各位置 i で同じ値が直前に出た位置を prev[i]（なければ 0）とすると、種類数は「区間 [l, r] の中で prev[i] < l の i の個数」に等しいので、列 prev にマージソート木を作ればオンラインに 1 回 O(log^2 N) で答えられる。
- 裏付け：
    - https://github.com/firiexp/library/issues/158 （ABC174 F を挙げ、「区間内で prev[i] < l の要素を数える変換」で種類数を求め、prev の上に Wavelet Matrix を作って数えると書いている。マージソート木には触れていない）
    - https://ikatakos.com/pot/programming_algorithm/contest_history/atcoder/2020/0802_abc174 （問題の設定と、標準の解き方がクエリを R の順に並べて最後の出現位置だけに 1 を立てる BIT であることを確かめた。オンラインの解き方には触れていない）
- 台帳の追加の提案：pages に {id: merge-sort-tree, role: practice} を足す（今は offline-queries の example だけ）。offline-queries の例題と同じ問題なので、本文では「先読みできないときの解き方」として、同じ prev の言い換えをマージソート木で数える対比にすると役割が重ならない

### abc202_e（台帳にあり、本文になし）

- 問題ID：abc202_e
- 題名：E. Count Descendants
- difficulty：1638（青）
- 役割：practice
- 要約：根付き木で、頂点 U を祖先に持つ（U 自身を含む）深さ D の頂点の数を Q 個の質問に答える。
- 方針の要点：行きがけ順で頂点を並べると U の部分木は区間 [in[U], out[U]) になるので、各位置に深さを書いた列にマージソート木を作り、区間の中で「D 以下の個数」から「D − 1 以下の個数」を引けば答えになる。
- 裏付け：
    - https://blog.hamayanhamayan.com/entry/2021/05/22/225525 （オイラーツアーで「ある区間 [L, R) について、値が D[i] である要素がいくつあるか」に言い換えると書いている。解き方は深さの順に頂点を BIT に足すオフラインの方法）
    - https://qiita.com/2yuu/items/898b95864905dcbc8e7d （深さごとに行きがけ順の番号を並べ、lower_bound 2 回の差で数える方法）
- マージソート木で数えるのは執筆者の判断。深さごとの列に二分探索するほうが簡単なので、マージソート木はやや大げさな道具になる。練習に置くなら「区間の値がちょうど D の個数は 2 回の数え上げの差」という使い方の練習として置く
