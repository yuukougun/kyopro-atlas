## 指摘

### 1. 直すべき｜事実・記法（F7）｜#basis（141 行）

- 問題：「XOR を**繰り返しのない**足し算とみて」とある。「繰り上がり」の誤記である
- 根拠：同じページの #properties では「繰り上がりのない足し算」と書き、表の性質の列の説明もそうである。bit-operations:179 も「繰り上がりのない足し算」。「繰り返しのない足し算」では意味が通らず、読者が別の概念と取り違える
- 直し方：「XOR を繰り上がりのない足し算（mod 2 のベクトルの和）とみて」にする

### 2. 直すとよい｜分かりやすさ（U3）｜#overview（86 行）

- 問題：「『性質』の列は、上の 2 つの性質のどちらを主に使うかを示す」と書いているのに、列の値は 4 種類（独立・打消・線形・上位）ある。線形・上位は #properties では「2 つから出る 2 つの見方」として出てきたので、「2 つのどちらか」と言うと数が合わない
- 根拠：86 行と、#properties の 60 行「次の 2 つと、そこから出る 2 つの見方」
- 直し方：「『性質』の列は、上の 2 つの性質と 2 つの見方のどれを主に使うかを示す」にする

### 3. 直すとよい｜分かりやすさ（U3）｜#choose-x 3 つ目（136 行）

- 問題：「Binary Trie の各ノードに部分木の中の最小を持たせる」は、部分木の中の**要素の**最小値と読める。持たせるのは「部分木の中の 2 要素の XOR の最小値」である
- 根拠：ds/binary-trie.md の例題 ABC308 G の方針（「部分木の中の 2 要素の XOR の最小値」）
- 直し方：「各ノードに、その部分木の中の 2 要素の XOR の最小値を持たせ、追加・削除のたびに根まで作り直す」にする

### 4. 直すとよい｜分かりやすさ（U4）・事実の言い過ぎ（F2）｜#path-xor（152 行）

- 問題：「閉路の値をすべて XOR 基底に入れ」とある。閉路は指数個ありうるので、文字どおりには実装できない。入れるのは、全域木に入らない辺 $(a, b, w)$ ごとの $d(a) \oplus d(b) \oplus w$（$M - N + 1$ 個）である
- 根拠：math/xor-basis.md#xor-walk 160 行「閉路の値は、木に入らない辺 $(a, b, w)$ ごとに $d(a) \oplus d(b) \oplus w$ と決める」
- 直し方：「そこで全域木に入らない辺 $(a, b, w)$ ごとに閉路の値 $d(a) \oplus d(b) \oplus w$ を XOR 基底に入れ」にする（ほかの閉路の値はこれらの XOR で作れる、と一言添えてもよい）

### 5. 直すとよい｜事実の言い方（F2）｜#range-xor 3 つ目（120 行）

- 問題：「$0 \oplus 1 \oplus \dots \oplus n$ は $n \bmod 4$ だけから決まる」は、値そのものが $n \bmod 4$ だけで決まる（4 通りしかない）と読める。実際は $n$・$1$・$n + 1$・$0$ で、$n \bmod 4$ が決めるのは式の形である
- 根拠：手元で $n = 0..11$ を計算すると 0,1,3,0,4,1,7,0,8,1,11,0。前提のページ bit-operations:90 の表のとおり
- 直し方：「$n \bmod 4$ で場合分けした式（$n$・$1$・$n + 1$・$0$）で決まる」にする。前提のページ bit-operations:90 の「$n \bmod 4$ だけで次のように決まる」も同じ言い方なので、あわせて直すかはメインが決める

### 6. 直すとよい｜図（G5）｜column-parity.svg の破線の括弧

- 問題：「同じ 3 が 2 回で消える」の破線の括弧は 2 行目の 3 から 4 行目の 3 まで縦に伸びていて、間にある 5 の行も囲んでいるように見える。3・5・3 の 3 行が消えると読み違えうる
- 根拠：render_svg の 360・720 の幅の PNG を目で見た。括弧は y=88〜148 の 1 本で、端の 2 か所だけに横線がある
- 直し方：2 つの 3 の行の左の「値」の列に同じ印（丸で囲む、同じ色の枠など）を付け、括弧はやめる。または括弧の端に矢印を付けて、5 の行を指していないことが分かるようにする

### 7. 直すとよい｜分かりやすさ（U7）｜ほかのページの練習・力試しの解き方を節の本文で書いている

- 問題：#xor-equals-sum の 166 行は「和を 1 つだけ持ち、右端を伸ばす前に和と新しい要素に共通の bit がないかを確かめる。代表は…力試しの ARC098 D」と、力試しの実装の要点まで折りたたみの外で書いている。#meet-in-the-middle の 172 行（ABC271 F：前半と後半の XOR が等しい組を数え、対角線のマスは一方にだけ入れる）も、練習の解き方をそのまま書いている。clarity.md U7 の「本文が練習の問題を指して、その解き方を折りたたみの外で書いてしまう」に当たる
- 根拠：two-pointers の 209 行・meet-in-the-middle の練習の方針は折りたたみの中にある。pattern のページは行の手法を書くのが本体なので、手法の名前と性質まで書くのはよいが、実装の決め手まで書くと持ち主のページで練習として解く意味が薄れる
- 直し方：166 行は「区間が条件を満たす間は XOR と和が等しいことを使うと、持つ値を減らせる」程度にとどめ、詳細は持ち主のページに任せる。172 行の「対角線のマスの値は一方にだけ入れる」は落とし穴として残してよいが、「代表は…ABC271 F」と同じ段落に並べず、手法一般の注意として書く。pattern のページで代表の問題をどこまで書いてよいかは、執筆者の手引きへの提案（表に問題の列を置かない書き方）とあわせてメインが決める

### 8. 直すとよい｜手引きとの一致（§4 pattern）｜#overview の表

- 問題：手引き §4 の pattern は「問題は行の代表だけで、表には label を文字で書く」としているが、表に代表の問題の列がない。代表は各節の本文に散らばっていて、表だけを引いた読者は問題が分からない
- 根拠：style-guide.md 89 行、見本 bracket-sequence の表（4 列目が「代表の問題」）。執筆者も報告の「手引きへの提案」で迷った点として挙げている
- 直し方：メインが決める。見本にそろえるなら、「ページ」の列の後に「代表の問題」の列を足して label を文字で書く（例：ABC147 D、ABC185 F、ABC201 E、ABC281 F・ABC308 G、ABC283 G・ABC236 F、ABC451 G、ABC117 D・ABC129 E、ARC098 D、ABC271 F、A33・A34・ABC368 F、ABC250 E・ABC367 F、ABC212 H、ABC150 F）。列が 5 つになるので、「性質」の列を落とすか、表の下に回す

### 9. 直すとよい｜分かりやすさ（U7）｜#abc171_e の方針

- 問題：方針の段落が、解法の詳細の 3 つの箇条とほぼ同じ内容（N−1 回現れて奇数なので 1 回分残る → $T \oplus A_i$）を言い切っていて、折りたたみの中に新しい情報がほとんどない。clarity.md U7「方針が答えそのもの」に近い
- 根拠：211 行と 222〜224 行
- 直し方：方針は「すべての $A_i$ を XOR すると、各人の値は何回ずつ現れるかを数える。N が偶数であることがどこで効くかを考える」程度にし、$T \oplus A_i$ の式と奇偶の議論は解法の詳細に任せる
