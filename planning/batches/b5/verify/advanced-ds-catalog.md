## 指摘

### 1. 直すべき｜事実（F2・F9）｜#table の後の「K-D tree」の段落（63 行）と参考（168 行）

- **問題**：本文は「最近点の探索は枝刈りによる経験的な速さで、最悪の上限はない」と書くが、表（49 行）は「最近点は最悪 $O(N)$」と書いていて食い違う。全点を見れば終わるので $O(N)$ という上限はある。参考の行も「最近点の探索に最悪の上限がないこと」と出典の内容を取り違えている
- **根拠**：OI Wiki「K-D Tree」は「単次查询最近点的时间复杂度最坏还是 $O(n)$ 的」と書く（最悪でも $O(n)$。部分線形の保証がないという意味）
- **直し方**：本文を「最近点の探索は最悪 $O(N)$ で、それより速い保証はない。速いのは枝刈りが効く経験的な場合である」のように直す。参考の行も「最近点の探索が最悪 $O(N)$ であること」に直す

### 2. 直すべき｜事実（F2）｜#table の後の「析合木」の段落（67 行）

- **問題**：析点の定義が「2 つ以上の連続する子の並びがどれも連続段にならない頂点」で、子の並び全体を除いていない。子の並び全体の和はその頂点の区間で、連続段である。このため、字面どおりなら析点は 1 つも存在しない
- **根拠**：OI Wiki「析合树」は、析点の子の並びの真の部分区間（長さ 2 以上）が連続段にならないことを述べている（全体の和は本原段で連続段）。Library Checker の task.md では prime node を「linear node でない頂点」と定義する
- **直し方**：「子の並び全体を除き、2 つ以上の連続する子の並びがどれも連続段にならない頂点」とする。または「合点でない頂点」と書き、性質として添える

### 3. 直すべき｜事実（F2）・分かりやすさ（U4）｜#table の後の「Kinetic Segment Tree」の段落（69 行）

- **問題**：「各ノードに、今の $t$ で勝っている子と、勝ち負けが入れ替わる次の時刻を持たせる」とある。これでは、そのノード自身の 2 つの子が入れ替わる時刻と読める。しかし「入れ替わりの時刻を過ぎたノードだけを降りて」作り直すには、部分木の中で次に入れ替わりが起きる時刻（部分木の最小値）が要る。ノードごとの値では、降りるべき部分木が分からない
- **根拠**：koosaga「Segment Tree Beats와 Kinetic Segment Tree」は melt[v] を「v の部分木にあるすべての insec の最小値」と定義している
- **直し方**：「部分木の中で次に勝ち負けが入れ替わる時刻（各ノードの入れ替わりの時刻の、部分木での最小値）」と書く

### 4. 直すとよい｜事実（F1）｜表の K-D tree の行（49 行）と 63 行

- **問題**：「長方形に入るものの探索」に対して「1 回 $O(\sqrt{N})$」とある。これは各ノードに集約（和・個数）を持たせて答える場合の値である。入る点をすべて列挙するなら、列挙する個数 $K$ の分が加わって $O(\sqrt{N} + K)$ になる
- **根拠**：OI Wiki の $O(\sqrt{n})$ は $T(n) = 2T(n/4) + O(1)$ からの値で、例は和を求める質問。列挙の分は数えていない
- **直し方**：表を「長方形の集約は 1 回 $O(\sqrt{N})$（列挙なら $+K$）」とする

### 5. 直すとよい｜分かりやすさ（U3）｜「2 次元セグ木と 2 次元 BIT の違い」（61 行）

- **問題**：「更新される点を先読みして各ノードの中を座標圧縮すると、メモリが $O(N \log N)$」の直後に「先読みできない（オンライン強制）ときは…この入れ子が残る手」と続く。読者は、先読みが要る圧縮版をオンラインでも使えると読みかねない。オンラインで座標が大きいときは、内側を動的セグ木にする（メモリ 1 点につき $O(\log H \log W)$ ほど）など、別の形になる
- **直し方**：「先読みできないときは、内側を[動的セグメント木](../ds/segment-tree-on-values.md#dynamic-segment-tree)にした入れ子が残る手になる（メモリは更新 1 回につき $O(\log H \log W)$）」のように、どの形の入れ子かを書く。動的セグメント木へのリンクは同じ節の 59 行にもあるので、どちらか 1 か所にする

### 6. 直すとよい｜事実（F1・F3）｜「Fast Set」の段落（65 行）と表（51 行）・参考（175 行）

- **問題**：(a)「どの操作も段ごとに 1 語だけを見るので、段の数回で終わる」とあるが、$x$ 以上の最小を探す操作は、0 でない bit が見つかるまで段を上ってから下りるので、段ごとに最大 2 語を見る（計算量の $O(\log_{64} N)$ は変わらない）。(b) 表は「メモリは $N/64$ 語ほど」、参考は「およそ $N/63$ 語」で値が違う（$N/64 + N/64^2 + \dots \approx N/63$。どちらも「ほど」としてはよい）
- **直し方**：(a)「上りと下りで段ごとに高々 2 語を見るので、段の数の 2 倍ほどで終わる」。(b) どちらかにそろえる（例：表を「$N/64$ 語ほど（全段で $N/63$）」にする）

### 7. 直すとよい｜分かりやすさ（U8）・規則（§14-11）｜#meldable-heap の確認問題（110〜111 行）

- **直し方**：`## 確認問題 {#quiz}` を参考の前に立てて移す。問いは本文の主張を別の場合に当てる形にする。例：「全体への加算があるとき、マージテクのまま（`priority_queue` とヒープごとの足す値で）併合できるか。できるなら、入れ直す要素の値をどう直すか」。答えは「各ヒープに足す値 $d$ を持ち、実際の値を『ヒープの中の値 + $d$』とする。小さい方の要素を入れ直すとき、$d_{\text{小}} - d_{\text{大}}$ を足してから入れる。計算量は $O(N \log^2 N)$ のまま」。ほかに「skew heap を再帰で書くと何が困るか」でもよい

### 9. 直すとよい｜コード（C2・C8）｜snippets/advanced-ds-catalog/leftist-heap.cpp の main（255 行の操作 1）

- **問題**：入力の操作 `1 a b` で $a = b$ のとき、`h.meld(root[a], root[a])` で自分自身と併合した後、`root[b] = 0` でヒープが空になり、要素が消える。乱択の試験は `i != j` で避けているが、入力の説明には $a \ne b$ の制約が書かれていない
- **確かめた結果**：入力 `1 5 / 0 0 3 / 0 0 1 / 1 0 0 / 3 0 / 3 0` の出力は `-1 -1`（期待は `1 3`）
- **直し方**：入力の説明のコメントに「$a \ne b$」と書くか、`if (t == 1 && a != b)` とする。取り込みの範囲（core）は変えなくてよい

### 10. 直すとよい｜出典（F9）｜#meldable-heap の表の pairing heap の行（86 行）

- **問題**：取り出しの「ならし $O(\log N)$」の出典が参考にない（執筆者の未解決の点）。GCC の文書は「push と join は最悪 $O(1)$、pop の最悪は高い」としか書かず、ならしの値は書いていない（今回読んで確認）
- **根拠**：pairing heap の delete-min がならし $O(\log n)$ になることは、Fredman・Sedgewick・Sleator・Tarjan（1986）の結果として知られている
- **直し方**：参考に en.wikipedia.org の「Pairing heap」（付録 B のドメイン）を足し、「取り出しがならし $O(\log N)$ であること」を記す。開いて確かめてから載せる

## 執筆者の未解決の点への見解

- **Kinetic Segment Tree の計算量**：koosaga.com/307 を読んで確かめた。update・query が $O(\log n)$、更新がないときの heaten の合計が $O(n \log^2 n)$（定理 1）、更新があるときが $O(n \log^2 n\,\alpha(n))$（定理 2）。表の書き方は正しい。heaten は全体の時刻を進める操作で、本文の「$t$ が減る方向には戻せない」とも合う。ただし段落の melt の説明は指摘 3 を直す
- **2 次元セグ木の値**：1 回 $O(\log H \log W)$・メモリ $O(HW)$（外 $O(H)$ 個のノードがそれぞれ $O(W)$ の木を持つ）と、先読みして圧縮したときのメモリ $O(N \log N)$（各点は外の木の $O(\log)$ 個のノードに入る）は、数え直して正しい。オンラインのときの形は指摘 5
- **析合木の代わりの手**：正しい。順列の区間 $[l, r]$ では、値が相異なるので 最大値 − 最小値 ≥ r − l が常に成り立ち、等号は値が連続するときに限る。よって「最大値 − 最小値 −（r − l）」の最小値は 0 で、0 の個数が連続段の個数になる。右端を進めながら、最大値・最小値の変化を単調スタックで区間加算として遅延セグ木に入れるのは、$O(N \log N)$ の定番の形である。lazy-segment-tree-patterns に節を足すかはメインの判断でよい
- **pairing heap のならし $O(\log N)$**：指摘 10

## そのほか確かめて問題のなかった点

- セグ木のマージ：両方にあるノードを訪れるたびにノードが 1 つ減るので、併合の合計は作ったノードの数（1 要素 $O(\log C)$）で抑えられる。分割は 1 回 $O(\log C)$
- leftist heap：右の背骨が $r$ 個の節点を持てば節点は $2^r - 1$ 個以上なので、$r \le \lfloor \log_2(n+1) \rfloor$。dist の定義（節点の数、`dist[0] = 0`、葉は 1）とコードが合う。lazy の持ち方（根の key は加算込み、`push` は子の key と lazy に足す）と、本文の 3 つの箇条（空の節点・降ろす順・根の比較）がコードと一致する。再帰の深さは右の背骨の長さの和で $O(\log N)$
- pb_ds：既定のタグは `pairing_heap_tag`、`join` は最悪 $O(1)$ で、`b` は空になる（コード片の `assert` でも確認）
- マージテクの数値：$2 \times 10^5 \times 18^2 = 6.48 \times 10^7$。$64^4 = 16\,777\,216 \approx 1.7 \times 10^7$
- Sqrt Tree：前計算 $O(N \log \log N)$・取得 $O(1)$、演算は結合法則を満たせばよい（cp-algorithms）
- Library Checker の 3 問の説明は task.md と合う
