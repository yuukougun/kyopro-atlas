## 指摘

### 1. 直すべき｜事実（F2）｜#shortest-path-properties（139 行）

- **問題**：「等号が成り立つ辺だけを集めると、最短路をすべて含む DAG になる」に、重みが正という条件がない
- **根拠**：反例 $s \to a$（重み 1）、$a \to b$・$b \to a$（重み 0）。$\mathrm{dist}[a] = \mathrm{dist}[b] = 1$ で、$a \to b$ と $b \to a$ はどちらも等号が成り立ち、閉路ができる。リンク先の shortest-path-dag#build も性質 3 を「重みがすべて正なら閉路はない」と条件付きで書き、見出しにも「重み 0 の辺に注意」とある
- **直し方**：「等号が成り立つ辺だけを集めると、最短路をすべて含むグラフになる。重みがすべて正なら DAG である（[最短路 DAG](…#build)）」のように条件を足す

### 2. 直すべき｜事実（F2）｜#shortest-path-steps（130 行）

- **問題**：「下に進むほど前提条件が強く、速い手法になる」が図と合わない。2 段目の DAG 上の DP は $O(N + M)$ で 3 段目のベルマンフォード法 $O(NM)$ より速く、前提（閉路なし）も 3 段目より強い。いちばん下のダイクストラ法は、1 つ上の BFS・01-BFS より前提が弱く遅い
- **根拠**：図の葉の並び（DAG 上の DP → ベルマンフォード法 → BFS → 01-BFS・ダイクストラ法）と、同じページの表の計算量
- **直し方**：この 1 文を消すか、「負の辺の有無を決めた後は、重みが等しい・0 と 1・非負の順に、前提が弱く遅い手法になる」のように、成り立つ範囲だけを書く

### 3. 直すべき｜事実（F1）｜#strings の表（349 行）

- **問題**：「ワイルドカード・ハミング距離」の計算量を $O((N + M) \log (N + M))$ としているが、ハミング距離（一致数）は文字の種類ごとに畳み込むので $O(\sigma (N + M) \log (N + M))$ である
- **根拠**：リンク先 convolution-ntt#string-matching の本文：「一致する文字の数」を「$O(\sigma N \log N)$（$\sigma$ は文字の種類）で求める」。ワイルドカードの一致判定は畳み込み 3 回で $\sigma$ によらない
- **直し方**：「ワイルドカードは $O((N + M) \log (N + M))$、ハミング距離は文字の種類 $\sigma$ を掛ける」とするか、行を 2 つに分ける

### 4. 直すべき｜事実（F2）｜#range-queries の「BIT とセグメント木」（166 行）

- **問題**：「最小値は接頭辞の最小値までしか求まらない」は、BIT で任意の一点更新のもとで接頭辞の最小値が求まるように読める。実際は、値が小さくなる向きの更新（chmin）だけのときに限る
- **根拠**：fenwick-tree#variants の「接頭辞の max」：「値が増えるだけ」なら動き、「値が減る更新や、途中から始まる区間の max には使えない」。min でも向きを逆にして同じ。反例：$a = (5, 9)$ の接頭辞の最小値を持つ BIT で $a_0 \leftarrow 7$（値を大きくする更新）をすると、箱の値 5 を min で 7 に戻せず、$\min(a_0, a_1)$ を 5 と答えてしまう（正しくは 7）
- **直し方**：「最小値は、値が小さくなる更新だけのときの接頭辞の最小値に限られる（[BIT の変種](../ds/fenwick-tree.md#variants)）」とする

### 5. 直すとよい｜分かりやすさ（U3・U6）｜#shortest-path-steps（112 行）

### 7. 直すとよい｜事実（F2）｜#shortest-path-properties の「負閉路の影響」（141 行）

- **問題**：「距離が $-\infty$ になるのは、負閉路から届く頂点だけである」は必要条件としては正しいが、その負閉路自体が始点から届くことが抜けており、十分条件とも読める
- **根拠**：始点から届かない負閉路から届く頂点は、距離が有限か $+\infty$ である
- **直し方**：「始点から届く負閉路から、さらに届く頂点だけである」とする
