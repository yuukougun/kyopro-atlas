## 指摘

### 1. 直すべき｜事実（F2）・コード（C8）｜edge-set の節の「辺が 64 本以下」（161 行）と「辺が 64 本を超えるときは」（175 行）

- 問題：辺 (c, par[c]) を子の番号 c の bit で表すので、使う bit は 1〜n−1 である。辺が 64 本（頂点 65 個）だと c = 64 になり、`1ULL << 64` は未定義動作になる。本文の条件は 1 本ずれている（snippet の注釈「n ≤ 64 なら」は正しく、本文と食い違う）
- 根拠：edge-set.cpp を `-fsanitize=address,undefined` でコンパイルし、65 頂点のパス 0–1–…–64 と制約 (63, 64) を入れると `runtime error: shift exponent 64 is too large for 64-bit type 'long long unsigned int'`（42 行）が出て、出力は −9223372036854775807（正しくは 2^63 = 9223372036854775808 で long long にも収まらない）
- 直し方：161 行を「木も小さい（頂点が 64 個以下、すなわち辺が 63 本以下）」に、175 行を「頂点が 64 個を超えるときは」にする（または「辺を c − 1 の bit で表せば辺 64 本まで入る」と書き、snippet もそうする）。あわせて 161 行の「パスが数本しかなく」は、例題の M ≤ 20 と合うよう「パスが 20 本程度まで」とするとよい

### 2. 直すべき｜コード（C6）・記法（F7）｜edge-set の節の popcount（167 行の本文、edge-set.cpp:count の 58–59 行）

- 問題：取り込んだコードが C++20 の `std::popcount`（`<bit>`）を使い、`popcount((unsigned)S)` と符号なしに変換しているが、本文に版の注記も C++ の章へのリンクもない。手引き §9・code.md C6 の「C++20 の機能は C++ の章へリンク」に当たる。読者（C++ の現代的な書き方に不慣れ）は `(unsigned)` の変換の理由も分からない
- 根拠：lcs.md 187 行は同じ関数に「C++20 の [`<bit>` の関数](../cpp/cpp-math-functions.md#bit-functions)で、符号なしの型しか受け取らないので `unsigned` に変換して渡す」と書いている。inclusion-exclusion.md 99 行は popcount を用語集へリンクしている
- 直し方：167 行の「辺の数は popcount で求まる」の popcount に [用語集](../guide/glossary.md#popcount) へのリンクを付け、コード片の後に「`popcount` は C++20 の [`<bit>` の関数](../cpp/cpp-math-functions.md#bit-functions)で、符号なしの型しか受けないので `S` は `unsigned` にして渡す」の 1 文を足す

### 3. 直すとよい｜分かりやすさ（U2）｜intersection の節「その両端は、4 つの LCA … のうち深い 2 つである」（113 行）

- 問題：交わる判定には「なぜ正しいか」があるが、共通部分の両端の規則には理由がなく、119 行の「コード片で確かめている」だけになっている。読者は「なぜ 4 つの LCA で、なぜ深い 2 つなのか」が分からない
- 根拠：規則そのものは正しい（上の全探索）。また、共通部分は「パス c–d の上で a に最も近い頂点」と「b に最も近い頂点」を結ぶパスで、それぞれ合流点 meet(a, c, d)・meet(b, c, d) である（全探索で一致）。これはこのページの合流点の節から 1 段で出る
- 直し方：113 行の後に直感の 1〜2 文を足す。例：「a–b がパス c–d に乗るのは、a から c–d へ最も近い点と、b から最も近い点の間である。これは 3 点 a, c, d と b, c, d の合流点で、それぞれ lca(a, c)・lca(a, d) と lca(b, c)・lca(b, d) のうち深い方になり、まとめると 4 つのうち深い 2 つになる」。119 行の検証の文は残してよい

### 4. 直すとよい｜事実（F2）｜meeting-point の節の「なぜ正しいか」（85 行）
