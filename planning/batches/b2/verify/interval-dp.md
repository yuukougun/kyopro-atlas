## 指摘

### 1. 直すべき｜事実（F5）｜力試し ABC325 G の要約（257 行目）

- **問題**：「2 種類の削除の操作（連続する 'of' を消す・ある文字の後ろの K 文字までを消す）」は問題と違う。操作は 1 種類で、「連続する 'of' を選び、それとその直後に続く K 文字以下をまとめて削除する」である。「ある文字の後ろの K 文字までを消す」が単独でできるなら、ほぼ何でも消せて別の問題になる。方針（262 行目）の「組む 'f' を選び、その後ろを K 文字まで消す」とも食い違う
- **根拠**：drken「AtCoder ABC 325 G - offence」（https://drken1215.hatenablog.com/entry/2023/10/22/202630）の問題概要「"of" を含むとき、それとその後に続く K 文字以下の文字を削除する」。同記事のコードも 'o'…'f' の組を消すときだけ後ろを消している
- **直し方**：「文字列から、連続する 'of' とその直後の K 文字以下をまとめて削除する操作を好きなだけ行ったときの、長さの最小を求める。」のようにする。台帳 abc325_g の summary も同じ誤りなので、メインが台帳を直す（下の台帳への提案）

### 2. 直すべき｜事実（F2）｜#split-point の「高速化」（123 行目）、使い分け（288 行目）

- **問題**：「cost が Monge という条件を満たすと、最適な境目が l・r について単調になり、O(N^2) に落とせる」は条件が足りない。Knuth-Yao の高速化には、四角不等式（Monge）に加えて、包含について単調（$a \le b \le c \le d$ なら $\mathrm{cost}(b, c) \le \mathrm{cost}(a, d)$）が要る。Monge だけでは境目が単調にならない例がある
- **根拠**：作業用のプログラムで、Monge を満たし単調でない cost を n = 3〜7 で乱択で作ると、境目の範囲を $[\mathrm{opt}[l][r-1], \mathrm{opt}[l+1][r]]$ に絞った DP が O(N^3) の答えと食い違う例が多数出た（3000 件中 895 件）。単調も満たす cost では食い違いなし。Yao (1980) の定理の条件も 2 つ（四角不等式と単調性）である
- **直し方**：「$\mathrm{cost}$ が Monge で、区間を広げても減らない（$[b, c) \subseteq [a, d)$ なら $\mathrm{cost}(b, c) \le \mathrm{cost}(a, d)$）とき、最適な境目が…」とする。使い分けの「コストの性質（Monge）を調べて」も「Monge と単調性」にそろえる。区間の和のコスト（Slimes）は両方を満たすので、例として一言添えると分かりやすい

### 3. 直すべき｜事実（F2）・分かりやすさ（U7）｜力試しの方針 ABC325 G（262 行目）

- **問題**：「全部消せた区間が後ろを何文字まで消せるかの情報も要るので、状態の値の意味を工夫する」は言い過ぎ。drken の記事はそう工夫しているが、それは一つの書き方で、必要ではない。$\mathrm{dp}[l][r]$ を残る長さの最小のままにして、先頭が 'o'・$s_m$ = 'f'・$\mathrm{dp}[l+1][m] = 0$ のとき $\max(0, \mathrm{dp}[m+1][r] - K)$ を候補にする遷移で正しく解ける（'of' を最後に消せば、後ろの区間を先に縮めてからその先頭の K 文字を消せるため）
- **根拠**：上の遷移と境目で分ける遷移だけの DP を、長さ ≤ 9・K ≤ 3 の 3000 件で操作の全探索と比べてすべて一致した
- **直し方**：最後の文を「'of' の削除を後回しにすれば、後ろの区間を先に最小まで縮めてから、その先頭の $K$ 文字以下を消せる」程度に替える。状態の値の工夫に触れるなら「drken の記事のように値の意味を広げる書き方もある」と別の書き方として述べる。執筆者の未解決の点（どこまで書くか）は、この形なら状態の定義を変えずに済むので、ここに残してよい

### 4. 直すとよい｜事実（F2）・分かりやすさ（U3）｜#split-point の一般形と積の例（109・115・117 行目）

- **問題**：一般形は $\min_m(\ldots) + \mathrm{cost}(l, r)$ で、cost を min の外に出している。ところが 2 つ目の条件の見出しは「区間と境目だけで決まる」で、117 行目の「左右の大きさの積」のコスト $(S_m - S_l)(S_r - S_m)$ は境目 $m$ によって変わり、この式の形に入らない。読者は「積でも使える」と言われても、上の式のどこに入れるのか迷う
- **根拠**：本文の式と例の比較
- **直し方**：一般形を $\min_{l < m < r}\bigl(\mathrm{dp}[l][m] + \mathrm{dp}[m][r] + \mathrm{cost}(l, m, r)\bigr)$ にし、「cost が $m$ によらないときは min の外に出せる（Slimes）」と添える。または積の例の直後に「この場合は cost が $m$ に依存するので min の中に入れる」と書く

### 5. 直すとよい｜分かりやすさ（U4）｜#last-operation の「区間の中で最後に消す要素を決める」（160 行目）

- **問題**：遷移の式がなく、本文だけでは書けない。とくに $l = 0$・$r = N$ のとき外の $a_{l-1}$・$a_r$ がないことの扱い（番兵を置くか、端の扱いを決める）が抜けている。例題・練習にもこの型の問題がないので、具体像がつかみにくい。また節の題「最後に残す・最後に消すもの」の「最後に残す」は節の中に出てこない
- **根拠**：clarity.md U4（境界・番兵）
- **直し方**：$\mathrm{dp}[l][r] = \min_{l \le k < r}\bigl(\mathrm{dp}[l][k] + \mathrm{dp}[k+1][r] + \mathrm{cost}(a_{l-1}, a_k, a_r)\bigr)$、$\mathrm{dp}[l][l] = 0$ を書き、「列の両端に番兵 $a_{-1}$・$a_N$ を足して $[0, N)$ を答えにする」と一言添える。題の「最後に残す」は front matter の題なので、変えるならメインへの提案にする

### 6. 直すとよい｜分かりやすさ（U6・U9）｜#split-point の応用の型「括弧の対応」（121 行目）

- **問題**：分割点型の節に置いていながら「次の節以降の『相手で分ける』型と同じ形である」と言っており、なぜこの節にあるのかが分からない。「括弧列が正しいかを数える」も意味が取りにくい（正しい括弧列の個数を数えるのか、判定なのか）
- **直し方**：「正しい括弧列の個数を数える・正しくするための最小の変更回数を求める」と書き直し、項目ごと #last-operation か #pair-with-left-end の末尾に移すか、ここに残すなら「境目 $m$ を『$l$ と対応する括弧の次』に限ると、分割点型が相手で分ける型になる」と結び付ける
