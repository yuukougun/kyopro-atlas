### 2. 直すべき｜分かりやすさ・事実（U4・F2・C3）｜prefix-versions の「K 番目に小さい値」（165 行）

- 問題：「$K < c$ なら左へ、そうでなければ $K$ から $c$ を引いて右へ」は、$K$ が 0 始まり（最小が 0 番目）のときだけ正しい。本文は $K$ が 0 始まりであることを書いていない。見出し・要点の「K 番目に小さい」をふつうの 1 始まりで読むと、この規則では 1 つずれる（1 始まりなら $K \le c$ で左）。冒頭の「添字は 0-indexed で書く」は配列の添字の話で、順位にも及ぶとは読み取りにくい
- 根拠：[l, r) = {1, 4}（A = (5, 1, 4, …) の [1, 3)）、K = 1（1 始まりで最小）で、左の子 [値 1 の側] の個数 c = 1。本文の規則では K < c が偽で右へ進み、4 を返す。正しい答えは 1。コード片 prefix-kth.cpp は `k`（0-indexed）と注記していて正しい
- 直し方：節の最初の方に「$K$ は 0 始まりで数える（最小の値が 0 番目）」と書く。または 1 始まりで書き、規則を「$K \le c$ なら左へ」にしてコードの呼び出しを `k - 1` にする。前者が小さな直しで済む

### 3. 直すとよい｜事実（F2）｜partial-vs-full の最後の段落（130 行）・落とし穴の最後（180 行）

- 問題：「どちらでも、ならし計算量の構造をそのまま永続にしてはいけない」と部分永続にも言い切るが、続く理由（重い操作の直前の版から何度でも枝分かれする）は完全永続にしか当てはまらない。部分永続では更新が最新の版への一直線の列なので、更新のならしの解析はそのまま成り立つ。部分永続で困るのは、読むだけのはずの操作が構造を書き換えるとき（経路圧縮、スプレー木の回転）である。本文は経路圧縮の例を挙げているので結論は合うが、言い切りの範囲が広すぎる
- 根拠：部分永続ではどの版から更新するかの選択がなく、版の列は更新の順に一直線である（本文の表の「版の形」も一直線）。よって「重い操作を何度もくり返す」反例は作れない。一方、過去の版への find が経路圧縮で過去の親を書き換えれば、その版の内容自体が変わる
- 直し方：「完全永続では、ならし計算量の構造をそのまま永続にしてはいけない（理由…）。部分永続でも、問い合わせが構造を書き換える操作（Union-Find の経路圧縮など）は過去の版を壊すので使えない」のように 2 つに分ける。落とし穴の 180 行も「完全永続では上限が保てず、部分永続でも読むときに書き換える操作は使えない」とそろえる
