## 未解決の点

1. abc339_g の制約（N, Q, A_i の上限）は第三者の解説で確かめられなかった（kmjp 氏のコードの配列の大きさから N は 2×10^5 程度と推せるだけ）。本文の例題では制約の数値を書かず、オーバーフローの話は落とし穴で一般の値（10^9・2×10^5）として書いた
2. 本文の「1〜2 秒で終わる目安」（N = Q = 2×10^5 で比較 約 1.3×10^8 回）は見積もりで、実測はしていない。complexity-estimation の「1 秒に 10^8 回」と比べて、二分探索の比較は軽い処理という前提を置いた
3. 「各段に BIT を持たせる」節は、木の軸を位置にした形を主に書き、kmjp 氏の abc467_g の形（値の順を葉、各ノードは位置の順）は入れ替えとして書いた。後者の各ノードの中で「位置が [l, r) にある今いる要素」を数える細部（二分探索で位置の範囲を出し、その段の BIT で範囲の和を取る）は本文で省いた
4. catalog の sections にあった choosing（使い分け）は、骨格の時点で外されていたので、定型の `## 使い分け {#comparison}` で書いた
