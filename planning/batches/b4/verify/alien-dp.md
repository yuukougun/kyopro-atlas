## 指摘

### 1. 直すとよい｜分かりやすさ（U2・U3）｜#binary-search-lambda の「2 の λ では、…だからである。」の段落

- **問題**：「1 つ小さい λ − 1 で個数が K を超えていたので、K は最適な個数の範囲に入っている」の理由が一段飛んでいる。続く文「この λ では K と同点の個数が並んでいてもよく、g(λ) の値は同点のどれから計算しても同じだからである」は「だからである」が何の理由か（答えに返った個数でなく K を掛けてよい理由）が前の文から読み取りにくい
- **根拠**：レート 1000 の読者は、cnt(λ−1) > K と cnt(λ) ≤ K から K が最適になる理由（f(K+1) − f(K) = λ になる）を自分で埋める必要がある。上の「実行して確かめたこと」の 2 行の議論で埋まる
- **直し方**：たとえば「λ − 1 では個数が K を超えるので f(K+1) − f(K) ≥ λ、λ では K 以下なので f(K+1) − f(K) ≤ λ。よって f(K+1) − f(K) = λ ≤ f(K) − f(K−1) で、K は λ で最適な個数の 1 つになる。3 で返った個数ではなく K を掛けてよいのは、同点の個数のどれから計算しても g(λ) が同じだからである」のように 2 文に分ける

### 2. 直すとよい｜事実（F2）｜導入の「ABC では difficulty 2500 を超える G・Ex に限られる。」

- **問題**：「限られる」は全数を調べた主張に読めるが、根拠は台帳とかんプリン氏の一覧の数問（abc218_h 2805、abc305_h 3344、abc355_g 2991、abc464_g 2592）だけである
- **根拠**：front matter の frequency_evidence も「古い ABC 3 問」。全数は確かめられていない
- **直し方**：「これまでの ABC の例は、difficulty 2500 を超える G・Ex である」のように、見た範囲の事実として書く

### 3. 直すとよい｜事実（F7）｜#with-monge の Monge の不等式

- **問題**：「$a \le b \le c \le d$ で $\mathrm{cost}(a, c) + \mathrm{cost}(b, d) \le \mathrm{cost}(a, d) + \mathrm{cost}(b, c)$」は $b = c$ のとき $\mathrm{cost}(b, b)$（空の区間）を使うが、この節の DP は $j < i$ の $\mathrm{cost}(j, i)$ しか定義していない
- **根拠**：noshi91 氏の記事は $i < j < k < l$ の狭義の不等号で条件を書いている。$\le$ の形は $\mathrm{cost}(i, i)$ を決めないと意味が定まらない
- **直し方**：「$a < b < c < d$ で」にするか、「（$\mathrm{cost}(i, i) = 0$ とする）」を添える

### 4. 直すとよい｜コード（C3）｜snippets/alien-dp/nonadjacent.cpp の alien の `// cnt(lo) > k、cnt(hi) ≤ k`

- **問題**：k が最大の個数 ceil(N/2) のとき cnt(lo) = k で、コメントの不変条件 cnt(lo) > k が成り立たない。結果は正しい（hi が −2Σ になり、そこで k は最適）が、コメントを信じた読者が「k = 最大のときは別扱いが要るのでは」と迷う
- **根拠**：lo = −2Σ−1 はどの差よりも小さいので cnt(lo) は最大の個数。試験で k = (n+1)/2 を含めて一致を確かめた
- **直し方**：コメントを「cnt(lo) は最大の個数（k が最大のときだけ k と等しいが、それでも結果は正しい）、cnt(hi) = 0 ≤ k」のように直す。コードは変えなくてよい

### 5. 直すとよい｜事実（F2）・分かりやすさ（U9）｜#undoable-greedy の「取り出す値は f(k+1) − f(k) そのもので、取り出すたびに小さくなる。」

- **問題**：同じ値が続くこと（A がすべて 4 なら 4, 4, 4 と出る）があるので「小さくなる」は言い過ぎ。前の節の「広義単調減少」とも言い方がそろわない
- **根拠**：case「6 3 / 4 4 4 4 4 4」で出す値は 4, 4, 4
- **直し方**：「取り出すたびに大きくならない（広義単調減少）」にする

### 6. 直すとよい｜事実（F9）｜参考の soi.ch の注記「同点の扱いの考え方」

- **問題**：記事の Degeneracy の節は TODO のままで、同点については「端点しか見つからないときは端点の間を線形補間する」と短く触れるだけである。本文の決まり（個数の少ない方を選び、K を掛ける）の出典に読める注記は言い過ぎ
- **根拠**：https://soi.ch/wiki/alien-optimization/ を読んで確かめた
- **直し方**：注記を「罰金と接する直線の見方、同点のときに端点の間を補間する考え方（その節は書きかけ）」とするか、同点の部分を外す

### 7. 直すとよい｜分かりやすさ（U6）・前提（F6）｜#with-monge の「LARSCH を使うと O(N)」

- **問題**：LARSCH・オンラインの形の DP は monge のページの #smawk-larsch の節で扱っているが、この節からはページへのリンクしかなく、断片で読むと LARSCH が何か分からない
- **直し方**：「LARSCH を使うと」に [SMAWK・LARSCH の節](../dp/monge.md#smawk-larsch) へのリンクを張る

### 8. 直すとよい｜分かりやすさ（U7）｜練習の方針の ABC355 G

- **問題**：「隣り合う 2 つの選んだ位置の間の点のコストを区間のコストとする」だけだと、最初に選んだ位置より左・最後より右の点の扱いが抜け、区間分割の形（0 から N+1 への路）に乗せる手前で読者が止まる
- **根拠**：kmjp 氏の記事は位置 0 と N+1 に「選ばない」番兵を置き、端の区間は片側のコストだけにしている
- **直し方**：「両端に番兵を置き、端の区間は片側の距離だけを数える」を 1 句足す
