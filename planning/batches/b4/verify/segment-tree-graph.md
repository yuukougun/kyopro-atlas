## 指摘

### 1. 直すとよい｜事実（F7）・分かりやすさ（U3）｜#library の 1 段落目「非再帰のセグメント木と同じ番号付け」

- **問題**：リンク先の #recursive-vs-iterative には番号付けの説明がなく、番号付け（子が 2k・2k+1、葉が size + i）はセグメント木のページの #invariants にある。しかもあちらは葉の数 size を N 以上の 2 の冪にした配置で、本文の「葉 v が N + v」（切り上げない）とは同じではない。読者がリンク先を開くと「size + i」とあり、どちらが正しいか迷う
- **根拠**：docs/ds/segment-tree.md の 115〜120 行目（#invariants）。本文の 2 つ目の箇条で「切り上げなくても正しく覆う」と断っているが、1 段落目の「同じ番号付け」と食い違って読める
- **直し方**：リンクを `../ds/segment-tree.md#invariants` にし、「[非再帰のセグメント木](../ds/segment-tree.md#invariants)の番号付け（ノード i の子が 2i と 2i+1）を、葉の数を N のまま（2 の冪に切り上げずに）使う。葉 v は N + v になる」のように、違いを先に言う

### 2. 直すとよい｜分かりやすさ（U2）｜#library の箇条「覆うノードの列挙」

- **問題**：「N を 2 の冪に切り上げなくても、このループは正しく覆う」が理由なしの言い切りで、セグメント木のページ（ACL と同じく 2 の冪に切り上げる）を読んだ読者には意外である。主張そのものは正しい（上の全探索で確かめた）
- **根拠**：2 の冪でない N では、内部ノードの中に葉が連続しない（端をまたぐ）ものがあるが、ループが取るノードはどれも [l, r) の中に収まる。読者はここで「本当に？」と止まる
- **直し方**：「（ループが取るノードは端をまたがないので、2 の冪でない N でも重なりなく覆う。不安なら 2 の冪に切り上げてもよい）」程度の一言を添えるか、コード片の試験が 2 の冪でない n を含むことを書く

### 3. 直すとよい｜分かりやすさ（U3）｜#abc414_g の方針と解法の詳細

- **問題**：方針は「列車ごとに中継の頂点を足し、基本料金はその頂点を通る辺のコストにする」と頂点 1 つの書き方だが、解法の詳細は「列車の乗る頂点から降りる頂点へは基本料金の辺」と頂点 2 つの書き方で、食い違って読める。また方針だけでは、なぜ 0 の辺の木 2 本でなく 4 本要るのか（移動距離を木の辺のコストに割り振るため、向きで割り振り方が変わる）が分からない
- **根拠**：kmjp 氏のコードは列車ごとに 2 頂点（id → id+1 にコスト C）。1 頂点でもコストを入る辺に足せば作れるので、どちらでもよいが、本文の中でそろっていない
- **直し方**：方針を「列車ごとに乗る頂点と降りる頂点を足し、その間に基本料金の辺を張る。移動距離の分は木の辺のコストに割り振るので、乗る用と降りる用の木を向きごとに用意する（4 本）」のようにそろえる

### 4. 直すとよい｜事実（F7）｜#abc414_g の解法の詳細「降りる区間 $[L, R]$」

- **問題**：ページのほかの所は半開区間で書いているのに、ここだけ断りなく閉区間 $[L, R]$ を使っている
- **根拠**：手引き §6・F7（閉区間を断りなく使わない）。問題文が 1-indexed の閉区間で与えるためと思われる
- **直し方**：「降りる駅の区間 $[L, R]$（問題文どおりの閉区間）」と断るか、「降りる区間の西端の駅 $L$」とだけ書いて区間の記号を使わない

### 5. 直すとよい｜事実（F9）｜#references の OI Wiki

- **根拠**：ページの `<title>` は「线段树基础 - OI Wiki」。節「应用：线段树优化建图」はこのページにある

### 6. 直すとよい｜分かりやすさ（U2）｜#two-trees「距離が変わらない理由」

- **問題**：理由は頂点 → 区間の場合だけで、区間 → 区間（中継の頂点 $x$）の場合が「上向きの木も向きを逆にして同じ」に含まれているのか読み取りにくい
- **根拠**：$x$ に入る辺はコスト $w$ の 1 種類だけで、$x$ を通る道は「0 で登る → $w$ → 0 で降りる」に限られる、という 1 文があれば足りる
- **直し方**：段落の終わりに「区間から区間の辺でも、$x$ に入るにはコスト $w$ の辺を 1 本通るしかないので、$x$ を通る道は元の辺 1 本（$[l_1, r_1)$ のどれか → $[l_2, r_2)$ のどれか）にちょうど対応する」を足す

### 7. 直すとよい｜図（G5）｜two-trees.svg の太い矢印

- **問題**：頂点 0 → [2, 4) の太い矢印が、下向きの木の [0, 2) → 頂点 1 の灰色の辺と交わる。360px でも読めるが、交点で灰色の辺が太線に紛れる
- **根拠**：360px・720px の PNG で目で確かめた。文字の重なり・はみ出しはない。矢印の向き（下向きの木は親 → 子、上向きの木は子 → 親）とラベル w は正しい
- **直し方**：急ぎではない。太線を少し上に曲げる（path の二次ベジェ）か、そのままでよい
