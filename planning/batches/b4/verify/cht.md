## 指摘

### 1. 直すべき｜事実（F2）｜#pitfalls「同じ傾きの直線」

- **問題**：「不要の判定式で $a_f = a_g$ になると、両辺が 0 になって正しく判定できない」は誤り。$a_f = a_g$ のとき 0 になるのは左辺 $(b_h - b_f)(a_f - a_g)$ だけで、右辺 $(b_g - b_f)(a_f - a_h)$ は一般に 0 でない
- **根拠**：$a_f = a_g$ を代入すると判定は $0 \le (b_g - b_f)(a_f - a_h)$、つまり $b_g \ge b_f$ のときだけ $g$ を消す形になる。$b_g < b_f$ のときは $f$ の方が不要なのに $g$ を残し、判定は $f$ を消さないので、不要な $f$ が deque に残る。本当の問題は「判定式は $a_f > a_g > a_h$（交点の分母が正）を前提にしていて、同じ傾きではその前提が崩れる」ことにある
- **直し方**：「不要の判定式は傾きが狭義に減ること（交点の分母が正）を前提にしている。同じ傾きの直線が来ると交点がなく、判定が正しくなくなる（片方の辺だけが 0 になる）」のように直す。対処（末尾と傾きが同じなら切片の小さい方だけを残す）はそのままでよく、コード片はこのとおりに書かれていて正しい

### 2. 直すとよい｜事実（F2）・分かりやすさ（U1）｜導入の第 2 段落

- **問題**：「ABC で CHT が想定解になった問題は、2019〜2026 年の F 以降で 2 問ほどしかない」は、台帳にある問題（cht を参照する 3 件）から出した言い切りで、ABC の全体を調べた根拠がない
- **根拠**：`data/problems.yaml` で cht を指すのは dp_z・abc289_g・abc228_h の 3 件だけ。frequency_evidence も「古い ABC 2 問」で、網羅を確かめた記録はない
- **直し方**：「この教材で集めた問題では、ABC で CHT が想定解のものは 2 問（ABC289 G・ABC228 H）しかなく、多くない」のように、根拠の範囲を言う形にする

### 3. 直すとよい｜事実（F2）｜#lines の箇条書き 2 つ目

- **問題**：「積の項が 2 つ以上ある（$x_i y_j + z_i w_j$ など）と、1 本の直線にはならない。この場合は CHT を使えない」は言い過ぎ。たとえば $z_i$ が $x_i$ の定数倍なら 1 つの積にまとまり、使える
- **根拠**：$x_i y_j + c x_i w_j = x_i (y_j + c w_j)$ は傾き $y_j + c w_j$ の直線になる
- **直し方**：「そのままでは 1 本の直線にならず、CHT は使えない（$i$ の側の値が比例するなど、1 つの積にまとめられる場合を除く）」とする

### 4. 直すとよい｜分かりやすさ（U1）・事実（F1）｜要点の「計算量」

- **問題**：要点は「クエリが単調でなければ 1 回 $O(\log N)$」で、front matter の complexity は「クエリだけ単調でないなら」。要点の言い方だと、傾きも単調でない場合も $O(\log N)$ の二分探索で済むように読める
- **根拠**：本文の #non-monotone-queries は「傾きが単調に追加されるが、クエリの $x$ がばらばら」の場合だけを扱い、傾きも単調でなければ Li Chao Tree か動的 CHT にすると書いている
- **直し方**：要点を complexity にそろえ「傾きが単調でクエリだけ単調でないなら 1 回 $O(\log N)$」とする

### 5. 直すとよい｜分かりやすさ（U3）｜#pitfalls「最小と最大の取り違え」

- **問題**：「このとき傾きの単調の向きも逆になることに注意する（減る順の追加が、増える順になる）」は、元の問題でどちらの順に追加すればよいのかが読み取りにくい。「減る順の追加が増える順になる」は「元で減る順なら反転後は増える順」なので、最小用の deque（傾きが減る順を要する）に入れるには元の傾きが増える順である必要がある、という結論が書かれていない
- **根拠**：読者が「最大の問題でも傾きが減る順に追加すればよい」と読み違える余地がある
- **直し方**：「$(-a, -b)$ で追加すると傾きの順が逆になるので、最小用の deque（傾きが減る順）に入れるには、元の直線を傾きが増える順に追加する」と、何をそろえればよいかまで書く

### 6. 直すとよい｜図（G5）｜envelope.svg の目盛り

- **問題**：「8/3」の文字が交点の縦の点線より左に 7px ほどずれていて（中心 180、点線 186.7）、「10/3」は右に 7px ずれている（中心 230、点線 223.3）。2 つの交点が近いので、どちらの文字がどちらの点線かは読めるが、ずれが左右逆向きで間隔が広がって見える
- **根拠**：360px・720px の PNG で目で確かめた。重なりやはみ出しはない
- **直し方**：文字の x を点線の位置（186.7・223.3）にそろえる。重なるなら font-size を 12 にする。急ぎではない
