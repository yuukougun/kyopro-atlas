## 指摘

### 1｜直すとよい｜事実（F2）・分かりやすさ（U3）｜#pitfalls の「頂点が 1 つ」の最後の文「最大値の初期値を 0 にすると、長さ 1 の解を見落とすことがある」

- **問題**：初期値が 0 か 1 かで解を見落とすことはない。merom686 氏の記録での失敗は「長さ 1 のムカデは次数 2 でもよい」という場合を落としたことで、初期値 0 はその見落としを隠さなかっただけである（記事も「初期値を 0 にしていたのがよくなかったか」と迷っている）。また、$N = 1$ の箇条に入っているが、この話は $N = 1$ と関係がない
- **根拠**：merom686 氏の記事の F の段落。全場合を正しく書いた DP（torus711 氏のコード、上の試しのプログラム）は初期値 0 でも正しい
- **直し方**：この文を消すか、「答えの下限が分かっている（どの木でも 1 以上など）のに DP が 0 を返すなら、場合分けの落としを疑う」のように、場合の見落としの話として別の箇条にする

### 2｜直すとよい｜事実（F1）｜#postorder の最後の段落「全体は $O(NK \log K)$ 程度」、練習の方針の ABC239 E

- **問題**：方針どおり「子の列と自分の値を合わせてソートし、$K$ 個に切り詰める」と、子が $k_v$ 人の頂点で $k_v K + 1$ 個をソートするので $O(k_v K \log(k_v K))$ になる。星形の木では根で $O(NK \log(NK))$ で、$O(NK \log K)$ にはならない（$K = 20$ では実害はない）
- **根拠**：$\sum_v k_v K \log(k_v K) \le NK \log(NK)$。$\log K$ で抑えるには、子を 1 人合わせるたびに $K$ 個へ切り詰める必要がある
- **直し方**：「$O(NK \log(NK))$ 程度」とするか、「子を 1 人ずつ合わせて毎回 $K$ 個に切り詰めれば $O(NK \log K)$」と書き方を添える

### 3｜直すとよい｜事実（F2）｜#greedy-children の最後の段落「外さずに $-\infty$ を足すと、オーバーフローするか、上限の本数の数え方がずれる」

- **問題**：コード片のように「正の得だけを取る」なら、$-\infty$ 由来の得は負なので選ばれず、本数の数え方はずれない。起きうるのは、$-\infty$ を `LLONG_MIN` のように取ったときの $w + \mathrm{rest}[c] - \mathrm{full}[c]$ のオーバーフローである
- **根拠**：greedy-children.cpp の `gain[i] > 0` の条件。NEG = LLONG_MIN / 4 なら外さなくても結果は同じ
- **直し方**：「外さずに $-\infty$ のまま得を計算すると、$-\infty$ の表し方によってはオーバーフローする（選べない辺を得の候補に入れないのが安全）」とする

### 4｜直すとよい｜事実（F2）・分かりやすさ（U3）｜要点の「部分木どうしは頂点を共有しないので」、導入の「部分木は根から見て互いに交わらないので」

- **問題**：$v$ の部分木と $v$ の祖先の部分木は交わる（入れ子になる）。交わらないのは「同じ頂点の子どうし（兄弟）の部分木」である。#postorder の本文（63 行）は「2 人の子の部分木も頂点を共有しない」と正しく書いているので、要点・導入だけが言い過ぎになっている
- **根拠**：部分木の定義
- **直し方**：要点を「子どうしの部分木は頂点を共有しないので」、導入を「同じ頂点の子の部分木どうしは交わらないので」とする。front matter の summary（「各頂点の部分木は互いに交わらない」）も同じなので、メインへの提案として報告に書く

### 5｜直すとよい｜事実（F2）｜#pitfalls の「再帰が深すぎる」の「ジャッジや手元の環境のスタックの上限を超えて落ちることがある」

- **問題**：cpp-environment の予定の節では「AtCoder の上限は大きい（新ジャッジの値は未確認）、手元は 8 MiB が多い」としている。本文の書き方では、主にジャッジで落ちると読める
- **根拠**：上の再現（8 MiB で 2×10^5 のパスが落ちる）と cpp-environment の sections の title
- **直し方**：「手元の環境（スタックの上限が 8 MiB のことが多い）では落ちる。ジャッジの上限は環境によるので、…」のように、手元で落ちることを先に書く

### 6｜直すとよい｜分かりやすさ（U4）｜#path-at-top の木の直径の段落

- **問題**：$\mathrm{up}[v] = 1 + \max_c \mathrm{up}[c]$ は頂点数で数えている（葉は 1）が、そう書いていない。直径は辺の数で言うことが多く、「上位 2 つの和に $v$ の分を足したもの」が頂点数だと気づかないと 1 ずれる。また子がないときの $\max$（空の最大を 0 とする）にも触れていない
- **根拠**：本文 113 行。例題 ABC447 F の詳細は「子がなければ 1」と書いているので、ここにも同じ断りがあるとそろう
- **直し方**：「頂点数で数える（葉は $\mathrm{up} = 1$。辺の数が欲しいなら最後に 1 を引く）」と 1 文足す

### 8｜直すとよい｜分かりやすさ（U2）｜#with-binary-search の dp の式の説明
