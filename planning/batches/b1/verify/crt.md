## 指摘

1. 重さ：直すべき／観点：fact（F2）・code（C8）／場所：#pitfalls「途中の積のあふれ」（194 行）
   - 問題：「`__int128` で掛けるか、掛ける前にそれぞれを法で割った余りにする」の後者では、あふれを避けられない
   - 根拠：$m_0 = 2$、$m_1 = 10^{18} - 1$、$r_0 = 0$、$r_1 = 10^{18} - 2$ のとき lcm は約 $2 \times 10^{18}$ で long long に収まるが、$u_1 = m_1$ で、$(r_1 - r_0)/g \bmod u_1 \approx 10^{18}$ と逆元 $p$（約 $5 \times 10^{17}$）は法で割っても小さくならず、積は約 $5 \times 10^{35}$ になる。ACL が long long で済ませているのは、先に $m_0 \ge m_1$ になるよう入れ替えて $u_1^2 \le \operatorname{lcm}$ を保つから（`atcoder/math.hpp` の crt のコメント `u1 * u1 <= m1 * m1 / g / g <= m0 * m1 / g = lcm(m0, m1)`）
   - 直し方：後者を「法の大きい方を $m_0$ に入れ替えてから、それぞれを $u_1$ で割った余りにして掛ける（$u_1^2 \le \operatorname{lcm}$ になる。ACL の `crt` の方法）」に直すか、後者を消して `__int128` だけにする

2. 重さ：直すべき／観点：fact（F2）・code（C8）／場所：#many-equations「答えに上限がある」（120 行）
   - 問題：「$z$ が上限を超えた時点で」とあるが、上限を超える統合の 1 回そのものが long long をあふれうることに触れていない。このページの `crt_merge` や ACL の `crt` で「超えるまで統合」すると壊れる
