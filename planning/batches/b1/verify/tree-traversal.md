## 結論の要約

## 指摘

1. **直すべき**｜観点：事実（F2）｜場所：`#to-tree-dp` の 1 段落目の最後の文（153 行）｜問題：「計算順序はどれもこのページの帰りがけ順か BFS 順の逆である」は言い過ぎで、すぐ下の箇条と食い違う。全方位木 DP は 2 回目の走査で「BFS 順で配る」（同じ節の 2 つ目の箇条）。tree-dp にも上から配る節（`#top-down`）がある。力試しの ABC133 E も行きがけ順（BFS 順）で決める。読者は「木 DP は必ず下から集める」と覚えてしまう｜根拠：同じ節の 2 つ目の箇条、`docs/dp/tree-dp.md` の `{#top-down}`、`docs/dp/rerooting.md`｜直し方：例「計算順序は、子から集めるときは帰りがけ順か BFS 順の逆、親から配るときは行きがけ順か BFS 順で、どれもこのページの順のどれかである」。または「部分木の値を集める計算は〜」と範囲を絞る。

2. **直すべき**｜観点：事実（F9）｜場所：参考の 2 件目（226 行）、gotoki_no_joe「ABC270 A～F をHaskellで」｜問題：「参考にした点」に「親を記録してパスを復元する」とあるが、記事は Y から DFS し、親を引数で渡して戻らないようにしながら、X に着いた枝のパスを `Maybe` で返す解き方である。親の配列を記録して Y からたどる方法は記事にない。記事が本文の方針（「X を根にして走査し、親を記録し、Y から親をたどる」）の裏付けになっていない｜根拠：記事を WebFetch で読んだ内容（C 問題は Y からの DFS で、X に着くまでパスを作る）｜直し方：参考にした点を「練習の問い（2 頂点を結ぶパスの出力）と、親を渡して戻らない DFS で探す別の解き方」のように記事の中身に合わせる。本文の方針の裏付けには、親を記録してたどる解説（執筆者の提案のとおり、木であることも書いた ABC270 の解説）を確かめて足す。台帳の evidence を足すのはメインに提案する。

3. **直すとよい**｜観点：分かりやすさ（U3）・事実（F2）｜場所：落とし穴「深さの基準を取り違える」（165 行）｜問題：「根を 0 として $\mathrm{dep}[u] - \mathrm{dep}[v]$ が世代の差になる」は、根を 1 にしても差は同じなので、「基準の取り違え」の落とし穴の説明になっていない。読者は根を 0 にしないと差がずれると誤解しうる｜根拠：$\mathrm{dep}$ に定数を足しても差は変わらない｜直し方：深さの差が基準によらないことを書き、本当に起きる誤り（「深さ $D$ の頂点を数える」のように深さの値そのものを使うときは、根を 0 と 1 のどちらで数えるかで答えがずれる。「$y$ 世代先まで」は差が $y$ 以下で、端を含む）に書き換える。

4. **直すとよい**｜観点：分かりやすさ（U6・U9）｜場所：`#pre-post-order` の 3 つ目の箇条（88 行）｜問題：「行きがけ番号 1〜4 の 4 個」は閉区間で、直前の式の半開区間 $[\mathrm{in}[v], \mathrm{in}[v] + \mathrm{sz}[v])$ と書き方が違う。手引き §6 は閉区間を明記するよう求める｜根拠：手引き §6「閉区間は『閉区間 $[l, r]$』と明記する」｜直し方：「行きがけ番号の区間 $[1, 5)$（番号 1〜4 の 4 個）」のように式の形を添える。

5. **直すとよい**｜観点：分かりやすさ（U4）｜場所：練習の方針の ABC309 E（209 行）｜問題：保険を買っていない人の値と、根（親がない）の値の初期値が書かれていない。「親の値から 1 引いたもの」が負の値のまま伝わることも含め、値を −1 から始めることが分からないと、実装で迷う｜根拠：ZOI_dayo の記事は、保険がないとき −1 として扱う｜直し方：「保険を買っていなければ自分の分を −1 とし、根は親の分を −1 とする」を一言足す。

6. **直すとよい**｜観点：コード（C2・C8）｜場所：`snippets/tree-traversal/dfs-order.cpp` 38〜43 行（区間の性質を確かめる assert のループ）｜問題：部分木の各頂点から祖先をたどるので、パス状の木では $O(N^3)$ になる。cases では問題ないが、読者がスタックを広げて大きな入力で試すと終わらない。検証でも、スタックの試験の前にこのループを外す必要があった｜根拠：パス状の木の N = 3×10^4 で、元の dfs-order は 2 分たっても終わらなかった（core だけの版はすぐ終わる）｜直し方：祖先の判定を $\mathrm{par}$ の 1 段だけで確かめる形にする（例：$v$ 以外の頂点 $u$ について、$\mathrm{in}[\mathrm{par}[u]] < \mathrm{in}[u] < \mathrm{in}[\mathrm{par}[u]] + \mathrm{sz}[\mathrm{par}[u]]$ を確かめる）。または N が小さいときだけ検査する。

7. **直すとよい**｜観点：コード（C3）・分かりやすさ（U3）｜場所：`#parent-depth-size` の取り込み（59 行）｜問題：この節で取り込む core に、`in`・`pre`・`post`（行きがけ番号・行きがけ順・帰りがけ順）が入っている。どれも次の節で初めて定義される。この節だけを読む読者（claude.ai の断片の読み方も含む）には、説明のない処理である｜根拠：C3「説明にない処理が取り込みの範囲に入っている」、U6｜直し方：取り込みの直後の段落に「`in`・`pre`・`post` は次の節の行きがけ順・帰りがけ順の記録である」と一言足す。または core を 2 つの印（親・深さ・サイズの部分と、順の記録を足した版）に分ける。
