## 指摘

### 1｜直すべき｜fact（F5）｜#practice の ABC475 D の要約（「作れればその 1 つを」）

- **問題**：要約は「作れればその 1 つを、作れなければ -1 を出力する」としているが、執筆者自身が「どれでもよいか最小かを確かめられなかった」と書いている。確かめていない内容を事実として書いており、しかも根拠の資料は「最小」を示唆している
- **根拠**：comet725 の記事（evidence）の説明文に「最小の素数を出力する」とある。Konini64・hyouri の解答も、素数を小さい順に調べて最初に一致したものを出力している（最小を出す実装）。問題文が「最小」を求めているなら、今の要約は誤りになる
- **直し方**：メインで問題の条件を確かめられるならそれに合わせる（最小なら「条件を満たす素数のうち最小のものを、作れなければ -1 を出力する」）。確かめられないなら、どちらでも誤りにならない書き方「文字列 S の各文字を…置き換えて、先頭が 0 でない素数を作れるか判定し、作れるならその素数を、作れなければ -1 を出力する」にとどめ、台帳への提案の summary も同じにする。練習の方針（小さい順に照合する）は最小を求める場合でもそのまま通る

### 2｜直すとよい｜clarity（U3）・fact（F2）｜#procedure の 2 つ目の箇条（「kp で k < p のもの」）

- **問題**：k = 1（p 自身）も「k < p」に入るので、文どおりに読むと p 自身も消えていることになる
- **根拠**：k = 1 には素因数がない
- **直し方**：「$p$ の倍数 $kp$ で $2 \le k < p$ のものは」とする

### 3｜直すとよい｜fact（F3）｜#memory の 1 つ目の箇条（「N = 10^8 の篩が 0.5 秒前後」）

- **問題**：報告によると、執筆者の計測は Σ N/i のループ（約 1.9×10^9 回）を同じプログラムに含んでいた。篩だけの時間としては大きめである
- **根拠**：篩と素数の数え上げだけを測ると、vector<bool> は 0.27〜0.28 秒、vector<char> は 0.78〜0.83 秒（上の「確かめたこと」）。bool が速いという結論は同じ
- **直し方**：「0.3 秒ほどで、vector<char>（0.8 秒ほど）より速かった」とするか、秒数を出さず「1 秒を十分に下回り、vector<char> より速かった」とする

### 4｜直すとよい｜fact（F2）｜#memory の 3 つ目の箇条（「N が 10^9 以上なら篩えない：表自体が大きすぎる」）

- **問題**：vector<bool> なら 10^9 でも約 125 MB で、メモリだけなら AtCoder の 1024 MiB に収まる。篩えない主な理由はメモリではなく時間（内側の回数が 10^9 の数倍、上の表から外挿して約 2.5×10^9）である
- **根拠**：上の表の 1 要素 1 bit の欄と、内側の回数の伸び（10 倍ごとに約 10.6 倍）
- **直し方**：「$N$ が $10^9$ 以上なら篩わない：bit で持てば 125 MB に収まるが、内側の回数が $2 \times 10^9$ を超え、時間が足りない」のように理由を直す

### 5｜直すとよい｜clarity（U3）｜#prefix-count の 3 段落目（「$s_r$ は $\pi(r - 1)$ に等しい」）

- **問題**：読者が使いたいのは「$x$ 以下の素数の個数」なので、添字を 1 ずらして読み替える手間が残る。例題の解法の詳細でも π(x) を引くとだけ書いてあり、s の添字との対応はこの 1 文に頼っている
- **根拠**：s の定義（[0, i) の個数）から π(x) = s_{x+1}
- **直し方**：「$\pi(x) = s_{x+1}$ なので」と、使う向きで書く

### 6｜直すとよい｜clarity（U4）｜#variants の最後の段落（メビウス関数の表）

- **問題**：「$p$ の倍数に $-1$ を掛け、$p^2$ の倍数を $0$ にする」だけでは初期値が分からず、そのまま書くと全部 0 のままになる実装もありうる。素数の見分け方（ω のように 0 で判定できない）も変わる
- **根拠**：μ の表は全要素 1 で始める必要がある
- **直し方**：「全部を $1$ で始め、素数 $p$ ごとに…」と初期値を足す（素数の判定は別の表か、詳しくはリンク先に任せる旨を一言）
