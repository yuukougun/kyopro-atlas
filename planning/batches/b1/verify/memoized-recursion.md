## 指摘

### 1. 直すべき｜事実（F1・F2）｜#dp-map-sparse「すべての k について ⌊N/k⌋ へ遷移する」の段落

- **問題**：「現れる値は O(√N) 個……N = 10^12 なら約 2×10^6 個で、`map` でも間に合うことが多い」とあるが、ページ自身の見積もり（状態の数 × 1 状態の遷移数）では間に合わない。この遷移では、状態 x の遷移先が ⌊x/k⌋ の異なる値で O(√x) 個あるので、全体は Σ√v ＝ O(N^{3/4}) になる
- **根拠**：N = 10^12 で、現れる各値 v について 2√v を足すと 5328413846（約 5.3×10^9）。`map` の log も掛かるので、数秒の制限には収まらない。状態の数だけを見て「間に合う」とするのは、要点の計算量の書き方とも食い違う
- **直し方**：状態の数は O(√N) だが、各状態が O(√x) 個の遷移を持つので全体は O(N^{3/4}) になると書く。N = 10^12 は約 5×10^9 で厳しく、N ≤ 10^9〜10^10 程度が目安だと直す（または「間に合うことが多い」を消し、「遷移も商ごとにまとめる必要がある（[商の列挙](../math/floor-quotient-enum.md#block-end)）」とつなぐ）

### 2. 直すべき｜事実（F2・F5）｜#challenge「力試しの方針」の ABC380 F

- **問題**：「1 手で出したカードより小さいカードしか手札に戻らないので、手札の数の合計は 1 手ごとに必ず減り」。「手札の数」は手札の枚数と読めるが、カードを 1 枚出して 1 枚取ると枚数は変わらないので、枚数の意味では誤り。減るのは手札に書かれた数の合計である（出したカード x を手放し、x より小さい y を得る）
- **根拠**：torus711 氏の記事（evidence）のルール：手札から 1 枚出し、出したカードより小さい場のカードを 1 枚まで手札に加えてよい。枚数は「出すだけ」なら 1 減り、「出して取る」なら変わらない
- **直し方**：「手札に書かれた数の合計（2 人分）は 1 手ごとに必ず減り」と書く。あるいは「手札の枚数が減るか、枚数が同じでも書かれた数の合計が減る」とする

### 3. 直すとよい｜事実（F3）｜#dp-map-sparse「⌊N/2⌋・⌊N/3⌋ への遷移」

- **問題**：「2^a 3^b ≤ N となる組 (a, b) は、a ≤ 60、b ≤ 38 の範囲の約千通り」。N = 10^18 では 2^60 > 10^18、3^38 > 10^18 なので、範囲の上限は a ≤ 59、b ≤ 37。組の数は 1178 通り（現れる値が 1012 個なのは、⌊N/(2^a3^b)⌋ どうしの一致と 0 のため）
- **直し方**：「a ≤ 59、b ≤ 37 の範囲の約 1200 通りで、値どうしが一致するものを除くと 1012 個」のように直す（「約千」のままでも大きな誤りではない）

### 4. 直すとよい｜事実（F3）・確認問題（U8）｜#dp-map-sparse の確認問題「現れる値の個数」の答え

- **問題**：a ≤ 60、b ≤ 38、c ≤ 26 は指摘 3 と同じく 1 ずつ大きい（59・37・25）。答えは「およそ 10^4」の見積もりだけで、実際の数がない（執筆者の未解決の点）
- **根拠**：2^a3^b5^c ≤ 10^18 の組は 10917 通り、実際に現れる値は 7254 個（手元の Python で数えた）。「およそ 10^4 通り、一致を除くと実際はそれ以下」という結論は正しい
- **直し方**：上限を 59・37・25 にし、「実際に数えると 7254 個」を足す。本文の 1012 個と並べると、見積もりの使い方が伝わる

### 5. 直すとよい｜分かりやすさ（U7）｜#write-memo の図・本文と、練習の ABC275 D

- **問題**：図と本文の例（f(0)=1、f(k)=f(⌊k/2⌋)+f(⌊k/3⌋)、N=10^18 で 1012 個・メモなし 4.5×10^14 回）が、練習問題 ABC275 D の漸化式そのもので、練習の方針まで本文で解き終わっている。練習として解く意味が薄く、本文を読んだ後に要約を見ると答えが分かる
- **根拠**：台帳の abc275_d の summary「f(0) = 1、f(k) = f(⌊k/2⌋) + f(⌊k/3⌋) で定まる f(N) を求める」と図の式が同じ。catalog の visual の text が「N → ⌊N/2⌋・⌊N/3⌋ の木」なので、図の題材としては指示どおり
- **直し方**：(a) 図と本文の漸化式の定数を変える（例：f(0)=0 にして f(k)=k+f(⌊k/2⌋)+f(⌊k/3⌋) など）か、(b) 練習の方針で「本文の図の漸化式そのもので、本文の書き方で解ける。手で書いて確かめる問題」と位置づけを明記する。どちらにするかはメインの判断に任せる

### 6. 直すとよい｜コード（C3）｜#write-memo のコードの前の文

- **問題**：本文は「f(n) = max(n, f(⌊n/2⌋) + f(⌊n/3⌋) + f(⌊n/4⌋))」とだけ書き、終わりの値 f(0) = 0 がない。4 段の 1 段目（終わりの状態）に当たる行がコードにあるのに、本文の式に対応がない。また本文の式は N の範囲を書いていないが、コードは n ≤ 10^17 に制限している（10^18 では答えが long long を超えうるため）
- **直し方**：「f(0) = 0、f(n) = max(…)（n ≤ 10^17）」と書く

### 7. 直すとよい｜分かりやすさ（U2）｜#vs-bottom-up「途中で打ち切れる」

- **問題**：「勝てる手が 1 つ見つかれば残りの手を調べなくてよい」は、ボトムアップでも 1 つの状態の中のループは break できるので、メモ化再帰だけの利点に見えない。利点は「調べなかった手の先の局面が、ほかから届かなければ一度も計算されない」ことにある
- **直し方**：「残りの手の先の局面は計算されずに済む（ボトムアップでは表のすべての局面を計算する）」と一言足す
