## 指摘

### 1｜直すべき｜図（G3）｜half-open.svg

- **問題**：viewBox の幅が 620 で、図の右端の約 120 は 1 行目の見出しのほかは空いている。スマホの表示幅（約 358px）では縮尺が 0.58 になり、本文の文字（font-size 15）が約 8.7px、a[i]・S[k] の添字のラベル（13）が約 7.5px になって読むのがつらい
- **根拠**：幅 390px の画面で画像にして確認した（narrow.png）。358 / 620 × 15 ≈ 8.7、× 13 ≈ 7.5。complexity-estimation の検証の指摘 3(c) と同じ基準（スマホで 10px 以上）
- **直し方**：棒と折れ線は x = 60〜500 にあるので、viewBox を幅 520 前後に詰め、長い見出し（1 行目・3 行目）は 2 行に折るか短くする。あわせて font-size を 17〜18 に上げると、スマホでも 10px 以上になる

### 2｜直すとよい｜図（G5）｜half-open.svg の「差 10」の矢印

- **問題**：赤の破線は $S_2$ の高さ（y = 436）から右へ伸びているが、$S_5$ の高さ（y = 326）には線がなく、矢印が x = 450（$S_5$ と $S_6$ の間）に立っているので、矢印の上端が $S_5 = 14$ を指していることが読み取りにくい。$S_6 = 16$ を指すようにも見える
- **根拠**：等倍の画像（full.png）で確認した
- **直し方**：$S_5$ の点から右へ同じ破線（y = 326、x = 420〜450）を引き、矢印をその 2 本の破線の間に置く。または矢印を x = 420 の点線に重ねて、$S_2$ の高さから $S_5$ の点まで引く

### 3｜直すとよい｜分かりやすさ（U3）・記法（F7）｜#abc122_c の「解法の詳細」

- **問題**：「$S[i] = \text{A}$ かつ $S[i+1] = \text{C}$」で文字列を $S$ と書いているが、このページでは $S$ は累積和の記号である。累積和の $T$ と並ぶので、$S_i$（累積和）と $S[i]$（文字）を取り違えやすい
- **根拠**：ページの #half-open 以降、$S_k$ は一貫して累積和
- **直し方**：文字列を小文字の $s$ にするか、「文字列の $i$ 文字目が A で $i + 1$ 文字目が C のとき」と言葉で書く

### 4｜直すとよい｜事実（F2）・分かりやすさ（U3）｜#pitfalls の「`accumulate` の初期値の型」

- **問題**：「同じ理由で、`partial_sum` や `inclusive_scan` は先頭に 0 を置かないので…添字が 1 つずれる」は、前の文（初期値の型であふれる）と理由が違い、「同じ理由で」がつながらない。`partial_sum` の足し算の型は入力の要素の型で、初期値の型の問題は起きない
- **根拠**：`std::partial_sum` は入力イテレータの値の型で累積する（cppreference の std::partial_sum）。先頭に 0 を置かないのは別の問題
- **直し方**：別の段落（太字の見出し「`partial_sum` は $S_0$ を作らない」など）に分け、「`s[0] = 0` を置き、`partial_sum(a.begin(), a.end(), s.begin() + 1)` と書けば $S$ になる」と避け方を添える

### 5｜直すとよい｜事実（F2）｜#circular の 3 段落目（ケーキの型）

- **問題**：「各始点 $i$ について $T_j = T_i + (\text{全体の和}) / 10$ となる $j$ を二分探索すればよい」に、全体の和が 10 で割り切れないときは No、という条件がない。割り切れないと整数の $/$ が切り捨てになり、誤って Yes を返しうる
- **根拠**：Reputeless の 076.md の解答も、まず全体が 10 で割り切れるかを調べている
- **直し方**：「全体の和が 10 で割り切れなければ不可能で、割り切れるなら…」と条件を足す。なお、この型は台帳にない問題（typical90_bx）なので、執筆者の「問題の補充の候補」をメインで判断してほしい

### 6｜直すとよい｜事実（F2）｜#next-tools の最後の段落（積）

- **問題**：「mod の積には左右からの累積かセグメント木を使う」は、任意の区間 $[l, r)$ の積の話の中に「左右からの累積」を挙げていて、左右からの累積では 1 つ除いた値しか求まらないことと食い違う
- **根拠**：#left-right の節（左右からの累積で求まるのは端を含む区間の組み合わせだけ）
- **直し方**：「1 つ除いた積なら左右からの累積、任意の区間の積ならセグメント木を使う」と分ける（0 の個数を別の累積和で数え、0 以外の積を累積する方法に触れてもよい）

### 7｜直すとよい｜事実（F9）｜参考の 1 行目（drken の ABC122 C）

- **問題**：「例題の累積和の取り方」とあるが、この hatenablog の記事は本文が「累積和」の一言と Qiita へのリンクだけで、累積和の取り方は書かれていない
- **根拠**：https://drken1215.hatenablog.com/entry/2019/03/28/181705 を読んだ。取り方は drken の Qiita「累積和を何も考えずに書けるようにする！」（https://qiita.com/drken/items/56a6b68edef8fc605821）の問題 3 にあり、半開区間 $[l, r)$ と $s_0 = 0$ で答える点が本文の方針と一致する
- **直し方**：参考の行を Qiita の記事に替えるか、Qiita の記事を足す。台帳への提案：abc122_c の evidence に Qiita の URL を足す
