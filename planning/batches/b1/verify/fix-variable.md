## 指摘

### 1｜直すべき｜事実（F2）・分かりやすさ（U3）｜#fix-middle の最後の段落

- **問題**：「条件が値の大小（$A_i < A_j < A_k$ など）でも、同じく真ん中を固定する。左右の個数は、ソート済みの列での二分探索や BIT で求める」とある。$i < j < k$ の位置の条件があるとき、「$j$ より左にあって $A_j$ より小さいものの個数」は、列全体をソートした列での二分探索では求められない（ソートすると位置の情報が消える）。読者は二分探索で数えようとして誤った解を書く
- **根拠**：反例 $A = (2, 3, 1)$（0-indexed）、$j = 1$（値 3）：$j$ より左で 3 より小さいものは 1 個（値 2）だが、ソート済み $(1, 2, 3)$ で 3 未満を数えると、$j$ より右の値 1 も入って 2 個になる。二分探索で済むのは、arc084_a のように位置の条件がなく 3 つの別の列から 1 つずつ選ぶときである。本文の #speed-up の表でも「左側にある、値が $A_j$ より小さいものの個数」は BIT としており、この段落と食い違う
- **直し方**：「位置の条件 $i < j < k$ もあるなら、左右の個数は $j$ を動かしながら [BIT](../ds/fenwick-tree.md) で数える。位置の条件がなく、3 つの別の列から 1 つずつ選ぶ（$A_i < B_j < C_k$）なら、各列をソートして[二分探索](../basics/binary-search.md#fix-one-side)で数えられる」のように 2 つの場合を分ける

### 3｜直すとよい｜事実（F2）｜#fix-middle の 2 段落め

- **問題**：「$i$ を決めても $j < k$ という $j$ と $k$ の関係が残るので、2 重ループが要る」は言い過ぎである。右側の「B の後に C が来る組の数」を後ろから前計算すれば、左端を固定しても $O(N)$ で数えられる（DP の形）。「要る」と言い切ると、読者は左端固定が必ず遅いと誤解する
- **根拠**：$\mathrm{bc}[i]$ ＝ 位置 $i$ 以降の (B, C) の組の数は、後ろから C の個数を持てば $O(N)$ で作れる
- **直し方**：「$j$ と $k$ の関係が残り、残りの数え方は単純な積にならない（もう 1 段の前計算が要る）」のようにする

### 4｜直すとよい｜事実（F1）｜#speed-up の尺取り法の文

- **問題**：「二分探索の代わりに尺取り法で、全体を $O(N)$ にできる」とあるが、直前の表の行は「ソートして二分探索」で、ソートに $O(N \log N)$ かかる。すでにソートされていない限り、全体は $O(N)$ にならない
- **根拠**：表の 1 行目の前提（ソート済み）
- **直し方**：「ソートの後の数える部分を $O(N)$ にできる」とするか、「（ソートを除いて）」を足す

### 5｜直すとよい｜分かりやすさ（U9・U3）｜#practice の ARC102 C の方針（190 行）

- **問題**：「『余りが $r$ の数の個数』×『余りが $s$ の数の個数』の 2 乗を足す」は、2 乗が積全体にかかるとも読める。正しいのは $\mathrm{cnt}[r] \times \mathrm{cnt}[s]^2$（$b$ と $c$ の 2 つ分）である。また 1 文が 155 字あり、textlint の文の長さの警告が出ている
- **根拠**：総当たりで $\mathrm{cnt}[r] \cdot \mathrm{cnt}[s]^2$ が一致することを確かめた（chk.py）。$(\mathrm{cnt}[r] \cdot \mathrm{cnt}[s])^2$ では一致しない
- **直し方**：文を 2 つに分け、「条件を満たす $r$ ごとに、$a$ の選び方 $\mathrm{cnt}[r]$ と、$b$・$c$ の選び方 $\mathrm{cnt}[s]$ ずつの積 $\mathrm{cnt}[r] \cdot \mathrm{cnt}[s]^2$ を足す」と書く
