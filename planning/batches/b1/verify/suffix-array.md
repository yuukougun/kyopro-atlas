## 指摘

### 1｜直すとよい｜図（G3）｜banana.svg（幅 700 の viewBox、文字 12〜14）

- **問題**：スマホの本文の幅（約 358px）に縮むと 0.51 倍になり、見出しの行（font-size 12）は約 6px、表の文字（14）は約 7px になる。マスの中の文字は読めるが、列名「順位 i」「sa[i]」と下の 3 行の説明は読みにくい
- **根拠**：上の 358px の画像。右の棒の列（x = 440〜660）が幅の 3 割を使い、左の表と離れている
- **直し方**：右の棒の列を表のすぐ右（x ≈ 330）へ寄せて viewBox の幅を 560 前後に縮めるか、下の 3 行の説明を本文の文章に任せて図から外す（本文の 65・69 行がすでに同じことを言っている）

### 2｜直すとよい｜分かりやすさ（U7）・事実（F5）｜#practice の「方針」ABC452 G（264 行）

- **問題**：「切った部分の列を…つなぎ」の「部分の列」が、元の数列の要素の列なのか、塊を 1 文字にした列なのかが書かれていない。元の要素のまま（l > c の塊を長さ l のまま両側に置く）と読むと、数える対象が変わって答えが合わない
- **根拠**：ikatakos 氏の記録の解法の節では、各塊を値 c の 1 文字として扱い、l > c の塊は前の部分の末尾と次の部分の先頭に「c の 1 文字」として置く（どの連続も長さちょうど c なので、値だけで形が決まる）
- **直し方**：「各塊を値 c の 1 文字に置き換え（使える塊はどれも長さちょうど c で並ぶので、値だけで決まる）、…」と一言足す。あわせて、執筆者の台帳の提案（abc452_g の summary を具体的にする）に賛成する。今の要約「条件を満たす連続部分列の種類数」では、読者が問いを思い出せない（U7）

### 3｜直すとよい｜分かりやすさ（U4）｜#rotations（164〜166 行）

- **問題**：$X$ の SA には、回転に当たらない接尾辞（位置 $N$〜$2N - 1$ と $3N$ 以降）も混ざる。本文は「位置 $i$ と $2N + j$ が回転」とは書くが、それ以外の接尾辞を数えずに読み飛ばすこと、それらがブロックに混ざっても数に影響しないことを書いていない。コード片は `sa[k] < n` と `2n ≤ sa[k] < 3n` だけを数えているが、本文だけで実装すると全部を S・T に振り分けてしまいうる
- **根拠**：rotations.cpp の 23〜26 行
- **直し方**：166 行に「位置 $N$〜$2N - 1$ と $3N$ 以降の接尾辞は回転ではないので数えない（同じまとまりに入っても、S・T のどちらとしても数えなければ影響しない）」と 1 文足す

### 4｜直すとよい｜分かりやすさ（U3）｜#build-your-own の Kasai 法（202 行）

- **問題**：「$S[q + 1, N)$ は $S[p + 1, N)$ より前にあり、先頭 $h - 1$ 文字が一致する」から「位置 $p + 1$ での値（辞書順で直前の接尾辞との LCP）は $h - 1$ 以上」への橋がない。直前の接尾辞は $S[q+1, N)$ そのものとは限らないので、読者は「なぜ直前とも $h - 1$ 文字一致するのか」で止まる。また $h \ge 1$ の場合の議論であること（先頭の文字が一致するので 1 文字落としても順序が保たれる）が書かれていない
- **根拠**：U3「飛躍」。必要なのは #lcp-rmq の性質（間にある接尾辞も同じ先頭 $h - 1$ 文字を持つ）
- **直し方**：「（$h \ge 1$ なら）先頭の 1 文字が同じなので、それを落とした $S[q + 1, N)$ は $S[p + 1, N)$ より前にあり、先頭 $h - 1$ 文字が一致する。辞書順でその間にある接尾辞も同じ $h - 1$ 文字を持つ（[任意の 2 接尾辞の LCP](#lcp-rmq)）ので、直前の接尾辞との LCP も $h - 1$ 以上である」とする

### 5｜直すとよい｜事実（F2）｜#concat-separator（150 行）「区切りが 2 つ以上になると、文字の種類では足りないので `vector<int>` にする」

- **問題**：区切りが 2〜3 個なら `#`・`$`・`%` など英小文字にない文字で `string` のまま作れるので、「2 つ以上で足りない」は言い過ぎである。足りなくなるのは、区切りの数が char で表せる値の数（256 から使う文字を除いた数）を超えうるとき
- **根拠**：char は 256 通りの値を持ち、ACL の `suffix_array(string)` はそのまま扱う
- **直し方**：「文字列の数が多い（数百を超えうる）と区切りに使える文字が足りないので、`vector<int>` にする」とする

### 6｜直すとよい｜事実（F3）｜#build-your-own（199 行）「組の順位はどちらも $0$ 以上 $N$ 未満の整数なので」

- **問題**：後ろの順位は、はみ出したとき $-1$（196 行）で、最初の段の順位は文字の値（コード片では 0〜255）である。「0 以上 N 未満」は 2 段目以降の前の成分だけに正しい
- **根拠**：本文 196 行と doubling.cpp の `rnk[i] = (unsigned char)s[i]`・`: -1`
- **直し方**：「組の値はどちらも $-1$ 以上 $\max(N, 256)$ 未満の整数なので（$-1$ は 1 つずらして 0 にする）」のように、範囲を値の数 $O(N + \sigma)$ で言う

### 7｜直すとよい｜分かりやすさ（U4）｜#distinct-substrings の証明（90 行）と #kth-substring（176 行）

- **問題**：$i = 0$ のときの $\mathrm{lcp}[i-1]$ の扱いが、この 2 節では書かれていない（「$\mathrm{lcp}[-1] = 0$ とする」は #concat-separator の 152 行にだけある）。節を単独で読むと（U6）、$i = 0$ の項で迷う。#kth-substring の擬似コードには `(i > 0 ? lcp[i-1] : 0)` があるが、本文の文にはない
- **根拠**：U4「初期値・番兵の扱いがない」、U6「節の中で定義のない記号」
- **直し方**：#distinct-substrings の証明の「よって…」の文に「（$i = 0$ では $\mathrm{lcp}[-1] = 0$ とする）」を足す。#kth-substring の 176 行にも同じ括弧を足す

### 8｜直すとよい｜記法（F7）｜#definition の見出しと sections の title「lcp の長さは n−1」

- **問題**：本文は長さを $N$ と書くが、見出しだけ小文字の n である（§6 の文字は $N$）
- **根拠**：手引き §6「列の長さ $N$」。本文 58・61 行は $N$
- **直し方**：見出しと front matter の sections の title を「lcp の長さは N−1」にそろえる（§13.2 により両方を同時に直す）

### 9｜直すとよい｜コード（C5）｜pattern-count.cpp の `(cmp(mid, t) >= 0 ? ok : ng) = mid;`

- **問題**：条件演算子の結果に代入する書き方は、手引きの読者（現代的な書き方に不慣れ）には読みにくい。二分探索のページ（basics/binary-search）の書き方とそろっているかも確かめたい
- **根拠**：手引き §9「読みやすさを優先する」
- **直し方**：`if (cmp(mid, t) >= 0) ok = mid; else ng = mid;` にする（2 か所）。二分探索のページが同じ書き方を使っているなら、そのままでよい
