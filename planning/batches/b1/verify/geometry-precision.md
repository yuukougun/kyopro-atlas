## 指摘

### 1｜直すべき｜事実（F2）・分かりやすさ（U4）｜#double-coordinates の垂直二等分線の段落（156 行）と、練習の方針の ABC467 D・力試しの方針の ABC220 G

- **問題**：垂直二等分線 $2(x_2 - x_1) x + 2(y_2 - y_1) y + (x_1^2 + y_1^2 - x_2^2 - y_2^2) = 0$ について「[直線の正規化](#line-normalization)がそのまま使える」と書いている。しかし #line-normalization の手順は「$(a, b)$ を gcd で割って符号をそろえ、**直線上の格子点から** $c$ を計算する」ものである。垂直二等分線は格子点を通るとは限らず（中点は半整数）、$\gcd(a, b)$ で割ると $c$ が整数にならないことがある。このため、この手順は使えない。ABC467 D の「正規化した $(a, b, c)$ の一致で判定」と ABC220 G の「垂直二等分線（正規化した直線）でまとめる」は、この手順を前提にしている
- **根拠**：$P = (0, 0)$、$Q = (1, 0)$ では $(a, b, c) = (2, 0, -1)$。$\gcd(a, b) = 2$ で割ると $c = -1/2$ になる。`normalize.cpp` の `line_through` も 2 つの格子点を通る直線用で、二等分線には使えない。comet725 氏の ABC467 D の記事は $g = \gcd(a, \gcd(b, c))$ で 3 つとも割り、$a < 0$、または $a = 0$ かつ $b < 0$ なら 3 つの符号を反転している（hyouri 氏は約分せず、掛け算で比べている）
- **直し方**：#double-coordinates の段落を、たとえば次のように直す。「係数が整数の直線になる。ただし格子点を通るとは限らないので、$c$ を点から計算し直す[直線の正規化](#line-normalization)の手順は使えない。代わりに $\gcd(\lvert a \rvert, \lvert b \rvert, \lvert c \rvert)$ で 3 つとも割り、$(a, b)$ と同じ規則で 3 つの符号をそろえる」。#line-normalization の末尾にも、係数が先に決まっている直線は 3 つの gcd で割るという一文を足すとよい。ABC467 D の方針は、平行の判定を $a_1 b_2 = a_2 b_1$、同じ直線の判定を 3 つの gcd で正規化した組の一致（または $a_1 c_2 = a_2 c_1$ かつ $b_1 c_2 = b_2 c_1$ を `__int128` で）にする。座標が $10^9$ なら $c$ は $2 \times 10^{18}$ 規模なので、掛け算には `__int128` が要ることにも触れる

### 2｜直すとよい｜図（G5）・事実（F3）｜double-spacing.svg の 1 行目と代替テキスト（57 行）

- **問題**：「仮数を 2 ビットにした」としているが、1〜2 の間隔が 1/4 になるのは、暗黙の 1 を含めて 3 ビット（小数部 2 ビット）の場合である。同じ図と本文では、double を暗黙の 1 を含めた「仮数 53 ビット」と数えているので、数え方が食い違う。この数え方なら、2 ビットの仮数では 1〜2 の間隔は 1/2 になる
- **根拠**：double は小数部 52 ビットで、1 での間隔は $2^{-52}$。図の 1〜2 には 1, 1.25, 1.5, 1.75 の 4 点がある。つまり小数部は 2 ビットである
- **直し方**：図の 1 行目と代替テキストを「仮数を 3 ビット（小数部 2 ビット）にした」か「小数部を 2 ビットにした」にする
