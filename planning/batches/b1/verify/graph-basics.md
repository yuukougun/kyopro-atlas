## 指摘

### 1｜直すべき｜事実（F2）｜#representations の表、辺リストの行

- **問題**：「速い操作」の列が「全辺を重みの順に並べ替えて順に見る」で、使う手法にベルマンフォード法を並べている。並べ替えるのはクラスカル法だけで、ベルマンフォード法は全辺を（順序に関係なく）繰り返し見るだけである。ベルマンフォード法も並べ替えると読める
- **根拠**：ベルマンフォード法は「全辺の緩和」を $N - 1$ 回繰り返す手法で、辺の順序は正しさに関係しない
- **直し方**：「全辺を 1 本ずつ順に見る（重みの順に並べ替えるのも簡単）」のように、並べ替えをクラスカル法の側の話として書く

### 2｜直すべき｜手引き（§13.1）｜#pitfalls の見出しと front matter の sections

- **問題**：落とし穴は §13.1 で定型の節とされ、sections に載せず `## 落とし穴 {#pitfalls}` と書く決まりだが、sections に載ったまま、見出しが「落とし穴（1-indexed・無向グラフは両方向に追加・多重辺・重みの和のあふれ）」と長い。執筆者も未解決の点に挙げている。同じバッチの見本 complexity-estimation（commit 91d7715）は sections から外して `## 落とし穴 {#pitfalls}` にしている
- **根拠**：style-guide §13.1（上の各節より優先）、docs/basics/complexity-estimation.md の sections と 164 行
- **直し方**：sections から pitfalls の行を外し、見出しを `## 落とし穴 {#pitfalls}` にする（§2.1 では sections の行を外す権限があいまいなので、メインが直すか、執筆者に許す）。binary-search など同じ形のページもそろえる

### 3｜直すべき｜図（G3）｜representations.svg

- **問題**：viewBox が 900×300 の横長で、4 つの図を横 1 列に並べているので、スマホの幅（表示幅 約 358px）では倍率が約 0.4 になり、本文の文字（15px）が約 6px、凡例と下の注記（13px）が約 5px になる。g[·] の数字や辺リストの文字が読めない
- **根拠**：幅 390px で描いた画像（scratchpad/v-graph-basics/mobile.png）。complexity-estimation の検証の指摘 3（約 7.8px で必須）より小さい
- **直し方**：2×2 の並び（上段にグラフと隣接リスト、下段に隣接行列と辺リスト。viewBox を幅 460 前後）にして、凡例を 2 行に折る。スマホで文字が 10px 以上になるようにする

### 4｜直すべき｜手引き（§7・F7）｜同じページへのリンクの重複

- **問題**：ページの中で最初の 1 回だけのはずのリンクが 2 回ある。DFS と BFS（#representations の表と、練習の方針の「深さ優先探索」「幅優先探索」）、トポロジカルソート（表と #terms の DAG）、オイラー路（#adjacency-extras と #handshake）
- **根拠**：`grep` でリンク先を数えた（dfs.md・bfs.md・topological-sort.md・euler-path.md がそれぞれ 2 回）。style-guide §7「用語へのリンクはページの中で最初に出たときの 1 回だけ」
- **直し方**：2 回目のリンクを外し、語だけにする

### 5｜直すとよい｜図（G5）｜representations.svg の隣接リスト g[2]

- **問題**：g[2] を (1, 0, 3) の順に描いているが、図の辺リスト (0, 1)・(0, 2)・(1, 2)・(2, 3) を本文のコード片の順で読むと g[2] は (0, 1, 3) になる。g[0]・g[1]・g[3] は辺リストの順と合っているので、g[2] だけが食い違う。辺 e を先頭に置いて目立たせたかったのかもしれないが、「辺リストから隣接リストを作る」コードと並べて読むと迷う
- **根拠**：snippets/graph-basics/build.yaml の 2 つ目の case（図と同じ形）を作る順と、手で辿った結果
- **直し方**：g[2] を 0, 1, 3 の順にし、橙の枠を 2 つ目のマスに移す。あわせて、代替テキストの「辺リストの 2 番目の行」は 0 から数えた番号なので、「辺リストの 2 番目（0 から数える）の行」か「(1, 2) の行」にすると取り違えない

### 6｜直すとよい｜事実（F1）｜front matter の complexity・要点の計算量・表のメモリ

- **問題**：complexity と要点はメモリを「隣接リストと辺リストで $O(N + M)$」、表は辺リストを $O(M)$ としていて、3 か所がそろわない
- **根拠**：辺リストは辺の数だけの列なので $O(M)$。表のほうが正確
- **直し方**：complexity と要点を「隣接リスト $O(N + M)$、辺リスト $O(M)$、隣接行列 $O(N^2)$」にそろえる

### 7｜直すとよい｜事実（F2）・分かりやすさ（U3）｜#terms の「閉路」

- **問題**：直前でパスを「頂点の繰り返しを許さない列」と定義しているので、「始点に戻ってくるパス」は定義どおりに読むと存在しない
- **根拠**：本文のパスの定義
- **直し方**：「始点と終点だけが同じで、ほかの頂点は繰り返さないウォーク」などとする。無向グラフで同じ辺を往復するもの（長さ 2）は閉路に数えないことも一言あるとよい

### 8｜直すとよい｜事実（F3）・分かりやすさ（U9）｜#representations の「long long でも 32 MB に収まる」と #pitfalls の「$2 \times 10^{14}$」

- **問題**：(a) $4 \times 10^6 \times 8$ バイトはちょうど 32 MB なので「32 MB に収まる」は何に収まるのかが読めない。(b) 「重みが $10^9$ まででも、$N - 1$ 本の辺を通るパスの長さは $2 \times 10^{14}$」は $N = 2 \times 10^5$ を前提にしているが、文に $N$ の値がない
- **根拠**：$2000^2 \cdot 8 = 3.2 \times 10^7$ バイト。$(2 \times 10^5 - 1) \cdot 10^9 \approx 2 \times 10^{14}$
- **直し方**：(a)「`long long` でも約 32 MB で、メモリ制限（1024 MiB）に十分収まる」。(b)「$N = 2 \times 10^5$、重みが $10^9$ までなら」とする

### 9｜直すとよい｜事実（F2）｜#adjacency-extras の CSR

- **問題**：「`vector` の中に `vector` を持つより速い」と言い切っているが、執筆者は計測しておらず、根拠も本文にない
- **根拠**：執筆者の未解決の点 2。速さの差は場合により（構築の手間が増える、差が小さいことも多い）
- **直し方**：「メモリが連続するので、`vector` の中に `vector` を持つより速いことが多い」と理由を添えて弱める

### 10｜直すとよい｜分かりやすさ（U4）・コード（C3）｜#representations の matrix のコード片の前の文

- **問題**：コード片は対角 `d[v][v] = 0` を入れているが、前の文は「辺のない組を INF で埋め、多重辺は最小を取る」だけで、対角に触れない。自己ループ（重み $w \ge 0$）があっても対角が 0 のままになる理由も書かれていない
- **根拠**：snippets/graph-basics/build.cpp の matrix の範囲
- **直し方**：「対角（自分から自分）は 0 にする」を足す。自己ループは `min` で 0 のまま残ることに一言触れてもよい

### 11｜直すとよい｜問題（F5・§10）｜#practice の数と台帳の提案

- **問題**：練習が 1 問で、手引き §10 の目安（2〜6）に足りない。例題の囲みの要約「…の個数についての条件を満たす頂点を数える」は条件が分からない
- **根拠**：ap.py で abc343_b（B. Adjacency Matrix、diff 53）・abc276_b（B. Adjacency List、diff 143）の実在と題名・diff を確かめた。例題の条件は sol/078.cpp で確かめた
- **直し方**：執筆者の提案（abc343_b → abc276_b → abc284_c の順で practice に追加、typical90_bz の summary の直し）に賛成する。台帳への提案：typical90_bz と abc284_c の `checked` に 2026-10-21 を入れる

### 12｜直すとよい｜分かりやすさ（U4）｜#pitfalls の「自己ループは隣接リストで $g[u]$ に $u$ 自身として現れる」

- **問題**：本文のコード（無向で両方向に足す）では、自己ループは $g[u]$ に $u$ が 2 回入る。確認問題の答え（「自己ループも $u$ の列に 2 回入る」）とは合っているが、落とし穴の文だけ読むと 1 回と取れる
- **根拠**：build.yaml の 3 つ目の case で頂点 2 の次数が 4（多重辺 2 本 + 自己ループで 2）
- **直し方**：「無向グラフとして両方向に足すと、$g[u]$ に $u$ 自身が 2 回現れる」とする
