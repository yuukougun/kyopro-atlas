## 指摘

### 1｜直すべき｜fact（F2）・clarity（U3）｜#offset の「順序が保たれれば、足し算以外の操作にも同じ考え方が使える。」（67 行付近）

- **問題**：この前置きの後に挙げる 2 つ（XOR、$a$ 倍して $b$ を足す mod $p$ の計算）は、どちらも大小の順を保たない。XOR の項目自身が「XOR は大小の順を保たない」と書いており、前置きと矛盾する。mod $p$ の値の $a$ 倍も順を保たない。読者は「順序が保たれる操作なら使える」のか「順序は要らない」のか分からなくなる
- **根拠**：反例。XOR：$1 < 2$ だが $1 \oplus 3 = 2 > 2 \oplus 3 = 1$。mod 7 で $2$ 倍：$3 < 4$ だが $6 > 1$
- **直し方**：前置きを「格納値と実際の値を 1 つの変数で行き来できれば、足し算以外の全体への操作にも同じ考え方が使える。ただし順序が保たれない操作では、ヒープや set の順序を格納値のまま使えない」のように直す。順序が要るかどうかは各項目で述べる（XOR の項目はいまの書き方でよい。$a$ 倍の項目にも「mod の値は大小の順を持たないので、ヒープとは組めない」を足す）

### 2｜直すべき｜fact（F5・F9）｜#references の hamayan の行の説明「練習の方針（前半と後半の入れ替えを実際には行わない）」、および執筆者の台帳への提案（abc199_c の evidence）

- **問題**：hamayan の記事は反転フラグ（入れ替わっているかのフラグ）を使っていない。文字列を前半 pre と後半 post の 2 つに分けて持ち、前半と後半の入れ替えを `swap(pre, post)` で行い、2 文字の入れ替えは位置で 3 通りに場合分けする。本文の練習の方針（フラグを持ち、位置を $N$ ずらして読み替え、最後に入れ替えて出力）とは解き方が違い、方針の裏付けにならない。「入れ替えを実際には行わない」も記事の内容と合わない（記事は 2 つの文字列を実際に swap している）
- **根拠**：https://blog.hamayanhamayan.com/entry/2021/04/25/002202 の本文とコード（「前半をpre, 後半をpostとしておくと、preとpostのswapのみでT=2を完結させることができる」）
- **直し方**：次のどちらか。(a) 練習の方針はフラグのままにし、参考の説明を「前半と後半を別の文字列で持ち、入れ替えを 2 つの文字列の swap で済ませる別の方法」に直す（方針の裏付けとしてではなく、別法として挙げる）。台帳への提案の根拠の書き方も同じく直す。(b) フラグを使う解説を別に探して参考と台帳の evidence に足す。フラグの方法そのものの正しさは、上の無作為の確かめで確認済み

### 3｜直すとよい｜fact（F2）・clarity（U3）｜#to-lazy-segment-tree の「全体代入の節の base と diff はこの特殊な場合である」

- **問題**：保留を「代入するか・代入する値・足す値」の組で持つのは、同じ範囲に代入と加算が続けて来る場合の合成である。全体代入の節で全体にかかる操作は代入だけで、加算は 1 か所ずつ（diff は要素ごとの値）なので、この組の特殊な場合とは言いにくい。読者が両者の対応を探して迷う
- **根拠**：全体代入の節の操作は「全体に代入」「1 か所に足す」「1 か所を読む」で、全体への加算がない。組 (代入, 足す値) の「足す値」に当たる全体の量がない
- **直し方**：「全体代入（代入）とオフセット（加算）を 1 つの変数の組で持てば、全体に対してこの合成を行うことになる」のように、オフセットの節と全体代入の節を合わせた形として述べる。あるいはこの 1 文を削る

### 4｜直すとよい｜clarity（U4）｜#offset の「全体を $a$ 倍してから $b$ を足す」の項目

- **問題**：組 $(a', b')$ を持つとだけあり、全体への操作のときの更新式と、入れるときに格納する値が書かれていない。この項目だけでは実装できない
- **根拠**：実際の値 $a' t + b'$ に「$a$ 倍して $b$ を足す」を行うと $a a' t + (a b' + b)$
- **直し方**：「全体への操作では $a' \leftarrow a a'$、$b' \leftarrow a b' + b$。値 $v$ を入れるときは $(v - b') \cdot a'^{-1}$ を格納する」を足す。$a = 0$ は全体代入なので全体代入の節で扱う、と一言添えるとなおよい

### 5｜直すとよい｜clarity（U3）｜#offset の「ヒープ・set・ソート済みの queue とそのまま組める」

- **問題**：「ソート済みの queue」が何を指すか、この時点では分からない（queue は普通ソートされない）。実体は練習の ABC379 D の、入れる値が単調なので queue の並びがそのまま大小順になる場合
- **直し方**：「入れる格納値が単調で、並びがそのまま大小順になる queue」と言い換える。または「ソート済みの queue」を外し、練習の方針の ABC379 D に任せる

### 6｜直すとよい｜clarity（U4）｜#assign-all の最後の段落（配列と時刻で持つ別法）

- **問題**：「配列で持ちたいときは…その位置の値を base で上書きしてから使う」の配列が、diff を持つのか実際の値を持つのかが書かれていない。直前まで diff の話なので、diff の配列を base で上書きすると読める（その場合は 0 に戻すのが正しく、base で上書きすると誤り）
- **直し方**：「各位置の実際の値を配列 $A$ に、最後に書いた時刻を配列に持つ。読むときや足すときに、その時刻が最後の全体代入より前なら、まず $A_i \leftarrow \mathrm{base}$ としてから使う」と、配列が持つものを明記する

### 7｜直すとよい｜clarity（U9）｜#rotation の回転と反転を組む段落の最後「式を自分で導けば、どちらの操作も $O(1)$ になる」

- **問題**：式は直前で与えられているので「自分で導けば」が文脈に合わない。読者は何を導くべきか迷う
- **直し方**：「どちらの操作も $\sigma$ と $s$ の更新だけで $O(1)$ である」とする。導き方を見せたいなら、右回転についても「新しい $i$ 番目は古い $i - 1$ 番目なので」と反転と同じ形で 1 句添える

### 8｜直すとよい｜code（C3）｜snippets/global-offset/flip-deque.cpp の `deque<int> d;`

- **問題**：オフセットの節とコード片 offset-heap では `d` がオフセットを表すが、flip-deque では同じ `d` が deque そのものになる。同じページで同じ名前が別の物を指し、取り込まれた `d[i]`・`d.size()` を「オフセット？」と読み違えやすい

### 9｜直すとよい｜fact（F7）｜#pitfalls の「回転量を $s - 1$ や $s - k$ で減らすと、C++ の `%` は負の値を返す」

- **直し方**：「$s - k$ が負になると、C++ の `%` は負の値を返す」とする

### 10｜直すとよい｜figure（G5）｜offset.svg の箱の並び

- **問題**：上の行の操作は「5 → 6 → 5」の順に入れているが、箱は左から格納値の小さい順（最後に入れた 5 が左端）に並ぶ。入れた順に並んでいると思って読むと、左端の「5 − 5」が最初の 5 に見えて合わない
