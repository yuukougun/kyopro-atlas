## 指摘

### 1｜直すべき｜事実（F1）｜要点の計算量（43 行）・front matter の complexity（14 行）・#what-it-does の表（58 行）

- **問題**：追加（push）の $O(\log N)$ がならしであることが、要点・complexity・表に書かれていない。本文の 54 行は「再確保を含めるとならし $O(\log N)$」と書いており、3 か所が本文と食い違う。手引き §2.2（計算量には条件を書く）と §5 ds（ならしかどうかを明記する）に反する
- **根拠**：`priority_queue::push` は中の `vector::push_back`（ならし定数時間、再確保のときは $O(N)$）と `push_heap`（$O(\log N)$）を呼ぶ。fact.md F1 の「よくある失敗」に vector の push_back が挙がっている
- **直し方**：要点と complexity を「追加 ならし O(log N)、取り出し O(log N)、…」にし、表の push の行を「ならし $O(\log N)$」にする（取り出しは再確保がないので最悪 $O(\log N)$ のまま）

### 2｜直すべき｜事実（F5）・分かりやすさ（U7）｜#practice の「練習の方針」ABC116 D（292 行）

- **問題**：「おいしさの大きい代表から $K$ 種類を選び」「種類数 $x$ を $K$ から 1 つずつ減らしながら」は、ネタの種類が $K$ 未満のとき成り立たない（$K$ 種類を選べない）。方針どおりに書くと範囲外の参照か誤答になる
- **根拠**：evidence の drken 氏の記事は、空の種類に番兵として非常に小さい値を入れて $x = K$ から始めている（種類数が足りない $x$ は番兵のせいで答えにならない）
- **直し方**：「種類が $K$ 未満なら、$x$ を種類数から始める（または足りない種類に十分小さい番兵を置く）」を一言足す

### 3｜直すとよい｜事実（F1）｜要点（43 行）・complexity（14 行）と #lazy-deletion の計算量（171 行）

- **問題**：遅延削除の $M$ が、要点・complexity では「追加の回数」、本文では「追加と削除の回数の合計」で、定義が違う
- **根拠**：削除の回数は追加の回数以下なので漸近的には同じだが、F1 は 3 か所の一致を求める
- **直し方**：どちらかにそろえる。本文の数え方（push と erase を合わせた回数）にそろえるのが分かりやすい

### 4｜直すとよい｜事実（F2）｜#pitfalls「遅延削除で、集合にない値を erase する」（209 行）

- **問題**：「$\mathit{del}$ の top が $q$ の top より大きくなり、その値は永遠に捨てられない」は言い過ぎで、起きることを取りこぼしている。(a) 消した値が今の最大より小さければすぐには大きくならない。(b) 後で同じ値が push されると、それが代わりに消える（別の要素を消してしまう）。(c) $q$ が空のまま $\mathit{del}$ が残ると、`size()` が負になり、`empty()` が false を返し、top で空の $q$ の top を読む未定義動作になる
- **根拠**：erasable-heap.cpp に `2\n2 5\n3\n`（何もない集合から 5 を erase して最大を問う）を与えると、`-fsanitize=undefined` が `reference binding to null pointer`（空の priority_queue の top）を出した
- **直し方**：「$\mathit{del} \subseteq q$ が崩れると、捨てられない値が残る・後で入れた同じ値が代わりに消える・大きさの差が負になり空の $q$ の top を読む、のどれかが起きる」のように、「なりうる」と起きることを書く

### 5｜直すとよい｜分かりやすさ（U3）｜#binary-heap の heapify の段落の最後（108 行）

- **問題**：「上から下げるか下から上げるかで、手間が多い頂点の数が違う」が何と何の対比か読み取りにくい。heapify は「下（葉の近く）の頂点から順に、各頂点を下へ下げる」、push の繰り返しは「各頂点を上へ上げる」で、「上から／下から」が処理の順と動かす向きのどちらを指すのか迷う
- **直し方**：「heapify では各頂点が下げる距離（葉までの高さ）が手間で、高さの大きい頂点は少ない。push の繰り返しでは各頂点が上げる距離（根までの深さ）が手間で、深い頂点が多い。だから合計が違う」のように、距離が高さか深さかで言う

### 6｜直すとよい｜記法（F7）・分かりやすさ（U3）｜#binary-heap の「保つ性質」（80〜81 行）

- **問題**：81 行の $d[\mathrm{par}(v)]$ の $\mathrm{par}$ が定義されていない。80 行は「親は $\lfloor (v-1)/2 \rfloor$」と書くだけで記号を置いていない
- **直し方**：80 行を「親は $\mathrm{par}(v) = \lfloor (v - 1) / 2 \rfloor$」にする

### 7｜直すとよい｜分かりやすさ（U3）｜#pitfalls「最大と最小の向きを取り違える」（199 行）

- **問題**：「このとき `pair` の 2 つ目の成分の向きも一緒に逆になる」が何と比べて逆なのか分からない。1 つ目の成分だけに $-1$ を掛けると、同じ値のときの順は `greater` を使った場合と逆（2 つ目が大きい方が先）になる、という意味だと読めるが、「一緒に逆になる」は 2 つ目も最小順になるとも読める
- **直し方**：「1 つ目の成分だけに $-1$ を掛けると、1 つ目が同じときは 2 つ目の大きい方が先に出る（`greater` を使ったときと逆）。2 つ目も小さい順にしたいなら両方に掛ける」と書く

### 8｜直すとよい｜コード（C3）｜snippets/priority-queue/offset-heap.cpp 10 行のコメント

- **問題**：「中身は「実際の値 − 入れた時点からの加算を除いた値」」は意味が通らない。本文 140 行は「中身はどれも「実際の値 − $\mathit{add}$」」と書いており、コメントと本文が合わない
- **直し方**：`// 中身は「実際の値 − add」（add は今までの全体への加算の合計）` にする

### 9｜直すとよい｜図（G5）｜heap-push-pop.svg（本文 76 行）

- **問題**：左の push(0) と右の pop() が、同じ 7 要素のヒープ [1,3,2,6,4,8,5] から別々に始めていることが図にも本文にも書かれていない。左右を続けて読むと「push(0) の後に pop」と受け取り、根が 0 でないことに戸惑う。また左の木は「0 を末尾に置いた直後（上げる前）」、右の木は「5 を根に移した直後（下げる前）」の状態で、経路はこれから動く道であることも書かれていない
- **直し方**：図の前に「どちらも同じヒープ $[1, 3, 2, 6, 4, 8, 5]$ から始める。木は動かす前の状態で、赤い線が値の動く経路」と 1 文足す（図の題か代替テキストに入れてもよい）
