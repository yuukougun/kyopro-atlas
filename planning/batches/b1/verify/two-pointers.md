## 指摘

### 1｜直すとよい｜事実（F7）・コード（C3）｜#implementation の 1 つ目のコード片（at-most-k-kinds.cpp の core 1 行目）と 96 行

- **問題**：ページは「区間は半開区間 $[l, r)$ で書く」と決めているが、右端の for の書き方ではコードのコメントが「区間 $[l, r]$」と閉区間になり、96 行の本文も断りなく閉区間で数えている（「右端が $r$ の区間は $r - l + 1$ 個」）。閉区間であることの説明は落とし穴の 161 行まで出てこない
- **根拠**：50 行の宣言と、core の `// cnt[v]：区間 [l, r] に v が何個あるか`
- **直し方**：96 行に「この書き方では $r$ を入れた後の区間は $[l, r]$（半開区間なら $[l, r + 1)$）である」と一言足す。コメントは「区間 [l, r]（a[r] を入れた後）」とするか、そのままでも本文の一言があれば足りる

### 2｜直すとよい｜分かりやすさ（U3）｜#negative-values の 1 段落目

- **問題**：「右端を伸ばせなくなった時点で、左端を進めればまた伸ばせるとは限らず、右端を戻す必要が出る」は、例で起きていること（$r(0) = 2$ なのに $r(1) = 1$ で、$l$ を進めると今の区間 $[1, 2)$ がすでに条件を破る）と論点がずれていて、なぜ右端を戻すのかが読み取りにくい
- **根拠**：$A = (-1, 2)$、和 $\le 1$ で $r(0) = 2$、$r(1) = 1$（空区間）。$r(l)$ が減る
- **直し方**：「$l = 0$ の最大の右端は 2 だが、$l = 1$ では右端 2 の区間がもう条件を破るので、最大の右端は 1 に下がる。$r(l)$ が単調でなくなり、右端を戻す必要が出る」のように例の値で言う

### 3｜直すとよい｜分かりやすさ（U9）｜#pitfalls「積の条件で 0 を見落とす」

- **問題**：「0 がなければ $a_i \ge 1$ で積は単調なので尺取りできるが、0 で割って取り除く処理は書けない」は、0 がない場合の話の中で「0 で割る」と言っており、矛盾して読める
- **直し方**：「0 を含む区間からは 0 で割って取り除けない。0 がなければ $a_i \ge 1$ で積は単調なので、割って取り除く尺取りができる。だから 0 を先に場合分けする」と順を入れ替える

### 4｜直すとよい｜分かりやすさ（U3）｜力試しの方針の ARC098 D

- **問題**：「今の和と $a_r$ の XOR が和と等しいか」は、どの「和」と比べるのかが曖昧（今の和 $S$ と比べると読める）
- **根拠**：evidence の drken の記事は `(sum ^ a[right]) == (sum + a[right])` で判定している（https://drken1215.hatenablog.com/entry/2018/06/26/125054）。区間が条件を満たす間は XOR 和 = 和なので、今の和 $S$ を XOR 和の代わりに使える
- **直し方**：「今の和を $S$ として、$S \oplus a_r = S + a_r$ か（$S$ と $a_r$ に共通の bit がないか）で確かめ」とする。区間が条件を満たす間は XOR 和と和が等しいので和だけ持てばよい、と一言あるとさらによい

### 5｜直すとよい｜分かりやすさ（U3）｜#monotonicity の 71 行の最後の文

- **問題**：「より大きい区間も満たす型でも、…同じ理由で最小の $r(l)$ は単調に増える」は、1 つ目の型と議論の向きが違う（対偶を使う）のに「同じ理由」で片付けている。確認問題が和の場合だけを扱うので、一般の型の理由が本文にない
- **直し方**：「$r < r(l)$ なら $[l, r)$ は満たさず、その内側の $[l + 1, r)$ も満たさない（満たすなら含む $[l, r)$ も満たすはず）ので $r(l + 1) \ge r(l)$」と 1 文で書く

## 指摘しなかった点（確かめて問題なし）

- 2 つの型の表・数え方（$r - l$、$N - r + 1$）、否定を取ると型が入れ替わること、$N(N+1)/2$ から引く数え方
- XOR の性質：$a \oplus b \le a + b$ で等号は共通の bit がないときだけ。区間では「どの bit も 2 つ以上の要素で立たない」と同値で、部分区間で保たれる
- 負の値の反例、和がちょうど $K$ を 2 つの「以下」の差で数えること
- 固定長の窓（入る $a_{i+M}$・出る $a_i$）と、座標の窓で左端を点に合わせてよい理由（ABC326 C）
- 積のオーバーフローの見積もり（掛ける前の積 $\le K \le 10^9$、$a_i \le 10^9$ で $10^{18}$ 以下）
- 空区間から取り除かない理由（$\mathrm{sum} \ge K \ge 1$ なら $r > l$）。drken の qiita の一般形（`l == r` なら `r` を進める）とも一致
- ABC153 F の方針（最も左の生き残りを左端に含む貪欲、キューかいもす法）は evidence の drken の記事と一致。ARC022 B の「値の範囲が小さい」は $1 \le A_i \le 10^5$ で正しい
- front matter の変更は complexity・stage だけ。要点の計算量と complexity が一致
- コード片の書き方（bits・using namespace std・'\n'・マクロなし）、取り込みの印、cases が空列・1 要素・K = 0・同じ値・大きな値を含むこと
