## 指摘

### 1｜直すべき｜事実（F5）・分かりやすさ（U4）｜#abc331_f の「解法の詳細」（264〜266 行）

- **問題**：「入力は 1-indexed の閉区間なので $[L-1, R)$ に直す」とあるが、更新の行は「位置 $x$ の文字を $c$ にするときは、前向きの $x$ と後ろ向きの $N - 1 - x$ を `set` で書き換える」と $x$ をそのまま使っている。この問題では更新の $x$ も 1-indexed なので、書かれたとおりに実装すると 1 つずれる（$x = N$ で範囲外にもなる）
- **根拠**：syamashi の記事（evidence）。クエリは `1 x c`・`2 L R` で x・L・R がどれも 1-indexed、コードは 3 つとも 1 を引いている
- **直し方**：1 行目を「入力の位置はどれも 1-indexed なので、更新の $x$ は $x - 1$ に、質問の閉区間 $[L, R]$ は半開区間 $[L - 1, R)$ に直す」とし、更新の行を「0-indexed の位置 $i = x - 1$ について、前向きの $i$ と後ろ向きの $N - 1 - i$ を書き換える」にする

### 2｜直すべき｜事実（F2）・分かりやすさ（U3）｜#recommended-design の 111 行と、確認問題（122 行）・#collision-bound（99 行）の食い違い

- **問題**：#collision-bound で示す保証は「1 組あたり $(L-1)/p$ 以下」である。この上界で計算すると、111 行の「ハッシュを $10^6$ 個作って全部の組を比べても、衝突の確率は小さいままである」は成り立たない（組は約 $5 \times 10^{11}$、$L = 10^5$ なら $5 \times 10^{11} \times 10^5 / 2.3 \times 10^{18} \approx 0.02$、$L = 10^6$ なら約 0.2）。一方、確認問題の答えは「1 組あたり約 $10^{-9}$（= $1/p$）とみなす」で計算している。本文は $(L-1)/p$ と $1/p$ の 2 つの見積もりを、違いを説明せずに使い分けている。読者は「どちらで見積もるのか」で迷い、断片で読んだ claude.ai が 111 行を保証として扱うおそれもある
- **根拠**：上の計算。$1/p$ で見積もるなら $5 \times 10^{11} / 2.3 \times 10^{18} \approx 2 \times 10^{-7}$ で、111 行の主張はこの見積もりのときだけ成り立つ
- **直し方**：#collision-bound の箇条に 1 つ足す。たとえば「$(L-1)/p$ は、どんな 2 つの文字列でも保証できる上界である。多くの組を比べる見積もりでは、1 組あたり約 $1/p$ とみなすことが多い（根拠と限界は[ハッシュの安全な設計](../string/hash-safety.md)）」。そのうえで 111 行を「1 組あたり約 $1/p$ とみなせば、$10^6$ 個の全部の組（約 $5 \times 10^{11}$ 組）でも衝突する組の数の期待値は約 $2 \times 10^{-7}$ である」に直す。確認問題の答えの「とみなすと」はそのままでよい

### 3｜直すとよい｜分かりやすさ（U6）｜#recommended-design の 116 行

- **問題**：「前の節のコードのように、$B$ をプログラムの開始時に 1 回だけ決める大域の定数にする」とあるが、直前の節は #collision-bound でコードがない。$B$ を大域の定数にしたコードは 2 つ前の #polynomial-hash にある
- **根拠**：本文の節の順（#polynomial-hash → #collision-bound → #recommended-design）
- **直し方**：「[多項式ハッシュの節](#polynomial-hash)のコードのように」とする

### 4｜直すとよい｜コード（C5）・分かりやすさ（U3）｜snippets/rolling-hash/substring-hash.cpp 400〜403 行（core に入り本文に出る。ほかの 2 片も同じ書き方）

- **問題**：`const unsigned long long B = [] { … }();` は、その場で呼ぶラムダ式で大域の定数を初期化する書き方である。手引き §9 が挙げるラムダの使い道（比較関数・DFS・判定の関数）に入らず、読者（現代的な書き方に不慣れ）には末尾の `()` の意味が分からない。本文にも説明がない
- **根拠**：手引き §1・§9。本文 116 行は「大域の定数にするとよい」とだけ書く
- **直し方**：普通の関数にする。たとえば `unsigned long long random_base() { mt19937_64 rng(…); return uniform_int_distribution<unsigned long long>(2, MOD - 2)(rng); }` と `const unsigned long long B = random_base();`。3 片をそろえる

### 5｜直すとよい｜コード（C5）｜snippets/rolling-hash/longest-repeat.cpp 365 行（core に入り本文に出る）

- **問題**：`(check(mid) ? ok : ng) = mid;` は条件演算子を代入の左辺に使う書き方で、読者には読みにくい。二分探索のほかのページの書き方ともそろわない可能性が高い
- **根拠**：手引き §9（読みやすさを優先）
- **直し方**：`if (check(mid)) ok = mid; else ng = mid;` にする
