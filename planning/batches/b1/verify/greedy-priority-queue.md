## 指摘

### 1｜直すべき｜事実（F2）・分かりやすさ（U4）｜#take-max の「同じ値はまとめる」の段落（67 行）

- **問題**：「残りの回数がそれより少なければ、$c$ 個を何段下げられるかを割り算で出し、余りは $v$ の段に足す」が誤り。残り $r$ 回で $c$ 個を $q = \lfloor r / c \rfloor$ 段下げた後、余りの $r \bmod c$ 回で得られる値は $v - q$（下げきった後の段の値）であり、$v$ ではない。書かれたとおりに実装すると、余りの分を $v$ で数えて答えが大きくなる。また、最後の値の種類の下の $v'$ を 0（楽しさが 0 以下になったら乗っても得がない）とすることが書かれておらず、最後の段で止める位置が分からない
- **根拠**：$c = 2$ 個が値 $v = 5$、次の値 $v' = 0$、残り $r = 5$ 回のとき、5・5・4・4・3 を取るので $q = 2$、余り 1 回の値は $5 - 2 = 3$。合計 21。「余りは $v$ の段」では余りを 5 と数えて 23 になる
- **直し方**：「余りの $r \bmod c$ 回は、$q$ 段下げた後の値 $v - q$ を足す」と書く。「最後の種類は $v' = 0$ まで下げる（0 以下は取っても得がない）」を一言足す

### 2｜直すべき｜事実（F2）｜#fix-max-keep-k の 1・3 段落目（113・117 行）

- **問題**：「固定した $A_i$ が実際の最大値でなくてもよい理由」の不等式（「$A_i \times$ 和は実際の値以上」）は、$A$ と $B$ の和が非負でないと成り立たない（負の数を掛けると不等号が逆になる）。条件が書かれておらず、型の説明（「$A$ の最大値と $B$ の和の積を最小にする」）は値の符号を限っていない
- **根拠**：$A = (4, 2, -2)$、$B = (3, -3, 1)$、$K = 2$ で、本文の手順は全探索の最小と違う値を返した（scratchpad/v-greedy-priority-queue/t.py の mxs_neg）。$A$・$B$ が正の範囲では 3000 ケースで一致
- **直し方**：1 段落目か 3 段落目に「$A$・$B$ が非負なら」と条件を書く（abc376_e はこれを満たす）。あわせて次の 2 点も書くとよい（U4・F2）
    - 評価するのは、ヒープに $K$ 個たまった $i$（0-indexed で $i \ge K - 1$）からであること
    - $A$ が同じ値の要素があるとき、$i^\ast$ は「最適解の要素のうち、並べた順で最も後ろのもの」と取ること（そうしないと最適解の要素が先頭から $i^\ast$ 番目までに収まらない）

### 3｜直すべき｜事実（F2）・分かりやすさ（U4）｜#k-best の 139 行と #pitfalls「列挙で同じ候補を 2 回入れる」（166 行）

- **問題**：「親を 1 つに決めにくいときは、取り出した**値**を `set` で覚えて重複を飛ばしてもよい」は、同じ値も重複して数える問題（この節の例の $a_i + b_j$ の列挙）では誤り。値で覚えると、別の組で同じ和になるもの（snippet の case の 5・5 や 0 0 0 0 0）まで飛ばしてしまう。覚えるべきなのは候補（組 $(i, j)$）である。直後の「同じ値の候補を 1 つと数える問題では、値で重複を除く」と区別しているつもりだが、前の文が「値」なので区別が読み取れない。落とし穴の「`set` で重複を除く」も、何を set に入れるかが書かれていない
- **根拠**：snippet の case `2 3 4 / 1 3 / 2 4 5` の期待 `3 5 5 6` は、値で除くと `3 5 6 7` になる。確認問題の答え（176 行）は「入れた組を `set` で覚える」と正しく書いており、本文と食い違う
- **直し方**：139 行を「取り出した（または入れた）**組**を `set` で覚えて、2 回目を飛ばしてもよい」にする。落とし穴も「入れた組を `set` で覚える」とする

### 4｜直すとよい｜分かりやすさ（U2）｜#from-last-day の 77 行（交換の議論）

- **問題**：「$x$ と $y$ の日を入れ替えてもどちらも間に合う」には、$x$ を行っている日 $d'$ が $d$ より前であること（$y$ が日 $d'$ にも間に合う理由）が要る。これは「日 $d$ より後の日は、貪欲と同じ選び方の最適解を取る」という前提から出るが、その前提が書かれていない。日 $d' > d$ なら $y$ は間に合わないことがあるので、読者は「本当に入れ替えられるか」で止まる
- **根拠**：交換の議論の標準の形（後ろの日から帰納的に、貪欲と一致する最適解を作る）
- **直し方**：「日 $d$ より後の日は貪欲と同じ選び方をしている最適解をとる。$x$ はまだ選ばれていないので、$d'$ は $d$ より前である」と 1 文足す

### 5｜直すとよい｜事実（F2）｜#regret の 154 行「一般には、選ぶ個数について答えが凸になる場合に、取り消し付きの貪欲で個数ごとの最適値が順に求まる」

- **問題**：凸であることだけでは、取り消し付きの貪欲が作れるとは言えない（凸でも取り消しの形が見つからない問題は多く、そのために Alien DP を使う）。この株の型も個数ごとの最適値を求めてはいないので、例とも合わない
- **根拠**：凸性は Alien DP（ラグランジュ緩和）が使える条件であり、貪欲の正しさの条件ではない
- **直し方**：「選ぶ個数について答えが凸になる問題の一部では、取り消し付きの貪欲で個数ごとの最適値が順に求まる」と弱めるか、「凸になる場合の一般的な扱いは Alien DP」とつなぎ方を変える

### 6｜直すとよい｜分かりやすさ（U2）｜#regret の 147 行（前から解く版の理由）

- **問題**：「入りきらなくなったときに最も安い 1 つを捨てれば、この条件を保ったまま報酬の和が最大になる（捨てる 1 つを別のものに替えても和は増えない）」は、条件を保つことは分かるが、「最大になる」の理由が括弧の中の一言で、なぜ今捨てたものを後で取り戻す必要がないかに答えていない
- **根拠**：執筆者の未解決の点。アルゴリズムは全探索と 3000 ケースで一致
- **直し方**：折りたたみで「最適解が今捨てた仕事 $z$ を含むなら、ヒープの中に最適解に入っていない仕事 $w$ があり（ヒープは $k+1$ 個を超え、最適解は条件により $k+1$ 個以下）、$z$ を $w$ に替えても条件は保たれ、$b_w \ge b_z$」の交換を足す
