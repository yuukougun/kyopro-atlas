## 指摘

1. **直すべき**・観点：fact（F1）・場所：#undo-last の最後の段落（「上書きの操作も、後ろから見ると簡単になる」）
   - 問題：「区間や集合をある値で塗る」操作について「確定した要素を集合から外していけば、各要素は 1 回しか処理されないので、全体で $O(N + Q)$ になる」と書く。区間を塗る場合は、区間の中の未確定の要素を飛ばして探す仕組み（「次の未確定の位置」を Union-Find で持つ、または std::set で持つ）が要り、単純には $O(N + Q)$ にならない（Union-Find なら $O((N + Q)\,\alpha(N))$、set なら $O((N + Q) \log N)$）。$O(N + Q)$ で済むのは、ABC477 D のように「未確定の集合の全体」を塗って空にする形のとき
   - 根拠：区間 [l, r) の塗りを逆順に処理するとき、確定済みの要素を毎回なめると、同じ確定済みの要素を何度も見るので「各要素 1 回」は成り立たない。飛ばす構造の分の手間が加わる
   - 直し方：「全体（テープのないマス全部）を塗る操作なら $O(N + Q)$。区間を塗る操作なら、次の未確定の位置を Union-Find か set で飛ばして $O((N + Q)\,\alpha(N))$ か $O((N + Q) \log N)$」のように分ける。front matter の complexity は「できることが多い」なので、そのままでもよい

2. **直すべき**・観点：fact（F2）・clarity（U3）・場所：#decide-from-back の「一意に決まる理由は「依存の向き」にある」の段落
   - 問題：「依存の矢印はすべて後ろから前へ向くので、後ろから決める順は依存を壊さない（トポロジカルソートの順の逆）」。矢印が後ろ（決めてから使われる値）から前（それを使う値）へ向くなら、後ろから決める順はその有向グラフのトポロジカル順そのもので、「逆」ではない。「逆」になるのは矢印を「i が j に依存する」の向き（前から後ろ）に取ったときで、文の中で向きの約束が食い違っている
   - 根拠：矢印 j → i（j > i、x_i が x_j を使う）のグラフで、トポロジカル順は添字の大きい順＝後ろから決める順
   - 直し方：括弧を「（この矢印の向きでのトポロジカル順）」にするか、括弧ごと消す

3. **直すべき**・観点：clarity（U8）・場所：#undo-last の確認問題「固定点がないとき」
   - 問題：見出しは「固定点がないとき」だが、問い (1, 1, 3) は最後まで固定点があり、空まで戻せて操作列 1, 1, 3 が答えになる。固定点がなくなる場面が一度も出てこないので、見出しと中身が合わない
   - 根拠：逆再生で (1,1,3) → (1,1) → (1) → () と各段に固定点がある（全探索のプログラムでも成功する）
   - 直し方：見出しを「固定点が 2 つあるとき」などに変える。または、見出しに合わせて問いを固定点がなくなる列（たとえば (1, 3, 2)：固定点は位置 1 だけで、取り除くと (3, 2) になり固定点がないので作れない。全探索のプログラムでも作れないと確かめた）に変え、答えに「作れない」を入れる。どちらにするかは執筆者に任せる

4. **直すとよい**・観点：fact（F2）・場所：#decide-from-back の第 1 段落
   - 問題：「条件 $i$ に $x_i$ より後ろの値しか出てこなければ、…条件 $i$ に残る未知数は $x_i$ だけになり」。文字どおりには $x_i$ 自身が条件に出てこないことになり、後半と食い違う
   - 根拠：例の条件 $i$ は $b_i, b_{2i}, \dots$ で、$b_i$ 自身を含む
   - 直し方：「条件 $i$ に $x_i$ と、それより後ろの値しか出てこなければ」とする

5. **直すとよい**・観点：fact（F5・F9）・clarity（U3）・場所：#challenge の ABC466 F と力試しの方針、参考の ikatakos 2 件
