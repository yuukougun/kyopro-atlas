## 指摘

### 1｜直すべき｜fact（F5）｜#arc092_a の解法の詳細、3 つ目の項目「この問題では赤どうし・青どうしの座標は異なるが、赤と青で同じ x がありうる」

- **問題**：制約では $a_1, \dots, a_N, c_1, \dots, c_N$（赤と青の x 座標を合わせた $2N$ 個）が互いに異なり、$b$・$d$（y 座標）も同様。しかも値は $0$ 以上 $2N$ 未満なので、x も y も $0$〜$2N-1$ の並べ替えになる。赤と青で同じ x はない
- **根拠**：台帳の evidence の drken「AtCoder ABC 091 C - 2D Plane 2N Point (ARC 092 C)」の制約の節（「$a_0, \dots, a_{N-1}, c_0, \dots, c_{N-1}$ はそれぞれ互いに相異なる」）
- **直し方**：「この問題では x 座標も y 座標も赤と青を合わせてすべて異なるので、同じ座標の処理順は答えに効かない。座標が重なりうる問題では、条件が『真に大きい』なので同じ x では青を先に処理する」のように、事実と一般の注意を分けて書く

### 2｜直すべき｜figure（G3・G5）｜timeline.svg の上端のラベル「クエリ t=4」「クエリ t=5」

- **問題**：2 つのラベルが中央揃えで 52px しか離れておらず、文字が重なって「クエリ t=4クエリ t=5」と読めない（等倍でも幅 358px でも重なる）
- **根拠**：full.png・narrow.png（上記の作業用の場所）。SVG の `<text x="258" y="16" text-anchor="middle">` と `<text x="310" y="16" ...>`、各ラベルは 12px で約 60px の幅
- **直し方**：ラベルを「t=4」「t=5」「t=8」と短くするか、t=4 と t=5 の高さをずらす（たとえば y=16 と y=30 にし、区間 A の線と重ならないよう上の余白を広げる）

### 3｜直すとよい｜clarity（U3）・fact（F3）｜#make-events、図の直後の段落「終了とクエリの順を逆にすると、A を余分に数えて 3 本と答えてしまう」

- **問題**：「終了 → 開始 → クエリ」の終了とクエリを入れ替えると「クエリ → 開始 → 終了」とも読め、その場合の答えは {A, B} の 2 本（本数は合うが中身が違う）で 3 本にならない。3 本になるのは「開始 → クエリ → 終了」（クエリを終了より先、開始より後）のとき
- **根拠**：座標 5 の直前の集合は {A, B}。開始 → クエリ → 終了なら {A, B, C} で 3、クエリ → 開始 → 終了なら {A, B} で 2
- **直し方**：「クエリを A の終了より先に処理すると（開始 → クエリ → 終了の順）、A を余分に数えて 3 本と答えてしまう」と順を明示する

### 4｜直すとよい｜fact（F2）・clarity（U2）｜#plane-sweep の折りたたみ「y が最大の赤い点を選んでよい理由（交換の議論）」

- **問題**：(a) 最適な組み方で $B$ がどの赤とも組んでいない場合が抜けている（$R$ が未使用なら $(B, R)$ を足せて最適に矛盾、$R$ が $B'$ と組んでいれば $R$ を $B$ に付け替えても組の数は同じ）。(b) 「$R$ が後の青い点 $B'$ と組んでいれば」とあるが、前の青い点と組んでいる場合を除く理由（それまでの貪欲の選び方と一致する最適解を取って帰納している）が書かれていない
- **根拠**：本文の場合分けは「$B$ が $R'$ と組む」の 2 通りと「$B$ が組める赤を持たない」だけ。主張そのものは乱数 600 件の比較で正しい
- **直し方**：冒頭を「前の青い点までは貪欲と同じ選び方をする最適な組み方を 1 つ取る。$R$ は貪欲で未使用なので、この組み方でも前の青い点とは組んでいない」とし、場合分けに「$B$ がどれとも組んでいない」を足す

### 5｜直すとよい｜fact（F2）｜#with-set の 1 つ目の項目「最大だけなら優先度付きキューでも書けるが」

- **問題**：直前の例は「重みの最小値」で、優先度付きキューは最小（`greater`）でも書ける。「最大だけなら」は例とずれ、最小には使えないと読める
- **根拠**：`priority_queue<T, vector<T>, greater<T>>` で最小を取り出せる
- **直し方**：「最小か最大の一方だけなら優先度付きキューでも書けるが」にする

### 6｜直すとよい｜fact（F5）・code（C8）｜#abc309_c の解法の詳細、最後の項目「`int` に収まるか制約で確かめ、迷ったら `long long` で持つ」（執筆者の未解決の点）

- **問題**：制約は $1 \le N \le 3 \times 10^5$、$1 \le a_i, b_i \le 10^9$、$0 \le K \le 10^9$ で、$\sum b_i$ は最大 $3 \times 10^{14}$ になり `int` に収まらない。「迷ったら」ではなく確定で書ける。答え $a_i + 1$ も最大 $10^9 + 1$ で `int` に収まる
- **根拠**：evidence の drken の記事は $N$ の上限だけを書き、コードで `long long` を使う。$a_i$・$b_i$・$K$ の上限は二次資料（Qiita「【AtCoder】黒〜緑のためのABC解説」https://qiita.com/ZOI_dayo/items/a55cc4342832efdc23ba の ABC309 C を検索結果の要約で確認。開いた本文ではない）。メインの判断で一次資料に近いもので確かめ直すとよい
- **直し方**：「錠数の和は最大 $3 \times 10^5 \times 10^9 = 3 \times 10^{14}$ になるので `long long` で持つ」にする

### 7｜直すとよい｜clarity（U3）｜導入「イベントの数に比例する手間で済む」

- **問題**：要点ではソートの $O(N \log N)$ と書いており、「比例する」と食い違う。言いたいのは「座標の範囲 $10^9$ ではなくイベントの数で決まる」こと
- **直し方**：「手間は座標の範囲ではなくイベントの数で決まる」にする

### 8｜直すとよい｜clarity（U4）｜#challenge の ABC128 E の方針「通行止めが時刻 $[S, T)$ なら」

- **問題**：問題では通行止めの時刻が $S - 0.5$ から $T - 0.5$ のように半端に与えられる（drken の記事の変換の前提）。読者は問題文の形からどうして $[S, T)$ になるかで止まる
- **根拠**：時刻 $D + X$（整数）が $S - 0.5$ 以上 $T - 0.5$ 以下にあることは、$S \le D + X < T$ と同値
- **直し方**：「問題の時刻の 0.5 のずれは、整数の時刻では $S \le D + X < T$（半開区間）に直る」と 1 文足す。問題文の転記にならないよう、ずれの式だけを書く

### 9｜直すとよい｜figure（G3）｜timeline.svg、幅 390px の表示

- **問題**：幅 358px に縮むと、表の文字（14px）が約 8px、目盛と上端のラベル（12px）が約 7px になり、読めるが小さい
- **根拠**：narrow.png
- **直し方**：表の部分の font-size を 16 程度に上げるか、viewBox の横幅を詰める（右の空きが大きい「処理するイベント」の列と「処理後の集合」の列の間を縮める）
