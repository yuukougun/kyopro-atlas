## 指摘

### 1｜直すべき｜事実（F2）｜#overflow の 2 段落目（「掛けてから割る」逐次計算）

- **問題**：「掛けた直後の値は答えの $k$ 倍あるので、答えが収まっても途中であふれることがある。その場合は途中を `__int128` で計算する」は、$k$ を $\min(k, n-k)$ に直す条件を落としている。$k > n/2$ のまま $k = 1, 2, \dots$ と進めると、途中の値は答えではなく行の真ん中の値まで大きくなり、`__int128` でも足りない。また「答えの $k$ 倍」は、その段の $\binom{n}{k}$ の $k$ 倍という意味で、最終の答えの $k$ 倍とは限らない
- **根拠**：Python で逐次計算の途中の最大値を測った。$\binom{1000}{998} = 499500$ は `long long` に収まるが、$k = 1 \dots 998$ と進めると途中の値は 1004 bit になり、`__int128`（127 bit）を大きく超える。$k \le n/2$ にそろえれば $\binom{n}{j}$ は $j \le k$ で増えるので、途中の値は $k \binom{n}{k}$（最終の答えの $k$ 倍）以下に収まり、答えが `long long` に収まるなら $k \le 33$ 程度で `__int128` に収まる
- **直し方**：「先に対称性で $k$ を $\min(k, n-k)$ にしておく。すると途中の値は最終の答えの $k$ 倍以下になる。それでも答えが収まって途中があふれることはあるので、途中を `__int128` で計算する」のように、対称性の一言を足して「答えの $k$ 倍」を「最終の答えの $k$ 倍以下」に直す。使い分けの表の 2 行目にも「$k$ を $\min(k, n-k)$ にして」と添えるとよい

### 2｜直すとよい｜事実（F2）・分かりやすさ（U3）｜#pascal の「mod を取らない正確な値」の箇条

- **問題**：「途中の値が最終の値より大きくならないので」は、1 回の足し算の中では正しいが、表を作る方法としては誤解を招く。$\binom{n}{k}$ を引くために $n - 1$ 行までの表を作ると、途中の行の真ん中の値は答えよりずっと大きくなる。たとえば $\binom{100}{2} = 4950$ でも、100 行の表には $\binom{99}{49} > 2^{63}$ が入る
- **根拠**：`math.comb(99, 49) > 2**63` は True
- **直し方**：「足し算だけで掛け算がないので、表のどの値も `long long` に収まる範囲（[次の節](#overflow)で $n \le 66$）なら途中であふれない」のように、条件を「答え」ではなく「表のすべての値」に置く。答えが小さくても $n$ が大きければ表は使えないことは、落とし穴「表の大きさが足りない」とつながる

### 3｜直すとよい｜分かりやすさ（U4）｜#kth の「逆に、与えられた列が何番目か」の段落

- **問題**：(a)「$\binom{\text{残りの長さ}}{\text{残りの 1 の数}}$」の「残りの 1 の数」が、その位置の 1 を含むのか含まないのかが読み取れない。正しくは含む数（そこを 0 にすると、その 1 も後ろに置くことになる）で、含まない数と読むと値がずれる。(b) 足した和に 1 を足して 1 始まりの順位にすることが書かれていない（コードは `r = 1` から始める）。(c)「そこを 0 にした列」は「そこより前は同じで、そこを 0 にした列」でないと「すべて前に来る」が成り立たない
- **根拠**：kth.cpp の rank_of は `binom(n - i - 1, k)` で、k はその位置の 1 を含めた残りの 1 の数。1001 では 1 + C(3, 2) + C(0, 1) = 4 で、和だけなら 3（0 始まりの順位）になる
- **直し方**：「先頭から見て 1 がある位置ごとに、そこより前は同じでそこを 0 にした列はすべて前に来る。その個数は、後ろの長さを $m$、この位置を含めてまだ置いていない 1 の数を $j$ として $\binom{m}{j}$ である。これらの和が前にある列の数なので、1 始まりの順位はその和に 1 を足したもの」とする。$n = 4$ の 1001 で 1 行の計算例（$1 + 3 + 0 = 4$）を添えると手順の確認になる

### 4｜直すとよい｜分かりやすさ（U3）｜#meanings の表の後の段落

- **問題**：「$i \in S$ なら $i$ 文字目を 1」は、集合が $\{0, \dots, n-1\}$ なので 0 文字目から数えるはずだが、ふつう「$i$ 文字目」は 1 から数えるので迷う。また表の 1 行目どうし（$\{0,1\}$ と 0011）が対応していないため、表の並びが対応の例だと誤読しやすい（$\{0,1\}$ に対応するのは 1100）
- **直し方**：「先頭を 0 文字目として、$i \in S$ なら $i$ 文字目を 1 にする（たとえば $\{0, 1\}$ は 1100）」と例を 1 つ添える。表の各列は辞書順などそれぞれの順で並べただけで、行どうしは対応しないと一言書くか、列の並びを対応させる
