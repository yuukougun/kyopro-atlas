## 指摘

### 1｜直すべき｜事実（F2）・分かりやすさ（U3）｜#pitfalls「K < μ を分けない」

- **問題**：「$(K - \mu) \bmod \lambda$ は負の数の剰余になり、C++ では負の添字を読む」とあるが、負の添字にはならない。C++ の `%` は 0 方向へ丸めるので $-(\mu - K) < (K - \mu) \% \lambda \le 0$ で、絶対値は $\mu - K$ 以下。したがって $\mu + (K-\mu)\%\lambda \ge K \ge 0$ になり、範囲内の**別の項**を黙って読む（例：$\mu = 10$、$\lambda = 3$、$K = 0$ で $(-10) \% 3 = -1$、番号 9 を読む。正しくは 0）。落ちずに答えだけ違うので、見つけにくさはむしろ大きい
- **根拠**：上の全数の確認（負になる組 0、違う番号になる組 4495）
- **直し方**：「C++ の `%` は 0 方向へ丸めるので $(K - \mu) \% \lambda$ は 0 以下になり、尾の中の別の項を読む（落ちずに答えだけずれる）」のように書き換える。$\mu - K < \lambda$ のときはたまたま $K$ 番目を読むので、小さな例では気づきにくいと添えるとよい

### 3｜直すべき｜事実（F5）｜#practice 典型90 058 の要約（台帳 typical90_bf の summary）

- **問題**：「各桁の和を足す操作を K 回行った後の値を求める」には「10^5 で割った余りに置き換える」が抜けている。実際の操作は $x \to (x + \text{桁和}(x)) \bmod 10^5$ で、余りを取らなければ値は増え続け、状態は有限にならない（答えも違う）。練習の方針の「表示される値は $10^5$ 未満」が要約から読めない
- **根拠**：E869120 の sol/058.cpp の `nxt[i] = (i + digit_sum(i)) % mod`（mod = 100000）
- **直し方**：執筆者の提案（報告の「台帳への提案」）のとおり、台帳の summary を「表示された値にその各桁の和を足して 10^5 で割った余りに置き換える操作を K 回行った後の値を求める。」に直し、fix_problems で本文に反映する。evidence に sol/058.cpp と Reputeless の 058.md の個別の URL を足すとよい

### 8｜直すとよい｜事実（F2・F3）｜#convergence

- **問題**：(a)「値が単調に減る操作や、0 になったら止まる操作は…数十回で固定点に入ることが多い」は、1 ずつ減る操作では成り立たない。数十回で済むのは「半分以下になる」「桁数が減る」など減り方が速いときである。(b)「$10^{15}$ 回後」は ABC106 C の 5000 兆 = $5 \times 10^{15}$ 回と食い違う（主張は変わらないが、例に結び付けるならそろえる）
- **直し方**：(a)「値が毎回半分以下になる・桁数が減るなど、速く小さくなる操作は」と条件を書く。(b)「$5 \times 10^{15}$ 回後」とする
