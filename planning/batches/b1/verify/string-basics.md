## 指摘

### 1｜直すべき｜事実（F3）・計算量（F1）｜#cost-pitfalls、185 行「$N = 2 \times 10^5$ 文字の答えを `ans = ans + c` で作ると…TLE する」

- **問題**：この大きさでは TLE しない。コピーの合計は約 $2 \times 10^{10}$ 文字で計算は正しいが、コピーされる文字列が 200KB 以下でキャッシュに収まり、memcpy が速いので 1 秒を切る。読者が試すと主張が外れる
- **根拠**：手元（i7-13700、g++-15 `-O2`）で $N = 2 \times 10^5$ は 0.67 秒、$5 \times 10^5$ は 4.3 秒、$10^6$ は 20.1 秒
- **直し方**：例の大きさを $N = 10^6$（コピーの合計 約 $5 \times 10^{11}$ 文字）にするか、「$2 \times 10^5$ ではメモリのコピーが速く間に合うこともあるが、$5 \times 10^5$ を超えると数秒かかる」のように、確かめた範囲で書く。どちらでも「`ans += c` に変えるだけで直る」はそのまま使える

### 2｜直すとよい｜計算量（F1）・分かりやすさ（U3）｜#rotation、169 行「素朴に行うと $O(N^2)$ かかる。$N$ が $10^5$ を超えるなら、線形時間の文字列検索…」

- **問題**：$N = 10^5$ ちょうどでも $O(N^2) = 10^{10}$ で、見積もりの目安（$10^8$ 程度）からは間に合わない側である。同じページの「$N \le 5000$ 程度なら $O(N^2)$」と境目がずれ、$10^5$ までは素朴でよいと読める
- **根拠**：計算量の見積もりの目安。なお `std::string::find` は定数が小さく、手元では $10^{10}$ 回相当の最悪ケースが 0.18 秒だったので、実際に落ちるかは場合による
- **直し方**：「$N$ が $10^4$ を超えるなら」か「$N$ が大きい（$10^5$ 程度）なら」にし、必要なら「`find` は最悪の計算量が保証されない」と表の行へつなぐ

### 3｜直すとよい｜計算量（F1）｜#substring-vs-subsequence、87 行「$N \le 5000$ 程度なら位置の組 $(l, r)$ を全部試せる」

- **問題**：組の数は $O(N^2)$ だが、各組で部分文字列を作ったり比べたりすると $O(N^3)$（$N = 5000$ で約 $2 \times 10^{10}$）になる。「全部試せる」は各組の処理が $O(1)$（ならし）の場合だけ
- **根拠**：組 $N(N+1)/2 \approx 1.25 \times 10^7$ に、長さ平均 $N/3$ のコピーか比較が掛かる。同じ段落の後半（ARC097 C）で長さを $K$ 以下に絞っているのも、この理由である
- **直し方**：「各組の処理が $O(1)$（右端を 1 つずつ伸ばして更新するなど）なら、$N \le 5000$ 程度で全部の組を試せる。組ごとに部分文字列を作ると $O(N^3)$ になる」とする

### 4｜直すとよい｜出典（F8）｜#concat-order 124 行と確認問題「b と ba」、例題の方針

- **問題**：長さが違うと誤る例 `b`・`ba`（`bba` と `bab`）は、参考に挙げた drken の ABC042 B の記事の例とそのまま同じである（F8「記事の例をそのまま使う」）。本文と確認問題の 2 か所で使っている
- **根拠**：drken「AtCoder ABC 042 B - 文字列大好きいろはちゃんイージー」の反例が `b` と `ba`
- **直し方**：例を独自のものに替える。たとえば `c` と `ca`（ソートすると `cca`、逆は `cac` で小さい）や `ab` と `aba`（`ababa` と `abaab`）。snippets の cases に `2\nb\nba\n` があるのは構わないが、本文の例に合わせて足すとよい

### 5｜直すとよい｜事実（F2）｜#lexicographic-order、56 行「空文字列はどの文字列よりも小さい」

- **問題**：空文字列は空文字列自身より小さくない。厳密には「空でないどの文字列よりも小さい」
- **根拠**：同じ行の規則（$S$ が $T$ の接頭辞で $S \ne T$ なら $S < T$）
- **直し方**：「空文字列は、空でないどの文字列よりも小さい」にする

- **直し方**：表の後の文で「`string_view` の寿命の注意は[文字列の操作](../cpp/cpp-string-api.md#string-view)」とリンクするか、表の `string_view` をリンクにする（見出しではないので可）

### 8｜直すとよい｜分かりやすさ（U3・U6）｜#rotation の記号

- **問題**：節の前半は $S$（長さ $N$）で回転を定義し、165 行から説明なしに $A$・$B$ に替わる。さらに同じページの練習の方針（ABC286 C）では $A$・$B$ がコストを表し、断片で読むと記号が衝突する
- **根拠**：U3「定義の前に記号を使う」、U6「節の中で定義のない記号」
- **直し方**：165 行を「文字列 $A$（長さ $N$）を 2 つつないだ…」とし、「$B$ は $A$ の回転か」の前に「長さ $N$ の文字列 $B$ が」と置く。あるいは節を通して $S$・$T$ で書く

### 9｜直すとよい｜事実（F2）｜#rotation、169 行「辞書順で最小の回転も、$A + A$ の Suffix Array を使うと…求まる」

- **問題**：正しいが、どの接尾辞を見るか（開始位置が $N$ 未満のもの）がない。開始位置が $N$ 以上の接尾辞は長さ $N$ 以下で、回転そのものではない
- **根拠**：開始位置 $i < N$ の接尾辞は長さ $2N - i > N$ で、先頭 $N$ 文字が $i$ 回転に一致する。回転の大小が違えば接尾辞の大小も同じ向きになるので、開始位置 $N$ 未満のうち最小の接尾辞が最小の回転を与える
- **直し方**：「$A + A$ の Suffix Array で、開始位置が $N$ 未満の接尾辞のうち最小のものを選ぶと」と一言足す

### 10｜直すとよい｜事実（C8 の観点を練習に）｜練習の方針 ABC286 C、231 行

- **問題**：答え $A k + B \times (\text{違う組の数})$ は $A$・$B$ が大きいと `int` に収まらない。基礎の読者が `int` で書いて落とす典型
- **根拠**：evidence の drken の記事のコードは $N$・$A$・$B$・コストを `long long` にしている（記事は制約の値を書いていないので、制約の数値自体は確かめていない）
- **直し方**：方針の末尾に「コストは `long long` で数える」を足す

## 確かめて問題がなかった主な点

- 計算量：front matter・要点・本文で、比較 $O(\min(\lvert S \rvert, \lvert T \rvert))$・回転の全探索 $O(N^2)$・連結の順のソート $O(L N \log N)$ が一致し、根拠も本文にある。`+=` のならし $O(1)$、`set<string>` の挿入 $O(L \log N)$ も正しい
- 文字の一斉置換：入れ替えの操作なら全単射が必要十分であることの説明（並べ替えに広げる・互換で作れる）は正しく、反例 `ab`→`cc` も正しい。片道の置き換えは条件が変わることを書き、正確な条件には踏み込まない判断（執筆者の未解決の点）は、基礎のページとして妥当
- 連結の比較関数の証明：$v(a + b) = v(a) B^{\lvert b \rvert} + v(b)$ からの同値変形、$f$ による推移律、隣の入れ替えで大きくならないこと、同等なものの順が結果を変えないことまで筋が通る。空文字列を除く条件も書かれている（空文字列があると同等関係が推移的でなくなるので必要な条件）
- 「$N$ 個から $K$ 個選ぶ型はソートの後に DP」：選んだものの最適な順はこの比較の順なので、ソートした列から部分列を選ぶ DP になり正しい
- 回転：$k$ 回転の $i$ 文字目 $S[(k + i) \bmod N]$、回転と書き換えの順の入れ替え、$A + A$ の窓、開始位置 $N$ を数えない注意は正しい
- コード片：本文の記号（`to`・`from`、添字 $(k + i) \bmod N$、`a + b < b + a`）と一致。取り込みは要点の数行で、`main` と assert のある完全なプログラム。cases に 1 要素・全部同じ文字・同等な文字列・片方向だけ一意の入力がある。`bits/stdc++.h`・`using namespace std;`・`'\n'` の決まりどおり
- 構成：基礎の technique の目安（応用の型・落とし穴・上位の手法とのつながり → 問題）に沿い、「使い分け」を例題の前に置くのも基礎の目安と合う。各節は冒頭の文で何の話かが分かり、断片で読める（指摘 8 を除く）。確認問題 3 つは理由まで答えにある
- 例題の方針は本文の concat-order の節だけで解き始められ、詳細は折りたたみにある。練習の要約は問いだけで、方針は折りたたみにある
- 図の内容：compare.svg の 2 例（abca と abd、ab と abc）・rotation-window.svg の 4 つの窓は本文・代替テキストと一致。catalog の visual（priority 2・static、「接頭辞が小さいことを空文字との比較で示す」）を compare.svg が満たす
