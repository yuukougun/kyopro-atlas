## 指摘

### 1. 直すべき｜事実（F2）・分かりやすさ（U3）｜#why-log の第 1・2 段落と囲みの主張、例題 abc329_f の方針

- **問題**：導入の例では、箱の中身を「色の集合」で持つ。ところが、そのすぐ後の「要素 x が移るとき、x の入っている集合の大きさは 2 倍以上になる」は、色の集合の大きさでは成り立たない。同じ色が重なると、併合後の大きさは a + b より小さくなる。例題 abc329_f の「色の移動は合計 N log₂ N 回以下」も、この議論をそのまま当てはめた形になっている。
- **根拠**：反例を挙げる。s_a = {1,2,3,9}（大きさ 4）、s_b = {1,2,3,4,5}（大きさ 5）とする。色 9 は移るが、移った後の集合は {1,…,5,9} で大きさ 6 < 2×4 になる。全体の上限そのものは正しい。1 回の手間 min(|s_a|, |s_b|) は「2 つの箱のボールの個数の小さい方」以下である。ボールの個数は併合で足し算になるので、ボールについては 2 倍の議論がそのまま成り立つ。よって合計は N log₂ N 以下である（折りたたみ「別の言い方」の min(a, b) の形）。
- **直し方**：#why-log の 2 倍の議論は「重なりのない集合（ボールそのもの・頂点そのもの）」の話だと明記する。そのうえで、色の集合のように重なりがまとまる場合を 1〜2 文で足す。中身は「1 回の手間は、小さい方の箱のボールの個数以下である。ボールの個数で上の議論を使えば、合計は同じ上限になる」。いまの折りたたみの内容を本文に出し、abc329_f の方針の「N log₂ N 回以下」の根拠もそこへ向ける。

### 2. 直すべき｜図（G5・G3）｜doubling.svg の 1 回目と 2 回目のラベル

- **問題**：バーの下のラベルが重なって読めない。1 回目は「x の側 1」（x=114）と「相手 1（1 ≥ 1）」（x=130）、2 回目は「x の側 2」（x=114）と「相手 3（3 ≥ 2）」（x=140）が重なる。font-size 12 の「x の側 1」は幅およそ 45px なので、16〜26px の間隔では収まらない。
- **根拠**：ヘッドレスの Chrome で描画した PNG で、2 行とも文字が重なっていた。3 回目（114 と 170）と 4 回目（114 と 240）は重ならない。
- **直し方**：「相手」のラベルを 2 段目（y を +16）に下げるか、バーの右端の外へ置く。または、全行で「x の側」をバーの左（x=40 付近）に、「相手」を各行の右側にまとめる。左には行の見出し「1 回目」があるので、その下の段に置いてもよい。

### 4. 直すとよい｜分かりやすさ（U7）・事実（F5）｜練習の方針 ABC394 G

- **問題**：質問の 2 つの建物が同じとき、「2 つの建物が初めてつながる高さ h」が併合の過程で決まらない。方針を読んだ読者は、答えを出しそこねる。執筆者も未解決の点に挙げていた。
- **根拠**：kmjp の解説は、同じ建物の質問を別に扱い、|S−E| と答える。
- **直し方**：方針の最後に「同じ建物の質問は、併合を待たずに |Y − Z| と答える」の 1 文を足す。

### 5. 直すとよい｜分かりやすさ（U4）｜#dsu-on-tree の最頻値の段落

- **問題**：最頻値の段落は「足すときは freq を動かして」とだけ書いている。引くときに freq も 1 つずつ減らす（または 0 に戻す）ことが書かれていない。「mx = 0 に戻せばよい」だけを読むと、freq を残したままにしてしまう。
- **根拠**：本文の手順を擬似コードにすると、cnt と freq を引く処理が抜ける。cnt を戻しても freq が残ると、次の部分木で freq[k] が多めに数えられる。
- **直し方**：「引くときは cnt と freq を 1 つずつ戻し、全部引き終えたら mx = 0 にする」と書く。

### 6. 直すとよい｜事実（F5）｜力試しの方針 ABC454 G の「N が 2.5 × 10^6 まで」

- **問題**：上限の値を確かめられなかった。ikatakos の記録は 503 で読めなかった。kmjp の記事には制約の記述がない。コードの配列の大きさは 3.03×10^6 で、矛盾はしない。入力の一部を擬似乱数で生成する形式（N state M F）であることも、方針から読み取れない。
- **根拠**：kmjp https://kmjp.hatenablog.jp/entry/2026/04/19/0900 の配列の大きさと入力の読み方。
- **直し方**：メインか次の検証で ikatakos の記録をもう一度読み、値を確かめる。確かめられなければ「N が数百万まであり」とぼかす。

### 7. 直すとよい｜事実（F5）｜練習の方針 ABC314 F の「答えは mod で求める」

- **問題**：Kazun の記事に、出力の法が書かれていない。執筆者も未解決の点に挙げていた。確率の比 a/(a+b) を逆元で扱う形なので、mod で求めるのは確からしい。ただし、資料で裏付けられていない。
- **根拠**：https://kazun-kyopro.hatenablog.com/entry/ABC/314/F の解法は、Γ・δ の加算と、成分サイズの比を使う。法の記述はない。
- **直し方**：法を書いた別の解説（付録 B のドメイン）で確かめる。確かめられなければ、「答えは mod で求める」の 1 文を消す。消しても方針は成り立つ。

### 8. 直すとよい｜分かりやすさ（U3）｜#subtree-merge 第 2 段落「小さい方の map の項目数は、小さい方の部分木の頂点数以下」

- **問題**：項目数で小さい方の map が、頂点数で小さい方の部分木のものとは限らない。そのため、この文は一読では飛躍に見える。主張そのものは正しい。min(項目数_A, 項目数_B) ≤ 小さい部分木の側の項目数 ≤ 小さい部分木の頂点数、だからである。確認問題 4 の答えも同じ書き方である。
- **根拠**：上の不等式の連鎖。
- **直し方**：「項目数の小さい方は、どちらの map の項目数以下でもあるので、頂点数の小さい方の部分木の頂点数以下でもある」と 1 段足す。
