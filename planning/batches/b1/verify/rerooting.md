## 指摘

### 1｜直すべき｜事実（F3）｜#abc222_f、「解法の詳細」の 4 つ目「値は $2 \times 10^5 \times 10^9$ を超えうるので `long long` で持つ」

- **問題**：答えは $2 \times 10^5 \times 10^9$ を超えない。最遠の値は「辺 $N-1$ 本ぶんの距離 ＋ 行き先の費用」で、$(N-1)\cdot 10^9 + 10^9 = N \cdot 10^9 \le 2\times10^{14}$ が上限である。超えるのは `int`（約 $2.1\times10^9$）の範囲である
- **根拠**：Kazun 氏の記事の制約 $N \le 2\times10^5$、$C_i, D_i \le 10^9$
- **直し方**：「値は最大で約 $2 \times 10^{14}$（$N \times 10^9$）になり `int` に収まらないので `long long` で持つ」とする

### 2｜直すとよい｜分かりやすさ（U3・U6）・図（G5）｜#what-changes の図 what-changes.svg のラベル「dp[2]：部分木 {2, 4, 5}」「dp[3]：部分木 {3, 6}」「dp[4]・dp[5]」「dp[3]」

- **問題**：(a) 図は #framework より前にあり、$\mathrm{dp}$ はまだ定義されていない。(b) #framework では $\mathrm{dp}[v]$ を「$v$ の子の側の値をすべて合成したもの」（$v$ 自身は含まない）と定めるので、「dp[2]：部分木 {2, 4, 5}」は後の定義とずれる。部分木 {2, 4, 5} の値は $\mathrm{add\_root}(\mathrm{dp}[2], 2, 1)$ である。読者が後の節で「dp[2] は {2,4,5} の値だったのでは」と迷う
- **根拠**：本文 72〜74 行の add_root と $\mathrm{dp}$ の定義、図の text 要素
- **直し方**：図のラベルを「頂点 2 の部分木 {2, 4, 5}」「頂点 3 の部分木 {3, 6}」「頂点 4・5 の部分木（同じ）」「頂点 3 の部分木」のように $\mathrm{dp}$ を使わない書き方にする（代替テキストはすでに dp を使っていないので、そのままでよい）

### 3｜直すとよい｜事実（F2）・分かりやすさ（U3）｜#framework の $\oplus$ の説明（71 行）と #exclude-self の「逆元や交換法則は使わない」（142 行）

- **問題**：71 行は「子の順番によって結果が変わらないもの」（交換法則）を求め、142 行は「交換法則は使わない」と言う。142 行は左右の累積そのものについては正しいが、枠組み全体では交換法則が要る（$\mathrm{dp}$ の合成は BFS の逆順、$\mathrm{ans}$ と $\mathrm{up}$ は隣接リストの順で合成し、親の分も途中に入るので、根によって合成の順が変わる）。並べて読むと矛盾に見える。また「木 DP の合成なら何でも使える」は言い過ぎ
- **根拠**：コード片 280 行（`dp[par[v]] = merge(dp[par[v]], …)` を逆 BFS 順）と 288〜292 行（`g[v]` の順に val を並べる）。非可換な合成では根ごとに順が変わり、値が根付き木の DP と一致しない
- **直し方**：142 行を「左右の累積そのものは結合法則と単位元だけを使い、逆元は使わない（交換法則は枠組み全体で子の順を問わないために要る）。だから結合法則と交換法則を満たす合成なら $\max$・$\min$・…・組でも使える」のようにする

### 4｜直すとよい｜事実（F7）｜#exclude-self の確認問題の答え「XOR も同じく $S \oplus a_c$ で除ける」

- **問題**：このページでは $\oplus$ を「子の側の値の合成」の記号として定義しているので、XOR を同じ $\oplus$ で書くと、「合成で除ける」と読める（合成が $\max$ なら誤り）
- **根拠**：71 行の $\oplus$ の定義
- **直し方**：「XOR も、総和 $S$ と $a_c$ の XOR を取れば除ける」と文章で書くか、$S \mathbin{\mathrm{xor}} a_c$ と書く

### 5｜直すとよい｜事実（F2）｜#what-changes、「どの頂点を根にしても、現れる部分木はこの $2(N-1)$ 個のどれかである」（63 行）

- **問題**：根そのものの部分木（木全体）は $2(N-1)$ 個に入らない。直後の「全部を 1 度ずつ求めれば、すべての根の値がそろう」の根拠としては、「根以外の頂点の部分木は」が正確
- **根拠**：根 $v$ の木全体は辺を切って得られる集合ではない。確認問題（241 行）の答えは「全体が変わるのを除けば」と正しく書いている
- **直し方**：「どの頂点を根にしても、根以外の頂点の部分木はこの $2(N-1)$ 個のどれかで、根の値はそれらを合成すれば出る」とする

### 6｜直すとよい｜分かりやすさ（U4）｜#framework の $\mathrm{ans}[v]$ の式（91 行）

- **問題**：$\mathrm{up}[c]$ の式には「最後の項は $p$ が根 $r$ のときはない」と断りがあるが、$\mathrm{ans}[v]$ の式の最後の項 $\mathrm{add\_root}(\mathrm{up}[v], \mathrm{par}[v], v)$ にはない。$v = r$ では $\mathrm{par}[r]$ がなく、読者が擬似コードを書くときに迷う（コードは `par[0] = -1` と隣接リストの比較で自然に除いている）
- **根拠**：88 行と 91 行
- **直し方**：91 行の式の後に「$v$ が根 $r$ のときは最後の項はない」と足すか、88 行の断りを両方の式にかかる形にする

### 8｜直すとよい｜事実（F5）｜#practice の TDPC N

- **問題**：方針は正しい（上の総当たりで確認）が、N の上限が確かめられていない。上限が小さい（$O(N^2)$ で間に合う）なら、この問題は全方位木 DP を要さず、ページの練習としては「全方位でも書ける」程度の位置づけになる。本文は「根ごとにやり直せば $O(N^2)$、全方位木 DP にすれば $O(N)$」とだけ書いており誤りではない
- **根拠**：sigma425 氏の記事は「根を全部試す」と書き、N の上限も 2 で割ることも書いていない。台帳の approach も「すべての根について木 DP する（全方位でも書ける）」
- **直し方**：メインが制約を確かめられる資料（付録 B のドメインの解説）で N の上限を確かめ、$O(N^2)$ で足りるなら方針に「制約が小さいので根ごとのやり直しでも間に合う」と 1 文足す。台帳の checked は、方針の正しさは確かめたが問いと制約は資料で確かめていないので、執筆者の提案どおりに入れるかはメインの判断に任せる
