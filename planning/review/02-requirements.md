# 設計の見直し 02：要件との照合・技術・制作の運用

工程4（設計の見直し）の成果物の1つ。設計書（[../design.md](../design.md)、2026-10-21 初版）と目次（[../catalog/](../catalog/)）を、要件（[../requirements.md](../requirements.md)）と決定事項（[../decisions.md](../decisions.md)）に照らして批判的に読んだ。

- 観点：要件と決定事項の照合、技術の実現性、claude.ai での解説と記録のスキル、制作の運用、設計書 §11 にないリスク
- 方法：文書を読んだうえで、技術の論点は一時ファイル置き場で実際に試した（Material 9.7.7・Zensical 0.0.71・Cytoscape.js 3.34＋dagre・g++-15・ヘッドレスの Chromium。条件と数値は付録 A）。リポジトリのファイルはこの文書のほかは変えていない
- 見直し01（学習者）・03（目次のデータ）と重なる事実は、該当する指摘の中でそう書いた。目次の個々の項目の当否は03に任せる

## まとめ

- 照合表：112項目のうち、満たす87・不足15・矛盾6・未定4
- 指摘：27件（重大2・中15・軽10）。最も重要な3つ：
  1. 使用量（トークン）と期間の見込みがなく、測る計画もない（指摘1）。規模は367ページ・問題の枠1,501・サブエージェントの実行が千回前後の見込み
  2. 問題の内容の裏付けを1か所で管理する仕組みがない（指摘2）。異なる問題1,158の確認が執筆と検証で重複し、research で「未確認」の問題が catalog に入っていても機械では止められない
  3. 367ページの規模で試すと、知識マップの全体図は外形が約27:1で読めず、related を描くと配置に42秒かかる。検索も、14ページで測った「30問中29問」が当てはまらない（指摘3・4）
- 実測で動くと確かめた方法（設計の未定の点に使える）：テンプレートで他ページの front matter を読む方法（前提・次に読むの表示）、生成した nav を `INHERIT` で読む方法、`overrides/` に静的ファイルを置く方法は、Material と Zensical のどちらでも動いた。Zensical への備え（独立スクリプト、hooks・プラグインを使わない）は妥当
